# opencode free models: limits, errors, fallback (research note)

Read date for every source: 2026-11-16. Local tool: opencode v2.3.0 (`opencode --version`).

Labels: `verified` = primary source (opencode docs, opencode repository PR or issue text written by maintainers, or a live check on this machine); `reported` = secondary source (user issue comment, forum, blog, bot comment); `inferred` = my reasoning, with the basis named.

Method note: pages were read through a fetch tool that summarises with a small model, so quotes are close but not guaranteed byte-exact. Re-read the linked page before quoting in code or docs. GitHub repository path is now `anomalyco/opencode`.

## Summary: what to do (with confidence)

1. Treat the free pool as one shared, server-enforced, daily-style quota per user or IP, not per model. Switching to another free model does not help (reported by several users, 2026-11-16; maintainers say the limit is "decided by the hosted free tier service"). Confidence: medium-high.
2. Detect the limit from the headless JSON event `{"type":"error","error":{"type":"provider.free-limit","status":429,"retryAfterMs":N,...}}` (verified shape from the typed-error PR, and a reported live sample from opencode 2.2.5). Your 2026-11-16 observation (429, about 6 h 44 min) matches that shape. Confidence: high for the shape, medium that it holds in every 2.x version.
3. Set `blocked_until = now + retryAfterMs` (the value is derived from the HTTP `Retry-After` header, verified in the PR). Every value seen in sources is under 24 h (3.6 h to 17.9 h; one Retry-After of 84692 s, about 23.5 h). So "stated reset" is always shorter than the owner's "24 hours" rule of thumb. Confidence: high that it is shorter; the 24 h rule is a safe upper bound, not what the server says.
4. Do not trust the stated reset blindly. Several users report the quota still blocked after the stated reset, or a reset time that moves day by day with no use (reported, issues #62593, #58995, #52894, #59387). Use a two-step rule: retry once at `retryAfterMs` plus a small margin; if that retry returns `provider.free-limit` again, block for 24 h from that second error, and after a third failure for a further 24 h or until the user re-enables the lane. Confidence: medium (inferred from the reports).
5. On `provider.free-limit` the lane is "usage-limited", not "broken": fall back to the next lane, never retry in a loop, and do not count it as a transient error. Maintainers' own advice: wait for the displayed reset, subscribe to OpenCode Go, or connect another provider (verified, pinned maintainer post #59387, 2026-10-26).
6. The free list is volatile ("limited time", deprecations). A free lane must be re-validated against `opencode models` at run time, and "model not found" must also mark the lane unusable (with a different reason from usage-limited). Confidence: high.

- Inference for the owner: the list changes on a weeks scale, so never persist a "this model is free" fact across runs without re-checking `opencode models`.

## 2. Stated usage limits, who sets them, data use

- verified (docs): the only numeric limit on the Zen page is LongCat 2.5 Free, "limit of 100 requests per day". No other free model has a stated number there. Beam Free and Inkling 2 Small Free are unavailable in several countries. "Free-tier chat models require OpenCode; use paid models or Go from other clients." Source: https://opencode.ai/docs/zen/.
- verified (docs): the Go page lists free models as "Unlimited" per period and does not mention a daily cap. This contradicts observed behaviour (see below), so treat "Unlimited" as marketing for the Go meter, not as the free-pool rule. https://opencode.ai/docs/go/
- reported: a user count of about 200 requests per day shared across free models (issues #33495, #33318, 2026-06 to 2026-10; no maintainer confirmed the number). A maintainer said free models "have their own limit and never draw on Zen balance" (issue #45324 as quoted in #42500, 2026-10-19), and that adding credits or signing in does not raise it (issue #43786, 2026-10-20). https://github.com/anomalyco/opencode/issues/33495 and https://github.com/anomalyco/opencode/issues/43786
- verified (maintainer statement): limits are enforced by the hosted free-tier service; billing and account problems go to the support mailbox, not GitHub. Pinned post by a maintainer, 2026-10-26: https://github.com/anomalyco/opencode/issues/59387
- reported / contradictory scope: one maintainer reply said limits apply "per IP address" (#43786, 2026-10-20); another issue author read the code as keyed by IP and by API key (#57540); the support route says "per account and network". Scope is not documented ("pool scope" documentation was requested in #57540, closed not planned 2026-11-12). Label for scope: reported, unresolved.
- reported: the pool is shared across free models. Users on 2.3.0 say switching free models gives the same block (#59387 comments, 2026-11-16). One user saw different displayed reset times per model (08:56 for Hy4 Flash, 08:24 for DeepSeek V4.1 Flash), which suggests per-model clocks, not proof of per-model quotas.
- reported: upstream-vendor limits are not what is applied here; the Zen gateway sets the limit ("set and enforced by the Zen console", bot comment, #58205, 2026-10-22). Label: reported (bot, not a named maintainer).
- verified (docs), data use, per model: general rule is zero retention and no training "with the following exceptions". Exceptions: Big Pickle (may be used to improve the model during the free period); Iceman Free and Iceman Contributor Free (retained and used to improve the model); Inkling 2 Small Free (retained, used for monitoring and training); Flint 40B Free (used to improve, retained 30 days); MiMo-V2.6-Flash Free (used to improve during free period); Nemotron 3 Ultra, 3.5 Lightning and 3.5 Super VL (NVIDIA trial endpoints, "do not submit personal or confidential data", logged); Beam Free (no training, 30-day retention); LongCat 2.5 Free (hosted in China; Go docs: requires Global regions in workspace privacy settings). GLM-5.3-Flash, DeepSeek V4.1 Flash, MiniMax M3.1 Flash and Hy4 flash Free: zero retention, no training. Sources: Zen docs and Go docs.
- Inference for the owner: a review lane sends repository diffs and plans, so only models in the zero-retention group (GLM-5.3-Flash Free, DeepSeek V4.1 Flash Free, MiniMax M3.1 Flash Free, Hy4 flash Free) should be offered by default; the others need a visible data-use warning in the picker. LongCat 2.5 Free also has the 100 requests per day cap and a region setting.

## 3. Errors at the limit, removed models, visibility, detection

### Limit reached

- verified (PR text): opencode 2.x maps the Zen 429 body `error.type == "FreeUsageLimitError"` to a typed session error `provider.free-limit` with an optional non-negative integer `retryAfterMs`. `retryAfterMs` comes from the 429 response `Retry-After` header; the body is used only to detect the type. Paid `opencode` 429s stay retryable `provider.rate-limit`; `GoUsageLimitError` stays non-retryable `provider.quota`. Fallback message: "Free usage limit reached. Connect a provider or subscribe to OpenCode Go to keep going, or switch models." Merged into `dev` 2026-10-20 (commit a9fa57b), no version stated. https://github.com/anomalyco/opencode/pull/57146
- verified (PR text): an earlier change classifies Zen codes `GoUsageLimitError`, `FreeUsageLimitError`, `CreditLimitExceeded` as quota errors, HTTP 402 as `QuotaExceeded`, and `RegionUnavailable` and `ModelNotFound` (HTTP 400) as `server_error`; it states `FreeUsageLimitError` carries a `retry-after` "up to 24h". Merged to `v2` 2026-09-16 (commit 4a27842). https://github.com/anomalyco/opencode/pull/49195
- reported (live sample from `opencode run --format json`, opencode CLI v2.2.5, 2026-11-04): `{"type":"error","error":{"type":"provider.free-limit","message":"Free usage limit reached. Connect a provider or subscribe to OpenCode Go to keep going, or switch models.","status":429,"response":{"body":"{\"type\":\"error\",\"error\":{\"type\":\"FreeUsageLimitError\",...}}"},"retryAfterMs":21486000}}`. `retryAfterMs` of 21,486,000 ms (5 h 58 min) matched the TUI text "You've used today's free messages. They reset at 5:58 AM". https://github.com/pingdotgg/t3code/issues/31088
- This confirms your observation (2026-11-16, 2.3.0: `provider.free-limit`, 429, `retryAfterMs` about 6 h 44 min = 24,240,000 ms). Label: your observation is a live check by you, the shape is verified from the PR.
- reported: other `retryAfterMs` values from users: 64,534,000 / 60,396,000 / 54,252,000 / 45,360,000 ms (about 17.9 h, 16.8 h, 15.1 h, 12.6 h; reset target drifted 08:03, 08:05, 08:44, 08:48 local, issue #62593, 2026-11-02 to 11-07); 32,217,000 ms (8 h 57 min, issue #58205, 2026-10-24); 35,711,000 ms (9.9 h, issue #58995, 2026-10-25); 41,031,000 ms (target about 00:00:01 UTC on 2026-10-24, from the search summary of related reports; issue not opened); `Retry-After: 84692` s (about 23.5 h, #57540, 2026-10-26). None exceeds 24 h.
- Text variants a human or a log may show (reported, issue #59387 pinned post, #58205): "Free usage exceeded, subscribe to Go"; "You've used today's free messages. They reset at ..."; `AI_APICallError: Free usage limit reached. Subscribe to OpenCode Go to keep going`; `AI.Error.QuotaExceeded: Free usage limit reached`. Raw body shape from a direct call: `{"type":"error","error":{"type":"FreeUsageLimitError","message":"Rate limit exceeded. Please try again later."}}` (#48988, #33495). A program should match on the structured type `provider.free-limit` first, then on the substring `FreeUsageLimitError` in `error.response.body`, then on status 429 plus "Free usage limit" text as a last resort (inferred: v1 and some builds show the older text form).
- Other errors from the same service (reported, #59387 pinned post, 2026-10-26): "OpenCode's free tier can only be used from within OpenCode" (`FreeTierError`, a client or User-Agent rule: third-party clients, proxies and direct API calls are refused); "OpenCode 1.18.0 or newer is required to use the free tier"; without an `x-opencode-session` header the endpoint returns 400 `MissingSessionID` (#48988). These are not usage limits and a retry will not help.
- reported: the 429 bodies may lack rate-limit headers in some paths ("no header" for a keyed provider, a third-party issue, https://github.com/lidge-jun/opencodex/issues/1145), but the typed `retryAfterMs` implies the header is present for `FreeUsageLimitError`. Do not assume it: treat missing `retryAfterMs` as "unknown reset, use the 24 h default".

### Visibility: headless versus TUI

- reported: `opencode run --format json` emits the typed error event above (v2.2.5 sample). The TUI/desktop dialog shows a human text with a local-time reset ("They reset at ..."), shown only "when the server sends one" (bot comment, #52894, 2026-10-27). Time remaining is not shown; maintainers "will consider" it.
- verified (live): `opencode run --help` on 2.3.0 shows `--format` with choices `default` and `json`, `--session`, `--model provider/model#variant`, `--auto`. A call was not made (spends quota).
- Inference: a runner that reads stdout JSON lines should treat any event with `type == "error"` as terminal for the lane and read `error.type`, `error.status`, `error.retryAfterMs`. The process exit code on this event was not verified; do not depend on it. In `--format default` the error is text on the console; use JSON for lanes.

### Removed or deprecated model

- verified (docs): removals are announced in the Zen docs deprecation list (dates above). The error returned at removal in 2.x headless JSON was not found in any source.
- reported: on 1.18.25 a deprecated free model gave `UnknownError` / "Unexpected server error" (#46760). On other cases a missing model gives `ProviderModelNotFoundError` (troubleshooting guides; official troubleshooting says it usually means a mistyped `providerId/modelId`); `opencode models --refresh` refreshes a stale catalog. Secondary: https://opencode.ai/docs troubleshooting mirror, https://www.developersdigest.tech/errors/opencode/provider-model-not-found.
- Inference: classify as "model unavailable" any of `ProviderModelNotFoundError`, `ModelNotFound`, `UnknownError` with "Unexpected server error" on a free lane when `opencode models` no longer lists the id. Different from usage-limited: do not set a retry time; mark the lane "unavailable" until the next catalog check.

### Reset boundary: fixed daily or rolling?

- Not established. No maintainer or doc states it. Evidence is mixed (all reported):
  - A shared-per-IP and UTC-day key resetting at 00:00 UTC (one commenter, 2026-11-02, #52894); one data point at 05:30 IST = 00:00 UTC (#58205); one `Retry-After` expiring about 00:00 UTC (#57540).
  - Against: resets shown at 21:00, 07:00, 07:59 to 08:00, 03:30 then 04:08 (after reinstall), 08:03 to 08:48 (drifting), 08:24 versus 08:56 per model (various local timezones, unknown); 429s at 03:29 and 06:13 UTC after an inferred 00:00 UTC reset (#58205); blocks that return at once after the stated reset (#52894 OP 2026-10-03, #59387 2026-10-27); a block still active 27 h and 24 h later (#33495, #58995).
  - Users also report the 2.3.0 upgrade shows the limit "with zero messages" for several days (#59387 comments, 2026-11-16), and a PC restart fixed one Desktop case.
- Inference: the stated reset is a server computation per user, IP or session key, not a universal clock; it is probably a rolling or per-key daily window that sometimes resets late. Your 6 h 44 min observation is consistent with a "next boundary" value shorter than 24 h. A retry at the stated time should usually work, but not always.

## 4. Recommended handling

- Honor the structured signal. `provider.free-limit` means "this lane is usage-limited until about now + retryAfterMs". Do not retry inside the run (verified rule in the PR: free-limit is a distinct non-generic type; maintainer advice is wait, subscribe to Go, or connect another provider, #59387). Retrying does not consume quota or bring the reset closer (reported, #52894, 2026-11-02), so it is only noise.
- Wait or switch? Switch immediately to the next lane in the owner's order (another provider lane, or another free model only if you have verified it is a different pool; today's evidence says all opencode free models share one pool, so another opencode free lane is not a fallback for this error). Inferred from the shared-pool reports.
- Blocked-until rule (inferred, for the owner's design):
  1. Record `blocked_until = now + retryAfterMs + 5 min` (or `now + 24 h` when `retryAfterMs` is missing).
  2. Next run, if `now >= blocked_until`, retry the lane once.
  3. If it fails with `provider.free-limit` again, record a fresh `blocked_until` from that error but at least `now + 24 h`; after two such failures show the user a notice that the free pool may be stuck (known reports: #62593, #58995) and suggest a paid or Go route.
  4. The owner's "next day or 24 hours" rule is safe but longer than any stated value; using `retryAfterMs` first gives the same-day retry that the live sample (about 6.7 h) allows. Keep the 24 h floor only as the second-failure rule.
- Do not retry a `FreeTierError` or `MissingSessionID` (client rules, not quota) and do not retry quota errors of another type (`provider.quota` for Go, 402 credit errors); those need the user to act.
- Other free or cheap routes and their stated limits:
  - OpenRouter `:free` models (verified, https://openrouter.ai/docs/api/reference/limits, read 2026-11-16): 20 requests per minute; 50 per day with under 10 credits ever bought, 1000 per day with at least 10 credits. HTTP 429, `error.code` 429, `metadata.error_type: rate_limit_exceeded`, headers `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` (ms since epoch), `Retry-After` when providers gave a hint. The counter is readable at `GET /api/v1/key` (`free_model_daily_requests`). This is the best-documented free route and carries a machine-readable reset.
  - Google Gemini API free tier (verified, https://aistudio.google.com/docs/rate-limits, read 2026-11-16): the docs page lists only one free-tier model with numbers (200 RPM, 50,000 TPM, 10,000 RPD); other models say to check the AI Studio rate-limit page. Daily quota "reset at midnight Pacific time"; error `429 RESOURCE_EXHAUSTED`. Free-tier data may be used by Google (not checked here; verify before sending code).
  - opencode Go (verified, docs): $10 per month, usage limits as monthly dollar amounts with 5-hour (20%), weekly (50%) and monthly (100%) windows; free models remain usable after the limit; `GoUsageLimitError` at the cap. The Go limit and the free pool are different meters.
  - Other vendors (Groq, Cloudflare, Mistral and others) were not researched; add only after a live check.

## 5. What could make "retry once the next day" wrong

- Quota still blocked after the stated reset (reported: #62593, #58995, #52894, #59387, 2026-10-03 to 2026-11-16). Mitigation: the two-step rule above.
- Shared pool and shared network: a headless lane, a TUI session and other tools on the same machine, IP or account drain the same pool (reported, scope unresolved). A lane may be blocked by usage outside the tool. Mitigation: after a failure, the lane's `blocked_until` should be global per machine, not per run.
- Account or network enforcement and no appeal path in the repository: maintainers send account issues to the support mailbox (verified, pinned post). Bans or abuse blocks are not described anywhere I could read; unknown. A model-specific ban was not found.
- Client restriction: free models are served only to the real opencode client (verified, pinned post: "Other clients, proxies and direct API calls can't use them"). A runner that calls Zen directly or through another harness will get `FreeTierError`/429 regardless of quota. Lanes must go through `opencode run`.
- Version gates: "OpenCode 1.18.0 or newer is required"; v1 "no longer supports free models and only gets fixes for critical bugs" (verified, pinned post, 2026-10-26). Upgrades can also reset or break the quota view (reported: 2.3.0 upgrade reports on 2026-11-16).
- Model removal or rename and "limited time" windows: a free model can disappear between runs (verified, docs deprecation list). A retry the next day may hit a missing model, not a limit.
- Pricing or policy change: Zen docs state most free models are limited-time; Go docs say "usage limits may change as we learn from early usage and feedback" (verified). A retry cannot assume the same free list or numbers.
- Data-use change: a model may be free in exchange for data (Iceman, Inkling, Big Pickle, Flint, MiMo; verified). Selecting by "free" alone sends code to those providers.
- Region limits: Beam Free and Inkling 2 Small Free are unavailable in several countries; LongCat needs Global regions (verified, docs). A region error looks like a failure, not a limit.
