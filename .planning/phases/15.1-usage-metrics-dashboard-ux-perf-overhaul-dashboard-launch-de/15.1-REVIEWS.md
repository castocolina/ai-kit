### Strengths

### Concerns
- **HIGH, NEW: `_codex_cwd_resolver` resets the cwd to the tool-call workdir for every decomposed step.** `_rows_for_record()` invokes the resolver once per step at `refiner.py:446-472`. The prescribed resolver sets `cwd_state.current = workdir`, observes the current step, and returns `workdir` every time at `15.1-02-PLAN.md:394-400`. For `cd src && pwd` with `workdir=/repo`, the first step updates state to `/repo/src`, but the second resolver call resets it to `/repo`, so `pwd` receives the wrong `resolved_cwd`. This violates `CwdState`'s explicit resolve-then-observe, next-step contract at `cwd_state.py:1-9` and `cwd_state.py:23-44`.
- **MEDIUM, NEW: The "single decode once per record" acceptance criterion is not implementable by the prescribed call graph.** `_codex_custom_tool_cmd()` and `_codex_custom_tool_workdir()` each call `_codex_custom_tool_args()` independently at `15.1-02-PLAN.md:374-391`; command extraction runs once, while workdir extraction runs once per decomposed step. That contradicts the single-decode claim at `15.1-02-PLAN.md:457-461`.

### Suggestions
- Decode the custom-tool argument once before the step loop, store the parsed result in record context, and set the explicit workdir as the record's initial cwd once.
- Let each step then use the ordinary `resolve_for()` followed by `observe()` sequence.
- Add a regression fixture for an explicit-workdir compound command such as `cd src && pwd`, asserting `/repo` for the `cd` row and `/repo/src` for the `pwd` row.

### Risk Assessment
**HIGH.** The principal Cycle-1 workdir path now exists, but it produces incorrect cwd attribution for compound commands and contradicts its own once-per-record parsing contract.
