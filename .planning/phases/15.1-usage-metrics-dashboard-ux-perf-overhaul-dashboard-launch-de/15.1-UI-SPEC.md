# Phase 15.1 — UI Design Contract

> Visual and interaction contract for the Usage Metrics Dashboard UX/Perf Overhaul. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Not a shadcn/React project.** `dashboard.py` generates a single self-contained static HTML file (embedded JSON, vanilla JS, `file://`-opened, no server, no build step — Phase 5 D-09, unchanged). CONTEXT.md D-04/D-05/D-06 explicitly reject shadcn/React+MUI in favor of Material Web Components loaded from CDN, driven by the `frontend-design` skill (invoked to produce this contract's direction). The shadcn gate and registry-safety gate are both **not applicable** for this reason — see `## Registry Safety` below.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Material Web Components (`@material/web`), CDN-loaded via ES modules — not shadcn |
| Preset | not applicable (no shadcn preset; Material's own default "Baseline" M3 scheme, per D-08) |
| Component library | `@material/web@2.5.0` (Google's official MD3 web components, framework-agnostic Custom Elements) |
| Icon library | Material Symbols Outlined (Google Fonts icon font, `<md-icon>` glyphs by ligature name) |
| Font | Roboto, weights 400 + 500 (Material's default type family — load via Google Fonts CDN; `@material/web`'s typography CSS references `Roboto` but does not bundle the font file) |

### CDN Dependencies (prescriptive — resolves CONTEXT.md D-03/D-07/D-09's open research)

| Purpose | Package | CDN entry point | Version pinned |
|---------|---------|------------------|-----------------|
| Controls/filters/dialogs (D-06) | `@material/web` | `<script type="module">` with an import map: `"@material/web/"` → `"https://esm.run/@material/web/"` (or `https://cdn.jsdelivr.net/npm/@material/web@2.5.0/+esm` per-file) | `2.5.0` |
| Type family | Roboto | `https://fonts.googleapis.com/css2?family=Roboto:wght@400;500&display=swap` | latest (Google Fonts is not versioned) |
| Icon font | Material Symbols Outlined | `https://fonts.googleapis.com/css2?family=Material+Symbols+Outlined` | latest |
| Table row virtualization (D-02/D-03) | `@tanstack/virtual-core` | `https://esm.run/@tanstack/virtual-core` (headless, framework-agnostic — pairs with a hand-styled `<table>` per D-06's "no official Material data-table" note; ESM import fits naturally alongside the `type="module"` Material Web Components script) | `3.17.11` |
| Charts (D-18) | `chart.js` | `https://cdn.jsdelivr.net/npm/chart.js@4.5.1/dist/chart.umd.min.js` (classic `<script>`, not ESM — keep it a separate non-module tag so a Chart.js load failure never blocks the module-scoped table/filter code) | `4.5.1` |

**Why these, not alternatives:** `@material/web` is the only official MD3 web-component library and is required by D-06. `@tanstack/virtual-core` was chosen over `Clusterize.js` because it is headless (full control over the hand-styled `<table>` markup D-06 requires, rather than imposing its own row-wrapper DOM) and ships a framework-agnostic core package that loads cleanly as an ES module next to Material Web Components — `Clusterize.js` is a reasonable fallback if `@tanstack/virtual-core`'s API proves awkward against a real `<table>`/`<tbody>` (rather than a generic scroll container) during implementation. `chart.js` was chosen over Apache ECharts for its native horizontal-bar/stacked-bar/doughnut support (D-18's chart 2 says "horizontal bar **or** treemap" — horizontal bar is chosen specifically to avoid pulling in the extra `chartjs-chart-treemap` plugin or a heavier ECharts payload).

**Confirmed absent from `@material/web@2.5.0`** (live-checked via `WebFetch https://cdn.jsdelivr.net/npm/@material/web/`, 2026-09-16): no date-picker component, no data-table component. This grounds D-06's "hand-styled table" and D-13's "two `<input type="date">` merged into one control" fallback — both are the only viable paths, not a default reached for without checking.

CDN-sourced, not a local `npm`-installed package (no `package.json` exists in this repo — confirmed via `find . -maxdepth 2 -iname package.json`, zero matches).

This is a **non-exhaustive** list of the components this phase actually needs — checking the full `@material/web@2.5.0` directory listing above for anything else (chips, switches, tabs, etc.) is the expected path, not an exception.

| Component | Import path | Notes |
|-----------|-------------|-------|
| Outlined select | `@material/web/select/outlined-select.js` | Runtime / model / family / subfamily filter dropdowns (D-10/D-11/D-12) |
| Outlined text field | `@material/web/textfield/outlined-text-field.js` | Command-text search filter, tokens min/max, price min/max |
| Icon button | `@material/web/iconbutton/icon-button.js` | Copy-to-clipboard trigger, dialog close, per-column sort-direction indicator |
| Icon | `@material/web/icon/icon.js` | Glyphs inside icon buttons and status badges (Material Symbols ligature text as light DOM content) |
| Dialog | `@material/web/dialog/dialog.js` | Full-command detail dialog — full text, copy button, decomposer step breakdown (D-14) |
| Filled button | `@material/web/button/filled-button.js` | "Copy command" primary action inside the detail dialog |
| Text button | `@material/web/button/text-button.js` | "Clear filters" secondary action, dialog "Close" |
| Checkbox | `@material/web/checkbox/checkbox.js` | "Group by session" toggle (replaces the plain `<input type="checkbox">`) |
| Linear progress | `@material/web/progress/linear-progress.js` | Indeterminate bar during initial payload parse / virtualizer mount on large datasets (see UI Considerations — loading) |
| Elevation | `@material/web/elevation/elevation.js` | Behind the filter bar, chart panels, and dialog surface — Material's tonal-elevation convention, not a drop-shadow card |

The `<table>` itself, the 3 charts, and the merged date-range control are **not** `@material/web` components (none exist for these) — hand-built using `--md-sys-color-*` / `--md-sys-typescale-*` CSS custom properties that `@material/web`'s theme CSS exposes, per D-06.

**Primary visual focal point:** the virtualized table (E2) — it is the largest surface, occupies the majority of the viewport below the filter bar, and is where every filter/sort interaction's result lands. The charts row (E4) is secondary, providing at-a-glance trend context above the table; the filter bar (E1) is tertiary, a persistent control strip rather than a destination.

**Icon-only button accessibility:** every `md-icon-button` instance (copy-to-clipboard trigger, dialog close, per-column sort-direction indicator) MUST carry an explicit `aria-label` — e.g. `"Copy command"`, `"Close dialog"`, `"Sort by {column}"` (with `{column}` substituted per header) — never rely on the icon glyph alone.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside badges/chips |
| sm | 8px | Compact filter-field internal padding |
| md | 16px | Default gap between filter fields, chart-panel internal padding |
| lg | 24px | Section padding (filter bar ↔ charts ↔ table) |
| xl | 32px | Gap between the 3 chart panels in the charts row |
| 2xl | 48px | Page-level top margin; icon-button minimum touch target |
| 3xl | 64px | Unused this phase (no page-level hero/section break exists — single dashboard view) |

Exceptions: table row height is fixed at **56px** (a multiple of 8) — required by `@tanstack/virtual-core`'s `estimateSize` callback so every virtualized row is a known, constant height. 56px is `2 × 24px` Body line-height plus `8px` vertical padding: it is the smallest constant height that accommodates the **two-line wrapped command cell** D-12 requires (see the overflow / long-text row of `## UI Considerations`). Icon-button touch target is 48px, which is already the `2xl` token and matches Material's own 48×48dp minimum touch target (not the 44px sometimes cited for other design systems).

> **Amendment 2026-09-16 (cross-AI plan review, Round 1 — REVIEWS.md `60503a8`):** this row-height exception previously read **40px**, paired with a single-line no-wrap command cell. That single-line decision contradicted locked decision **D-12** ("command (wrapped, with a popup/dialog for the full text)"). Corrected here and in the `## UI Considerations` overflow row below: the command cell wraps to a **fixed two-line clamp**, and the constant row height rises from 40px to 56px to hold it. `estimateSize` stays a constant — the virtualization contract is unchanged, only its value.

## Typography

M3's own type scale (Roboto, two weights only — Regular 400 for display/heading/body, Medium 500 for label), loaded via the Google Fonts CDN entry above. These are M3's real baseline scale values (Headline Small, Title Large, Body Large, Label Large), not invented sizes.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (Regular) | 24px (1.5) |
| Label | 14px | 500 (Medium) | 20px (1.43) |
| Heading | 22px | 400 (Regular) | 28px (1.27) |
| Display | 24px | 400 (Regular) | 32px (1.33) |

Usage: **Display** = the page `<h1>` "Usage metrics". **Heading** = dialog title, chart-panel titles, table section label. **Body** = table cell text, dialog body text (full command, decomposer steps). **Label** = filter-field labels, column headers, badges (source_confidence, inferred_family, "(conditional)" execution marker).

## Color

Material's default "Baseline" M3 scheme (no seed color, no custom brand palette — D-08), with light/dark values switched automatically via `prefers-color-scheme` using `@material/web`'s own light/dark CSS custom-property blocks. All values below are M3's real, documented baseline token hex values.

| Role | Value (light / dark) | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFBFE` / `#1C1B1F` (`--md-sys-color-surface`) | Page background |
| Secondary (30%) | `#E7E0EC` / `#49454F` (`--md-sys-color-surface-variant`) | Filter bar background, table header row, chart-panel surfaces, dialog surface |
| Accent (10%) | `#6750A4` / `#D0BCFF` (`--md-sys-color-primary`) | Active/selected sort-column indicator, the currently-selected table row, the "Copy command" filled button, the primary chart series (tokens/price-per-day line), focus rings |
| Destructive/warning | `#B3261E` / `#F2B8B5` (`--md-sys-color-error`) | Low-confidence / `inferred_family` badges, the `(conditional)` execution-uncertain marker, price-unknown badge, and the payload-parse-failure error state |

Accent reserved for: the active sort-column header icon, the selected/highlighted table row on click, the "Copy command" button fill, and the primary line in the tokens/price-per-day chart. Never used for plain body text, borders, or every interactive element indiscriminately.

Chart categorical palette (for the **five** runtime categories present in the real dataset and for the family/subfamily distribution — a prescriptive, non-arbitrary set drawn from M3's own baseline tonal palettes, not an invented brand hue):

| Series order | Light | Dark |
|---|---|---|
| 1 | `#6750A4` (primary) | `#D0BCFF` |
| 2 | `#7D5260` (tertiary) | `#EFB8C8` |
| 3 | `#625B71` (secondary) | `#CCC2DC` |
| 4 | `#79747E` (outline) | `#938F99` |
| 5 | `#1C1B1F` (neutral N10 — M3 baseline `on-surface` light) | `#E6E1E5` (neutral N90 — M3 baseline `on-surface` dark) |

**Deterministic reuse beyond five series:** series index `n` (zero-based) uses palette entry `n % 5`. This is the locked rule — an executor must never pick an ad-hoc additional hue, and must never silently truncate a series list to the palette length. Five entries is not an arbitrary ceiling: the real refined store contains exactly five runtimes (`claude`, `rtk`, `opencode`, `codex`, `cursor`), so the doughnut and the per-day stacked bars are fully covered without reuse; the modulo rule exists for the family/subfamily distribution chart, whose series count is data-dependent.

> **Amendment 2026-09-16 (cross-AI plan review, Round 1 — REVIEWS.md `60503a8`):** this table previously stopped at four entries and was captioned "3–4 runtime categories", while both the human check in Plan 01 and the chart tests in Plan 05 expect all five real runtimes. Series 5 and the modulo rule were added to close that gap.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Copy command" (copy-to-clipboard button inside the full-command detail dialog, D-14) |
| Empty state heading | "No commands match these filters" |
| Empty state body | "Widen the date range or clear a filter to see more." |
| Error state | "Couldn't load usage data. Regenerate the dashboard with `ai-kit-usage-metrics dashboard`." (shown if the embedded JSON payload fails to parse — replaces the table area) |
| Destructive confirmation | none — this is a read-only dashboard; no destructive action exists in this phase's scope |

Secondary copy used inline in the table (not full states, but locked wording so the executor doesn't invent variants):
- Missing/unknown price cell: `—` with a tooltip "unknown — model not in catalog" (never a bare `0`, which is D-16's actual bug).
- Missing/unknown date cell: `—` (never a blank cell with no visual marker — D-16's other bug).
- Execution-uncertain rows (`execution_certain === false`): a small error-tinted badge reading "conditional" (upgrades today's plain `(conditional)` text to a colored badge using the Destructive/warning role above, consistent with the other confidence badges).

## UI Considerations

> Computed via `ui-consideration-probe.cjs` against 6 UI-SPEC surfaces (E1 filter bar, E2 virtualized table, E3 full-command dialog, E4 charts row, E5 loading indicator, E6 icon buttons), classified by element kind (form / list-collection / media / nav / interactive-control / static-content — user-confirmed, no missed kind) — **46 applicable considerations**: 16 resolved (explicit), 2 resolved (backstop), 2 unresolved (deferred), 26 dismissed as not independently applicable to their surface (rolled up below, not one row each).

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty (table) | E2 filtered table rows | ✅ resolved — explicit | Zero-row filter result renders the "No commands match these filters" empty state from the Copywriting Contract instead of an empty `<tbody>` (today's dashboard leaves the table silently blank — this is a real gap this phase closes). |
| empty (charts) | E4 the 3 chart panels (D-18) when active filters produce zero rows | 🧪 resolved — backstop | Each chart panel shows "No data for this range" inside the canvas area rather than a blank canvas — no hard visual spec was decided, so this needs an explicit verification check rather than an assumed pass. |
| loading (page) | E1 filter bar, E2 table, E5 progress indicator | 🧪 resolved — backstop, with one explicit sub-decision | An indeterminate `md-linear-progress` bar (E5) shows until the first virtualized row batch paints, then is removed — no hard timing threshold decided, needs explicit verification. **Explicit sub-decision:** E1's filter controls (`md-outlined-select`/`md-outlined-text-field`) are disabled for the duration of this loading state, re-enabled once the progress bar is removed — prevents filtering over a not-yet-mounted virtualizer. |
| error (page) | E1 filter bar, E2 table, E4 charts | ✅ resolved — explicit | A corrupted/unparseable embedded JSON payload replaces the table area with the Error state copy; the filter bar and chart row are hidden/disabled behind the same page-level error state rather than each rendering an independent error UI. |
| populated | E1 filter dropdowns, E2 table, E3 dialog, E4 charts | ✅ resolved — explicit | E1: dropdowns populated via `distinctValues()`, always shown including the single-option case (see zero-one-many row below). E2: extends the existing `filterRows`/`sortRows`/render pattern — virtualization changes only which DOM rows are materialized. E3: full text + copy button + decomposer steps per D-14. E4: normal chart render using the categorical palette from the Color section. |
| partial | E2 rows with null `price`/`date`/`family`; E4 chart aggregation over rows with null tokens/price | ✅ resolved — explicit | E2: `—` placeholder + tooltip per the Copywriting Contract's secondary-copy rows (fixes D-16's price=0 and date-empty bugs at the render layer as well as the data layer). E4: chart sums skip null-valued rows silently — the same null-skips-as-zero-contribution behavior the existing `groupBySession` aggregation already uses, not a new pattern. |
| overflow / long-text | E2 `command_text` cell; E3 dialog's decomposer step list when many steps | ✅ resolved — explicit | E2: the command cell **wraps** (D-12's locked "command (wrapped, …)"), clamped to a **fixed two lines**. The clamp belongs to a dedicated `.command-text` child of the cell, **never to the `<td>` itself**: `.command-text { display: -webkit-box; -webkit-line-clamp: 2; -webkit-box-orient: vertical; overflow: hidden; overflow-wrap: anywhere; flex: 1 1 auto; min-width: 0; }` (the `overflow-wrap` so an unbroken long token still wraps rather than widening the table). The `<td>` is the flex row around it (`display: flex; align-items: flex-start; gap: 4px; overflow: hidden;`) and carries no clamp, so the compound-step marker — a `.step-marker` sibling with `flex: 0 0 auto` and a `min-width` of the 48px `2xl` token — sits **outside** the clamped box in reserved horizontal space and can never be swallowed by the clamp. Text longer than two lines ends in the clamp's own ellipsis; the full text + copy button + decomposer steps live in the detail dialog (D-14). The two-line clamp is what makes the constant 56px virtualized row height in `## Spacing Scale` correct, and the marker's 20px Label line height fits inside that same height beside the text. E3: the dialog itself shows the full untruncated command text (no truncation inside it, by design); when a compound command has MANY decomposer steps, the step list scrolls internally within a fixed max-height dialog rather than the dialog growing unbounded — **user-locked decision**, this session. |

> **Amendment 2026-09-16 (cross-AI plan review, Round 2 — REVIEWS.md `faf76ad`):** the overflow / long-text row above previously put `-webkit-line-clamp: 2` on the command **cell** while the compound-step marker was described as a clamp-exempt sibling inside it. That is not how line-clamp works — every child of the clamped element participates in the clamped box — and the fixed 56px height reserved no space for the marker. Corrected here and in `15.1-03-PLAN.md` Task 3: the clamp moves onto a `.command-text` child, and the marker becomes a reserved-width flex sibling. The two-line clamp, the 56px row height and D-12 are all unchanged; only the element the clamp is attached to, and the marker's space reservation, are newly specified.
| zero-one-many | E1 filter dropdown with only 1 distinct value; E2 session grouping; E4 chart series count | ✅ resolved — explicit | E1: a filter dropdown with only one distinct value in the current data is still shown (not hidden) — **user-locked decision**, this session: layout stays consistent regardless of how many values exist. E2: zero sessions matching filters reuses the table empty state above; one or many sessions render through the existing `groupBySession` aggregation unchanged. E4: the chart categorical palette is explicitly sized for the 5 real runtime series, with a locked `n % 5` reuse rule for the data-dependent family/subfamily distribution chart (Color section); the zero-series case is the charts-empty backstop above. |
| zero (dialog, non-compound command) | E3 decomposer step section when `step_count <= 1` | ⚠ unresolved — planner must treat as assumption | **Deferred, explicitly** — the user had no fixed preference and said the right call depends on how it actually looks once built (character count, wrap vs. truncate behavior in the dialog), not something to lock sight-unseen. The planner/executor must pick a concrete behavior (hide the step section entirely, or show it with an explicit "single command" empty state) and record the choice — this is NOT silently defaulted. |

**Dismissed as not independently applicable** (26 of the 46 probe rows — each surface's own state is fully subsumed by a page-level resolution above, or the surface is stateless):
- **E1 filter bar** (5): empty/error/partial/overflow/long-text — the filter bar itself never independently shows these; it's the table/chart region that does (covered above), and its text/number inputs rely on native browser input-overflow handling, not a custom surface.
- **E3 dialog** (3): empty/loading/error — the dialog only ever opens from an already-rendered row with already-loaded data; it has no independent loading or error path of its own.
- **E4 charts** (3): loading/error/overflow — charts render only after the page-level loading state clears and hide behind the page-level error state (both covered above); panel dimensions are fixed per the Spacing scale, so Chart.js handles internal scaling without custom overflow handling.
- **E5 loading indicator** (7, all categories): the element IS the loading signal itself — asking what it shows "while loading" is circular, and it is a stateless singleton with no data-bound empty/error/partial/overflow/collection behavior.
- **E6 icon buttons** (8, all categories): stateless icon-only affordances (copy trigger, dialog close, sort indicator) with no independent data-bound state. (Their accessibility labeling gap was already flagged by the UI checker as a non-blocking recommendation — a distinct concern from state coverage.)
