# Phase 15.1 — UI Design Contract

> Visual and interaction contract for the Usage Metrics Dashboard UX/Perf Overhaul. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Not a shadcn/React project.** `dashboard.py` generates a single self-contained static HTML file (embedded JSON, vanilla JS, `file://`-opened, no server, no build step — Phase 5 D-09, unchanged). CONTEXT.md D-04/D-05/D-06 explicitly reject shadcn/React+MUI in favor of Material Web Components loaded from CDN, driven by the `frontend-design` skill (invoked to produce this contract's direction). The shadcn gate and registry-safety gate are both **not applicable** for this reason — see `## Registry Safety` below.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Material Web Components (`@material/web`), CDN-loaded via ES modules — not shadcn |
| Preset | not applicable (no shadcn preset; Material's own default "Baseline" M3 scheme, per D-08) |
| Component library | `@material/web@2.5.0` (Google's official MD3 web components, framework-agnostic Custom Elements) |
| Icon library | Material Symbols Outlined (Google Fonts icon font, `<md-icon>` glyphs by ligature name) |
| Font | Roboto, weights 400 + 500 (Material's default type family — load via Google Fonts CDN; `@material/web`'s typography CSS references `Roboto` but does not bundle the font file) |

### CDN Dependencies (prescriptive — resolves CONTEXT.md D-03/D-07/D-09's open research)

| Purpose | Package | CDN entry point | Version pinned |
|---------|---------|------------------|-----------------|
| Controls/filters/dialogs (D-06) | `@material/web` | `<script type="module">` with an import map: `"@material/web/"` → `"https://esm.run/@material/web/"` (or `https://cdn.jsdelivr.net/npm/@material/web@2.5.0/+esm` per-file) | `2.5.0` |
| Type family | Roboto | `https://fonts.googleapis.com/css2?family=Roboto:wght@400;500&display=swap` | latest (Google Fonts is not versioned) |
| Icon font | Material Symbols Outlined | `https://fonts.googleapis.com/css2?family=Material+Symbols+Outlined` | latest |
| Table row virtualization (D-02/D-03) | `@tanstack/virtual-core` | `https://esm.run/@tanstack/virtual-core` (headless, framework-agnostic — pairs with a hand-styled `<table>` per D-06's "no official Material data-table" note; ESM import fits naturally alongside the `type="module"` Material Web Components script) | `3.17.11` |
| Charts (D-18) | `chart.js` | `https://cdn.jsdelivr.net/npm/chart.js@4.5.1/dist/chart.umd.min.js` (classic `<script>`, not ESM — keep it a separate non-module tag so a Chart.js load failure never blocks the module-scoped table/filter code) | `4.5.1` |

**Why these, not alternatives:** `@material/web` is the only official MD3 web-component library and is required by D-06. `@tanstack/virtual-core` was chosen over `Clusterize.js` because it is headless (full control over the hand-styled `<table>` markup D-06 requires, rather than imposing its own row-wrapper DOM) and ships a framework-agnostic core package that loads cleanly as an ES module next to Material Web Components — `Clusterize.js` is a reasonable fallback if `@tanstack/virtual-core`'s API proves awkward against a real `<table>`/`<tbody>` (rather than a generic scroll container) during implementation. `chart.js` was chosen over Apache ECharts for its native horizontal-bar/stacked-bar/doughnut support (D-18's chart 2 says "horizontal bar **or** treemap" — horizontal bar is chosen specifically to avoid pulling in the extra `chartjs-chart-treemap` plugin or a heavier ECharts payload).

**Confirmed absent from `@material/web@2.5.0`** (live-checked via `WebFetch https://cdn.jsdelivr.net/npm/@material/web/`, 2026-09-16): no date-picker component, no data-table component. This grounds D-06's "hand-styled table" and D-13's "two `<input type="date">` merged into one control" fallback — both are the only viable paths, not a default reached for without checking.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside badges/chips |
| sm | 8px | Compact filter-field internal padding |
| md | 16px | Default gap between filter fields, chart-panel internal padding |
| lg | 24px | Section padding (filter bar ↔ charts ↔ table) |
| xl | 32px | Gap between the 3 chart panels in the charts row |
| 2xl | 48px | Page-level top margin; icon-button minimum touch target |
| 3xl | 64px | Unused this phase (no page-level hero/section break exists — single dashboard view) |

Exceptions: table row height is fixed at **40px** (a multiple of 8; Material's own "dense" data-table row-height convention) — required by `@tanstack/virtual-core`'s `estimateSize` callback so every virtualized row is a known, constant height. Icon-button touch target is 48px, which is already the `2xl` token and matches Material's own 48×48dp minimum touch target (not the 44px sometimes cited for other design systems).

## Typography

M3's own type scale (Roboto, two weights only — Regular 400 for display/heading/body, Medium 500 for label), loaded via the Google Fonts CDN entry above. These are M3's real baseline scale values (Headline Small, Title Large, Body Large, Label Large), not invented sizes.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (Regular) | 24px (1.5) |
| Label | 14px | 500 (Medium) | 20px (1.43) |
| Heading | 22px | 400 (Regular) | 28px (1.27) |
| Display | 24px | 400 (Regular) | 32px (1.33) |

Usage: **Display** = the page `<h1>` "Usage metrics". **Heading** = dialog title, chart-panel titles, table section label. **Body** = table cell text, dialog body text (full command, decomposer steps). **Label** = filter-field labels, column headers, badges (source_confidence, inferred_family, "(conditional)" execution marker).

## Color

Material's default "Baseline" M3 scheme (no seed color, no custom brand palette — D-08), with light/dark values switched automatically via `prefers-color-scheme` using `@material/web`'s own light/dark CSS custom-property blocks. All values below are M3's real, documented baseline token hex values.

| Role | Value (light / dark) | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFBFE` / `#1C1B1F` (`--md-sys-color-surface`) | Page background |
| Secondary (30%) | `#E7E0EC` / `#49454F` (`--md-sys-color-surface-variant`) | Filter bar background, table header row, chart-panel surfaces, dialog surface |
| Accent (10%) | `#6750A4` / `#D0BCFF` (`--md-sys-color-primary`) | Active/selected sort-column indicator, the currently-selected table row, the "Copy command" filled button, the primary chart series (tokens/price-per-day line), focus rings |
| Destructive/warning | `#B3261E` / `#F2B8B5` (`--md-sys-color-error`) | Low-confidence / `inferred_family` badges, the `(conditional)` execution-uncertain marker, price-unknown badge, and the payload-parse-failure error state |

Accent reserved for: the active sort-column header icon, the selected/highlighted table row on click, the "Copy command" button fill, and the primary line in the tokens/price-per-day chart. Never used for plain body text, borders, or every interactive element indiscriminately.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Copy command" (copy-to-clipboard button inside the full-command detail dialog, D-14) |
| Empty state heading | "No commands match these filters" |
| Empty state body | "Widen the date range or clear a filter to see more." |
| Error state | "Couldn't load usage data. Regenerate the dashboard with `ai-kit-usage-metrics dashboard`." (shown if the embedded JSON payload fails to parse — replaces the table area) |
| Destructive confirmation | none — this is a read-only dashboard; no destructive action exists in this phase's scope |

Secondary copy used inline in the table (not full states, but locked wording so the executor doesn't invent variants):
- Missing/unknown price cell: `—` with a tooltip "unknown — model not in catalog" (never a bare `0`, which is D-16's actual bug).
- Missing/unknown date cell: `—` (never a blank cell with no visual marker — D-16's other bug).
- Execution-uncertain rows (`execution_certain === false`): a small error-tinted badge reading "conditional" (upgrades today's plain `(conditional)` text to a colored badge using the Destructive/warning role above, consistent with the other confidence badges).

## UI Considerations

Applicable state considerations resolved: 7 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | filtered table rows | ✅ covered | Zero-row filter result renders the "No commands match these filters" empty state from the Copywriting Contract instead of an empty `<tbody>` (today's dashboard leaves the table silently blank — this is a real gap this phase closes). |
| loading | initial payload parse + virtualizer mount | 🧪 backstop | An indeterminate `md-linear-progress` bar is shown until the first virtualized row batch paints, then removed — no hard timing threshold was decided in CONTEXT.md, so this needs an explicit verification check rather than an assumed pass. |
| error | corrupted/unparseable embedded JSON payload | ✅ covered | Replaces the table area with the Error state copy above instead of a raw JS exception / blank page. |
| populated | normal virtualized, filtered, sorted table | ✅ covered | Extends the existing `filterRows`/`sortRows`/render pattern; virtualization changes only which DOM rows are materialized, not the filter/sort logic itself. |
| partial | rows with null `price`/`date`/`family` | ✅ covered | `—` placeholder + tooltip per the Copywriting Contract's secondary-copy rows (fixes D-16's price=0 and date-empty bugs at the render layer as well as the data layer). |
| overflow / long-text | `command_text` cell | ✅ covered | Single-line ellipsis truncation in the wrapped command column, full text + copy button + decomposer steps in the detail dialog (D-14). |
| zero-one-many | session grouping (`group by session`) | ✅ covered | Zero sessions matching filters uses the same empty state above; one or many sessions render through the existing `groupBySession` aggregation unchanged. |
| empty (charts) | the 3 chart panels (D-18) when active filters produce zero rows | 🧪 backstop | Each chart panel should show "No data for this range" inside the canvas area rather than a blank canvas — CONTEXT.md didn't decide this explicitly, so it needs an explicit verification check, not an assumed pass. |
