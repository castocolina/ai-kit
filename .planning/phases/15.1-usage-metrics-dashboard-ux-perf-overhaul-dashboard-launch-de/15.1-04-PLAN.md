<objective>
Close the last two data-visible defects and the state gaps: the full-command detail
dialog that makes ellipsis truncation lossless (D-14), the session-grouping dedup key
that silently under-sums when a runtime has no turn concept (D-16 session dup), and the
empty, loading and error states the dashboard has never had.

Purpose: RESEARCH.md's Pitfall 3 proved the reported "duplicate rows" symptom is two
separate things. Plan 03 fixed the visual half with a step marker. This plan fixes the
arithmetic half: 29,437 rtk rows carry no turn id at all, so every rtk row in one session
collapses to the same dedup key and only the first row's figures are summed. It is
financially inert today because those figures are themselves null, but the key is wrong
and a future runtime with real figures and no turn id would silently under-report.

Output: a dialog that surfaces the decomposer data already sitting unused in every row, a
dedup key that is honest about what it can and cannot dedup, and three page states that
replace today's silent blankness.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| embedded JSON payload -> dialog body | The full untruncated command text, the most attacker-influenced string in the payload, becomes rendered page content |
| dialog -> system clipboard | Row-derived command text is written to the OS clipboard on user action |
| embedded JSON payload -> parse handler | A malformed or truncated payload must fail into a state rather than a broken page |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15.1-01 | Tampering | Dialog body, step list and the three state surfaces in `dashboard.py` | high | mitigate | Full command text and every step entry are set through `textContent` on created elements; state copy is fixed locked strings, never row-derived; `test_no_data_driven_innerhtml_assignment` stays unmodified and is re-asserted by Task 1's verify gate |
| T-15.1-13 | Tampering | Clipboard write of row-derived command text | low | accept | The user explicitly activates copy on a command from their own local history, and the written value is the exact `command_text` already displayed above the button — no transformation, no additional data. The residual risk is that a command from a captured session lands on the clipboard, which is the feature's entire purpose |
| T-15.1-14 | Denial of service | Per-row dialog listeners against recycled virtualized rows | medium | mitigate | One delegated listener on the table body resolving rows by virtualizer index, never one listener per rendered row — recycled rows would otherwise accumulate stale handlers as the user scrolls a large payload |
| T-15.1-15 | Denial of service | Unbounded dialog growth on a many-step compound command | low | mitigate | Fixed maximum dialog height with internal scrolling on the step list, pinned by an assertion on the generated markup; RESEARCH.md live-verified a real 55-step command |
| T-15.1-16 | Tampering | Unhandled embedded-payload parse failure | medium | mitigate | The parse is wrapped and failure routes to the locked page-level error state rather than leaving a half-rendered page whose controls act on undefined data |
| T-15.1-02 | Tampering | `_encode_payload` embedded JSON block | high | mitigate | Untouched by this plan; no second inline JSON or script data block is introduced |
</threat_model>
