# Phase 15.1 Plan 04: Full-Command Dialog, Turn-Identity Dedup Fix, and Page States Summary

**Sibling-resolved command dialog (indexByRawRef/stepEntries), the SD-4 turnKey() dedup identity replacing the under-counting session-grouping key (with a corrected refined_store.py docstring), and a real paint-guaranteed loading/empty/error state trio for the dashboard.**

## Accomplishments

- **Task 1 (D-14):** Added the full-command detail dialog. `indexByRawRef(rows)` builds a `Map` from `raw_ref` to that record's rows sorted by `step_index`, exactly once at load over the full embedded payload (SD-3), stored as `rowsByRawRef`. `stepEntries(rowsByRawRef, row)` returns one `{position, total, operator, text}` entry per sibling for a multi-step row, empty for a single-step one. A single `md-dialog` is wired via a delegated `click`/`keydown` listener on `#usage-tbody` that resolves the activated row through a `data-row-index` attribute the painter now sets on every materialized `<tr>`. A module-scoped `dialogTrigger` plus one `closed`-event listener (never `close`) restores focus to the activating command cell, or to the `tabindex="-1"` `#table-scroll` container when the virtualizer has recycled that row away. The "Copy command" filled button covers both clipboard-refusal shapes (absent API, rejected write) through one visible status message.
- **Task 2 (D-16 session dup):** Added `turnKey(row)` — the SD-4 two-branch dedup identity — and rewired `groupBySession` to call it instead of building its own key. A null-turn compound command's shared token/price figures are now summed exactly once (keyed on `(session_id, raw_ref)`), not once per sibling step; two distinct null-turn commands in one session stay distinct. `refined_store.py`'s module docstring was corrected in the same task to state this same identity and explicitly retract the obsolete pair-only `SELECT DISTINCT session_id, turn_id, …` prescription that SQLite's NULL-equality behavior silently broke — a docstring-only change, verified via `git diff --stat`.
- **Task 3 (empty/loading/error states):** Added a pure `shouldShowEmptyState(rows)` predicate driving a locked empty-state panel when the filtered/grouped row set is zero-length. Wrapped the embedded-payload `JSON.parse` in try/catch; failure now hides the filter bar and charts row behind one page-level error state naming the regeneration command. Restructured the page bootstrap into SD-10's three steps — show the `md-linear-progress` bar and disable filter controls synchronously, defer with a double `requestAnimationFrame` (`setTimeout(fn, 0)` fallback), then run `decorateSubfamily`/`indexByRawRef`/`fillSelect`/`render`/`mountVirtualizer` inside the deferred callback before removing the bar and re-enabling controls.
