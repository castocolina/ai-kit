## SD-1 — Subfamily extraction (CANONICAL — Plan 03 mirrors this definition verbatim)

The algorithm previously planned here ("skip the family token, skip leading flags, return
the next token") **does not satisfy D-11**. For `git -C /path commit` it returns `/path`,
because `-C` consumes a following value argument that is not itself flag-shaped, and a
naive flag-skip loop has no way to know that. D-11 states the required answer explicitly:
`git -C /path commit` -> subfamily `commit`, not `-C`. The corrected algorithm below is
the canonical definition; Plan 03's JavaScript mirror is a literal port of it, and both
are checked against the same hardcoded spec table, not merely against each other.

### `family.subfamily_of(command_text) -> str`

1. Split on whitespace. Run `family_of`'s **exact** existing skip loop — env-var
   assignments matched by `_ASSIGNMENT_RE`, wrapper binaries in `_WRAPPERS`, and each
   wrapper's own leading flags — to land index `i` on the family-determining token. If
   `i >= len(tokens)`, return `""`.
2. `family_token = os.path.basename(tokens[i])`. Look up
   `value_flags = _VALUE_FLAGS.get(family_token, frozenset())`.
3. `i += 1`. Then loop while `tokens[i]` starts with `-`:
   - If the token is exactly `--`, consume it and stop the loop (end of options).
   - Otherwise capture `flag = tokens[i]`, `i += 1`, and if `"=" not in flag` **and**
     `flag in value_flags` **and** `i < len(tokens)`, consume one more token (`i += 1`) —
     that token is the flag's value, not the subcommand. The attached forms `--flag=value`
     and `-fvalue` consume nothing extra, which the `"=" not in flag` guard and the exact
     set membership already handle.
4. If `i >= len(tokens)`, return `""`.
5. **Plausibility filter.** The candidate `tokens[i]` must match
   `^[A-Za-z][A-Za-z0-9_.:-]*$`. If it does not, return `""`. A path, a quoted fragment,
   a variable expansion, a redirect or a numeric literal is not a subcommand, and putting
   one into the subfamily filter dropdown would recreate on the new axis exactly the
   family-noise problem D-16 exists to remove.
6. Return the candidate as written: **no** `os.path.basename` reduction and **no**
   curated-substitution mapping — a subcommand is not a binary path.

### `_VALUE_FLAGS` — module-level in `family.py`

Semantic definition, and the rule for deciding membership: **a flag belongs in this table
when its following separate argument is a configuration value rather than the command's
subcommand.** A flag whose argument IS the meaningful second token (for example
`python3 -m <module>`) is deliberately absent, so the skip loop steps over the flag and
lands on the module name.

Required seed entries (the `git` row is D-11's locked example and MUST be present):

| family token | value-consuming flags |
|---|---|
| `git` | `-C`, `-c`, `--git-dir`, `--work-tree`, `--namespace`, `--exec-path`, `--config-env` |
| `make` | `-C`, `--directory`, `-f`, `--file`, `-j`, `--jobs`, `-o`, `-W` |
| `docker` | `-H`, `--host`, `--context`, `--config`, `--log-level` |
| `kubectl` | `-n`, `--namespace`, `--context`, `--cluster`, `--user`, `--kubeconfig` |
| `npm` | `--prefix`, `-w`, `--workspace`, `--registry` |
| `cargo` | `--manifest-path`, `--config`, `-Z` |
| `go` | `-C` |
| `pip`, `pip3` | `-r`, `--requirement`, `--index-url`, `--extra-index-url`, `-t`, `--target` |
| `systemctl` | `-H`, `--host`, `-M`, `--machine` |
| `apt`, `apt-get` | `-o`, `-c`, `-t` |
| `tar` | `-f`, `--file`, `-C`, `--directory` |
| `rsync` | `-e`, `--exclude-from`, `--files-from` |

### SD-1 spec table (hardcoded expectations — the oracle)

Both the Python function and Plan 03's JavaScript mirror are asserted against these exact
expected values. This table is what makes the cross-language parity test meaningful: two
implementations agreeing on a wrong answer cannot pass it.

| `command_text` | expected `subfamily` | what it pins |
|---|---|---|
| `git commit -m msg` | `commit` | plain second token |
| `git -C /path commit` | `commit` | **D-11's locked example** — `-C` consumes `/path` |
| `git -C mydir commit` | `commit` | the value is not path-shaped; only the arity table gets this right |
| `git --git-dir=/x status` | `status` | attached `=` form consumes nothing extra |
| `sudo git -C /srv pull` | `pull` | wrapper skip composed with value-flag skip |
| `FOO=bar git -c user.name=x log` | `log` | assignment skip composed with value-flag skip |
| `nice -n10 git push` | `push` | the wrapper's own leading flags are skipped |
| `make -C build test` | `test` | a second binary in the arity table |
| `rg -n pattern` | `pattern` | no arity entry for `rg`; `-n` is skipped as a plain flag |
| `python3 -m unittest tests.x` | `unittest` | `-m`'s value IS the subcommand — deliberately not in the table |
| `git -- status` | `status` | the bare `--` end-of-options marker |
| `ls -la /tmp` | `""` | `/tmp` fails the plausibility filter |
| `python3 -c 'import os'` | `""` | `'import` fails the plausibility filter |
| `git` | `""` | tokens exhausted after the family token |
| `git --version` | `""` | only flags remain |
| `` (empty string) | `""` | empty input |
| `   ` (whitespace only) | `""` | whitespace-only input |
