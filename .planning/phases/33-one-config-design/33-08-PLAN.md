Executor shell rules (owner rules, verbatim; pass them word for word to every subagent you start):

The owner runs with bypass permissions and is often away. Any command that makes the host ask for
permission stalls the whole run until the owner comes back. So:

- One simple command per shell call: a single program with plain arguments and absolute paths or
  `git -C <dir>`. Everything more complex goes into a `.sh` or `.py` file under `tmp/`, and the call
  just runs `bash <file>` or `python3 <file>`.
- Never `cd` into a directory, alone or chained (`cd <dir> && ...`, `cd <dir>; ...`).
- Never use heredocs (`<<EOF`), command substitution (`$(...)`, backticks), subshells (`( ... )`),
  process substitution (`<(...)`), `eval`, or long chains of `&&`, `||`, `;` or pipes.
- Never use `sed -i` or another in-place editor on a file; use the file-edit tool, or a script.
- Never delete outside `tmp/`, and never use `rm -rf` on a variable path.
- Write files with the file-write tool, not with `echo`/`printf` redirection, except appending one
  line to a ledger under `tmp/`.
- Pass these rules, word for word, to every subagent and executor you start.

Further rules: AI_KIT_REFUSE_REAL_HOME=1 for every test run; English only; change only the named lines (a name or path swap, plus the trust wording in two places); never `--no-verify`.
