## Summary

The roster code is small and well-factored: `cfg_resolve` returns `{"policy": ..., "reviewers": [...]}` (`config_io.py:450`), and every runtime consumer (`quota.resolve_reviewers`, `cli.py`, `assemble_candidates`) reads only that dict. Keeping that return shape and only changing where it is read from (`config.toml` `[lanes]`) confines the change to `config_io.py`, `trust.py`, `provider_check.py`, `cli.py` (`trust-local`, `render-toml`) plus a new `config_migrate.py` and `toml_splice.py`. The runner side is the larger cost: `resolveRetry` and about 16 existing self-test cases are built on `planningConfig: {workflow:{cross_ai_retry}}` and `cross-ai.json`; all of them change.

Four findings the CONTEXT did not anticipate and the planner must handle (details in sections below): (1) the live user roster has an entry with `purpose = "execute"` inside `[[reviewers]]`, which D-12 would migrate into `[[lanes.review]]` (open question O1, needs a decision before the migration plan); (2) there is NO lock in the runner today (`writeCycleState` is temp+rename only), so SPEC's "takes the runner's existing lock" has nothing to reuse; (3) `tests/test_arch.py` contains no rule that forbids skills importing `tools/` or `tools/` importing skills (CONTEXT's "`tools/` imports no skill (`tests/test_arch.py`)" is a convention, verified true by rg, not an enforced test); (4) `.claude/gsd-core/` and `.aikit/` are git-ignored (`.gitignore:8`, `.gitignore:12`), so tests cannot read gsd-core's key list and `.aikit/review-spec.toml` is NOT tracked.

**Primary recommendation:** keep `cfg_resolve`'s return shape; add `config_migrate.py` + `toml_splice.py`; do the runner as one sequential chain (template edit, then re-render, then shard timings); land migration before any caller switch.
