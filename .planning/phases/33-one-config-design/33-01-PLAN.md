Design (fixed here, so no executor decision is left):
- Value spans: a statement line (not blank, not a `#` comment, not a header) starts a `key = value` span; the span grows line by line until `tomllib.loads` of the joined span lines succeeds (multi-line arrays and strings are consumed whole, so a `[` inside them is never taken for a header). The key path comes from the text before the first `=` that is outside quotes, parsed with `tomllib.loads(key_text + " = 0")` and walked to the leaf (so `extra = { a = 1 }` is the key `extra`, while `extra.a = 1` is the key path `extra`, `a`).
- Headers: after the spans are consumed, a line whose stripped form starts with `[[` is an array-of-tables header and one starting with `[` a table header; the inner text runs from after the opening `[` (or `[[`) to the first `]` found outside double-quoted strings (inside quotes a backslash escapes the next character), so a quoted name may hold brackets (`[runner.retry.scopes."p[1]"] # note`, a scope name the runner writes, review concern C2-2) and a trailing comment is never part of it; the path comes from `tomllib.loads(inner_text + " = 0")` walked to the leaf (handles quoted keys such as `[runner.retry.scopes."myproj/workstreams/ws1"]`). When that parse raises TOMLDecodeError, split_blocks raises SpliceError(f"line {n}: cannot parse this table header") with n the header's 1-based line number, never the raw TOMLDecodeError (review concern C3-1): a literal-quoted name holding `]`, such as `['foo]bar']`, is valid TOML but its inner text is cut to `'foo`; such a name is already outside the subset the runner reads (Plan 02), so the write fails closed with the line named and nothing is written.
- Leading comments: contiguous `#` lines directly above a header (no blank line between) belong to the header's block; a blank line breaks the attachment.
- Newline: `"\r\n"` when the input contains `"\r\n"`, else `"\n"`; every line the splicer writes ends with it; a last input line without a newline gets one before anything is appended after it.
</context>
