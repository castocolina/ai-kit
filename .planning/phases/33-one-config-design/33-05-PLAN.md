Executor shell rules (owner rules, verbatim; pass them word for word to every subagent you start):

The owner runs with bypass permissions and is often away. Any command that makes the host ask for
permission stalls the whole run until the owner comes back. So:

- One simple command per shell call: a single program with plain arguments and absolute paths or
  `git -C <dir>`. Everything more complex goes into a `.sh` or `.py` file under `tmp/`, and the call
  just runs `bash <file>` or `python3 <file>`.
- Never `cd` into a directory, alone or chained (`cd <dir> && ...`, `cd <dir>; ...`).
- Never use heredocs (`<<EOF`), command substitution (`$(...)`, backticks), subshells (`( ... )`),
  process substitution (`<(...)`), `eval`, or long chains of `&&`, `||`, `;` or pipes.
- Never use `sed -i` or another in-place editor on a file; use the file-edit tool, or a script.
- Never delete outside `tmp/`, and never use `rm -rf` on a variable path.
- Write files with the file-write tool, not with `echo`/`printf` redirection, except appending one
  line to a ledger under `tmp/`.
- Pass these rules, word for word, to every subagent and executor you start.

D-11 refinement (recorded here, reviewed by /gsd-secure-phase): D-11 states that an attacker who can edit `.aikit/config.toml` but not a command entry gains nothing. Because `cfg_merge_reviewers` merges a project entry's fields into a user entry with the same `key`, a project entry without `command` can still change the arguments of a user `command` entry (the existing test `test_show_renders_local_fields_merged_into_a_global_command` relies on that merge). So `command_lanes_bytes` also counts project entries whose `key` matches a user command-bearing entry (`user_command_keys`, empty for a `local-only` project); Plan 07 passes the user keys. The same merge folds every later project row with the same `key` into the first (`by_key[key].update(r)` for each local row, config_io.py lines 368-371), and `render_reviewer_command` fills placeholders from the entry's extra fields (commands.py lines 111-132), so a second project row `key = "x"`, `tool = "evil"` changes the argv of a trusted `key = "x"` command row (review concern C1-12). `command_lanes_bytes` therefore also counts every entry of the file, in any role, whose `key` matches a command-bearing entry of the same file. Over-inclusion is fail-closed: an extra entry in the digest only means an edit to it needs a new trust.

Legacy text transform rules (`migrate_text`), using `toml_splice.split_blocks(old_text)`: the root block's lines are kept, with the line `[lanes]` inserted before its first key span (after the file-level comments), or appended after them when the root has no key; a `[[reviewers]]` block and the non-array blocks right after it whose path starts with `reviewers` form one entry group; the group is written once per role from `split_by_purpose` (review first, then execute), each copy with its leading comments, header `[[lanes.<role>]]` and sub-table headers `[lanes.<role>.<rest>]`; a `[policy...]` table becomes `[lanes.policy...]`; any other header gets `lanes.` in front; header rewrites keep leading whitespace and a trailing comment; every written line ends with the file's newline. A root key `reviewers` written as an inline array raises LegacyRosterError(old, "[[reviewers]] written as an inline array is not migrated; rewrite it as [[reviewers]] tables") (comment: `# shortcut: inline-array rosters are refused, not migrated; migrate them when one is seen`).
