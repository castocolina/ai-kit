<interfaces>
`listModels(cli, bin, env, limit) -> Promise<{ok: boolean, ids: string[], reason: string}>`: one
`runChild` call (18-10) with `capMs = LIST_CAP_MS (15000)` and `limit` = the run's `deadline`,
so it gets `min(15 s, time left)` and is cleaned up like every other child; never throws. `ok`
is true only for exit 0 and at least one parsed id; `reason` is one of `exit <n>`, `timeout`
(including a zero budget), `spawn error`, `unparseable`, `no ids`. claude has no listing (`ok`
false, reason `no listing`, and no note is printed for it). The prototype's 15 s `spawnSync`
form is not used: it blocks timers and signal handlers and ignores the remaining budget.

Preflight in `main`: once per candidate, before its first spawn, never under `--print-argv`.
Listing ok and model absent -> `bad_model` for that CLI (stderr names it), fallback to the next
candidate without spawning; listing not ok -> the `model list unavailable` note, then run.

Retries: a run whose `classify()` result is `transient` retries after `CONFIG.backoffS[i]`
seconds while attempts <= `CONFIG.retries` and the deadline leaves room; then the status is
`capacity`. The prototype's resume logic stays.

Fake `pi` modes added here: `flaky` (first call: stderr `429 Too Many Requests`, rc 1, no edit,
using a counter file `$HOME/.fake-flaky-count` in the case's own scratch HOME, never inside the
repo the runner snapshots; second call: edits `a.txt` and answers); `overloaded` (always stderr
`429`, rc 1, no edit). The fake `pi` listing gains `FAKE_PI_LIST=hang` (waits until killed).
</interfaces>
