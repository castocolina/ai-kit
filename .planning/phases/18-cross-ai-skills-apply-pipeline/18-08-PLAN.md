  or not a list -> [])

  an existing root `r` (trailing `/` stripped) covers the skill when `r` starts with `~/` and
  `value == r or value.startswith(r + "/")`, or when `r` is absolute and `real_dir == r or
  real_dir.startswith(r + "/")`. Comment: `shortcut: lexical comparison; a root reached only
  through a symlink is proposed again (harmless duplicate approval); gsd-core canonicalizes
  roots at use`
- `proposals(affinity, inv) -> list[dict]`: notes `{"kind": "skill_proposal", "key": name,
  "text": "unknown skill <skill> (<root_kind>): <description>; wire with plan-set
  agent_skills.<agent>"}` for addressable skills in no family, not `gsd-`-prefixed, with a
  non-empty description, sorted by name, at most `PROPOSAL_CAP`; when more exist, one extra note
  `{"kind": "skill_proposal_more", "key": "skills", "text": "<n> more unknown skills not listed;
  see the inventory's skills list"}`

`locate` change (18-07 function): a project entry with `escapes_root` true is skipped, so
precedence falls to the global, then the plugin copy; `resolve` adds the note `not wired:
<skill> (its project copy resolves outside the project)` when no other copy exists.

`resolve` change: a global skill with `escapes_root` true, no project copy and a null
`real_dir_home` is never wired (no `~/`-relative trusted root can name it); it adds the note
`not wired: <skill> resolves outside the home directory` (no path in the text). Project, plugin
and non-escaping global skills need no trusted root, so a null `real_dir_home` never affects
them (a project outside HOME keeps its `skills/<name>` wiring).

Trusted-root entry (from `_skills_layer`): key `agent_skills_security.trusted_global_roots`,
source `affinity`, `status="needs_choice"`, `value None`, candidates from `trusted_roots`, why
`approve with plan-set agent_skills_security.trusted_global_roots '<json list>' or keep the
current value with plan-unset; a declined root leaves the skill wired and gsd-core skips it
(apply reports the warning)`, where `<json list>` is the merged list: `existing_roots(inv)` in
order and in their recorded form (absolute included), then the new candidate values (18-14
accepts an element that is a candidate, or equal to one in the entry's recorded `existing` list
in any form; a new element must be `~/`-relative). No entry when every proposed root is
covered.
