<interfaces>
PATTERNS markers: a line `// <patterns>`, then `const PATTERNS = {...};` (JSON, keys in check
order, values are regex source strings compiled with flag `i`), then a line `// </patterns>`:
- `permission_blocked`: `permission denied|requires approval|approval required|workspace trust required|pre-dispatch filters`
- `auth`: `\\b40[13]\\b|unauthori[sz]ed|token_expired|invalid_refresh_token|could not be refreshed|not logged in|log ?in required|please (?:log|sign) ?in|invalid api key|requires an opencode API key|credential gate`
- `billing`: `spending limit|billing|payment required|\\b402\\b`
- `bad_model`: `model not found|unknown model|invalid model`
- `quota`: `quota exceeded|insufficient_quota|usage limit`
- `capacity`: `overloaded|at capacity|service unavailable|\\b503\\b`
- `transient`: `temporarily unavailable|cooling down|is locked|rate.?limit|too many requests|\\b429\\b|\\b50[24]\\b|ECONNRESET|ETIMEDOUT|socket hang up|stream (?:closed|disconnected)`

`classify(stderrText, structuredError) -> status | 'transient' | null`: walks `PATTERNS` in key
order over the two inputs only. The prototype's `TRANSIENT`/`FATAL` regexes and its
blob-of-stdout classification are deleted.

Lifecycle (one per run, computed in `main` before the first child): `deadline` = start + inner
seconds; `finalizeBy = deadline + Math.min(FINALIZE_CAP_MS, Math.floor(marginMs / 2))` with
`FINALIZE_CAP_MS = 10000` and `marginMs` = (outer - `innerTimeoutS(outer)`) * 1000, the D-29
margin (`--timeout` lowers `deadline` only). `budgetMs(capMs, limit) = Math.max(0,
Math.min(capMs, limit - Date.now()))`. Work before and during a CLI run uses `deadline`; the
after-run snapshot, the kill grace and the pipe drain use `finalizeBy`.

`runChild(bin, argv, opts) -> Promise<{code, signal, timedOut, spawnErr, stdout, stderr}>`
(`opts`: `input`, `env`, `cwd`, `capMs`, `limit`, optional `onStdout`/`onStderr`): spawns
detached (own process group) and settles exactly once (a `settled` guard). On the child's `exit`
event (never `close`): SIGTERM the group, read the pipes for at most `budgetMs(PIPE_DRAIN_MS =
2000, finalizeBy)`, destroy them, SIGKILL the group, resolve. On the budget timer
(`budgetMs(capMs, limit)`, 0 means no spawn and an immediate timeout): `timedOut`, SIGTERM the
group, wait for `exit` at most `budgetMs(KILL_GRACE_MS = 2000, finalizeBy)`, SIGKILL the group,
resolve. On `error`: resolve with `spawnErr`. `runOnce` (a CLI run: heartbeat, stderr echo) is
`runChild` plus the heartbeat; `treeState` and 18-11's `listModels` use `runChild` too.

`treeState(cwd, limit) -> Promise<{head, tree} | null>`: `git rev-parse HEAD` (null head on an
unborn branch) plus `git add -A` and `git write-tree` with `GIT_INDEX_FILE` pointing into a
fresh `fs.mkdtempSync` dir that is removed afterwards, each through `runChild` with `capMs =
GIT_CAP_MS (10000)`; null on a timeout, a zero budget, a spawn error or a failing git command
(other than the unborn-HEAD case). Async, so timers and signal handlers keep running while git
works. "Changed" means head or tree differs from the state taken before the CLI ran.

Status added to the 18-09 table: `unverified` -> exit 1, action stop.

Outcome mapping per CLI run (exec mode): rc 0 + non-empty parsed text + no structured error +
changed -> ok; rc 0 + non-empty text + unchanged -> no_change; rc 0 + empty text -> empty_answer;
classify() hit -> that status; otherwise non-zero rc -> crash. A fallback status with a changed
state becomes `stop` (status kept, `tree=dirty`) and no later CLI runs. Unknown state: a null
before-state skips the spawn and finishes `unverified` (`cli_rc=-`, `tree=unknown`); a null
after-state maps rc 0 + non-empty text + no structured error to `unverified`, and any other
outcome keeps its status with `tree=unknown` and action `stop`.

Fake `pi` modes added here (name after `fake/`): `nochange` (rc 0, prints an answer, no edit);
`empty` (rc 0, no stdout, no edit); `crash` (stderr `boom`, rc 7); `quote` (edits `a.txt`, rc 0,
answer contains `429 rate limit` and `billing`); `billing` (stderr `402 payment required`, rc 1);
`auth` (stderr `401 unauthorized`, rc 1); `perm` (stderr `permission denied`, rc 1); `quota`
(stderr `quota exceeded`, rc 1); `dirtycrash` (edits `a.txt`, then rc 7); `reedit` (appends to
the untracked `dirty.txt` the case pre-creates, prints an answer, rc 0); `hang` (spawns a node
grandchild with `stdio: 'ignore'` and no `detached` option, so it stays in the fake CLI's process
group, the group the runner created by spawning the CLI detached; the grandchild writes its pid
to `<repo>/gc.pid` and loops; the fake then waits forever). A detached grandchild would start its
own process group and survive `process.kill(-pid)`, so the fake never detaches it. Task 2 also
adds `gcpipe` (spawns a non-detached grandchild with `stdio: 'inherit'`, so it holds the fake's
stdout and stderr, writes its pid to `<repo>/gc.pid` and loops; the fake then edits `a.txt`,
answers and exits 0), `gcterm` (as `gcpipe`, but the grandchild ignores SIGTERM) and `gitfail`
(edits `a.txt`, creates `$HOME/.fake-git-fail`, answers, rc 0).
