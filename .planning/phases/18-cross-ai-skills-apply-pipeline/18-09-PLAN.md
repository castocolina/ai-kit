CONFIG markers: a line exactly `// <config>`, then `const CONFIG = ` followed by the text of
`JSON.stringify(cfg, sortedKeys, 2)` and `;`, then a line exactly `// </config>`. Default values:
`{"backoffS": [30, 60], "extraArgs": {}, "heartbeatS": 30, "models": {}, "outerTimeoutS": 1800,
"prefer": ["pi", "cursor", "opencode"], "retries": 2, "routerBacked": {}, "scrubEnv": [sorted
HOST_SIGNAL_ENV_VARS]}`. Below the block: `const TIMEOUT_MARGIN_S = 30;` and
`const GSD_DEFAULT_TIMEOUT_S = 300;` (comment: gsd-core's own default when
`workflow.cross_ai_timeout` is absent, `execute-phase/detail/elaboration.md:74`).

Status table (status -> exit, action), used by `finish()` from this plan on: ok 0 stop;
no_change 1 fallback; empty_answer 1 fallback; crash 1 fallback; contract_violation 1 stop;
usage 2 stop; no_model 2 stop; empty_stdin 2 stop; permission_blocked 69 fallback; bad_model
69 fallback; auth 69 fallback; billing 69 fallback (75 retry-later when
`CONFIG.routerBacked[cli]`); quota 75 retry-later; capacity 75 retry-later; timeout 124 stop;
not_installed 127 fallback; signal 128+n stop. Any fallback action becomes `stop` when the run
left `tree=dirty` or `tree=unknown` (the prototype also refused to fall back when git state was
unknown). An unknown id in `--prefer` is `usage`. The top-level rejection handler (the
runner's own internal error) prints `cross-ai: internal error ...` and ends through
`finish('crash', ...)` with `tree=unknown`, so even that path ends with the status line.

Status line (stderr, last line, one per invocation in run mode):
`AIKIT-XAI status=<s> cli=<id or -> model=<m or -> exit=<n> cli_rc=<rc or -> elapsed=<int>s out=<stdout bytes> tree=<clean|dirty|unknown> action=<a>`.

Flags kept from the prototype: `--prefer`, `--model-<cli>`, `--mode`, `--timeout`,
`--print-argv`, `--no-preamble`, `--self-test`. No header-state flag (the prototype's
`headerState` export is deleted).

Self-test harness (replaces the prototype's white-box `selfTest`):
- `tmp = fs.mkdtempSync(path.join(os.tmpdir(), 'xai-st-'))`; `<tmp>/bin` holds the fake CLIs and
  two symlinks, `node` -> `process.execPath` and `git` -> the `git` found on the parent's PATH
  (missing git -> print `self-test: git not found` and exit 1); `<tmp>/home` is the scratch
  HOME; `<tmp>/calls.log` records fake runs. The temp dir is removed in a `finally`.
- `hermeticEnv(tmp, extra)` returns only: `PATH=<tmp>/bin`, `HOME=<tmp>/home`,
  `XDG_CONFIG_HOME=<tmp>/home/.config`, `GIT_CONFIG_GLOBAL=os.devNull`,
  `GIT_CONFIG_NOSYSTEM=1`, `GIT_AUTHOR_NAME`/`GIT_COMMITTER_NAME=xai-selftest`,
  `GIT_AUTHOR_EMAIL`/`GIT_COMMITTER_EMAIL=xai-selftest@example.invalid`, `LANG=C`,
  `FAKE_CALLS=<tmp>/calls.log`, plus `extra`. Nothing comes from `process.env`. Every case and
  every git call the harness makes uses it.
- `writeCopy(tmp, name, override)`: this file's raw bytes with the CONFIG block replaced by the
  test CONFIG (defaults with `models {}`, `routerBacked {}`, `backoffS [0, 0]`, then `override`
  merged on top), written to `<tmp>/runner-<case>.mjs`.
- Case table entries: `{name, args, stdin = 'prompt\n', env = {}, config = {}, exit, status,
  check}`. Per case: a fresh repo `<tmp>/r-<case>` (`git init -q`, `a.txt` committed), a copy
  from `writeCopy`, then `spawnSync(process.execPath, [copy, ...args], {cwd: repo, env:
  hermeticEnv(tmp, env), input: stdin, encoding: 'utf8', timeout: 30000})`. Pass means: exit code
  equals `exit`; exactly one stderr line starts with `AIKIT-XAI `; it is the last non-empty
  stderr line; it matches the regex `status`; `check(result, ctx)` (optional) returns null. All
  cases run; failures print `self-test FAIL <case>: <reason>` and the run exits 1; otherwise it
  prints `self-test ok` and exits 0.
- Fake CLIs are node scripts written to `<tmp>/bin/<cli>` with first line `#!` +
  `process.execPath` and mode 0o755. Each appends `<cli> <mode>` to `$FAKE_CALLS` (`pi rpc` for a
  listing call) and reads stdin to EOF. The fake `pi` takes its mode from the `--model` value after `fake/` and acts by
  a `FAKE_MODES` table in its source; this plan adds `ok` (append a line to `a.txt`, print
  `# Summary` and `ok`, exit 0); later plans add modes. Called with `--mode rpc` it answers the
  model listing instead: with `FAKE_PI_LIST` unset it prints one line
  `{"id":"1","type":"response","command":"get_available_models","success":true,"data":{"models":[...]}}`
  listing `{"provider":"fake","id":"<mode>"}` for every `FAKE_MODES` key (so `fake/missing` is
  never listed); `FAKE_PI_LIST=broken` prints `not json` and exits 0; `FAKE_PI_LIST=fail` exits 1.
  Nothing calls the listing until 18-11.

Python side (tests/test_cross_ai_runner_e2e.py): `runner_env(tmp) -> dict` builds the same
hermetic env for Python-launched runs (`<tmp>/bin` with `node` and `git` symlinks resolved by
`shutil.which` on the test process's PATH, scratch HOME, the same git variables). Every Python
test that runs the template or a rendered script uses it.
