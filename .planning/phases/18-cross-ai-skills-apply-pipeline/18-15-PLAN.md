<interfaces>
plan_edit.py additions:
- `SCRIPT_MODEL_PREFIX = "script:cross-ai.model."`, `SCRIPT_PREFER_KEY = "script:cross-ai.prefer"`
- `runtime_candidates(inv, runner_id) -> list[dict]`: up to 3 inventory candidates of
  `cross_ai.RUNNER_CLI[runner_id]` in price order (`{"model", "price"}` rows)
- `plan_unset(call: EditCall, key: str) -> tuple[dict, list[str]]`

Pseudo-key rules (artifact = the `cross-ai-script` entry of `plan["artifacts"]`; missing
artifact -> `PlanEditError("no cross-AI script artifact; rerun recommend with --cross-ai-exec y")`):
- `plan-set script:cross-ai.model.<id> <model>`: `<id>` must be in `config.prefer`; sets
  `config.models[id]`, sets `config.router_backed[id]` to the inventory candidate's `is_router`
  (false when the model is not an inventory candidate), deletes `choices[id]`; a model not
  listed for that runtime in the inventory -> refused unless `--force`.
- `plan-set script:cross-ai.prefer '<json list>'`: every id in `RUNNER_CLI`, not the plan's host,
  its runtime installed; refused otherwise (no `--force` override); an empty list -> refused
  with `removing every target would leave no execution target; plan-set
  workflow.cross_ai_execution false instead`. Ids dropped from the list lose their `models`,
  `router_backed` and `choices` rows; ids added get `choices[id] = {"candidates":
  runtime_candidates(...)}`.
- `plan-unset script:cross-ai.model.<id>`: removes `config.models[id]` and
  `config.router_backed[id]` and sets `choices[id] = {"candidates": runtime_candidates(...)}`;
  the target stays in `prefer`.
- After every pseudo-key edit: artifact `source` = `user`; artifact `status` = `needs_choice`
  when `choices` is non-empty else `ok`; the `workflow.cross_ai_command` entry gets
  `status="needs_choice"` with `candidates=[]` in the first case and loses `status`/`candidates`
  in the second.

Refusal messages added: `<k> is not in the plan; nothing to unset`;
`workflow.cross_ai_timeout is required while workflow.cross_ai_execution is on`; `script target
<id> is not one of pi, cursor, opencode, codex, is the host, or is not installed`.

Execution invariants (added to `plan_io.validate_plan`, so they run after every edit and at
every load; "effective value" = the entry's `value` for op `set`, its `existing` for op `keep`
(apply never writes a keep, so the config keeps that value; 18-14 also requires a keep's
`value` to equal a non-null `existing`), None for `unset` or no entry; review cycle 2):
- `workflow.cross_ai_execution` effectively true -> the `workflow.cross_ai_command` entry is
  `needs_choice`, or its effective value is `cross_ai.CROSS_AI_COMMAND` or a `forced` value;
  otherwise `workflow.cross_ai_command is required while workflow.cross_ai_execution is on`.
- effective command == `CROSS_AI_COMMAND` -> exactly one script artifact (`the cross-AI script
  artifact must exist while workflow.cross_ai_command runs it; rerun recommend`) and an
  effective `workflow.cross_ai_timeout` int >= 1800 (the existing timeout message).
- execution not effectively true -> `artifacts == []` (`a cross-AI script artifact needs
  workflow.cross_ai_execution on`).
</interfaces>
