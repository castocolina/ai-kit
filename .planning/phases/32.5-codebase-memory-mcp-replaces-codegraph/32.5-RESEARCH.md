## Summary

The swap is mostly mechanical text and a small number of real behaviour changes. The real work is: (1) `flow_index.py` replaces a
five-verb codegraph decision tree with one `index_repository` call; (2) `flow_brief.py` replaces the `codegraph explore` output parser
with one `query_graph --format json` call; (3) `detection.py` replaces subprocess `mcp list/get` health probes with a read-only reader of host
config files (D-05); (4) the advisor hook, tool presence and global-rules writer lose their `.codegraph/` directory test because
codebase-memory-mcp keeps its index in `~/.cache/codebase-memory-mcp/<project>.db`, never in the repo.

Two facts correct or sharpen the SPEC. (a) The default stdout of `cli` is a compact text format, not JSON, for every tool except
`index_repository`; `--format json` (or `--json` for the raw MCP envelope) gives JSON. Passing raw JSON as the positional argument still
works but prints a deprecation warning on stderr: use flags (`--repo-path`, `--mode`). (b) The tripwire stubs (`HOST_CLI_NAMES` in
`tools/run_unittest_parallel.py`) hold host CLIs only; codegraph is not there today and is faked per test through `tests/index_fakes.py`. The SPEC
constraint "the tripwire stubs gain the new binary" therefore needs a new small stub set, not an edit of `HOST_CLI_NAMES` (drift tests pin that set to `RUNTIMES`).

**Primary recommendation:** call the tool as `codebase-memory-mcp cli <tool> --flag value ...` with cwd = checkout and `--repo-path .`
(same project name as the absolute path, so the existing "checkout as cwd, `.` as argv" rule and its test survive); read results as JSON
(`index_repository` always, others with `--format json`); detect registration by reading host files as data; never run the tool's `install`.

## `.cbmignore` (D-07)

- Syntax: one pattern per line, gitignore style; blank lines and `#` comments ignored; trailing `/` matches directories only; leading `/` anchors to the repo root; no `/` matches at any depth; `**` crosses directories; `!` re-includes; only the root file is read; nested ones are not [CITED: raw.githubusercontent.com/DeusData/codebase-memory-mcp/main/docs/cbmignore.md].
- Precedence: built-in skip list, repo `.gitignore` (with `info/exclude`), nested `.gitignore`, `.cbmignore`, git global excludes. `.git`, `node_modules`, `.worktrees`, `.claude-worktrees` are a non-negatable safety core [CITED: same doc]. Changes take effect on the next (re)index [CITED: same doc].
- Content to write: a single line `.planning/` (a comment line above it is allowed). Proven in a scratch repo [VERIFIED: out2/idx1.out vs idx2.out]: before, `excluded.dirs` = `[".git"]`, 32 nodes, a search for a section heading in `.planning/phases/PLAN.md` returned it; after adding `.cbmignore` with `.planning/` and re-indexing: `excluded.dirs` = `[".planning",".git"]`, 26 nodes, the same search returned `results: 0` (out2/sg2.out) and `search_graph --file-pattern '.planning/**'` returned 0.
- Plan check after the re-index (real repo, run by the executor, writes only the tool's cache): `codebase-memory-mcp cli index_repository --repo-path . --mode full` (cwd = checkout), assert the JSON `excluded.dirs` contains `".planning"`; then `codebase-memory-mcp cli search_graph --project <name> --query SPEC --file-pattern '.planning/**' --limit 3` shows `results: 0`. Note `excluded.dirs` may be `truncated:true` with a capped list (73 dirs on the real repo, 5 shown): `.planning` might not appear in the 5-element sample. The reliable check is therefore the search (`total: 0`), or `check_index_coverage`. [ASSUMED: sample order; verify when the executor runs it.]
- `.gitignore` swap: line 9 `.codegraph/` -> `.codebase-memory/` [VERIFIED: .gitignore:9 via rg].
- Worktrees: `.cbmignore` is a tracked root file, so it exists in every checkout; whether the tool also reads it when the root is a worktree was not stated in the docs; the scratch worktree test had no `.cbmignore` committed. Low risk; the check above can also be run once inside a worktree. [ASSUMED]

## Common Pitfalls

### P1: `search_graph --file-pattern` takes a single glob
**What goes wrong:** comma or brace lists silently return 0 results (verified). **Avoid:** `query_graph` with `IN [...]`.
### P2: raw JSON positional args print a deprecation warning
Flag form only; tests assert the argv uses `--repo-path`/`--mode` and not a JSON blob (would also break the "no argv contains the path" test).
### P3: error output is on stderr and is sometimes JSON, sometimes plain text
`repo_path is required` and `unknown tool` are plain text; pipeline failure is JSON with a `hint`. The one-line failure report must handle both (parse JSON, fall back to first line, 80 chars like `_first_line`).
### P4: `index_status.status` is `ready`, `index_repository.status` is `indexed`
Do not share a constant.
### P5: Cypher string escaping
File paths from `git diff` can hold `'` or `\`. Escape both before building the `IN [...]` literal, or the query errors (rc 1). Add a unit test with a quote in a path. [ASSUMED: Cypher escape is backslash; confirm with one scratch run in the executor's first task]
### P6: `query_graph` default 200 rows
More than 200 symbols across 50 files is plausible; set `--max-rows` explicitly (for example 2000) and read `has_more`/`truncated`; label the brief "partial" like today's dropped-count label.
### P7: the brief must work when the index is absent or stale
`list_projects` has no match, or the project's `root_path` differs (a moved checkout): report `file names only: ...` and continue; never fail the boundary.
### P8: `.codegraph/` references that tests use as a generic directory
`test_flow_boundary.py:352-368` and `test_flow_index_e2e.py:144` use `.codegraph` as a stand-in; swap for `graphify-out` or fake-log assertions, not for `.codebase-memory`.
### P9: pinned doc tests
`test_rules_docs.py` pins clause count 13, AGENTS.md section text, R07 signals, runbook headings and phrases, and the skill-judge and design bullets. Edit AGENTS.md and `code_exploration.py` in one commit with the test changes.
### P10: live-set check and replacement notes
The SPEC allows only lines that say codegraph was replaced; operationalize as: every line matching `codegraph` (case-insensitive) in the scope also contains `codebase-memory-mcp`. Some planned lines will not (the SPEC/REQUIREMENTS IDX-07 row 808: "History records keep their codegraph wording" has no cbm name; the 32.5 ROADMAP block lines 546-557 partly). Add the tool name to those lines or allowlist the IDX/32.5 blocks explicitly in the plan's scope script.
### P11: completed-phase rows in REQUIREMENTS.md/ROADMAP.md
24 and 19 lines describe Phase 30 behaviour as built (checked boxes). They are "live rows" per SPEC R6 text; see Q2 for the rewrite rule.
### P12: `ensure-runner` after the template comment edit
The dogfood copy must be re-rendered in the same commit or `make check-dogfood` fails.
### P13: shared machinery
Edits to `tools/run_unittest_parallel.py` (tripwire), `tests/host_fakes.py` and `tests/index_fakes.py` (covers two or more modules) trigger the full unit and arch groups at commit. Plan them as dedicated plans, run `AI_KIT_REFUSE_REAL_HOME=1 make test-unit` once after each.
