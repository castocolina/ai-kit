## Warnings

### WR-01: Unit brief silently loses symbol names and misstates why (query_graph output budget)

**File:** `skills/ai-kit-commit-fold/scripts/flow_brief.py:134-152, 166-169`
**Issue:** `explore_names` makes one `query_graph` call with `--max-rows 2000` and treats `has_more`/`truncated`
as "more than 2000 rows". The real tool cuts the page at an output budget long before that. A live call with
`--max-rows 2000` returned only `"returned":178,"total":5103,"truncated":true,"truncation_reason":"output_budget"`.
- **Failing case:** a unit that changes `cross-ai.mjs` (hundreds of functions) or many Python modules gets
  only about 180 names in the brief.
- **Effect:** the mention search misses documents for every dropped name, and the label says
  `partial: more than 2000 rows`, which is false. This breaks the AGENTS.md rule that no result may claim
  more certainty than its sourcing.
- **Test gap:** the fake in `tests/index_fakes.py` never models an output-budget cut, so the tests cannot catch it.

**Fix:** Page with the `--offset` that the tool reports. `--offset` works (verified live: `next_offset` is
returned and accepted). Stop at `MAX_QUERY_ROWS`, and label the result with the real counts:
```python
names, offset, total = set(), 0, None
while len(names) < MAX_QUERY_ROWS:
    rc, out, _ = run([... "--max-rows", str(MAX_QUERY_ROWS), "--offset", str(offset), "--query", query], top)
    if rc != 0: ...
    data = json.loads(out); rows = data.get("rows") or []
    names |= {r[1] for r in rows if isinstance(r, list) and len(r) > 1 and isinstance(r[1], str)}
    total = data.get("total", total)
    if not data.get("has_more") or not rows: break
    offset = data.get("next_offset", offset + len(rows))
# partial label: f"partial: {len(names)} of {total} rows"
```
Also make the fake return `truncation_reason: output_budget` with a small budget, so that a test covers paging.

### WR-02: Every new worktree leaves a full index database behind in the user's cache

**File:** `skills/ai-kit-commit-fold/scripts/flow_index.py:89-106` (called from `refresh`, `drain` at 319/324 and the `detach` post-checkout hook at 367)
**Issue:**
- **Old behaviour:** codegraph's index lived inside the checkout (`.codegraph/`), so it disappeared with the worktree.
- **New behaviour:** `cbm_step` runs `index_repository --mode full` on every queued checkout. The
  post-checkout hook queues every `git worktree add`, and codebase-memory-mcp stores one database per
  project root under `~/.cache/codebase-memory-mcp/`. Research verified that a worktree gets its own project.
- **Failing case:** each executor or unit worktree adds about 117 MB to the user's cache, the size of this
  repo's database today (`var-home-bazzite-git-personal-ai-kit.db`).
- **Why it leaks:** nothing ever calls `delete_project` (RESEARCH line 182 confirms the verb exists). After
  `git worktree remove`, the database stays forever.

This goes against the AGENTS.md rule that closing a plan leaves nothing behind (large files outside `tmp/`).
Neither the SPEC nor CONTEXT considered the growth.
**Fix:** In `refresh` (or `drain`), before indexing, call `list_projects` once. Run `delete_project --project
<name>` for each project whose `root_path` no longer exists and was a worktree of this repo (same common dir;
a missing path from `git worktree list --porcelain` marked `prunable`). Report one `note:` line per deleted
project. As a lower-cost alternative, have the doctor report stale projects. Add one fake-backed test.

### WR-03: Claude registration reader ignores CLAUDE_CONFIG_DIR, so lanes miss the MCP tools

**File:** `skills/ai-kit-spec-review/ai_kit_spec/detection.py:1179`, `tools/config_doctor_checks.py:656`
**Issue:**
- **What it reads:** both copies always read `$HOME/.claude.json`.
- **What Claude Code uses:** with `CLAUDE_CONFIG_DIR` set, Claude Code keeps its global config, including
  user-scope `mcpServers`, at `$CLAUDE_CONFIG_DIR/.claude.json`. The repo already honours that variable for
  the same host in `tools/global_rules.py` (`global_instruction_paths`).
- **Failing case:** with `CLAUDE_CONFIG_DIR=/x` and codebase-memory-mcp registered in `/x/.claude.json`:
  - `cbm_registration("claude")` returns `registered=False`, so reviewer and executor lanes get the CLI-form
    line instead of the MCP tool list;
  - the superpowers adapter skips its pre-dispatch index;
  - the doctor row shows `claude: not registered`.

**Fix:** In both copies:
```python
base = env.get("CLAUDE_CONFIG_DIR") or home
paths = [os.path.join(base, ".claude.json")]
```
Then extend the existing parity test (`TestCodeIndexRows`) and `test_cbm_detection.py` with a
`CLAUDE_CONFIG_DIR` case. If Claude's exact lookup is not verified on this machine, flag the detail string
as inferred.

### WR-04: Doctor reports "codebase-memory-mcp block" while a codegraph block still sits in the same file

**File:** `tools/global_rules.py:84-87, 281-289`
**Issue:**
- **How a file is classified:** `_plan_one` marks a file `already` as soon as it holds a codebase-memory-mcp
  block, even when a full `CODEGRAPH_START/END` block also sits there. Keeping that file byte-equal is a
  deliberate choice (`test_codebase_memory_mcp_and_legacy_blocks_together_stay_byte_equal`).
- **What the summary says:** `summary()` then returns `codebase-memory-mcp block`, and the doctor row
  matches its recommended value.
- **Failing case:** a tools-installer or codegraph re-run (the SPEC Background names this risk) appends the
  old block to `~/.claude/CLAUDE.md`. Agents are again told to run `codegraph init -y`, a tool the owner
  uninstalled, and both the doctor and the wizard say everything is fine.

**Fix:** Keep the bytes as they are, but report the state honestly. For example, in `_plan_one`, return status
`"both"` when a complete legacy block is also present. In `summary()`, append
`; leftover codegraph block beside it: <hosts>`, and in `_SKIP_TEXT` add
`"both": "codegraph block beside the codebase-memory-mcp block (left for manual removal)"`. Add one test
assertion on the summary value.

### WR-05: Code-index alternative is offered without checking that the alternative has the server registered

**File:** `skills/ai-kit-spec-review/ai_kit_spec/detection.py:1321-1343`
**Issue:**
- **What the SPEC asks:** R3's target says that spec-config's preference "reads that result" (the
  per-runtime registration).
- **What the code does:** `find_code_index_alternative` returns the first installed multi-provider CLI that
  lists the model, whether or not codebase-memory-mcp is registered there.

**Fix:** Filter the candidates on the read-only reader that already exists:

```python
for candidate_cli in _MULTI_PROVIDER_CLIS:

```
Then add one test with the alternative registered and one with it unregistered (use
`host_fakes.write_cbm_registration` in a scratch HOME).

#### RR-01 (WARNING): removing a trailing codegraph block strips the file's last newline; a mid-file removal can join two paragraphs

**File:** `tools/global_rules.py:89-99`
**Issue:** The separator rule breaks the triage contract ("one adjacent blank-line separator, every other
byte equal") in two layouts:
- **Block at the end of the file** (the usual layout when an installer appends `\n\n<block>\n`):
  `re.search(rb"\r?\n$", head)` uses `$`, which also matches *before* a final newline. With
  `head = b"...end -->\n\n"` the match starts at the first `\n`, so both newlines go.
  - Probe: `CBM + b"\n\n" + LEG + b"\n"` -> `b"...<!-- codebase-memory-mcp:end -->"`, with no final newline.
  - The tight layout `CBM + b"\n" + LEG + b"\n"` (LF or CRLF) also loses the final line end, because the
    head is trimmed even though the block's own line end was already consumed.
- **Mid-file, blank line only after the block:** `b"A\n" + LEG + b"\n\nB\n"` -> `b"A\nB\n"`. The rule always
  drops a following blank line, even when none came before the block. Two Markdown text paragraphs merge
  into one.

The tests miss both layouts. `"at the end"` (`test_global_rules.py:319`) has no final newline, and no
mid-file case has the blank line on one side only. The fixer flagged this rule for human verification.
**Fix:** Consume the block's own line end, then take a second newline only when the head already ends a
blank line (or the head is empty). At end of file, trim the head only when nothing was consumed after the
block. Use `\Z`, not `$`:
```python
head, rest = data[:begin], data[end:]
own = re.match(rb"\r?\n", rest)
if own:
    rest = rest[own.end():]
if not head or re.search(rb"\r?\n\r?\n\Z", head):   # a blank line already precedes the block
    extra = re.match(rb"\r?\n", rest)
    if extra:
        rest = rest[extra.end():]
    elif not rest and head:                          # block ended the file: drop the blank before it
        head = head[: re.search(rb"\r?\n\Z", head).start()]
```
Add cases: `cbm\n\nleg\n -> cbm\n`, `cbm\nleg\n -> cbm\n`, the same two with CRLF, and
`A\nleg\n\nB -> A\n\nB`. The existing `"at the end"` case then expects `cbm + b"\n"`.

#### RR-04 (INFO): prune scope is "the parent of the git common dir", which is not the checkout for a bare or separate git dir

**File:** `skills/ai-kit-commit-fold/scripts/flow_index.py:139-145` (via `flow_record.main_worktree`,

**Issue:** For `git clone --separate-git-dir ~/gitdirs/x.git`, or a bare `~/x.git` with worktrees elsewhere,

**Fix:** Prune only when the common dir is `<main>/.git` (`os.path.basename(common) == ".git"`), else return
