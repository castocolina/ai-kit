# Phase 32.5: codebase-memory-mcp replaces codegraph — Specification

**Created:** 2026-11-14
**Ambiguity score:** 0.12 (gate: ≤ 0.20)
**Requirements:** 7 locked

## Goal

Every live place where ai-kit indexes, checks, recommends or documents a code-exploration tool uses
codebase-memory-mcp instead of codegraph: the unit flow's boundary refresh and brief, `make setup-dev`, the doctor,
the global-rules writer, the tool advisor hook, the project-rules code-exploration rule, the lane tooling guidance for
every runtime (opencode and pi included), and the docs and skills that name it. History records stay as written.

## Background

The owner's input for this spec (2026-11-14, verbatim intent, highest priority): find every reference to `codegraph`
and change it to `codebase-memory-mcp`, knowing that agents in opencode and pi can use it too. It is a set of tools to
index and explore the codebase; it supports more languages, indexes documents better and supports pi. Add an entry to
`~/.claude/CLAUDE.md` and to the global instruction files the other tools read by default (Copilot CLI, Cursor,
opencode, pi). Index with the new tool now and compare the indexes. The owner uninstalled codegraph on 2026-11-14.

Live facts checked for this spec (2026-11-14, at `bb34055`, with codebase-memory-mcp itself, `rg` and scratch runs
under `tmp/cbm/`):

- **The tool.** `codebase-memory-mcp` 0.12.1 is installed at `~/.local/bin`. It runs as an MCP server on stdio and as
  a one-shot CLI (`codebase-memory-mcp cli <tool> '<json args>'`). Its `install` command lists 45 client surfaces,
  pi, opencode, Codex, Copilot CLI and Cursor among them; the owner's install wrote its MCP entry for Claude Code,
  opencode, Cursor and Copilot CLI, a pi extension (`~/.pi/agent/extensions/cbmem.ts`) and skill, and its managed
  instruction block in the opencode, pi and Copilot global files and a pointer in Codex's. Indexes live under
  `~/.cache/codebase-memory-mcp/` (one database per project root); `index_repository` can also write
  `.codebase-memory/graph.db.zst` inside the repo when `persistence` is set. Its watcher keeps a session project's
  index fresh (`auto_watch = true`).

## Requirements

1. **Boundary refresh and brief on codebase-memory-mcp**: the unit flow's boundary step and `fold.py index` refresh the codebase-memory-mcp index of the checkout (or worktree) instead of running codegraph, and the unit brief names the previous unit's changed functions from it.
   - Current: `flow_index.codegraph_step` runs `codegraph status`, then `init -y`, `sync` or `index`; the brief reads codegraph; a missing codegraph is reported with its install line.
   - Target: the step runs `codebase-memory-mcp cli index_repository` on the checkout root (the worktree root inside a worktree) and reads its result; the brief gets changed functions from the new index; a missing binary is reported once with its install command and the step still exits 0 and still runs graphify; no codegraph command is run.
   - Acceptance: `tests/test_flow_index.py`, `test_flow_brief.py` and `test_flow_boundary.py` pass against host fakes for the new binary (current index, missing tool, failing index, worktree path); a test asserts no argv names codegraph.

2. **Lane tooling guidance names codebase-memory-mcp on every runtime**: the tooling guidance given to review and execute lanes (spec-review, spec-execute, the superpowers adapter) tells each lane how to use codebase-memory-mcp, with the MCP tools where the lane's host has them and the CLI form where it does not.
   - Current: the guidance offers codegraph when a `.codegraph/` index exists.
   - Target: the guidance names codebase-memory-mcp when the binary is on the child's PATH and the repo is indexed (or indexable), lists the MCP tools for hosts that register it (Claude Code, opencode, pi, Codex, Copilot CLI, Cursor) and the `codebase-memory-mcp cli <tool> '<json args>'` form otherwise; nothing mentions codegraph.
   - Acceptance: unit tests build the guidance for each runtime in the `RUNTIMES` table with the binary present and absent; the expected text names the new tool and no test fixture or expected string names codegraph.

3. **Detection and the CLI preference move with it**: the spec-review detection that checks codegraph's health and runs its index, and spec-config's codegraph-aware CLI preference, read codebase-memory-mcp instead.
   - Current: `detection.py` probes codegraph per runtime (`run_codegraph_index`, a timeout constant, health checks), and spec-config prefers CLIs with codegraph wired.
   - Target: detection reports, per runtime, whether codebase-memory-mcp is registered for that host and whether the repo has an index, with no auto-install and no write to the user's global config; spec-config's preference reads that result; the codegraph probe and its constants are removed.
   - Acceptance: detection tests run against host fakes for registered, unregistered and missing-binary cases; a test asserts detection never writes outside the scratch home; `rg -i codegraph skills/ai-kit-spec-review/ai_kit_spec` finds nothing.

4. **Machine setup, doctor, global rules, advisor hook and wizard**: `make setup-dev`, the doctor, the global-rules writer, the tool advisor hook and the setup wizard check, recommend or write codebase-memory-mcp instead of codegraph.
   - Current: `setup_dev.py` installs codegraph; the doctor checks it; `global_rules.py` writes a codegraph code-exploration rule; the advisor hook suggests codegraph over grep; the wizard shows a codegraph card.
   - Target: `make setup-dev` installs or checks codebase-memory-mcp through a guarded step that reports a failure with its manual command and still exits 0; the doctor checks the binary and its MCP registration per host; the global-rules block and the advisor hook name the new tool and its CLI form; the wizard card names it; every write stays atomic through the existing helpers.
   - Acceptance: `tests/test_setup_dev.py`, `test_config_doctor.py`, `test_doctor_apply_safety.py`, `test_global_rules.py`, `test_tool_advisor_core.py` and `test_wizard_app_3.py` pass with the new name; no test touches a real config.

5. **Project rules and shared rules package**: the shared rules package and `ai-kit-project-rules-agents` generate their code-exploration rule with codebase-memory-mcp.
   - Current: `code_exploration.py` and `tool_presence.py` emit codegraph rules and presence checks; the agents skill's rules follow them.
   - Target: the generated rule tells agents to query codebase-memory-mcp first, index when no project covers the repo, check coverage of cited paths, and use the CLI form without the MCP tools; tool presence checks the new binary.
   - Acceptance: `tests/test_ai_kit_rules_common.py`, `test_ai_kit_project_rules_agents.py` and `test_rules_docs.py` pass with the new rule text.

6. **Docs, skills and planning text**: `AGENTS.md`, `README.md`, `docs/run-book/graphify.md`, every live SKILL.md and reference, the runner template comment, `.gitignore`, the live REQUIREMENTS and ROADMAP rows, the pending todos and ai-kit's agent memory name codebase-memory-mcp where they named codegraph.
   - Current: they describe codegraph (index, explore, sync) as the code-exploration tool.
   - Target: each live mention is rewritten for codebase-memory-mcp with its own commands (`search_graph`, `trace_path`, `get_code_snippet`, `query_graph`, `get_architecture`, `check_index_coverage`, `index_repository`, CLI form); `.gitignore` ignores `.codebase-memory/` in place of `.codegraph/`; a committed `.cbmignore` keeps `.planning/` out of the index so planning history does not flood search results (owner, 2026-11-14); the rendered dogfood runner copy is re-rendered.
   - Acceptance: `rg -i -l codegraph` over the live set (skills, tools, tests, docs other than `docs/superpowers`, `AGENTS.md`, `README.md`, `.gitignore`, pending todos and the live REQUIREMENTS and ROADMAP rows) returns only lines that say codegraph was replaced; `make check-dogfood` passes.

7. **History stays as written; graphify stays**: records of past work keep their codegraph wording, and the graphify step is unchanged.
   - Current: history files and graphify are untouched.
   - Target: no file under `.planning/milestones`, `.planning/phases` (other than this phase), `.planning/research`, completed todos, `.planning/goals` or the dated `docs/superpowers/` plans and specs is edited for this rename; the boundary step still runs graphify and the GSD graph copy as today; a backlog entry records an evaluation of whether codebase-memory-mcp's document graph makes graphify redundant.

## Boundaries

**In scope:**
- Code, tests and docs listed in R1-R6; the backlog entry in R7.
- Removing codegraph-only code paths (status parsing, lock retry, health probe, timeout constant) that have no
  counterpart.

**Out of scope:**
- The global instruction files outside the repo — already done (Background); the doctor and global-rules writer
  in R4 cover future writes.
- Removing or replacing graphify — evaluated later (R7 backlog).
- Installing codebase-memory-mcp's client integrations for the user (its own `install` command owns that); ai-kit
  only checks and recommends.
- Deleting existing `.codegraph/` folders in checkouts — they are reported, never removed.
- Phase 39's lane capability block — it inherits the new name through an amendment.

## Constraints

- Runtime code stays stdlib-only; codebase-memory-mcp is reached only as a subprocess (`cli`) or as the host's MCP
  server, never imported.
- No test calls the real binary: tests use host fakes, as the codegraph tests do; the tripwire stubs gain the new
  binary.
- Every config write stays atomic through `_read_json_checked()`/`_atomic_write_json()` and the marked-block writer.
- Tests stay flat under `tests/test_*.py`, join the runner's groups by its rules and read no `.planning/` path.
- English only; no machine-specific absolute path in source, tests or docs.
