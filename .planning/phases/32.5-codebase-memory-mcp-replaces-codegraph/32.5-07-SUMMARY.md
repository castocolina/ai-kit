# Phase 32.5 Plan 07: setup-dev reports codebase-memory-mcp as a manual step, and the doctor reads its binary and registration

**`make setup-dev` reports codebase-memory-mcp as a manual step and never runs its installer, and the doctor adds read-only binary and per-host registration rows in codegraph's old slot, held equal to detection by a parity test.**

- **Duration:** unmeasured (the start time was not recorded at the start of this run)

## Accomplishments

- `tools/setup_dev.py` replaces the codegraph row with a `codebase-memory-mcp` row that has no install tuple. `_tool_step` reports `codebase-memory-mcp: not installed; manual: <the tool's own install command>`, counts it as a manual step, and never runs it. The script still exits 0.
- `tools/config_doctor_checks.py` adds `cbm-binary` (the binary on PATH) and `cbm-registration` (per host: registered, not registered, disabled or unknown), directly before `cbm-global-block`. The registration row reads Claude, opencode (including `$OPENCODE_CONFIG`), Cursor, Copilot, Codex and pi's extension file as data, and prints only `host: state`.
- The doctor's path and state rules mirror `ai_kit_spec.detection`. `TestCodeIndexRows` compares paths and states host by host over eight shared fixtures, and compares the key tables.
- The catalog counts are now 28 registered rows and 27 displayed rows.
- The doctor table caps the Current cell at `CURRENT_CELL_MAX = 16` characters, the last one an ellipsis, so Recommended stays on a 120-column screen. The detail pane shows the full value on a `Current:` line (commit `787bd9e`, resolving the integration blocker below).

## Decisions Made

- A Tool with an empty install tuple is never executed. setup-dev prints the tool's own install command as the manual step, which keeps the curl-to-shell command out of every recorded argv.
- The doctor reads every JSON host through the JSONC reader, as detection does, so comments and trailing commas parse the same way in both.
- An empty PATH means the binary is absent. `shutil.which` with an empty path would search the working directory.
- pi's `registered` is labelled `inferred from its extension file`, because the extension name is installer-chosen and not documented.

## Resolved blocker: integration gate failure (`tests.test_config_doctor_pty`)

Resolved in `787bd9e` by option (a), with the cap set by measurement: `CURRENT_CELL_MAX = 16`. The Check column is 86 wide, so a cap of 40 still left Recommended past column 120. With the cap at 40 the PTY module failed 2 of 4 (checked by running it), and at 16 it passes 4/4. The plan's row strings are unchanged, and the PTY assertions are unchanged. The original diagnosis follows.

- `make test` stops at the integration tier. `tests.test_config_doctor_pty` FAILED 2 of 4: `test_config_doctor_renders_one_real_row_end_to_end` and `test_config_doctor_renders_under_piped_stdin` both assert `3650` on the rendered screen, and that value is no longer drawn.

Two new rows carry long values: `cbm-registration` (140 characters, six `host: state` pairs) and `cbm-binary` (114 characters when the binary is absent: the install command). At the base commit the widest Current value is 8 characters. On the 120-column PTY the Recommended and Confidence columns move past the edge; the dumped screen shows only Runtime, Check and Current, so the `3650` cell is never drawn.
- Why not fixed here: the two strings are the plan's specified outputs (must_haves and the expectations for `cbm-binary` and `cbm-registration`). The table layout (`tools/config_doctor_app.py`) and the PTY test (`tests/test_config_doctor_pty.py`) are outside `files_modified`.
- Options for the owner or orchestrator: (a) cap the Current column in `tools/config_doctor_app.py` and truncate long values, keeping the full text in the detail pane; this keeps the plan's strings and fixes the width where it lives. (b) Shorten the two row values and amend this plan's expectations. (c) Point the two PTY assertions at a column that stays visible. Recommendation: (a).
