## Summary

The fold skill is three small modules plus a CLI: `fold.py` (argparse, subcommands `fold|gsd|superpowers|status`, `main()` handler dict at the bottom) [VERIFIED: skills/ai-kit-commit-fold/scripts/fold.py:141-153], `fold_engine.py` (`fold(repo, cp, group, mode)` returns a `Result`; `_guard` holds the merged-ref check), `fold_adapters.py` (`gsd_checkpoint`, `superpowers_checkpoint`). New flow commands slot in as new subparsers in `build_parser()` and new keys in the `handlers` dict, each implemented in new `flow_*.py` modules beside the fold modules so `fold.py` stays a thin CLI.

Merged-ref guard gap (Phase 29 ruling): both adapters build `Checkpoint(..., merged_refs=(), ...)` [VERIFIED: fold_adapters.py:268 and :310, quoted `merged_refs=()`]. `_guard` refuses `range_on_merged_branch` only for refs in `cp.merged_refs` (fold_engine.py:379-394). So the unit flow must compute the merged unit branches from the stack record (state merged) and pass them in; add an optional `merged_refs` parameter to `gsd_checkpoint`/`superpowers_checkpoint` (or a `dataclasses.replace(cp, merged_refs=...)` in the flow before calling `fold_engine.fold`; Checkpoint is a dataclass at fold_engine.py:53).

Hook-kind finding (answers D-03 spike rule): `step` hooks with `ref.command` run `gsd_run <words> --phase N --raw` only (words match `^[a-z][a-z0-9-]*( [a-z][a-z0-9-]*)*$`) and are advisory, never blocking [VERIFIED: references/loop-hook-dispatch.md ref.command bullet + "A step is advisory by construction"]. A BLOCKING command at `execute:wave:pre` or `ship:pre` is a `gate` whose `check.predicate` is `{kind: "command-exit-zero", command, timeout}`, run via bounded `sh -c`, max 4096 chars, placeholders `${PHASE_NUMBER}`, `${PHASE_DIR}`, `${PHASE_REQ_IDS}` [VERIFIED: bin/lib/gate-predicate-evaluator.cjs:34-41, 65-78]. So no hook form is missing; no return to the owner is needed for the six hook points. Caveat: `gates[].check` is NOT disclosed in the install consent prompt [CITED: loop-hook-dispatch.md gate section], so the dogfood install must state it.

**Primary recommendation:** Grow `fold.py` into a thin router over new `flow_*.py` modules; one pre-split of all new test modules in plan 1 so later parallel plans never touch the generated Makefile/.pre-commit listings.

## Common Pitfalls
1. **Parallel plans regenerate the one-line Makefile listing** - pre-create all test modules in Plan 01 (section 3).
2. **Advisory step used as a guard** - steps never block; guards must be `gate`+`command-exit-zero` (section 2).
3. **`merged_refs=()` in both adapters** - the guard never fires unless the flow supplies merged refs (summary).
4. **`git.base_branch` set to the stack parent** - breaks ship/diff/protected checks; keep unset (D-03).
5. **Retargeting order in merge-chain** - retarget the next PR to the trunk before deleting the parent's branch (D-10); merge commits only so no restack is needed (probe_chain).
6. **gh fake stateless** - merge-chain needs state across calls (section 3).
7. **Install is not committed** - `.claude/` is gitignored; dogfood install must be an explicit step plus `check-dogfood` assertion.
8. **Hook gate not disclosed at install consent** - mention in the install step and SKILL text.
9. **Pyright runs only at push** - run `make pyright` before the plan's last commit.
10. **Tests must not touch real remotes** - local bare remote + scrubbed env (`git_env`), `AI_KIT_REFUSE_REAL_HOME=1`.
