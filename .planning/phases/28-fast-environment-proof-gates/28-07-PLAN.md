The mapper diffs `<from>...<to>` (three dots, as pre-commit's own `git.py:158-165` does); where pre-commit falls back to two dots (no merge base), the mapper's git call fails instead, which is a mapper error and runs every over-budget e2e module.
- Why the narrowing proof is enough: the runner cannot see git's ref lines (pre-commit consumed them), but it can check that no local branch or worktree HEAD is unpushed outside the pushed commit's history (`git rev-list --exclude=refs/stash --exclude=refs/tags/* --all --not --remotes <TO>`; `--all` includes every worktree's HEAD, `refs/stash` is excluded because a stash is never pushed, `refs/tags/*` because tags leave only by name, `--tags`, `--mirror` or `--follow-tags` (the last adds only annotated tags reachable from the pushed refs), and `--remotes` covers every remote, since a commit that reached any remote passed a push hook on its way). When that set is empty and the checkout is TO, any other branch in the push points into TO's history or at commits a remote already holds, and the range covers every change. Otherwise the hook cannot tell which refs the push carries, so it runs every over-budget e2e module. Git updates the remote-tracking refs after each successful push, so a single-branch push from its own checkout takes the fast path. Leaving tags out is what makes that true here (review cycle 3, HIGH): on 2026-11-03 this checkout's 27 unpushed local tags (`archive/*`, `backup/*`, `precompact-*`, `v1.2`, `v1.3`, ...) held 817 commits outside every remote-tracking ref, so the proof with tags counted could never hold; with `--exclude=refs/tags/*` it printed 0 (`--branches --not --remotes HEAD` also 0).
- No state is written at commit: the push hook recomputes the covering e2e set from the tree, so nothing can go stale between the two hooks.
