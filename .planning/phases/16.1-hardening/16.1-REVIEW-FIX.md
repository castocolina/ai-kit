### D-21 refinement (for the orchestrator to amend)

With an explicit branch on an existing clone, the sequence is:

1. `git check-ref-format --branch B`
2. Refuse when the tree is dirty (`git --no-optional-locks status --porcelain`; a failing status also refuses) or an index.lock is present.
3. Refuse when local B has commits that no origin ref has: `rev-list --count refs/heads/B --not --remotes=origin`. This runs BEFORE the fetch, because a shallow fetch makes a clean branch look ahead.
4. `--dry-run` prints the plan and stops here.
5. `git ls-remote --exit-code --heads origin B`, refusing when B is not found.
6. `remote set-branches --add origin B`, only when the refspec is not already listed.
7. `fetch --depth 1 origin B`, then `switch -C B --track origin/B`. If either fails, the refspec added in this run is removed (`config --fixed-value --unset`).

Without an explicit branch, an existing clone runs `pull --ff-only origin <current branch>` (the branch comes from `symbolic-ref --short`, and a detached HEAD refuses). Because the branch is explicit, a refspec left over from a branch deleted upstream cannot break the update.

`--dry-run` also leaves a non-git (tarball) INSTALL_DIR untouched.
