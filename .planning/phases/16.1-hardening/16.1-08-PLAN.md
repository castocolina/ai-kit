<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cloned repository `.aikit/review-spec.toml` → reviewer spawn | a third party controls the file a user's review run reads |
| trust store → cfg_resolve | the recorded consent decides whether project content is used |
| review-spec.toml parse → review flow | a parse failure used to switch cross-AI review off silently |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16.1-18 | Elevation of Privilege | cfg_resolve (project-local commands) | critical | mitigate | untrusted local file ignored entirely; trust keyed by realpath and content sha256; any edit re-blocks; tests cover probe-quota and resolve-reviewers |
| T-16.1-19 | Tampering | trust check vs. parsed content | high | mitigate | bytes read once; the same bytes are hashed and parsed, so no check-then-read gap |
| T-16.1-20 | Denial of Service | cfg_load_toml | medium | mitigate | ConfigError with path and message; the three CLIs exit 2 instead of silently disabling review |
| T-16.1-21 | Tampering | cache_write_json concurrent writers | medium | mitigate | mkstemp per writer + os.replace; temp unlinked on error |
| T-16.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | no package installs; uv/make calls run with `UV_NO_SYNC=1 UV_OFFLINE=1` |
</threat_model>
