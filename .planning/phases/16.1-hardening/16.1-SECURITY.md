## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| project-local `.aikit/review-spec.toml` -> reviewer argv | A cloned repo's config names commands ai-kit spawns | command templates (critical) |
| reviewer/probe child process <- host environment | Host-identity variables could leak into a cross-AI child | env vars (high) |
| CLI stdout/stderr -> classifiers and merge-reports | External output decides quota/failure status and the merged verdict | status text (high) |
| `install.sh --branch` -> git argv | User-supplied branch name drives fetch/switch on the install checkout | ref name (high) |
| usage data -> dashboard HTML | Recorded text is embedded in a `<script>` data block | JSON payload (high) |
| ai-kit -> GSD `config.json` | Config changes go through `gsd-tools config-set` only | config keys (high) |
| ai-kit -> user CLI configs (`~/.claude`, `~/.cursor`, opencode, codex, pi, gsd) | ai-kit must never write them during detection/live checks | user config (high) |
| project-local gsd-core -> `node` | A project's own `gsd-tools.cjs` is run without a trust step (D-18) | code execution (medium, documented) |

### T-16.1-47 resolution

The plan-24 fingerprint guard failed: `~/.cursor/cli-config.json` changed during the live checks.
The mitigation's intent is "ai-kit never writes user CLI configs", and that intent is verified two ways
(RUN-38; jev Laya B 0.46 / TypeSafe C 0.48, both low confidence, so the orchestrator decided):

1. **Attribution reproduced.** Under a scratch HOME holding copies of `cli-config.json` and the auth
   file (the real `~/.cursor` untouched; the copies deleted afterwards), running `cursor-agent models`
   alone rewrote the `privacyCache` key.
2. **ai-kit writes nothing.** `ai-kit-spec.py detect-runtimes` ran with `env -i`, under a scratch HOME
   holding synthetic copies of all 7 fingerprinted configs, with inert fake binaries for every CLI on
   PATH. All 5 CLIs were detected and none of the 7 files changed. A static grep by the security
   auditor also found no write path to `~/.cursor` in `ai_kit_spec`.

Residual: a fingerprint guard over real configs cannot tell a CLI's self-writes from ai-kit's. Future
live checks should fingerprint only after excluding keys the CLIs rewrite themselves, or run ai-kit
against isolated copies. This goes to uz in the final run report.
