# 16.1-03: Test gating is single-source and parallel

Every `tests/test_*.py` runs in exactly one runner group, every Makefile tier and both unittest hooks call the runner, and workers stay within 40% of the available CPUs.

## Accomplishments

- `tools/run_unittest_parallel.py` discovers `tests/test_*.py` and assigns each module to exactly one of `unit`, `arch`, `unit-uv`, `integration`, or `e2e`, with a one-line comment on every explicit set. `worker_count` caps the pool at 40% of `os.process_cpu_count()`, then the affinity mask, then `os.cpu_count()`, and `AI_KIT_TEST_CPU_SHARE` can only lower that share.
- A stale exception name, an unknown group, mixed group and module arguments, and a module that runs zero tests all fail the run. Tests pin the CPU bounds (24 → 9, 4 → 1, 1 → 1, None → 1, an above-cap override clamped, workers never above the module count).
- The four tiers and both hooks call the runner with `--group`. The `unittest` hook runs `unit` + `arch` and `unittest-wizard` runs `unit-uv` + `integration`, so `e2e` is the only group kept out of `make validate`. The four modules that were in no hook now pass in the gate.
- `tests/test_gate_scope.py` pins group coverage, hook order, runner use, and the no-hardcoded-workers rule, and `TestGateScopeNonVacuity` feeds each checker a synthetic violation.
- Two `unit` modules (`test_config_doctor`, `test_config_doctor_pty`) need uv but must stay named on the `unittest` hook entry, because their own gate-registration tests search that entry for their names. `UV_MODULES` sends them through the uv invocation, and `tools/gen_test_groups.py` regenerates the module names in the Makefile comment block and both hook entries from discovery so those tests stay true. No module failed only when run alongside others, so no serial set was added.
