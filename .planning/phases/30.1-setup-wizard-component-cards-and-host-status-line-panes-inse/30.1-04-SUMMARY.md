# Phase 30.1 Plan 04: Setup's side of the status-line toggle Summary

Setup's commit now acts per host on one action table: off removes only ai-kit's own `statusLine`, a kept foreign entry is never written, and a foreign entry is removed or replaced only after a backup and `foreign_ok`. The doctor factory and the backup-first foreign callable are injected into the wizard context.

## Accomplishments

- `_statusline_action(host_state, examples_forced=False)` is the one table; `_commit_host_statusline` dispatches on it and returns `action` in every per-host outcome.
- Off on an ai-kit-owned host (`remove_ours`) removes only `statusLine` through `unwire_statusline` / `unwire_statusline_cursor`, which write through `_atomic_write_json` / `_commit_unwire`.
- `keep_foreign` and off+unset `unchanged` return before any re-read, backup or write.
- `_prepare_foreign(paths, host, dry=False)` takes the backup through `config_doctor_appliers.backup_before_write` under `backups_dir/<host>/`, refuses JSONC and unparseable Cursor configs, and takes no backup on a dry run.
- `_remove_statusline_entry(paths, host, dry, approved)` compares the entry it pops with the approved command in the same read; a changed or already-gone entry prints `changed after approval` and writes nothing.
- `resolve_paths().backups_dir` comes from `config_doctor_appliers.backups_root(env)`.
- `_config_doctor_ctx(env)` is shared by `cmd_config_doctor` and the wizard; `_make_doctor_factory(env, dry)` returns a fresh screen per call, and a dry install makes every confirmed apply a preview.
- `launch_wizard(..., env=None)` injects `doctor` and `prepare_foreign`, and sets `ctx.state["_examples_forced"]`; `cmd_install` passes `env`.
