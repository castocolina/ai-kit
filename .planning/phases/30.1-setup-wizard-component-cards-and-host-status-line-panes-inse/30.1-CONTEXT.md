<domain>
## Phase Boundary

The setup wizard gets one tab per component kind, a host band with an on/off toggle on both status-line panes (off
can restore the host's default, a foreign entry only after a backup and a confirmation), a real-render board
preview, and the config doctor behind `d` on Done as a screen shared with `--config-doctor`. The doctor's appliers
stop overwriting unparseable files and back up first, and a new doctor row fixes the Playwright MCP browser path on
Bazzite. Cursor status-line parity is Phase 30.2.
*Amended 2026-11-06 (owner, D-06; clarified the same day):* a host whose status line is foreign gets three states
instead of the toggle: keep current (the default; nothing written), remove so the host shows its own built-in
default, or customize with ai-kit (the last two after the backup and the confirmation).
</domain>

## Implementation Decisions

### Component tabs (SPEC R1, amended)

- **D-01: The cards are tabs, one card on screen.** A tab row such as `[skills 25/25] agents 1/1 hooks 3/6` sits
  above the card; only kinds with items get a tab, in the order skills, agents, commands, hooks. ←→ switches kind
  (wrapping), ↑↓ move inside the card on screen (wrapping), and each tab keeps its own cursor position. `a`/`n` act on
  the card on screen, `A`/`N` on every card. The tab on screen is shown bold with the accent colour and brackets, the
  others dim, so the active one does not rely on colour alone. Footer and help name ←→ "Kind". SPEC R1 amended in
  place (dated).
  - Owner choice (option C; not the recommended stacked cards).
- **D-02: Item rows keep today's text.** Name, padded to 30, then the full description cut at the card width, as
  `_choose_component_row` does now. No first-sentence trimming and no detail line.
  - Owner choice (option B; not the recommended trimmed rows).

### Host band and toggle (SPEC R2, R3)

- **D-03: One filled band above each host board.** Bold host name in dark text (`#0d1117`) on the host accent: Claude
  `#D97757`, Cursor `#8B949E` (contrast 6.06 and 6.15, measured with `tmp/p30.1/contrast.py`; white text fails on
  both). The toggle sits at the band's right end, for example `[ off │●on ]`. Lane borders stay cyan; the focus,
  tray and preview colours do not change. The accents are named constants beside the palette in `wizard_app.py`.
  - Owner choice (recommended).
- **D-04: The toggle key is `o`** (Space already toggles a chip). It shows in the footer and in help on both host
  panes. The toggle replaces the yes/no gate, so `_adoption_gate_markup`, `_render_adoption_gate` and
  `_key_arrange_gate` go, and every detected host's pane is visited (an already-ours host no longer skips its pane).
  - Own reasoning, not objected by the owner.
- **D-05: Off keeps the board on screen, dimmed and locked, and says so.** One visible line on the pane states what
  Review will do (for example "Off: Review removes ai-kit's entry; Claude Code shows its default status line. Press o
  to turn it on."). Keys that would edit the board (Space, ↑↓←→, Tab, `r`) are ignored and each shows a short notice
  ("Status line is off; press o to turn it on"), never silently. Enter and Esc still move between panes. The
  arrangement is kept, so turning it back on restores it; the preview shows "host default (ai-kit's status line off)"
  instead of a render.
  - Owner choice (option B, with the honesty rules the owner added; not the recommended message panel).
  - *Amended 2026-11-06 (D-06 amendment):* on a foreign host the board is locked, with the same notice rule, in
    `keep` and in `remove`, and editable in `customize`; each of the three states shows one line saying what Review
    will do. In `keep` the preview shows `current status line kept (another tool's; no ai-kit preview)`; in `remove`
    it shows `host default (foreign status line removed)`. The arrangement is kept across the cycle, as above.
- **D-06: The foreign-entry confirmation runs on Review, before anything else is written.** Enter on Review, with
  a foreign removal pending, first takes the backup (D-08), then opens a modal that shows the exact entry, the file
  and the backup path, defaulting to No. Yes continues the commit; No cancels the whole confirm and returns to Review
  with nothing written apart from the backup. The commit re-reads the host file and refuses on a mismatch, reusing the
  pinned `adopt_command` check.
  - Own reasoning, not objected by the owner.
  - *Amended 2026-11-06 (owner decision on the cycle-2 HIGH in 30.1-REVIEWS.md; the owner's words: "Keep current,
    Remove and show default, customize using aikit"; clarified the same day: "Remove and show default" means the
    default that Claude shows when it has no status line, the host's own built-in default, not ai-kit's):* a host
    whose status line is foreign has three states instead of on/off, cycled with `o` in the order keep → remove →
    customize → keep, shown in the band:
    1. **Keep current**, the start state for a foreign entry: the entry stays untouched, setup writes nothing to that
       host's file (action `keep_foreign`), no backup and no modal; the install continues for that host.
    2. **Remove, host default**: on Review, the backup-first, default-No modal above, then setup removes the foreign
       `statusLine` entry and writes no ai-kit line in its place, so the host shows its own built-in default (action
       `remove_foreign`). Its refusals match `replace_foreign`: an unparseable file is refused, an entry that changed
       after approval is refused, and every other key keeps its value.
    3. **Customize with ai-kit**: the board unlocks, starting from ai-kit's default arrangement (the pane's initial
       arrangement, what `r` resets to); on Review the same modal, then ai-kit's line is written with the owner's
       arrangement (action `replace_foreign`). There is no separate "ai-kit default without customizing" state: the
       owner can accept the starting arrangement unchanged.

    The confirmation stays on Review, as written above, for choices 2 and 3 (jev, confidence 0.92). Its No still
    cancels the whole confirm and returns to Review, where Esc leads back to the pane. A host with ai-kit's own entry,
    or with no entry, keeps the two-state on/off toggle (D-04, D-05).
- **D-07: Removal reuses and extends today's writers.** ai-kit's entry: `unwire_statusline` / `unwire_statusline_cursor`.
  A foreign entry: the same commit path drops only `statusLine` through `_atomic_write_json` after the backup. A JSONC
  `cli-config.json` stays refused, as today (`_cursor_config_for_write`), with its warning on Done.
  - *Amended 2026-11-06 (D-06 amendment):* a foreign entry is kept (nothing written), removed by the path above
    (only after the backup and `foreign_ok`, comparing the entry it pops with the pinned `adopt_command` in the same
    read) or replaced (today's persist path with `assume_overwrite=True`, after the backup and `foreign_ok`). The
    JSONC refusal stays for both writes.

### Backups (SPEC R3, R6)

- **D-08: Backups go to `paths.backups_dir/<host>/`** (`~/.local/state/ai-kit/backups/<host>/`, XDG state), named
  `<file name>.<UTC timestamp>.bak`; for doctor applies `<host>` is the row's runtime (`claude`, `codex`,
  `opencode`, `cursor`). The copy is written atomically before the target write; a failed backup aborts the write.
- **D-09: Keep the last 10 backups per file.** After a new backup is written, older backups of the same file in that
  folder beyond the newest 10 are deleted. The pruning never deletes the backup just taken (it is excluded by path,
  not by sort order) and touches only files matching that file's backup name pattern. A test covers both rules.
  - Owner choice (option B; not the recommended keep-all).

### Real-render preview (SPEC R4)

- **D-10: The board preview runs through the host's `engine.render_preview`** (today's `_engine_ns`) in a Textual
  thread worker, about 150 ms after the last board change; only the newest result is applied, older ones are
  dropped. A render that fails or takes over 2 s shows the inventory samples with the "sample text, render
  unavailable" note. SGR output is converted to Rich text (`Text.from_ansi`), with other control codes stripped.
  - Own reasoning, not objected by the owner.
- **D-11: The preview renders at the preview panel's inner width**, with rows set high enough that every line shows
  (`STATUSLINE_LINES` large), so the owner sees what fits this window.
  - Owner choice (recommended).
- **D-12: The preview title is set at render time from the host on screen** ("live preview — <host label>"); the
  tray title becomes "OFF (Space turns a chip on → its home line)".
  - *Amended 2026-11-03 (30.2 D-08):* the title adds "(sample data)" — "live preview — <host label> (sample
    data)" — because both hosts' previews render the sample payload, and the owner ruled that a sample render is
    never presented as live. Needs confirmation.

### Config doctor screen (SPEC R5, R6, R7)

- **D-13: The doctor body becomes one `Screen` class in `tools/config_doctor_app.py`** (table, detail, per-row
  confirm). `ConfigDoctorApp` pushes it at mount; the wizard pushes it on `d` from Done and pops it on Esc. The wizard
  receives a doctor factory through `WizardContext` (a callable setup builds from `config_doctor_checks.build_catalog`
  and `apply_row`), so `wizard_app.py` still imports nothing from setup and the catalog is built when `d` is pressed.
  `d` works only after the commit finished. Done shows a hint line: "d · check your AI-CLI configs (config doctor)".
  - Own reasoning, not objected by the owner.
- **D-14: Applier safety lives in one shared apply helper** used by every applier: parse check (refuse unparseable
  or non-object with a reason), backup (D-08, D-09), re-read and compare before the atomic replace, then write. The
  two Claude appliers that today fall back to `{}` move onto it, and so do the opencode and codex appliers.
- **D-15: The Playwright row is a Claude-runtime row**, id `claude-playwright-mcp-browser`. It shows only when
  `enabledPlugins` in `~/.claude/settings.json` marks `playwright@claude-plugins-official` enabled; that detection is
  labelled inferred (the key's exact shape was not verified against a real file). The checks are file-existence only:
  `/opt/google/chrome/chrome`, the value of `env.PLAYWRIGHT_MCP_EXECUTABLE_PATH`, and
  `/var/lib/flatpak/exports/bin/com.google.Chrome` for the apply. The apply goes through D-14 and adds or replaces only
  that one `env` key. Its label: the variable reaching the MCP process and a headed launch are inferred until the
  Phase 54 live check.
  - Owner choice for the browser and target (Round A); the detection is own reasoning.

- `wizard_app.py` and `config_doctor_app.py` import nothing from setup; everything arrives through their contexts.
