## Summary

The wizard is ONE Textual `App` (`WizardApp`) with four string-rendered panels toggled by `.display`, not separate Screens. All state is in dataclasses (`FlowState`, `HostPane`, `CommitState`, `HousekeepingState`). Today's per-host "adoption gate" is a first-class concept wired through `HostPane.answered`, `FlowState.gate_done`, `_render_footer`, `_enter_host_arrange`, `_board_back`, `_all_hosts_gate_done`, `_review_*`, `_adopted_views` and about 55 test lines (wizard_app_1/2/3 and the PTY file). Removing it is the widest change of the phase; the new Choose tabs, band and real preview are additive.

Everything the preview needs already exists: `setup._engine_ns(...).render_preview(segments, layout)` renders the host's real entry on its sample payload. I timed it live under a scratch HOME: about 0.03 s per host (claude 3 lines, cursor 2 lines, both carry SGR codes), so the 2 s bound is slack and debounce is the only latency. The engine hard-codes width through `STATUSLINE_COLS` default 200 (`_preview_child_env`), so D-11 needs a small `setup.py` change to pass the panel width.

Three Textual 8.2.7 facts, probed under `uv run` this session, change the design: (1) `WizardApp.on_key` also receives keys while a pushed Screen is on top (a Screen `q` binding fired AND `app.on_key` saw `q`), so `q` on the doctor screen would exit the whole wizard unless `on_key` returns early when `len(self.screen_stack) > 1`; (2) an exclusive thread worker that was cancelled still runs to the end and its `call_from_thread` still lands, so "only the newest result" needs a sequence token, not just `exclusive=True`; (3) `App.query_one` finds base-screen widgets while a modal is on top, so `_render()` from a worker is safe while a modal is open.

**Primary recommendation:** 7 plans in 4 waves (table below). Keep `tools/wizard_app.py` single-owner per wave, put the shared backup/refuse helper in `config_doctor_appliers.py` (stdlib, already imported by `setup.py` through `_sibling`) and have setup's foreign-removal backup call it, so there is one backup implementation for the phase (Phase 30's `global_rules._claim_backup` stays separate).

### Anti-Patterns to Avoid
- **Keeping `gate_done`/`answered` "just in case":** remove them; leaving dead state is how stale gate branches survive in `_render_footer`, `_board_back`, `_review_from_board`, `_all_hosts_gate_done`.
- **Trusting `exclusive=True` for newest-wins:** verified false for thread workers.
- **Using `ConfirmApplyScreen` for the foreign confirmation:** its bindings make `enter` confirm [VERIFIED: tools/config_doctor_app.py:50-55 `("enter", "confirm", "Confirm")`]; the foreign modal must default to No, so it needs its own `ModalScreen` in `wizard_app.py`.

## Toggle commit contract (what setup must implement)

States per host: `start_state in {unset, ours, foreign}` x `on in {True, False}`.

| start | toggle | Review outcome text (SPEC) | Commit action |
|-------|--------|----------------------------|---------------|
| unset | on | wire ai-kit | existing `persist_statusline(adopt=True)` |
| ours | on | unchanged (or "update ai-kit's layout" when the board changed) | persist when changed, else skip |
| foreign | on | replace the foreign entry (after confirmation) | `persist_statusline(..., assume_overwrite=True)` only when the replace was confirmed |
| unset | off | unchanged | nothing written |
| ours | off | remove ai-kit's | `unwire_statusline` / `unwire_statusline_cursor` |
| foreign | off | remove the foreign entry, backed up | backup, modal Yes, then drop only `statusLine` via `_atomic_write_json` |

Details the planner must pin:
1. **Modal ordering (D-06):** `_key_review` Enter -> `_has_net_change` -> if any host is foreign-pending: call `ctx.prepare_foreign(host_id)` (setup closure: backup + returns `{"entry", "file", "backup"}` or `{"error"}`), then `push_screen(ForeignConfirm(...), callback)`; No returns to Review with only the backup written; Yes sets `foreign_ok` in that host's state and starts `_run_commit`. The commit itself must refuse a removal without `foreign_ok` (defence in depth).
2. **Replace confirmation gap (SPEC R3 vs D-04/D-06):** SPEC says on+foreign replaces "only after today's replace confirmation", but D-04 deletes today's gate and D-06 specifies a modal only for removal. Recommend reusing the same modal class with replace wording, default No, and also taking the backup (cheap, replace destroys the value too). Flagged as Open Question 2.
3. **Off + ours writes through `unwire_*` (checks ownership itself), so the "second run writes nothing" idempotency edge holds: off+unset writes nothing, on+ours with an unchanged board is skipped.**
4. **JSONC `cli-config.json`:** `_cursor_config_for_write` returns None and prints to stderr (not allowed inside the worker; commit already redirects stdout/stderr into the per-host log). ## Backup helper contract (one implementation, in `config_doctor_appliers.py`)

```python
def backup_before_write(path, backups_dir, label, keep=10, now=None) -> str:
    """Copy path atomically into <backups_dir>/<label>/<basename>.<UTC stamp>.bak; prune; return the new backup path.
    Missing path -> return "" (no backup needed). Raises OSError on failure (caller aborts the write)."""
```
- Name pattern: `<name>.<%Y%m%dT%H%M%S%fZ>.bak` with microseconds, created exclusively (`O_EXCL`/`os.link` of a temp copy) with a `-1`, `-2` suffix on collision, so two applies in one session make two backups (SPEC adjacency edge) and a fixed clock in tests does not overwrite.
- Prune: list files matching `^<re.escape(name)>\.\d{8}T\d{12}Z(-\d+)?\.bak$`, sort by `(st_mtime_ns, name)`, delete beyond newest `keep`, always skipping the path just returned (D-09 "excluded by path, not by sort order").
- `backups_dir` for the doctor is derived from `env` (no setup import): same formula as `resolve_paths`; add a test asserting equality with `setup.resolve_paths(env).backups_dir` to prevent drift. `setup.py` reaches the helper via `_sibling("config_doctor_appliers")` (the same lazy pattern `_config_doctor_checks()` uses at setup.py:97-99).
- Safe JSON apply front door for the 4 appliers: `read_json_checked` -> refuse (`{"ok": False, "reason": "refused: <file> cannot be parsed as a JSON object; nothing was written"}`) -> compute -> if not dry: backup -> re-read and compare to the first read (mismatch refuses) -> `atomic_write_json` -> result names `"backup": <path>`. Dry run: no backup, no write.
- Phase 30 overlap: 30-03 adds `apply_codegraph_global_sentence` (markdown, delegates to `global_rules.apply` with its own `_claim_backup` under `backups/global-rules/`). It is not a JSON/TOML applier; treat it as satisfying R6 through its own backup and say so in the structural test's allowlist instead of re-wrapping it.

## Common Pitfalls

### Pitfall 1: `q` or `?` pressed on the doctor screen quits/toggles the wizard
**What goes wrong:** keys bubble to `WizardApp.on_key`. **Why:** verified probe. **Avoid:** early return when `len(self.screen_stack) > 1`. **Warning sign:** pilot test pressing `q` on the doctor screen ends the app.

### Pitfall 2: stale preview overwrites a newer one
**What/why:** cancelled thread workers still run `call_from_thread`. **Avoid:** sequence token compared on the UI thread; test with a fake engine that sleeps on the first call and returns immediately on the second (no `time.sleep` in the test: use `threading.Event`).

### Pitfall 3: removing the gate breaks ~55 test lines and the two-host PTY
gate keys (`y`/`n`) appear in `test_wizard_app_1` (11 hits for gate-related patterns), `_2` (6), `_3` (27), `test_wizard_pty` (11). The commit-time `staged-tests` hook runs every module covering a staged file, so the commit that deletes the gate must also carry the rewritten tests or it cannot commit. Keep "gate removal" and its test rewrites in ONE plan.

### Pitfall 4: `HostPane`/`WizardContext` shape changes
`WizardContext` is a `NamedTuple`: new fields need defaults [CITED: 30.1-PATTERNS.md Risks]; `tests/wizard_fixtures.make_ctx` builds it positionally by keyword so defaults keep it working. Pylint `too-many-instance-attributes` on `WizardApp` (see Pattern 2).

### Pitfall 5: broad `except` in the preview worker
`tests/test_arch.py` rule 9 allows `pylint: disable=broad-exception-caught` only at listed `(file, function)` pairs (`_BROAD_EXCEPT_BACKSTOPS`, ~line 1838-1851). Either catch a concrete tuple or add the new worker to that set (and keep its non-vacuity companion).

### Pitfall 6: Phase 30 not merged into this branch
`tools/global_rules.py`, `_global_rules_items`, `rules_review`, `WizardContext.state["_global_rules"]` do not exist at HEAD (grep: `tools/global_rules.py` absent). 30.1 plans execute after Phase 30; every plan's first read step should re-`rg` for these symbols and treat absent ones as "Phase 30 not landed" blockers, not as code to invent. `_make_wizard_commit` will then have the signature `(paths, entries, dry, counts, examples_flag=None, *, rules_env=None, rules_review=None)`.

### Pitfall 7: mtime-based prune with same-second backups
Sorting by name with `-N` suffixes mis-orders `-10` before `-2`; sort by `(st_mtime_ns, name)` and exclude the new path.
