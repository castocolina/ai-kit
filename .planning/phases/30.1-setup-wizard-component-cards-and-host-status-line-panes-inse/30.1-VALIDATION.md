> Per-phase validation contract for feedback sampling during execution. Source: `30.1-RESEARCH.md` § Validation Architecture.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | `unittest` (`IsolatedAsyncioTestCase` + Textual `App.run_test()` pilot; PTY via the existing `tests/test_wizard_pty.py` helpers) |
| **Config file** | runner groups in `tools/run_unittest_parallel.py`; listings regenerated by `python3 tools/gen_test_groups.py` |
| **Quick run command** | `AI_KIT_REFUSE_REAL_HOME=1 uv run python tools/run_unittest_parallel.py tests.<module>` (stdlib modules: `python3` instead of `uv run python`) |
| **Full suite command** | `make test`, once per plan through the plan's `scope.py test` |
| **Estimated runtime** | a few seconds per module; no `time.sleep` in tests (injected clocks, `threading.Event` in fakes, `await pilot.pause()`) |

---

## Sampling Rate

- **After every task commit:** the module(s) the task owns (quick run command).
- **After every plan wave:** the affected runner group; `make arch-test` after any plan that touched `tests/test_arch.py`.
- **Before `/gsd-verify-work`:** `make test` green, plus the orchestrator's `uv run` scratch-HOME wizard capture (tabs, both panes on and off, Review, Done, doctor screen).
- **Max feedback latency:** about 30 seconds per task.
