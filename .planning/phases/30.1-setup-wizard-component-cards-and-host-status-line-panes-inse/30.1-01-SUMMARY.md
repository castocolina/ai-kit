# Phase 30.1 Plan 01: Guarded doctor apply, backups, and the Playwright browser row Summary

Every config-doctor apply now refuses a file it cannot parse, backs the file up first (newest 10 kept), and a new Claude row detects and fixes the Playwright MCP browser path.

## Accomplishments

- `apply_guarded` in `tools/config_doctor_appliers.py`: parse check, backup, re-read and compare, atomic write. A failed backup aborts the write; a failed write keeps the backup.
- `backup_before_write` claims `<basename>.<UTC stamp>[-n].bak` exclusively (hard link, numbered suffix on collision) under mode 0o700/0o600; `prune_backups` keeps the newest 10 and excludes the new backup by path.
- Four appliers moved onto the helper: claude-retention, claude-sandbox-enabled, opencode-share-mode, codex-history-persistence. Unparseable targets return `refused:` with the file byte-identical and no backup folder.
- The Playwright row `claude-playwright-mcp-browser` (confidence MEDIUM): visible only with `enabledPlugins["playwright@claude-plugins-official"]` true; reads ok when the default Chrome or `env.PLAYWRIGHT_MCP_EXECUTABLE_PATH` names an executable; its apply writes only that env key, refuses `nothing to fix` on a second apply, and offers no apply when the flatpak wrapper is missing.
- `tests/test_doctor_apply_safety.py` (28 tests): backup helper, guarded apply, a row loop over every applier, edge cases (UTF-8, before-replace hook, backup failure, write failure), and the Playwright row.
