## Warnings

### WR-01: A commented `# [cursor]` block before a live `[cursor]` table produces a duplicate table, so the save fails

**File:** `tools/setup.py:565`
**Issue:** `start = next(i for i, line in enumerate(lines) if _header_name(line) == table)`
takes the FIRST header named `cursor`. `_header_name` matches commented headers too. The
shipped recipe (`tools/cursor-statusline.toml.sample`) ends with a commented `# [cursor]`
block. Suppose a user adds a live `[cursor]` table after it, for example
`[cursor]\nextra_alert_usd = 5.0`, and then presses `x` in the wizard. The patcher edits the
commented block, inserts `extra_alert_usd = 5.00` there and uncomments its header. The
result declares `[cursor]` twice. Reproduced: `tomllib` reports
`Cannot declare ('cursor',) twice`. `write_toml_preserving` then rejects the candidate, so
the Cursor save fails and the user's alert change is lost. The user is told only that the
save was rejected.
**Fix:** Use a live header when one exists. Fall back to a commented header only when there
is no live one:
```python
headers = [i for i, line in enumerate(lines) if _header_name(line) == table]
live = [i for i in headers if not lines[i].lstrip().startswith("#")]
start = (live or headers or [None])[0]
```
Add a `test_setup` case with a commented block followed by a live table.

### WR-02: The host-key save rewrites keys the user did not change, which breaks the key-granular surgical-edit rule

**File:** `tools/setup.py:3387-3389` (with `patch_host_keys` at `tools/setup.py:546-590`)
**Issue:** `_persist_layout` checks for a change table by table (`v != current[t]`), then
passes the WHOLE table to `patch_host_keys`. Every non-None key in that table is rewritten
or appended. Reproduced: with `[cursor]\nextra_alert = true\nextra_alert_usd = 20  # my cap`,
toggling only `extra_alert` also rewrites the untouched line to `extra_alert_usd = 20.00  # my cap`.
With no `[cursor]` table and only an override set, the patcher also appends the default
`extra_alert = true`. `patch_segments` rewrites only changed keys, and AGENTS.md requires
managed config edits to keep every other byte. This patcher does not meet either.
**Fix:** Send only the changed keys:
```python
key_changes = {}
for t, v in (state.get("host_keys") or {}).items():
    if t in current:
        diff = {k: x for k, x in v.items() if current[t].get(k) != x}
        if diff:
            key_changes[t] = diff
```
A None value in `diff` still comments out a live override line, so clearing the override
keeps working. Add a test that pins the byte-identity of the unchanged line.

## Info

### IN-01: The `math.isfinite` check in the threshold box can never fail (necessity)

**File:** `tools/wizard_app.py:1114`
**Category:** necessity
**Issue:** `ALERT_AMOUNT_RE` (`[0-9]+(\.[0-9]{1,2})?`, full match) and `max_length=10` limit
the text to at most 10 ASCII digits plus a point. `float()` of such text is always finite, so
`math.isfinite(float(text))` is dead code, and so is the `import math` at line 21.
**Fix:** Remove the `math.isfinite(...)` clause and the `math` import from `wizard_app.py`.

### IN-02: The doctor loads the Cursor config twice per `--doctor` run

**File:** `tools/statusline-doctor.py:475-480, 568, 575`
**Issue:** `_cursor_knobs` calls `cfg_load_config`, and `cmd_doctor` calls it again at
line 575. Each call runs external-provider discovery again. The two loads can also disagree:
a type-broken config gives `knobs=None`, which means the alert defaults, while the second
load reports the error.
**Fix:** Load the config once before `quota_report` and pass `cfg.host_knobs` to it. The order
the docstring requires (the quota refresh before the dry render) still holds.

### IN-03: `cursor_limit_text` rebuilds the quota cache path by hand

**File:** `tools/setup.py:620-625`
**Issue:** `os.path.join(base, "cursor", "usage.json")` copies the path layout from
`cursor_quota.probe_cache_paths`, and skips that function's symlink and owner checks. The
copy exists for a good reason: `probe_cache_paths` creates the directory. Still, if the cache
layout changes, the wizard's limit text silently becomes "not read yet".
**Fix:** Split the path computation out of `probe_cache_paths` into a pure helper, for example
`core_cache_paths(base)`. Both callers then use it, and only the probe creates and checks the
directory.

### IN-04: The `patch_host_keys` docstring says where a missing key goes, but the code puts it elsewhere

**File:** `tools/setup.py:550-552, 579-585`
**Issue:** The docstring says a missing key is inserted "after the table's last key line". The
code inserts it after the last WRITTEN key, or straight after the header when nothing was
written, so the new key can land above existing commented keys. This is harmless for TOML.
Only the docstring is wrong.
**Fix:** Change the docstring to "after the last rewritten key, else after the header", or
track the last key line seen.
