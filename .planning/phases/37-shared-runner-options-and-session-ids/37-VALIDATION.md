# Phase 37 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Source: 37-RESEARCH.md "Validation Architecture".

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | `unittest` (stdlib), one subprocess per module through `tools/run_unittest_parallel.py`; the runner's own `--self-test` for spawn-level behaviour (shards `tests/test_cross_ai_selftest_{logic,runtime}_<i>_e2e.py`) |
| **Config file** | none; groups in `tools/run_unittest_parallel.py`; module listings in `Makefile` and `.pre-commit-config.yaml` are generated by `python3 tools/gen_test_groups.py` (plan 37-02 registers every new module once as a stub) |
| **Quick run command** | `python3 tools/run_unittest_parallel.py tests.test_<module>` |
| **Full suite command** | `make test` |
| **Estimated runtime** | quick about 5-60 seconds per module; unit plus arch about 10-13 minutes |

---

## Sampling Rate

- **After every task commit:** the plan's own `<automated>` command; the commit hook also runs the staged modules.
- **After every plan wave:** `python3 tools/run_unittest_parallel.py --group unit --group arch`.
- **Before `/gsd-verify-work`:** `make test` green and `make check-dogfood` green (the live runner copy is re-rendered by plan 37-23).
- **Max feedback latency:** 780 seconds (a commit that stages shared machinery runs the full unit and arch groups).
