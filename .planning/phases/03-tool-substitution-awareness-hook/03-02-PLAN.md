## Planner decisions recorded here (not silent)

1. **Cursor gets a bare Python script, not a Node shim.** RESEARCH Assumption A1
   left this unconfirmed. Every live `sessionStart`/`preToolUse` entry on this
   machine proves `command` is a free-form shell string — one resolves a Node
   binary through a `for` loop, one is the compiled binary `rtk hook cursor`,
   one is an inline `sh` conditional. A `python3 -S <abs path>` string is the
   same class of value, and it keeps ai-kit's Cursor side dependency-free per
   D-07. Task 1's end-to-end subprocess test executes the stored string exactly
   as written, which is what promotes A1 from assumption to verified.

2. **The empty array is left in place on unwire, and no key is deleted.**
   Deleting `hooks.sessionStart` or the `hooks` object when ai-kit's entry was
   the last one would mutate a structure ai-kit did not create. An empty array
   is valid, honest, and cannot disable anything.

3. **The no-ai-kit-entry uninstall case writes nothing at all**, and the test
   asserts that by comparing raw bytes rather than parsed JSON. A write that
   preserved every value but re-serialized the file would still be a write that
   should not have happened, and byte comparison is the only assertion that
   catches it.

4. **Cursor's top-level `version` is set only on file creation.** The live file
   carries `version: 1` alongside `hooks`. Overwriting an existing `version`
   would be ai-kit asserting a schema version it has no authority over; omitting
   it entirely on a file ai-kit creates would produce a shape unlike any real
   one. Create-only is the narrow, honest middle.

5. **`unwire_statusline` is still not retrofitted onto `_atomic_write_json`.**
   Plan 03-01 note 3 recorded the same boundary. `cmd_uninstall` now calls a
   non-atomic writer (`unwire_statusline`) and two atomic ones side by side;
   that asymmetry is deliberate scope discipline (ONESHOT-RULES Rule 4 —
