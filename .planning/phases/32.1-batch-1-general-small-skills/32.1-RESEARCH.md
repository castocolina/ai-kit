```

### Anti-patterns
- **Hard-coding a backend name in client code outside an adapter or `TABLE`.** `TestSeam.backend_literals` (test file lines 1361-1384) walks the AST and
  flags any string literal that names `laya`, `typesafe` or `opencode` outside `_<name>_*` functions and the `TABLE` literal. Leftover reporting must
  therefore compute "names not in `TABLE`" generically (`row_named`/`[row["name"] for row in TABLE]`), never write `"opencode"`.
  Change `NAMES` (line 1359) to `("laya", "typesafe")` together with the row removal.
- **Committing `.py` fixtures that do not parse** (cst-refactor unparseable sample). Ruff, py-compile, pyright and vulture cover `tests/`
  (AGENTS.md Testing) and `tests/test_gate_scope.py` pins ruff/py-compile selection of every shipped `.py`. Store samples and expected outputs as
  `.py.txt`/`.txt` under `tests/fixtures/` and copy them to `.py` inside the test's temp folder.

## Common Pitfalls

### P1: A new test module without regenerated listings
Adding `tests/test_cst_refactor.py`, `tests/test_cst_refactor_codemods.py`, `tests/test_ai_kit_spec_review_fixer.py` (all flat), or moving a module
into `UNIT_UV_MODULES`, makes `tests.test_gate_scope` fail until `python3 tools/gen_test_groups.py` rewrites the `# BEGIN GENERATED test groups` blocks in
`Makefile` (line 9 comment lists unit-uv) and the hook config. Every plan that touches module membership ends with that command and a `git diff --stat` check.
`UNIT_UV_MODULES` today (`tools/run_unittest_parallel.py` lines 94-97): `"tests.test_framework_profiles"`, `"tests.test_skill_frontmatter_pyyaml"`.

### P2: `check`'s count check pins loop 32 to inputs.json
`_count_problems` (judge_loop.py lines 1091-1104) requires `record["last_v4"] == inputs["skills"][skill]["last_v4"]` and re-derives the count. D-19 changes that for
loops that have a prior loop; the existing loop 32 record must stay valid (no prior loop → fall back to `inputs.json`). Existing tests that pin
"count inputs differ from inputs.json" (test_judge_loop.py lines 709-712) stay green only if the fallback is exact.

### P3: jev's `next_model` path loses its only real-table test
`_post` (jev_review.py 1549-1554) re-sends a group with the row's next model id; only the `opencode` row has two `models`. Tests
`test_model_policy_opencode_free_id_first_then_paid` (995), `_402_switches_model` (1007), `test_opencode_both_models_exhausted_keeps_the_last_reason` (1017),
`test_model_policy_opencode_pinned_sends_only_that_id` (1032) cover it. Rewrite them on `self.stub_row("quad", stub, ...)` patched into `JR.TABLE`
(helper at test file lines 404-411 already gives `models=("q-1","q-2")`, `model_env="JEV_Q_MODEL"`; pass `classify=JR._typesafe_classify`, `remote=True`,
`response_model=JR._JEV_RESPONSE` so a 402 yields `next_model`). Do not delete them: "never remove existing features".

### P4: the markdown-to-pdf argv tests assert exact lists
`test_pandoc_latex_with_tectonic` expects `["pandoc", "in.md", "-o", "out.pdf", "--pdf-engine=tectonic"]` and `test_chromium_is_standalone` expects
`["md-to-pdf", "in.md", "--output", "out.pdf"]` (test file lines 105-115). Add the resource folder as an **optional** `build_command(..., resource_dir=None)` argument that appends
`--resource-path=<dir>` only when given, and these stay green.

### P5: assets folder clutter
`render_mermaid._render_fences` writes `puppeteer-config.json` and each `diagram-N.<fmt>.mmd` into the `work_dir` it is given (render_mermaid.py lines 55-59, 62-65, 82-86).
Passing the persistent `<out>-assets/` as the work dir (what `render_only` does) leaves those files beside the diagrams. For the HTML deck, either render into the temp work dir and copy only
`diagram-*.<fmt>` into `<out>-assets/` (then rewrite the links), or accept the clutter and say so.

### P6: loop-32 judge lanes were refused at ingest, twice for a zero-width joiner and twice for a verdict-shape reason
REJUDGE.md lines 40 and 53: the referee-three lane for markdown-to-pdf and for session-wake returned `verdict judge '<opencode id with an invisible U+200D after the first letter>:router-env/my-referee-three' is not the lane's judge`
(the raw character is not reproduced here); lines 47, 54, 59: referee-two verdicts refused with `finding D5-1 line 156 is beyond the file's 150 lines` and `D3 is below its max but has no finding`.
In each case the native `ai-kit-judge` replaced the refused lane and the record says so. For loop 32.1: expect to rerun or substitute one lane, keep the `--replaces`/`--reason` ingest flags ready, and never edit a record by hand (`ingest` refusing a mismatch is correct).

### P7: `--include-tests` needs a `tests/` folder
In the template, `--include-tests` appends `Path("tests")` and `iter_python_files` raises `ValueError("Path does not exist: tests")` when it is absent
(`codemod_template.py.txt` lines 398-399, 224-225). A behaviour test that passes the flag must create `tests/` in its temp folder.

### P8: `history` gate scans every shipped `.md` for planning pointers
`tests/test_skill_text_history.py` rejects, in every `.md` under a skill (outside `evals/`): phase folders (`32.1-name/`), phase files, backlog ids (`999.N`), `D-NN` ids and
`router-env/`/`referee-*` names; and in SKILL.md main flow (above a trailing `## Evidence`): dates, `as of`, run logs, and a tool version in prose
without a constraint word (`Jev 1.14` in prose fails unless the sentence has `when`, `if`, `needs`, ...). Put Jev 1.14 facts in `reference.md`/`backends/typesafe.md`
(date-bearing headings there are allowed because only pointer rules apply to non-SKILL files).

#### B3. Template runs (run, `cst/runcases.log`)
Invocation (cwd = a scratch case folder; the template copied to `codemod_template.py`; `--no-project` stops uv walking up to the repo's pyproject):
`uv run --no-project --with "libcst>=1.5,<2" python codemod_template.py <subcommand> <flags>`
In the repo test use `[sys.executable, <tmp>/codemod_template.py, <subcommand>, ...]` (see B4).

Facts common to all subcommands:
- File discovery: ONLY `--paths` (required, `nargs="+"`), files or directories; directories walked with `rglob("*.py")` in filesystem order (unsorted); no git, no config, cwd only matters for relative paths. `--include-tests` appends the cwd-relative path `tests` (not repo-root relative) when `Path("tests")` is not already in `--paths`.
- Output: nothing on stdout or stderr on success, rc 0. A file is written only when the text changes (no-match file is byte-identical, mtime untouched).
- Errors are uncaught tracebacks: argparse errors rc 2; every `ValueError` and libcst error rc 1.
- Not atomic and no dry run: files are rewritten one by one as they are visited.

Per-case record (argv shown after `codemod_template.py`):

1. rename-symbol `rename-symbol --old-name old_fn --new-name new_fn --paths pkg` (rc 0). Renames EVERY `Name` token: definition, calls, imports, attribute (`m.old_fn`) and keyword-argument name (`m.call(old_fn=4)`); a comment and a string literal holding the old name stay unchanged. `tests/` untouched unless `--include-tests`; `pkg/c.py` (`x = 1`) byte-identical. Second identical run: rc 0, everything byte-identical (idempotent).
   Before `pkg/a.py`:
   ```
   def old_fn(x):
       # old_fn stays in this comment
       return "old_fn" + str(x)


   class Box:
       def run(self):
           return old_fn(1)
   ```
   After:
   ```
   def new_fn(x):
       # old_fn stays in this comment
       return "old_fn" + str(x)


   class Box:
       def run(self):
           return new_fn(1)
   ```
   Before `pkg/b.py`: `from a import old_fn` / `import m` / blank / `print(old_fn(2))` / `m.old_fn(3)` / `m.call(old_fn=4)`. After: same with `new_fn` in all five places.
   `--include-tests` run: `tests/test_a.py` (`from a import old_fn` ... `assert old_fn(1)`) becomes `new_fn` in both places. With `--include-tests` and no `tests/` folder: first path rewritten, then `ValueError: Path does not exist: tests`, rc 1 (the rewrite is not rolled back). Same old and new name: `ValueError: Old and new names must differ.` rc 1. Missing path: `ValueError: Path does not exist: nope` rc 1. Non-.py file: `ValueError: Path is not a Python file: pkg/n.txt` rc 1. No `--paths`: argparse `error: the following arguments are required: --paths` rc 2.

2. rename-parameter `rename-parameter --function greet --old-name name --new-name person --paths m.py` (rc 0). Signature, uses inside the function (including inside the f-string), and `greet(name=...)` keywords change; docstring text, `other(name=...)` and `obj.name` unchanged.

   ```
   def greet(name, greeting="hi"):

       return f"{greeting} {name}"

   greet("b", greeting="yo")

   After: `def greet(person, greeting="hi"):`, docstring unchanged, `return f"{greeting} {person}"`, `greet(person="a")`, other lines unchanged.
   `*args` rename works: `def f(*args, **kwargs): return args, kwargs` with `--function f --old-name args --new-name rest` gives `def f(*rest, **kwargs): return rest, kwargs`.

3. add-parameter. Input `def f(a, b=1):\n    return a + b\n\n\nf(1)\nf(1, b=2)\nobj.f(3)\ng(4)\n`.
   `add-parameter --function f --param flag --default False --paths m.py` (no `--call-value`, rc 0): only the def changes, to `def f(a, b=1, flag = False):` (note the spaces around `=`, libcst default formatting); call sites unchanged.

   Without `--default` after a defaulted param: libcst `CSTValidationError: Cannot have param without defaults following a param with defaults.` rc 1, file untouched.
