## Warnings

### WR-01: A reference definition with its destination on the next line is no longer rewritten (regression from the WR-03 fix)

**File:** `skills/markdown-to-pdf/scripts/markdown_to_pdf.py:35-36` (`_REF_DEF`)
**Issue:**
- CommonMark allows the destination of a definition on the line after the label (spec example
  "`[foo]:\n/url`"). marked (md-to-pdf) and markdown-it (marp) both accept it, so the source
  renders the image.
- The old pattern used `\s*` after the colon, which crossed the newline. The new pattern uses
  `[ \t]*`, so the definition no longer matches.
- Probe, input `![l][i]\n\n[i]:\n  img/a.svg\n` with `img/a.svg` present:
  - `cb10c38` chromium: `[i]:\n  asset-0.svg` (copied). HEAD chromium: `[i]:\n  img/a.svg`, no
    copy. md-to-pdf serves only the work folder, so the image is broken in the PDF.
  - `cb10c38` deck pdf/pptx: `<SRC>/img/a.svg`. HEAD: stays `img/a.svg`, which resolves in the
    temp folder, so the image is broken in the deck too.

**Fix:** let group 1 take one optional line break after the colon. The lookahead stays anchored
to the destination's own line:
```python
_REF_DEF = re.compile(
    r"(?m)^( {0,3}\[(?!\^)[^\]]+\]:[ \t]*(?:\n[ \t]*)?)(<[^>\n]*>|[^\s<]\S*)"
    r"(?=(?:[ \t]+[\"'(].*)?[ \t]*$)")
```
I checked this pattern. It rewrites the case above to `/S/img/a.svg`. It does not match
`[Update]: the API changed last week` or `[Note]:\nthe API changed`. The existing
`PROSE_AND_DEFS` expectation still holds. Add the input above to
`test_only_image_reference_definitions_are_rewritten` or a sibling test.

## Info

### IN-01: A code span in the alt text hides an image from the link rewrite

**File:** `skills/markdown-to-pdf/scripts/markdown_to_pdf.py:79-84` (`paragraph`), `:128-130` (`collect`)
**Issue:** `paragraph` cuts the text at every code span before `fn` runs, so `![` and `][i]` /
`](...)` end up in separate chunks.
- `` ![`x`][i] `` + `[i]: img/a.svg`: `collect` never sees label `i`, so the definition stays
  relative on both paths. This is a regression of `3ad1a9b`: `cb10c38` rewrote it, because it
  rewrote every definition.
- `` ![`x`](img/a.svg) `` stays relative too. This form was already broken in iteration 1.

Code in alt text is rare.
**Fix:** either collect labels with `_outside_code(text, collect, spans=False)` (an over-collected
label only rewrites a definition an image might use), or add a `shortcut:` line to
`_outside_code` that names the limit.

### IN-02: Orphan comment left in `_LINK_PATTERNS`

**File:** `skills/markdown-to-pdf/scripts/markdown_to_pdf.py:29`
**Issue:** `# reference definition `[id]: path` (not a footnote)` still sits in the tuple, but its
pattern moved to `_REF_DEF`. It now reads as if it describes the HTML image entry under it.
**Fix:** delete line 29.

### IN-03: `count_entry` is no longer called by production code

**File:** `tools/judge_loop.py:994-996`
**Issue:** after `8212fe7`, `_cmd_count` calls `with_base(..., prior_base(..., pin))` directly.
`count_entry` has no caller in `tools/` or `skills/`. Only the test fixtures call it
(`tests/test_judge_loop.py:518`, `:1718`, `:1807`). So the runtime module keeps a helper whose pin
source (the records, or no pin at all when the loop has none yet) differs from the real
count path (the rubric). The tests therefore build count records by a path `count` no
longer takes.
**Fix:** move the helper into `tests/test_judge_loop.py` (or have the fixtures call
`with_base(entry, prior_base(repo, records, name, loop, read_pin(pkg)))`), and delete it from
`judge_loop.py`.
