# Phase 32.1 Plan 04: Prior-loop judge base and regression limit

**The judge loop counts and grades each skill against its prior loop's lowest percent, with a 7.0-point regression limit enforced in the report and the gate.**

## Performance

- **Duration:** unknown (start time not recorded)

## Accomplishments
- `count --loop L` takes each skill's base from the newest prior loop that ranked it; the base commit is the newest commit under `skills/<name>/` whose digest matches the worst verdict's digest.
- `check` recomputes the same base from records and fails a hand-edited `percent`, `critical`, `high` or `source` (`count inputs differ from the prior loop's base`); `judged_at` is never compared.
- `report` and `check --gate` fail a round whose lowest valid percent is more than 7.0 points under the prior base, with the clause `not met: lowest percent <low> is more than 7.0 points under the loop <L> base <base>`.
- Loop 32 is unchanged: no prior loop, so `count` copies `inputs.json` and the report clause is byte for byte as before. `check .planning/judge` exits 0 on the committed records.
