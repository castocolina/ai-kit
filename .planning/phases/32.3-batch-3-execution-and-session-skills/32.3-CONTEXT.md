- **D-02: Every other Python caller holds a whole, byte-identical copy named `secret_shapes.py` in its own folder:**

  and `skills/ai-kit-session-wake/ai_kit_session_wake/`. Imports follow each folder's habit: plain sibling imports
  (`gp_render.py:24`, `flow_pr.py:13`), a relative import in session-wake (`cli.py:13-20`). `jev_ladder.py` is loaded
  by file path in tests (`tests/test_jev_fast_decision.py:53-65`), so it loads its sibling from its own `__file__`

  phase or plan file (`tests/test_skill_text_history.py`). No cross-skill import or path shim is added;
  `_CROSS_SKILL_FROZEN` is unchanged. A later group install can swap each copy for an import. **Own reasoning** (jev
  whole_file_copy low 0.52 laya; marked_block low 0.64 typesafe): a marked block clashes with existing names

  need. Ledger.
- **D-03: API.** `SHAPES = (("name", r"source"), ...)`, a plain literal; `detect(text) -> list[str]` searches each
  shape on the original text and returns each matching name once, in table order, never the match;
  `redact(text, marker) -> str` runs one substitution per shape in table order and returns clean text unchanged.
  The runner runs the same loop. **Own reasoning** (jev sequential_per_shape low 0.55 laya, low 0.73 typesafe): it is
  the loop both redactors run today (`cross-ai.mjs:1573-1576`, `reset_parse.py:138-139`), and neither marker holds a
  shape, so markers never nest. Ledger.

### Shape table (SPEC R2)

- **D-04: The shape set** (provisional regex sources; D-06 lets research raise a floor):
  - existing, at the lowest minimum and widest class any copy uses today: `sk`/`rk` with `-`
    (`[A-Za-z0-9_-]{8,}`, so the runner's hyphenated test sentinel stays redacted, `cross-ai.mjs:5500`), GitHub
    `gh[pousr]_[A-Za-z0-9]{20,}` and `github_pat_[A-Za-z0-9_]{20,}`, Google `AIza[0-9A-Za-z_-]{20,}`;
  - from the jev guard, as real formats: Slack `xox[abposr]-` (widened from `xox[abp]`), and any PEM begin line
    `-----BEGIN [A-Z0-9 ]+-----` (the guard refuses every PEM line today, so it keeps doing so); jev's non-format
    variants (`ghp-`, `gho-` with a hyphen, `xox?_`, bare `pk-`/`pk_`) are dropped;
  - new: AWS `(?:AKIA|ASIA)[A-Z0-9]{16}`, GitLab `glpat-[A-Za-z0-9_-]{16,}`, xAI `xai-[A-Za-z0-9]{16,}`, JSON Web Token
    (`eyJ` header and `eyJ` payload segments of 10+ each, joined by dots, with a signature segment), Stripe secret and
    restricted keys `(?:sk|rk)_(?:live|test)_[A-Za-z0-9]{16,}`, Hugging Face `hf_[A-Za-z0-9]{30,}`, npm
    `npm_[A-Za-z0-9]{36}`, Groq `gsk_[A-Za-z0-9]{20,}`.
  - choice 0.82 (typesafe: lowest_existing_minimum; laya low 0.51 provider_exact) for the lengths; choice 0.77 (laya:
    any_pem_block) for the jev variants.
- **D-05: Syntax both languages read the same way.** Every source is case-sensitive, with no flags, no capture group
  and no inline modifier; every prefix is guarded by an explicit ASCII lookbehind such as `(?<![A-Za-z0-9_])`, never
  `\b` (live check, python3 3.15.2 and node v24.21.0: after "é", Python's `\b` and Node's differ, the explicit
  lookbehind agrees). Consequence, accepted: the runner and session-wake no longer redact an upper-case `SK-` or
  `GHP_` prefix, which they catch today only through their case-insensitive flag; provider prefixes are lower case and
  no current test uses upper case (SPEC R2 amended). Analyzer, Confident; not asked.
- **D-06: Provider formats are an open question for the phase researcher.** It checks each new shape's current
  documented format against provider docs (AWS key id prefixes, GitLab token length and newer formats, xAI, every
  Slack prefix including `xapp-`, JWT segment floors, Stripe, Hugging Face, npm, Groq, `AIza` length) and records the
  sources; the plan pins the final regex strings. Research may raise a new shape's floor or add a documented prefix,
  never lower an existing shape's minimum below D-04 or drop a catch. Own reasoning; nothing in this run depends on
  it. Ledger (Blocks: plan regex strings).
