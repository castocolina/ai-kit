# Phase 32.3: Batch 3, execution and session skills — Specification

**Created:** 2026-11-13
**Ambiguity score:** 0.12 (gate: ≤ 0.20)
**Requirements:** 7 locked

## Goal

One shared secret-shape scanner, stdlib-only and safe under copy installs, holds every distinctive key shape that
ai-kit's scanner copies cover today plus the new ones, and every former caller uses it with a unit-tier test that it
catches each new shape (DEF-02); a guard test stops the copies from drifting apart or coming back.
`ai-kit-spec-execute-superpowers` and `ai-kit-session-wake` keep their judge bar, and loop `32.3` judges only a
SKILL.md this phase adds or materially changes.

## Background

The owner's batch scope "Narrow" (2026-11-07, 32.1 D-01) is locked: `ai-kit-spec-execute-superpowers` (86.4 B) and
`ai-kit-session-wake` (87.2 B) keep their bar with only the DEF-02 change; `ai-kit-cross-ai` (76.8 C) is deferred to
Phases 37-38 and is neither brought to the bar nor judged here. Skills a later phase removes or replaces (the seven
`ai-kit-project-rules-*` skills and `ai-kit-commit-fold`) are never judged (rails, Per phase end 0).

## Requirements

1. **One shared key-shape scanner**: one stdlib-only definition holds the set of distinctive key shapes, with a detect function that returns the names of the shapes found (never the matched text) and a redact function that replaces each match with a marker the caller passes.
   - Current: five separate shape lists, each with its own subset and lengths; detection and redaction written per caller.
   - Target: one canonical definition; any other copy that a copy install needs is generated from it or held equal to it by a test; detect returns shape names in a stable order; redact leaves text with no match unchanged.
   - Acceptance: a unit test calls detect and redact on one synthetic sample per shape and on clean text; detect never returns the sample's text; redact on clean text returns it byte for byte.

2. **More key shapes, no noisy ones**: the shared set holds every distinctive shape the copies cover today and adds AWS access key ids, GitLab personal tokens, xAI keys, every Slack token prefix, PEM private key headers, JSON Web Tokens, Stripe live and test secret keys, Hugging Face tokens, npm tokens and Groq keys.
   - Current: no caller catches an AWS, GitLab or xAI key; only the jev guard catches a Slack token or a PEM header.
   - *Amended 2026-11-13 (32.3 D-14):* "no caller" means no shipped caller: the eval test helper already matches `glpat-` and `xai-` (16+). The PEM shape matches any PEM begin line, as the jev guard does today (D-04); the shapes are case-sensitive, so an upper-case `SK-` or `GHP_` prefix, which the runner and session-wake redact today only through their case-insensitive flag, is no longer a key shape (D-05).
   - Target: each named shape has a synthetic sample that detect finds; ordinary text is not flagged: a 40-character commit hash, a UUID, the words "risk-assessment", "Basic authentication" and "sk-learn", a phase number and a slash command such as `/gsd-autonomous`.
   - Acceptance: a unit test holds one synthetic sample per shape, all found, and the near-miss list, none found; no real key appears in any test, fixture or doc.

3. **Every former caller uses the shared scanner**: the runner template's shape rules, session-wake's redactor, goal-prompt's detector, the jev ladder's item guard, commit-fold's GitHub-token redactor and the curated-config eval test helper take their key shapes from the shared scanner, and each keeps only its own extra rules.
   - Current: each caller has its own list; the extra rules are the runner's and session-wake's `Bearer`, `Basic`, `conn:`, UUID, key=value, id=value and copy rules (plus session-wake's 32+ hex rule), goal-prompt's home and configured-secret checks, the jev guard's 48+ base64 rule, and the test helper's key-name rules.
   - Target: no caller defines a distinctive key shape of its own; each caller's extra rules keep today's behaviour; every caller has a unit-tier test that it catches each new shape and still catches every sample its current tests catch.
   - Acceptance: per caller, a unit-tier test fails on the phase-start code (a new shape not caught) and passes after; the caller's existing test modules pass unchanged in what they assert.

4. **Copy installs keep working (DIST-03)**: each caller, installed as real copied folders together with only the sibling skills it already needs today, runs its scanner and catches a new shape.
   - Current: goal-prompt, jev-fast-decision and commit-fold run alone from a copy; session-wake runs with `ai-kit-spec-review` beside it; nothing under `skills/_shared/` reaches a copy.
   - Target: the same holds after the change; no caller reads the scanner from `skills/_shared/` or from another skill's folder; `_CROSS_SKILL_FROZEN` is unchanged or smaller.
   - Acceptance: a unit-tier test copies each caller's folder (and session-wake's existing sibling) into a temporary skills root with no symlink, runs that copy's scanner on a new shape in a child process with a temporary HOME, and sees it caught; `tests/test_arch.py` passes.

5. **A guard stops drift and new copies**: a test fails when any copy of the shared scanner, including the runner template's shape table, differs from the canonical definition, and when a distinctive key-shape pattern appears in tracked shipped code under `skills/` or `tools/` outside the sanctioned scanner files.
   - Current: nothing ties the copies together; session-wake's port and the runner already differ by one rule.
   - Target: the guard compares every sanctioned copy with the canonical definition and scans `git ls-files` under `skills/` and `tools/` for key-shape patterns; tests and fixtures with synthetic samples are outside its scan; non-vacuity cases prove a drifted copy and a new pattern each fail it.
   - Acceptance: the guard passes on the tree; its non-vacuity cases fail as stated; it runs in the unit or arch tier.

6. **The runner keeps its contract and its rendered copy stays pristine**: the runner template's redaction catches the new shapes, keeps its key and quote preservation and copy replacement, and this project's rendered runner copy is refreshed so `make check-dogfood` passes.
   - Current: the template's `SECRET_RES` holds eight rules; the self-test's redaction cases cover them; `.planning/scripts/cross-ai.mjs` is a pristine render.
   - Target: a runner self-test case redacts one sample per new shape; the existing redaction self-test cases pass; the rendered copy matches the template outside its config block.
   - Acceptance: `node skills/ai-kit-spec-review/references/cross-ai.mjs --self-test` passes, the self-test shards pass, and `make check-dogfood` exits 0.

7. **Judge scope and the bar (JDG-04)**: loop `32.3` judges exactly the SKILL.md files this phase adds or materially changes, each keeping its bar with no regression beyond judge variation; when none changes, the verification records that no loop `32.3` judge ran and why.
   - Current: `ai-kit-spec-execute-superpowers` and `ai-kit-session-wake` are at the bar (loop 32); no SKILL.md names a key-shape list.
   - Target: a SKILL.md changes only where its text would become false; any changed one is judged by `tools/judge_loop.py` with the judges from `.planning/config.json` (JDG-06: two judges only near the pass mark, 73-87); `ai-kit-cross-ai`, `ai-kit-commit-fold` and the project-rules skills are never judged; `ai-kit-spec-execute-superpowers` is unchanged and keeps its evals passing.
   - Acceptance: `python3 tools/judge_loop.py check .planning/judge` exits 0; 32.3-VERIFICATION.md lists each changed SKILL.md with its bar result, or states that none changed; `git diff --stat` against the phase start shows nothing under `skills/ai-kit-spec-execute-superpowers/` or `skills/ai-kit-cross-ai/`.

## Boundaries

**In scope:**
- The shared key-shape scanner, its canonical home and any copy a copy install needs (R1, R4).
- The new shapes and the near-miss list (R2).
- Moving every former caller onto it, the curated-config eval helper included, with a unit-tier test per caller (R3).
- The copy-install test (R4) and the drift and new-copy guard (R5).
- The runner template's shape table, its self-test case and the refreshed dogfood copy (R6).
- The judge-scope record in the verification (R7).

**Out of scope:**
- The callers' broad redaction rules (`Bearer`, `Basic`, `conn:`, UUID, hex runs, key=value, id=value, copy
  replacement), goal-prompt's home and configured-secret checks and the jev guard's base64 rule — they stay with their
  callers, unchanged in behaviour; a detector would refuse ordinary text with them (spec S3).
- A parity test between the runner's and session-wake's broad redaction rules — they are a deliberate port (26 D-37);
  nothing in DEF-02 names them.
- Bringing `ai-kit-cross-ai` to the bar, giving it evals or changing its Markdown — Phases 37-38 (32.1 D-01).
- New-shape evals for `ai-kit-session-wake` — the phase that next materially changes its SKILL.md (JDG-03, JDG-04).
- Any change inside `ai-kit-spec-execute-superpowers` — it has no scanner.
- Removing session-wake's existing reach into `ai-kit-spec-review`, or choosing vendor versus group install for
  `ai_kit_spec` — Phase 52 (DIST-03 spike, DIST-09).
- Re-rendering runner copies in other projects — the template's own update flow does that.
- Scanning repository history or uncommitted files for real secrets — the guard checks code shapes, not content.

## Constraints

- Runtime code stays stdlib-only; no new dependency (AGENTS.md).
- No cross-skill import or path shim is added; `_CROSS_SKILL_FROZEN` may only shrink.
- Test samples are synthetic key shapes, built at run time where a whole literal would trip a scanner; no real key,
  no key value printed, logged or committed.
- Tests stay flat under `tests/test_*.py`, join the runner's groups by its rules and read no `.planning/` path.
- A changed runner template keeps the self-test shard split in budget (`tests/cross_ai_selftest.py`).
- Every changed SKILL.md keeps passing `tests/test_skill_frontmatter.py` and `tests/test_skill_text_history.py`.
- English only; no machine-specific absolute path in source, tests or docs.
