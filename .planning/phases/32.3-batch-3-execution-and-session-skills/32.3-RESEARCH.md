## Summary

Every provider publishes a prefix, but almost none publishes a length. Official pages fetched this session document: AWS `AKIA`/`ASIA` (and `ABIA`/`ACCA` as other credential id prefixes), the GitLab prefix table, Slack `xoxb-`/`xoxp-`/`xapp-`/`xwfp-`/`xoxe.xapp-`, Stripe `sk_/rk_` with `live`/`test` (and `sk_org_`), the npm `npm_` prefix with a CRC32 tail. xAI, Groq, Hugging Face length, Google `AIza` length, JWT and PEM formats have no official length in anything fetched; those lengths below are secondary (gitleaks, secretlint) or D-04 provisional floors and are labelled that way. No D-04 floor was lowered and no catch dropped. Four additive changes are recommended: Slack body floor and extra prefixes, a wider GitLab prefix set, npm `{36,}` instead of exact `{36}`, and a PEM source that also swallows the key body through the END line.

The Python `re` and Node `RegExp` engines agree on all 116 synthetic samples (every shape at its minimum and one character short, every Slack/GitLab/Stripe prefix, adjacency, empty prefix, wrong case, JWT segment floors, PEM header and body, and the SPEC R2 near-miss list). One near-miss does match, by D-04's own design: `sk-learn-pipeline-config` (the `-` in the body class is needed so the runner's hyphenated sentinel `sk-aikit-SENTINEL-<pid>` stays redacted); bare `sk-learn` (5 body characters) does not match.

The D-12 guard works as designed with one correction to its pattern: a lookbehind before the prefix would miss `\bAIza[` style copies (the `b` of `\b` precedes `A`), and grouped alternations `(?:sk|rk)-[` and `(sk|rk)-[` need their own alternative. A probe with an explicit-separator prefix list plus a group alternative flags exactly the 12 pre-change lines in the five shipped copies and nothing else in `skills/` and `tools/` (a generic `gl[a-z]+` prefix would flag 14 `glob(` lines, so the GitLab prefix list must be explicit).

**Primary recommendation:** pin the 14-row regex set in "Final shape table" below into the plan verbatim; build D-12 from explicit prefix-plus-separator alternatives (no lookbehind, one group alternative); register the new test modules with `python3 tools/gen_test_groups.py` and commit the regenerated `Makefile` and `.pre-commit-config.yaml` blocks.

### Anti-Patterns to Avoid
- **Lookbehind in the D-12 guard regex:** misses `\bAIza[...` (the `b` of `\b` precedes `A`). Use no boundary guard; the explicit separator after the prefix keeps it precise (probe, below).
- **Generic `gl[a-z]+` prefix in the guard:** flags 14 `glob(` lines; list GitLab prefixes explicitly.
- **Sharing a samples helper across test modules:** widens every staged run to the full unit tier (D-13 already settles this).
- **Writing a whole sample literal** (even `"ghp_" + "a"*36` is fine, a complete 40-char literal is not): GitHub push protection scans pushed content.

## Common Pitfalls

### Pitfall 1: Python `\b` vs Node `\b` next to non-ASCII
**What goes wrong:** the two engines disagree after `é`. **Avoid:** the explicit ASCII lookbehind (D-05); probe confirms both engines agree on every sample, including `é` before `sk-` (matches in both).

### Pitfall 2: PEM header-only redaction
**What goes wrong:** with D-04's header-only source, `redact` leaves the base64 body behind. **Avoid:** use the optional lazy END tail (probe: `<redacted>` for header+body); the runner relays line by line, so its multi-line PEM handling stays line-bound (header lines only); not a regression versus today.

### Pitfall 3: greedy `sk-` body swallows a neighbouring key joined by `-` or `_`
**What goes wrong:** `sk-aaaaaaaaghp_aaaa...` is one match. **Avoid:** this is the D-14 behaviour (glued pair redacted whole); the test asserts no tail remains.

### Pitfall 4: `sk-learn-pipeline-config` is flagged
**Why:** the body class includes `-` so the runner sentinel stays redacted. **Avoid:** record it in the near-miss test as a documented known match, not a defect; bare `sk-learn` stays clean.

### Pitfall 5: same-named module `secret_shapes` collisions
**What goes wrong:** two skills' `scripts` dirs on `sys.path` in one process import whichever is first. **Avoid:** copies are byte-identical (guard); jev loads by path under a unique module name; the runner executes one module per process.

### Pitfall 6: guard blind to alternation and `\b` copies
See Anti-Patterns; use the probe-validated RX above.

### Pitfall 7: text-history and docstring rules
`tests/test_skill_text_history.py` forbids phase or plan-file names in skill text; the shared module docstring must be identical in all copies and name none.

import re

_COMPILED = tuple((name, re.compile(source)) for name, source in SHAPES)

def detect(text: str) -> list[str]:
    return [name for name, rx in _COMPILED if rx.search(text)]

def redact(text: str, marker: str) -> str:
    for _name, rx in _COMPILED:
        text = rx.sub(marker, text)
    return text

## Security Domain

### Applicable ASVS Categories
| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | no | - |
| V3 Session Management | no | - |
| V4 Access Control | no | - |

| V6 Cryptography | no | none implemented; no key material generated or stored |

### Known Threat Patterns
| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Secret echoed in logs or reports | Information disclosure | detect names only, `redact` with marker, tests assert sample absent |
| Regex backtracking on hostile input | Denial of service | every body is a single bounded class with a simple quantifier; only the PEM lazy tail scans to an END line, linear per BEGIN; no nested quantifiers |
| Real key committed in a test | Information disclosure | samples built at run time from `prefix + filler*n`; push protection as the backstop |
| Shape copy drift | Tampering | byte-equal guard (R5) |
