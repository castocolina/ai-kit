```

   |

   |
   v

        |                 |-- builders (gp_sections): wrap_items for lists/commands;

        v

        |                                         |--problems--> GuardError(names the cap or section), nothing written
        v

spec-discuss SKILL.md (text)
   range -> run mode (derive, order, (Recommended)) -> pre-run summary + owner go-ahead

curated-config: --project-dir
   v1 ensure-project --mkdir <dir>/.planning--> config-new-project --> later writes resolve inside
   v2 inventory (outside config = absent) -> recommend -> apply (mkdir before config_path resolves; dry-run writes nothing)

                   check: regenerate + byte compare; drift between snapshot and tree = a note

### Anti-Patterns to Avoid
- **Editing a golden by hand or accepting an unread regeneration:** regenerate once with `UPDATE_GOLDEN=1`, read the diff, and keep `worked-example.md` excerpts contiguous with it.
- **Putting `skip` before `test tier` in a rail line:** trips `SKIP_RE` (gp_render.py:113).
- **A wrap that splits inside a `--x` token or drops a separator:** splits fall at spaces; flag guard stays as is.
- **A test that reads `.planning/` or `tmp/`:** AGENTS.md; use committed fixtures (`tests/fixtures/goal_prompt/`) and temp dirs.
- **Running the D-15 recipe without the `git init` and `config-path` guards:** it binds to the real project (observed).
- **Live tree read inside `render_report`:** breaks `check`'s byte compare and fails the pre-push `check-dogfood` on every new test module (D-18).

## Common Pitfalls

### Pitfall 1: A nested scratch under the repo binds to the real project
**What goes wrong:** the D-15 repro (or a test) writes backups into this checkout's real `.planning/`.
**Why:** `project-root.cjs` heuristic (3) needs `.git` between the start folder and the ancestor `.planning/` (lines 86-104, 182); a plain nested folder walks to the real repo.
**How to avoid:** `git init` the synthetic outer, run `config-path --cwd <inner>` first and abort unless it prints a scratch path; sha256 the real config before and after; export `AI_KIT_REFUSE_REAL_HOME=1` with a temp HOME.
**Warning signs:** `existing_config.path` outside the scratch; `config.json.bak-*` in `.planning/`.

### Pitfall 2: `fit_line` cuts, wrap must not
**What goes wrong:** reusing `fit_line` on a list silently drops items. **How to avoid:** the wrap helper never cuts (gp_sections.py module docstring: "a list of work items is never cut").

### Pitfall 3: UNIT_SENTENCE merged away
**What goes wrong:** the guard "DONE WHEN lacks 'Unit tests alone never count as done.'" (gp_render.py:236-237) refuses every render. **How to avoid:** keep the exact sentence in the merged "Phase status" line.

### Pitfall 4: A non-native all-fields render is refused
61 lines. State it in SKILL.md and test that the refusal names "more than 60 rule lines".

### Pitfall 5: `ensure-project` creating `.planning/` in a folder that should be a plain project already
`os.makedirs(..., exist_ok=True)` is idempotent; the existing "folder already holds `.planning/`" test (`test_parent_project_config_is_never_touched`) must keep passing unchanged.

### Pitfall 6: The report's facts file makes `check` fail on every new test module
Make the drift a note, not a problem (D-18), mirroring the stale-digest note at judge_loop.py:1278-1280.

### Pitfall 7: Judging a skill with no material change
`ai-kit-gsd-curated-config`, `jev-fast-decision`, `ai-kit-usage-metrics`, `ai-kit-spec-review`, `ai-kit-session-wake` keep their stale-digest notes (D-19) and are listed in 32.4-VERIFICATION with the reason; never re-judge them, never judge `ai-kit-commit-fold` or the project-rules skills.

# Source: derived from fit_line (gp_sections.py:141) and the D-01 contract; not yet in the repo
def wrap_items(head, items, tail="", sep=", ", section="a rule", cap=LINE_CAP):
    """Whole items per line, separator kept at the line's end; first line bulleted by assemble_rails."""
    lines, current, prefix = [], head, RULE_BULLET
    for index, item in enumerate(items):
        piece = item + (sep if index < len(items) - 1 else tail)
        if len(prefix) + len(current) + len(piece) > cap and current.strip():
            lines.append(current.rstrip() if sep.endswith(" ") else current)
            current, prefix = "   ", ""
        if len(prefix) + len(current) + len(piece) > cap:
            raise GuardError(f"one item is longer than a whole line in {section}")
        current += piece
    lines.append(current)
    return lines
```
