### Goal-prompt wrapping (SPEC R1)

- **D-01: One wrap helper beside `fit_line` in `gp_sections.py`, used by every list or command builder.** It takes a
  head, the items, a tail and a separator (", " for lists, " " for command words), fills each line greedily with the
  prefix counted, keeps a separator at the end of its line, bullets the first line and starts later lines with three
  spaces, which `assemble_rails` (gp_sections.py:478-485) already leaves unbulleted. Callers: `order_lines` (308, 312,
  321), the candidate-skill line of `plan_rule_lines`, `superpowers_rule_lines` and `generic_rule_lines` (205, 223,
  235), `superpowers_order_lines` (246, 250), the gates and mockups of `done_lines` (463, 472) and the runner sub-line
  of `quota_lines` (350). Continuation lines count toward the 60-line cap (`_rule_lines`, gp_render.py:219). Splits
  fall at spaces only, so no `--x` token can appear and the flag guard (gp_render.py:244-252) is unchanged. An item
  longer than a whole line is refused with a message that names its section, found the way `_flag_section` finds it.
  Analyzer, confident; jev not asked.
- **D-02: E2E command lines wrap too** (SPEC R1 amended): `_e2e_lines` (gp_sections.py:441-456) puts a long command
  on continuation lines split between command words, each piece in its own code span, and the inferred-confirmation
  suffix stays after the last piece. DEF-03 says "commands", and the folded todo names a long e2e command as one of
  the refusal cases. **Own reasoning** (jev leave_e2e_out 0.70 laya; second opinion low 0.45 typesafe same): the
  answer contradicts DEF-03's wording, and no confident second opinion exists. Ledger.

### Goal-prompt owner run rules and the caps (SPEC R3, R4)

- **D-03: Six structured optional answers fields, checked in `goal_prompt._check_answers` with `_require` (field
  name, never the value):** `push_after_fold` (true); `turn_cap` (a whole number of 1 or more, or `null` for no cap;
