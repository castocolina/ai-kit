## Warnings

### WR-01: Any subfolder passed as `--project-dir` silently becomes a separate nested project, not only an empty one

**File:** `skills/ai-kit-spec-review/ai_kit_spec/gsd_tools.py:371-374`, `skills/ai-kit-gsd-curated-config/ai_kit_gsd_curated_config/inventory.py:83-93`, `skills/ai-kit-gsd-curated-config/SKILL.md:30`
**Issue:** `ensure_config_exists` creates `<project_dir>/.planning/` whenever `project_dir` is a directory (`if os.path.isdir(project_dir)`). It does not check that the folder is empty or that it is not already part of an outer project. Likewise, `project_config_path` maps any config that gsd-core resolves outside `project_dir` to the folder's own `.planning/config.json`. The SKILL.md describes this as "**An empty folder** inside another GSD project ... becomes its own project", but the code applies it to every folder. Concrete case: in a GSD repository, run `ensure-project --project-dir <repo>/tools` (for example, an agent that passes its cwd while standing in a subfolder). Before this change, gsd-tools answered `already_exists`, and later writes landed in the real project. Now the command creates `<repo>/tools/.planning/config.json`. Every later `apply-*`/`apply` write goes there, and the real project config is silently left alone. The split is never reported. The output is still `{"ensured": true}`.
**Fix:** Make code and doc agree, and make the split visible. Smallest: keep the behaviour for every folder, change SKILL.md:30 from "An empty folder" to "Any folder without its own `.planning/`", and print one stderr note when the folder was not already a root, so a mis-scoped run is visible:
```python
# gsd_tools.ensure_config_exists
planning = os.path.join(project_dir, ".planning")
if os.path.isdir(project_dir) and not os.path.isdir(planning):
    os.makedirs(planning)
    print(f"note: {project_dir} becomes its own GSD project", file=sys.stderr)
```
Stricter alternative: create `.planning/` only for an empty folder or a git top level, and otherwise refuse with a message naming the outer config that `config-path` resolved.

### WR-02: A failed or timed-out `ensure-project` leaves an empty `.planning/` behind, which changes later runs

**File:** `skills/ai-kit-spec-review/ai_kit_spec/gsd_tools.py:371-386`
**Issue:** The directory is created before `config-new-project` runs. When that call fails (non-zero exit, `TimeoutExpired`, spawn `OSError`), the function returns `False` and leaves the new empty `.planning/` in place. The v2 `apply` path rolls this back (`_missing_dir_chain` / `_rmdir_chain` in `apply.py:856`). The v1 `ensure-project` command (`cli.py:92`) has no rollback. After one failed run, gsd-core treats the folder as a project root that has no config. A following v1 `apply-profile` then targets the inner folder, and `config-set` creates the sparse config that `references/v1-path.md:15` warns about, instead of failing as `test_v1_apply_profile_without_ensure_writes_nothing_outside` expects.
**Fix:** Remove the folder only when this call created it and the run did not succeed:
```python
planning = os.path.join(project_dir, ".planning")
made = os.path.isdir(project_dir) and not os.path.isdir(planning)
try:
    if made:
        os.makedirs(planning)
    result = run_fn(...)
except (OSError, subprocess.SubprocessError):
    result = None
ok = result is not None and result.returncode == 0
if made and not ok:
    try:
        os.rmdir(planning)  # only removes it while still empty
    except OSError:
        pass
return ok
```
Add one unit test: a fake `run_fn` that returns rc 1 leaves no `.planning/`.

### IN-01: `judge_loop report` writes `facts.json` before the report is rendered, so a render error leaves the two out of step

**File:** `tools/judge_loop.py:1936-1941`
**Issue:** `_cmd_report` writes `facts.json` atomically, then calls `render_report`. A `JudgeLoopError` raised in `render_report` (for example, `<skill>: no verdict records`, which `TestReport` exercises) exits 1 after the new `facts.json` is on disk while `REJUDGE.md` is still the old one. `check` then reports `REJUDGE.md differs`, which is recoverable by re-running `report`, but the failed command has already changed tracked records.
**Fix:** Write the snapshot to a temp name, render, then `os.replace` both. Or let `render_report` take the facts as an optional argument and write both files only after it returns.

### IN-02: `_code_chunks` counts the trailing suffix against every word, not only the last one

**File:** `skills/ai-kit-spec-goal-prompt/scripts/gp_sections.py:590-610`
**Issue:** The guard `len(f"`{word}`") + len(end) > room` adds `end` (up to 45 characters for `" (inferred: confirm it runs the real app);"`) for every word. But `end` follows only the last chunk. An inferred e2e command whose middle word is 152-195 characters long (a long URL or path argument) is refused with "one list item or command word is longer than a line", even though that word fits on its own continuation line.
**Fix:** Apply `len(end)` only to the last word: iterate with `enumerate`, and use `extra = len(end) if index == last else 0` in both the guard and the fit check.

### IN-03: `OWNER_FIELDS` is a second, unenforced copy of the field list `_check_owner_fields` validates

**File:** `skills/ai-kit-spec-goal-prompt/scripts/goal_prompt.py:48-55`, `goal_prompt.py:575-609`
**Issue:** `OWNER_FIELDS` is used only by `tests/test_ai_kit_spec_goal_prompt_skilltext.py:294` (the SKILL.md documents each field). The validator spells out each name by hand. A seventh field added to `_check_owner_fields` and the renderer would pass the skilltext test without ever being documented.
**Fix:** Have a test assert that the keys `_check_owner_fields` reads equal `OWNER_FIELDS` (for example, feed it a dict with one wrong-typed value per `OWNER_FIELDS` entry and expect a refusal for each). Or drive the validator from a `{name: (predicate, expected)}` table keyed by `OWNER_FIELDS`.

### IN-04: `module_list` repeats `build_module_index`'s error mapping instead of calling it

**File:** `tools/judge_loop.py:193-210`
**Issue:** Lean: `module_list` builds the index itself inside its own `try/except mapper.MapperError`, duplicating `build_module_index`, which was added in the same change.
**Fix:** `if index is None: index = build_module_index(root)` before the `try`. That leaves only `covering_modules` inside the remaining `try`.

### IN-05: Generality without instantiation: a one-element `steps` tuple driving a loop in `apply-review`

**File:** `skills/ai-kit-gsd-curated-config/ai_kit_gsd_curated_config/cli.py:383-387`
**Category:** necessity
**Issue:** After `review.effort.opencode` was dropped, `steps` holds exactly one entry, whose label equals its key. The tuple-plus-loop no longer abstracts over anything: line 383 is its only instantiation, and no other caller builds `steps`.
**Fix:** Call it directly: `code = _config_set_exit(ctx, "workflow.plan_review_convergence", True, "workflow.plan_review_convergence")`, followed by `if code is not None: return code`.
