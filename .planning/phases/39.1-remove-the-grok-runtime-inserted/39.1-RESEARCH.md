## Summary

The removal is small in code and wide in tests. Code: one table row (`detection.py:136-141`), one builder
(`commands.py:26-36`), one CLI branch (`cli.py:1207-1211`) plus its import (`cli.py:53`), four `runner`-field readers, three

rest (model names, vendor prefixes, the `agent`-alias guard, `grok-worker`, `GROK_AGENTS_HOME`) stay.

Three findings the CONTEXT did not name, all decide-ready below: (1) after the row leaves the table an unknown runtime string
is NOT refused anywhere on the load/dispatch path today: it routes `unverified` and reaches the runner (Q1), so the load-time
drop of D-03 is mandatory, not cosmetic. (2) `detect-runtimes --runtime grok` (`detect_unlisted_runtimes`) would start
reporting grok as an "installed, no listing" runtime once it is not in the table (Q3): it is a seventh call site for the
removal helper. (3) `"grok"` must leave `HOST_CLI_NAMES` in `tools/run_unittest_parallel.py`, because
`tests/test_run_unittest_parallel.py:606` pins that set to the table binaries plus the goal-prompt host map (Q4).

**Primary recommendation:** drop the removed lanes from the raw `[lanes]` tables at the top of `cfg_combine` (one function,
covers the flat, review and execute views, local and user layers), keep `normalize_legacy_*` untouched so save still refuses,
and build everything else exactly as the D-08 slice order says.

## Q1. Today's behavior for an unknown runtime id (D-03 first task)

Use `fake-runtime` (any id not in `RUNTIMES`; `grok` is a row today so it cannot serve as the unknown example).

**LOAD, `runtime = "fake-runtime"`.** No code looks at the id:
- `normalize_legacy_entry` only acts on `cli`, `native_runtime`, and `runtime_id()` aliases; `fake-runtime` is not in

  ```

      if not notes or label in _LEGACY_NOTED:
  ```

  `"{key}: cli={cli} has no runner formula and no command; this entry is skipped (build-command --runtime {rid} generates a

## Common Pitfalls

1. **Dropping removed lanes inside `normalize_legacy_*`.** That function also runs on save (`_cfg_render_reviewers`), so save
   would silently drop a grok lane instead of refusing it. Drop in `cfg_combine` only.
2. **Checking only `runtime`.** A legacy `cli = "grok"` + `command` becomes a custom command lane after normalization
   (config_io.py:108-109) and would still run. Filter on the raw `cli` and `runtime` before normalization.
3. **Assuming `\bgrok\b` guards `GROK_AGENT`.** It does not (underscore). Add the explicit `GROK_AGENT` pattern.
4. **Leaving `grok` in `HOST_CLI_NAMES`.** `tests/test_run_unittest_parallel.py:606` fails; also removing it from the stubs means
   a real `grok` on this machine's PATH (`~/.local/bin/grok`) is no longer tripwired, which is fine because no code path calls
   it any more.
5. **Baseline drift.** Converting grok custom-command tests removes `keyval grok-4*` hits; the arch test then fails until the
   baseline lines are removed by hand (Q7).
6. **The save/`build-command` messages are pinned by tests.** Keep `tests/test_no_seed_refusal.py:153-154` text for non-removed
   unknown ids and the `hand-written command` tail for `build-command` (test_ai_kit_spec.py:4691), or edit those tests together.
7. **`execute_selection` message.** Keep "has no runner row in the RUNTIMES table" (test_ai_kit_spec.py:5352).
8. **Dedupe state.** `_LEGACY_NOTED` is process-global and never cleared by tests: unique config path per test, or a test
   asserting "emitted once" fails the second time for the wrong reason.
9. **Template version pins.** 17 text and golden pins move with the bump; goldens are tool-written, never hand-edited.
10. **Stale cached snapshot.** A pre-change `runtimes.json` can hold a `grok` row; routing ignores it (routing.py:112). Do not
    bump `RUNTIMES_SCHEMA_VERSION` (test pins 8).
11. **Skill text rules.** `test_skill_text_history` rejects dates and "confirmed live" in SKILL.md main flow; the rewritten
    paragraph stays behavioral.
