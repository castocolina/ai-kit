# Phase 39.1: Remove the grok runtime — Specification

**Created:** 2026-11-23
**Ambiguity score:** 0.20 (gate: ≤ 0.20)
**Requirements:** 10 locked

## Goal

ai-kit stops knowing `grok` as a runtime: no runtime-table row, command builder, host signal, CLI profile or doc and skill text
names it as one, a saved config that names it is reported as removed instead of run, and every grok MODEL reachable through
opencode, pi and cursor-agent stays a selectable catalog candidate.

## Background

Requirement RUN-15 (REQUIREMENTS.md, added 2026-11-19, owner decision). The owner's reasoning: a rare runtime that adds no value
is not worth maintaining; its models run from more flexible runtimes and cursor-agent may replace it. Phases 36, 37 and 38.1
carry an owner directive of 2026-11-20 ("grok is not a cross-AI target") and kept the grok code until this phase.

**The owner's decisions (highest priority):**

- 2026-11-19 and 2026-11-20: remove the runtime; its models stay usable through opencode, pi and cursor-agent.
- 2026-11-23, answers to this phase's question batch: (1) a stale grok lane is skipped with one message and the other lanes
  run (the whole config is not refused); (2) `cursor-agents/grok-worker.md` stays (a model pin, not the runtime); (3) the guard
  test scans structure and shipped text, not structure alone.
- 2026-11-23, clarification (translated from Spanish): "this is about removing grok as a runtime, but it will remain a grok
  model candidate to use."

**Decided by own reasoning on 2026-11-23, the owner may overrule:** the `GROK_AGENT` scrub signal is removed (nothing reads it
once grok is not a host); `GROK_AGENTS_HOME` stays (it is gsd-core's own home-resolver contract, also copied into
`edge_floor.py` and `gsd_tools.py`, not grok-runtime knowledge); a user's own custom `command` lane that starts with `grok` runs
like any custom command under the unchanged trust gate (ai-kit never names grok there).

**Live facts checked for this spec (2026-11-23, this machine):**

- Seventeen shipped source and doc files outside the dated history name grok (counts by file: `references/cli-profiles/grok.md`

## Requirements

1. **The runtime table has no grok row (RUN-15)**: `RUNTIMES` in `skills/ai-kit-spec-review/ai_kit_spec/detection.py` has no
   `grok` key, so `KNOWN_CLIS`, installed-CLI detection and every list derived from the table omit it.
   - Current: `RUNTIMES["grok"]` exists, `KNOWN_CLIS` lists `grok`, and a machine with a `grok` binary on PATH reports it
     installed; four grok-keyed exceptions sit in `test_runtime_list_drift.py`.
   - Target: no `grok` key; a `grok` binary on PATH is ignored; nothing is changed on the machine; the four drift exceptions
     are gone.
   - Acceptance: a test with a stub `grok` binary first on PATH asserts `detect_installed_clis()` has no grok entry and
     `KNOWN_CLIS` lacks `"grok"`; the runtimes-table test expects exactly `pi, opencode, cursor, codex, claude, copilot`;
     `test_runtime_list_drift.py` has no grok-keyed exception; with no CLI on PATH, detection reports an empty list and
     raises nothing.
   - Clarification (2026-11-24, verified fact; AGENTS.md Workflow): "an empty list" means no installed binary.
     `detect_installed_clis()` returns one key per `RUNTIMES` row mapped to a path or `None`
     (`skills/ai-kit-spec-review/ai_kit_spec/detection.py:228-235`), so with no CLI on PATH it returns the six runtime keys
     `pi, opencode, cursor, codex, claude, copilot`, each mapped to `None`, not an empty list. The API is unchanged.

2. **No grok command builder and no grok build-command path (RUN-15)**: `build_grok_command` and its import and use in `cli.py`
   are removed, and `build-command --runtime grok` exits 1 with the removal message of requirement 4 and prints nothing on
   stdout.
   - Current: `build-command --runtime grok` prints a custom-entry JSON with `grok -p {prompt} -m {model} --output-format
     plain` and exits 0.
   - Target: exit 1, empty stdout, the removal message on stderr.
   - Acceptance: a CLI test runs `build-command --runtime grok` and asserts exit code 1, empty stdout and the message;
     `commands.py` defines no function whose name contains `grok`; `TestBuildGrokCommand` is deleted; `--runtime Grok` and
     `--runtime ''` get the generic unknown-runtime handling of any other unknown id (runtime ids are exact-match).

3. **No CLI profile, doc or skill text names grok as a runtime (RUN-15)**: `references/cli-profiles/grok.md` is deleted, and the
   text that presents grok as a runtime is rewritten or removed in `cross-ai-dispatch.md`, `ai-kit-spec-config/SKILL.md` and
   `references/cli-model-selection.md`, `ai-kit-spec-review-checklist/SKILL.md`,
   `ai-kit-spec-execute-superpowers/references/resolution-stops.md`, `README.md`, `cli.py` help and code comments, and the
   other shipped files that list grok as a runtime.
   - Current: the profile exists and the files above call grok a runtime, a headless CLI or a custom-command example.
   - Target: grok appears in shipped text only as a model name, as the `agent`-alias collision note, as `GROK_AGENTS_HOME`,
     as the removal message, or as the `grok-worker` model pin.
   - Acceptance: `references/cli-profiles/grok.md` does not exist and the guard test of requirement 8 passes over the shipped
     text.

4. **A stale grok lane is reported as removed and never run (RUN-15)**: when a loaded `config.toml` names the grok runtime in a
   lane's `runtime` field or in a legacy `cli` field, the load emits one message per such entry saying grok was removed as a
   runtime, naming opencode, pi and cursor-agent as the runtimes that reach grok models, and naming the re-save command; that
   lane is skipped and the other lanes load and run; the file on disk is unchanged; saving a lane with `runtime = "grok"` is
   refused with the same message.
   - Current: save refuses `runtime = "grok"` with "has no runner formula"; load keeps the row and a grok lane is not covered
     by any removal message (how dispatch treats such a lane today is not pinned by a test found for this spec; discuss
     pins it).
   - Target: the lane never reaches a dispatch, a spawn or a runner call.
   - Acceptance: tests over a config with one `runtime = "grok"` lane and one pi lane assert (a) one removal message naming
     opencode, pi, cursor-agent and the re-save command, (b) the roster lists only the pi lane, (c) a dispatch spy records no
     call for the grok lane, (d) the file bytes are unchanged; the same holds for a legacy `cli = "grok"` entry; save with
     `runtime = "grok"` exits non-zero with the message; a custom `command = "grok -p {prompt} -m {model}"` lane with no
     runtime still loads as a custom lane; a lane `runtime = "cursor"` with model `grok-4.6` loads and runs with no message; a
     config whose only lane is the grok lane yields the message and then the handling of a config with no lanes; loading the
     same config twice in one process emits each message once; the other lanes keep their roster order; an id other than
     exactly `grok` (for example `Grok`) gets the generic unknown-runtime handling.

5. **The `GROK_AGENT` host signal is gone and `GROK_AGENTS_HOME` stays (RUN-15)**: `GROK_AGENT` appears in no scrub list: not
   in the runtime table, not in the runner's scrub list in `cross-ai.mjs`, not in the test baseline of
   `tools/run_unittest_parallel.py`; `GROK_AGENTS_HOME` stays in `gsd_tools.py`, `edge_floor.py` and the test baseline.
   - Current: `GROK_AGENT` is a scrub signal in the table and listed in `cross-ai.mjs` and `run_unittest_parallel.py`;
     `detect_current_runtime({"GROK_AGENT": "1"})` returns `"unknown"`.
   - Target: the three lists agree without it; `detect_current_runtime` still returns `"unknown"` for it.
   - Acceptance: the existing table-mirror drift test passes with `GROK_AGENT` absent from all three lists; a test asserts
     `detect_current_runtime({"GROK_AGENT": "1"}) == "unknown"`; a test asserts `GROK_AGENTS_HOME` is still read by
     `gsd_tools.py`; a scrub of `GROK_AGENT` never strips `GROK_AGENTS_HOME` (the first is a prefix of the second);
     `detect_current_runtime({"GROK_AGENT": ""})` returns `"unknown"`.

6. **Grok models stay selectable models of opencode, pi and cursor-agent (RUN-15)**: model discovery, the catalog, vendor
   inference and the model preference rules still treat grok models as models of the runtimes that list them.

     infers vendor `xai` from those prefixes; `preference_match.py` has the rule `grok>=4.6`; the fixtures hold the names.

## Boundaries

**In scope:**
- The runtime table row, installed-CLI detection, the command builder, `build-command`, the CLI profile, the shipped docs and
  skill text, the `GROK_AGENT` scrub signal, the stale-lane message, the guard test, the dated amendments and the judge loop
  of the changed skills.
- Tests and fixtures that pin grok as a runtime.

**Out of scope:**
- Removing grok MODEL names: catalog, fixtures, vendor prefixes, preference rules stay (owner clarification 2026-11-23).
- Deleting `cursor-agents/grok-worker.md` or its pins (owner decision 2026-11-23).
- `GROK_AGENTS_HOME` and gsd-core's resolver list (a gsd-core contract).
- Dated history under `docs/superpowers/` and `.planning/`: it records what was true then and stays untouched.
- Uninstalling the grok binary or editing any host config on a machine.
- Any change to the custom-command trust gate or the custom launcher (a user's own `grok ...` command stays a custom command).
- Removing or changing any other runtime (copilot, codex and the rest).

## Constraints

- Runtime code stays stdlib-only; the stale-lane message goes through the existing load path and its atomic-write rules
  (no config write happens at load).
- No machine-specific absolute path in source, tests or assets.
- After the removal no table row has `runner=False`; whether the `runner` field, `_RUNNER_RUNTIMES` and the "has no runner
  formula" branches stay is a discuss decision (dead-code risk for vulture).
- Phases 36, 37 and 38.1 are complete; their plans, summaries and verification files stay as written (only the five
  documents of requirement 9 get an amendment line).
