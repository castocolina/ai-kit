<decisions>
## Implementation Decisions

### Runtime table and save validation
- **D-01: Delete `Runtime.runner`, `_RUNNER_RUNTIMES` and the "has no runner formula" branches.** Save validation checks that
  a lane `runtime` is a table row (`_validate_pair_fields` in `config_io.py`); `test_runtime_list_drift.py` builds its id
  sets from the table keys; `copilot`'s explicit `runner=True` goes too. *(owner answer 2026-11-23, recommended option)*
  - Evidence: no row has `runner=False` once grok is removed; `row.runner` is read by `config_io.py`, `cli.py` and
    `test_runtime_list_drift.py:90`.
  - **Reversibility:** reversible — re-adding a capability field later is a small edit to the table and its readers.

### Removed-runtime notice
- **D-02: One `REMOVED_RUNTIMES` constant in `detection.py` and one message helper.** The constant maps a removed id to the
  runtimes that reach its models (`grok` → `opencode`, `pi`, `cursor-agent`); the helper builds the removal message. Load,
  save, `build-command` and any subcommand that rejects an unknown runtime call the helper; no call site holds its own
  wording. Together with the allowlisted model names these are the only places in code that name grok as a removed runtime
  (the guard's allowlist covers them). **Own reasoning** (jev not asked): four call sites would otherwise duplicate the
  wording, and a second future removal becomes a one-line change. Ledger.
- **D-03: The stale-lane notice rides the existing legacy-note channel.** At load, `config_io.py` removes a lane whose
  `runtime` (or legacy `cli`) is in `REMOVED_RUNTIMES` before routing sees it; the notice goes through the `warn` callback
  and the once-per-process dedupe of `_emit_legacy_note` (key: file and entry), names the lane entry and the runtime id only
  (no `command` or model value, SPEC prohibition 3), the replacement runtimes, and the existing re-save text ("re-save it with
  the ai-kit-spec-config wizard or render-toml --out <file> --replace"). An id that is not in the table and not in
  `REMOVED_RUNTIMES` (for example `Grok`) keeps today's handling. **Own reasoning:** the architecture already loads legacy
  fields in memory with a note naming the entry and the re-save command. Ledger.
  - **The plan's first task pins today's behavior** for an unknown runtime id at load and at dispatch with a failing test
    (SPEC requirement 4 left this to discuss; it stays a plan-time check, not a guess).
  - **Reversibility:** reversible — the constant and helper are local to two modules.

### Guard test
- **D-04: The guard of requirement 8 is a new module in the arch group.** It carries its own non-vacuity class (four fixture
  violations fail, an allowlisted model line passes, a wrong root cannot pass vacuously) and is registered in the runner's
  arch set; `tests/test_gate_scope.py` enforces the registration. *(owner answer 2026-11-23, recommended option)*
  - Reversibility: reversible — moving a test module is a rename plus a runner-set edit.

### Runner template and live copy
- **D-05: Removing `GROK_AGENT` from the `cross-ai.mjs` scrub list follows the template recipe of Phase 39 plan 39-17:** bump
  the template version, re-render the project's live runner copy, re-record the shard times
  (`tests/cross_ai_selftest.py --record-times`) and re-run `make check-dogfood`. **Own reasoning:** the project's own copy must
  stay a pristine render of the shipped template, and requirement 5 needs the three scrub lists to agree. Ledger.

### Tests, fixtures and docs
- **D-06: Grok-pinning tests are deleted or inverted, never skipped.** `TestBuildGrokCommand` is deleted;
  `test_grok_agent_is_never_a_detected_host` becomes a plain unknown-signal test; the four drift exceptions and the
  `runtimes.json` grok key go; the `agent`-alias collision test, `test_cursor_agents.py` and every model fixture stay.
  **Own reasoning:** SPEC requirements 6 and 7 keep those; a skipped test would hide a regression. Ledger.
- **D-07: Docs that used grok as the custom-command example use a generic placeholder** (`my-cli -p {prompt} -m {model}`), the
  "Grok has no runner formula" paragraph of `ai-kit-spec-config/SKILL.md` is removed, `cli-profiles/grok.md` is deleted, and
  `cli-profiles/cursor.md` keeps its factual note that two CLIs ship an `agent` binary (allowlisted). **Own reasoning:** the
  custom entry is a general feature that grok only exemplified. Ledger.
- **D-08: Build order is a vertical slice.** Table row, `REMOVED_RUNTIMES`, load, save and `build-command` behavior with their
  tests first; then docs, profile and template; then the guard; then the amendments; the skill-judge loop of the changed
  SKILL.md files last.
