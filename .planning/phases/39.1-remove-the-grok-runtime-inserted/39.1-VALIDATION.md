> Per-phase validation contract for feedback sampling during execution. Source: 39.1-RESEARCH.md § Validation Architecture.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | stdlib `unittest` through `tools/run_unittest_parallel.py` (python3; uv for unit-uv, integration, e2e) |
| **Config file** | `pyproject.toml`; test groups in `tools/run_unittest_parallel.py` (regenerated listings: `python3 tools/gen_test_groups.py`) |
| **Quick run command** | `python3 tools/run_unittest_parallel.py tests.<module> [tests.<module> ...]` |
| **Full suite command** | `make test` (never two suites at once) |
| **Estimated runtime** | quick about 10-60 seconds per module set; full suite about 7-8 minutes |

---

## Sampling Rate

- **After every task commit:** the task's module list (table below) plus `tests.test_gate_scope` when the runner or a test listing changed; the commit hook runs the covering modules.
- **After every plan wave:** `make test-unit` and `make arch-test`.
- **Before `/gsd-verify-work`:** `make test`, `make e2e-docker`, `make check-dogfood` green; `make ruff pyright vulture pylint` before each code commit (the commit hook does not run pyright or vulture).
- **Max feedback latency:** 120 seconds per task-level run.
