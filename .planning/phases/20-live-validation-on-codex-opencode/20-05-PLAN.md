HIGH 5): this plan runs under `workflow.cross_ai_timeout` = 1800 s. Task 1's first command stamps
`mkdir -p tmp/p20/headless && date +%s > tmp/p20/plan05.start`. Every child is bounded and the
bounds sum below the dispatch: the smoke child `--timeout 900 --outer-timeout 930`; the `#high`
probe `--timeout 120 --outer-timeout 150`; the C-W12 inventory `run-with-timeout 120`; each of
the two signal probes `run-with-timeout 200` (`--timeout 170 --outer-timeout 185`): 930 + 150 +
120 + 400 = 1600 s. Before every child: `remaining = 1800 - (now - start)`; when the child's bound
plus 60 s exceeds `remaining`, it is not started: the executor commits what passed, records
`budget exhausted before <command>` in the SUMMARY and stops, and the orchestrator re-dispatches
once for the rest. Any command above about 120 s runs in the background with its output in a
`tmp/p20/` log polled every 30-60 s; never one foreground call longer than the host tool's own
command timeout. A full retry of the smoke inside the same dispatch only after a fast failure
(`elapsed=` below 300 s), otherwise the task records the probe verdict and stops. A killed or hung
child is probed with a short foreground run that polls output growth before any retry (user
memory rule). A skipped gate is never reported as passed. Every probe runs under its own
`run-with-timeout`, so a parent deadline never leaves a detached probe behind.
Re-dispatch and shell state (plan-check W2/W3): the budget is per dispatch. When this plan's
SUMMARY already records `budget exhausted before`, the first command of the new dispatch
overwrites `tmp/p20/plan05.start` before anything else, and completed tasks are not re-run.
Shell variables do not survive between commands, tasks or dispatches. Every value a later
command needs (a model id, the `--scratch-root` arguments, a pid) is written to a file under
`tmp/p20/` when it is derived and read back with `$(cat <file>)` in each later command. A
command never relies on a variable set by an earlier command.
