host-signal scrub, record every status line, and assemble `20-SMOKE-CODEX.md` and
`20-SMOKE-OPENCODE.md`: the names-only env lists (D-05 input), the host-written smoke evidence

deferred-in probes (codex event types, CR-03/CR-04 signals, C-W12 enumeration).

everything that can break is found and fixed headless first; the interactive scripts (20-06) then
only confirm. These files say "headless" in their title and never claim EVAL acceptance.
Output: two evidence files, raw outputs under gitignored `tmp/p20/headless/`, the SUMMARY with the
process proof.

Rules binding every task: the runner runs from the repo root with `--no-preamble`; the host's cwd is
this checkout; real applies happen only on the smoke's scratch projects (19 D-03); the host CLIs use
their real auth through the real HOME while every gsd install inside the smoke uses the throwaway
HOME (D-09); nothing under `~/.codex`, `~/.config/opencode`, `~/.pi`, `~/.cursor` or `~/.gsd` is
read, listed or hashed by the executor beyond the harness's own allowlist guard; the user's opencode
managed service is never stopped or restarted; no `--host` flag inside the hosts (detection is part
of the evidence). D-04: a product defect found here is fixed in-phase only when it is one Python
module with a regression test; otherwise it is recorded and becomes a decimal phase. A harness
defect is fixed in `tests/gsd_curated_eval.py` with its test and the run repeated.
