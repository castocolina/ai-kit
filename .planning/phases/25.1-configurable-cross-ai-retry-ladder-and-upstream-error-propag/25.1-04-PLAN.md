<objective>
Pass the upstream error through verbatim and safely (SPEC R4; D-16, D-17): the runner extracts
the matched error line or event and its structured retry fields from the raw capture, redacts the
body with one extended redactor, caps it by code points, and prints it as labelled upstream data
after the report line. It never interprets a reset time and never changes a wait from it.

Purpose: QTA-09. The waiting agent needs the router's own words (`reset after 4h 15m`,
`retry_after` 15303) to infer when to come back; the runner must not leak keys or ids doing it.
Output: runner changes with pure and black-box self-tests, one commit per task.

Budget note: the estimate (110000 tokens) is above the 100000-token smart zone; the overage is
accepted (one runner file, three tasks that share the redactor and report path, one plan per wave
limits the blast radius).

   `.planning/scripts/cross-ai.mjs` with full permissions and `AI_KIT_REFUSE_REAL_HOME=1` exported;
   they commit once per task unless a task says otherwise. `executor: orchestrator` plans open with
   a guard line and are never dispatched.

   `~/.codex`, `~/.pi`, `~/.gsd` files. Tests use temp dirs and synthetic content; sentinel keys are

8. Never switch harness, provider or model (owner rule). Never `--no-verify`, never stash, never
