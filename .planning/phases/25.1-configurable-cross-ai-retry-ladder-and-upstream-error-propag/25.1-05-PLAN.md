<objective>
Make the error catalog evidence-labelled data the owner can extend (SPEC R5; D-05, D-06): a JSON
file in the skill compiled into the runner's `<patterns>` block by a generator with a drift test,
new `tier`, `route` and `provider` columns, OmniRoute's reason codes as rows of their own, every
25.1-EVIDENCE.md sample as a fixture, and an owner overlay validated row by row.

Purpose: QTA-10. A status code alone must never decide a class (Kimi's 403 is a usage limit; a
router 402 can reset in 2 minutes; `Combo has no executable targets` matched nothing in Phase 25).
Output: one data file, one generator, one test module, runner changes, one commit per task.

One row schema (plan review 2026-10-25): the runner's `validateRow` is the only row validator. It
must validate overlay rows anyway, and its self-test cases refuse a bad shipped row; the Python
generator only loads, renders, splices and checks drift.

Budget note: the estimate (120000 tokens) is above the 100000-token smart zone; the overage is
accepted (the data file, its generator and the runner's reader land together, and one plan per
wave limits the blast radius).

   `~/.codex`, `~/.pi`, `~/.gsd` files. Tests use temp dirs and synthetic content; sentinel keys are

   reset the tree; a claim that a failure is pre-existing is checked against `git stash`-free
   evidence (a run on the parent commit in a temp worktree) before it is written down.
