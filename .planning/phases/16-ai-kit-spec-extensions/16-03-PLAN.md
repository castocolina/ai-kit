<objective>
Version both ai_kit_spec caches (runtimes.json and model-catalog.json) so that a missing or older
`schema_version` counts as stale under `--if-stale` regardless of TTL, so the 30-day caches written
before this phase (they lack codex/claude model lists and the new catalog fields) get one
successful automatic refresh; a refresh that fails stays stale and is retried on the next
`--if-stale` run. No manual deletion is needed.

Purpose: 16 D-12. Without it, existing caches stay "fresh" for up to 30 days and never pick up the
new enumeration or fields. It also establishes the reserved `_meta` object in model-catalog.json
that plan 16-04 uses to record models.dev's anthropic ids, and the `cached_runtimes` skip-test
variable that 16-04 extends with a claude catalog-freshness condition.
Output: version constants and helpers in `detection.py` and `model_catalog.py`, schema-aware
`--if-stale` in `cli.py`, `_meta`-preserving catalog writes, tests (including regression tests in
the two sibling skills that read model-catalog.json), an AGENTS.md contract bullet and a
design-spec erratum.

Cache-write concurrency (review cycle 1, recorded so nobody over-claims it): `cache_write_json`
gives single-writer atomic replacement only (one fixed `<path>.tmp` + `os.replace`). Two
simultaneous writers are UNSUPPORTED — they share that `.tmp` path. This plan does not change
`cache.py` and must not describe concurrent writes as safe or "last-writer-wins" anywhere (code
comments, docs, SUMMARY).

Locked decisions honored here (from .planning/phases/16-ai-kit-spec-extensions/16-CONTEXT.md):
16 D-12 (add `schema_version` to runtimes.json and model-catalog.json; missing or older version is
stale under `--if-stale` whatever the TTL; reversible). Claude's discretion (recorded here): the
representation is an integer, current value 2 for both files (pre-Phase-16 files implicitly
version 1); in runtimes.json it is a top-level key; in model-catalog.json it lives in a reserved
top-level `_meta` object because every other top-level key there is a `provider/model` entry and
existing readers iterate them (a bare integer at the top level would crash `current_candidate_keys`
and `_find_existing_key_for_runtime`, which call `.get` on every value). The check lives in the
cli.py command bodies, never inside cache.py. `cache_is_stale` is a generic mtime/TTL helper
whose only callers are the two `--if-stale` skip tests in cli.py (`detect-runtimes` and
`fetch-model-catalog`). `cache.py` also backs `cache_write_json`,
which many writers share: cli.py (runtimes, fetch-meta, catalog and the `probe-quota` quota
write), `dispatch.py` (`write_resumable_state`), and the two execute adapters (`ai_kit_spec_gsd`'s
`gsd_config.py` writes and quota write, `ai_kit_spec_superpowers`'s quota write). `quota.py`
itself imports only `cache_base`. Keeping both helpers generic avoids touching any of those
writers.
