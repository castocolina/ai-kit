<objective>
Give catalog entries an optional `image_input` boolean, sourced exactly in the 16 D-09 order:
models.dev `modalities.input`, then `opencode models --verbose` for opencode ids with no models.dev
statement, otherwise absent (unknown) and never written as false — while every cache written before
this change keeps loading.

Purpose: SPEC-03 (`image_input` half; the `reasoning_modes` half landed in 16-01). Phase 17's vision
rule (`gsd-ui-auditor`, `gsd-dom-verifier` must have `image_input`) consumes this field.
Output: `image_input` and its provenance field `image_input_source` in `_FIELD_TYPES`, models.dev
extraction in `cli.py`, an opencode `--verbose` parser plus fixture in `detection.py`,
provenance-aware runtime-metadata plumbing, and tests.

Field-level provenance (addresses review cycle 2 MEDIUM "the cache does not remember which source
supplied `image_input`"). Without it, a value that came from opencode runtime metadata is copied
forward on a fetch-skipped run as if models.dev had stated it, and `_apply_runtime_meta` (default
`runtime_wins_image_input=False`) refuses to replace it, so a True -> False runtime change is
lost in a field Phase 17 uses as an eligibility gate. Fix chosen: every written `image_input`
carries `image_input_source` (`models_dev` or `opencode`). A skipped or failed models.dev fetch
carries forward only a `models_dev`-sourced value. A runtime-derived value, or one with no source
(for example confirmed by an older wizard run), is left for the current opencode reading to
replace. The new field is optional, type- and value-checked, and absent from
`_MANDATORY_CATALOG_FIELDS`, so every cache written before it still loads (SPEC-03). The
validator also enforces the pairing (addresses review cycle 3 "schema validation does not
enforce provenance/value co-presence"): a non-null `image_input_source` is rejected unless
`image_input` is a bool. `confirm-catalog-entry` persists whatever `validate_catalog_entry`
accepts, so the validator is the guard against orphan provenance. A legacy `image_input` with
no source is still accepted. The D-09
order is unchanged: models.dev statements still win over runtime readings. Runtime `image_input`
is read only from `clis.opencode`, because D-09 names `opencode models --verbose` as the only
runtime source, so the `opencode` label is always accurate.

Locked decisions honored here (from .planning/phases/16-ai-kit-spec-extensions/16-CONTEXT.md):
16 D-09 (optional `image_input: bool`; source 1 models.dev `modalities.input` contains `image`;
source 2 `opencode models --verbose` for opencode-routed ids with no models.dev match, e.g.
`router-env/*`; source 3 absent = unknown, never written as false; add to `_FIELD_TYPES`; cached
entries without the field still load), 16 D-07 (real binary, argv list), 16 D-06 (opencode id list
behavior unchanged). Interpretation recorded here: "never written as false" applies to the
no-source case; an explicit source statement of "no image input" (models.dev input list without
`image`, or opencode `capabilities.input.image: false`) is recorded as `false` because it is a real
statement, not a guess. Observation, not implemented (D-09 fixes the source list): `codex debug
models` also reports per-model `input_modalities`; codex ids get `image_input` from models.dev's
openai provider instead.
