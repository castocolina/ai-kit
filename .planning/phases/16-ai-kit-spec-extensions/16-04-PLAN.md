<objective>
Make `detect-runtimes` enumerate claude with the hybrid source 16 D-04 locks in: hardcoded aliases,
full model ids taken from models.dev's anthropic provider through the model-catalog refresh path,
and a small, dated, clearly labeled fallback list when no catalog data exists — without ever
executing claude.

Purpose: SPEC-02 (claude half). Phase 17 needs claude host models (aliases for tier slots, full ids
for scoring). Claude Code has no list-models command (`claude --help`: `--model` takes an alias or a
full name), so the full ids must come from the catalog.
Output: claude constants, `claude_runtime_fields` and `claude_runtime_is_current` in
`detection.py`, a lazy `catalog_fn` hook on `build_runtimes_snapshot`, a catalog-aware
`detect-runtimes --if-stale` skip test, anthropic-id recording in `fetch-model-catalog`, tests, and
a design-spec erratum describing the runtimes shapes Phase 17 consumes.

Catalog -> runtimes freshness edge (addresses the review cycle 1 HIGH shared by 16-03 and 16-04):
the approved refresh order is `detect-runtimes --if-stale` THEN `fetch-model-catalog --if-stale`
(design spec §3). On the first upgraded run, detection happens before the catalog holds any
anthropic ids, so it writes the dated fallback; the fetch then records the ids; and, without a
dependency edge, the now-fresh, current-schema runtimes.json would make every later
`detect-runtimes --if-stale` skip for up to 30 days, stranding claude on the fallback. Fix chosen
here: runtimes.json's claude portion is DERIVED from model-catalog.json `_meta`, so the catalog is
an input of the runtimes cache. `detect-runtimes --if-stale` therefore also re-detects when the
cached claude entry differs from what the current catalog yields (`claude_runtime_is_current`).
Rejected alternatives: re-stamping `clis.claude` from inside `fetch-model-catalog` (it would
write into its `--runtimes-json` INPUT, which a wizard may have narrowed to a custom path), and
fetching the catalog before detection (catalog discovery needs the runtimes snapshot first). The
tracer test runs the REAL order and ends with `models_source: catalog`.

Locked decisions honored here (from .planning/phases/16-ai-kit-spec-extensions/16-CONTEXT.md):
16 D-04 (hybrid: aliases `fable`, `opus`, `sonnet`, `haiku` hardcoded; full ids from models.dev's
`anthropic` provider via the catalog refresh path; a small DATED fallback list labeled as a dated
fallback, not a live list), 16 D-07 (real binaries only; for claude nothing is executed at all).
Orchestrator resolution 2: the dated fallback is an in-module constant (dated, labeled fallback,
not live). Design choice recorded here: aliases are stored in a separate `aliases` key, not inside
`models`, so catalog discovery (which walks every `models` array) never tries to match a bare alias
against models.dev and never mints bogus `anthropic/opus`-style keys. The anthropic ids are stored in
model-catalog.json's reserved `_meta` object created by plan 16-03, not as discovered candidates,
so a wizard run that narrows its runtimes snapshot to chosen models is never polluted with every
anthropic model.
