## 21.3-01

### Summary
The tracer-first structure is sound: it connects setup wiring to the stored command, the Claude envelope and the shared advisor before expanding command recognition and large-read reporting. The replan repairs the specific quoted-operator and comment cases identified in cycle 1, but the new lexer still has a reproducible false-positive case.

### Strengths
- **The command-quoting regression now tests the actual configured command.** The tracer uses an install path containing a space and executes the stored string through `sh -c`, rather than bypassing quoting with an argv list. See `.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-01-PLAN.md:185`.
- **The output gate preserves the existing envelope while excluding permission fields.** The proposed optional arguments extend the current `emit` mechanism rather than introducing a second writer. - **Cycle-1 comment handling is concretely covered.** The table includes a comment followed by a subsequent command, an embedded `#`, and a quoted operator. See `.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-01-PLAN.md:275`.

### Concerns
- **MEDIUM — Non-POSIX tokenization mistakes an escaped operator for a pipeline.** The prescribed lexer and separator rule tokenize `echo \| grep x` as `echo`, `\`, `|`, `grep`, `x`; the separator rule then treats `grep` as executable although it is only an argument to `echo`. I reproduced this with the specified `shlex` settings. The current table does not cover escaped operators. See `.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-01-PLAN.md:205–217,275`.

### Suggestions
Preserve escape information when recognizing operators, and add `echo \| grep x → []` alongside the quoted-operator regression. This needs a focused tokenizer correction, not a general Bash parser.

### Risk Assessment
**MEDIUM.** Wiring and output safety are well covered; command recognition can still produce incorrect advice for valid shell syntax.
