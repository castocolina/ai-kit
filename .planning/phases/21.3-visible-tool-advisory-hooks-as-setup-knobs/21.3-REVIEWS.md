## 21.3-01

**Summary:** The end-to-end tracer and shared output gate provide a strong foundation. The main weakness is the prescribed shell lexer: its token-processing rules lose distinctions needed to meet the quoted-text and multiline-command guarantees.

### Strengths
- The output-gate test checks exact key sets, making permission decisions and input rewrites structurally difficult to introduce. See [`21.3-01-PLAN.md:188–193`](.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-01-PLAN.md#L188-L193) and [`21.3-01-PLAN.md:267–272`](.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-01-PLAN.md#L267-L272).
- Large-read tests cover thresholds, ranged reads, binary input, special files and bounded counting rather than just a happy path. See [`21.3-01-PLAN.md:313–334`](.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-01-PLAN.md#L313-L334).

### Concerns
- **MEDIUM — Quoted operators become command separators.** The algorithm classifies a token containing only `|&;()` as a separator after POSIX `shlex` has removed its quotes. Thus `echo "|" grep x` produces tokens `echo`, `|`, `grep`, `x` and incorrectly treats `grep` as a command. This contradicts the quoted-word guarantee in [`21.3-SPEC.md:77`](.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-SPEC.md#L77). The problematic algorithm is prescribed at [`21.3-01-PLAN.md:204–210`](.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-01-PLAN.md#L204-L210).
- **MEDIUM — Newline replacement breaks shell-comment boundaries.** With default `shlex` comment handling, replacing newlines before lexing turns `echo a # comment\ngrep x f` into one line whose comment consumes the later `grep`. Wrapper options with arguments also remain unsupported: skipping `-u` in `sudo -u root grep x f` leaves `root` in command position. Neither case appears in the extensive table at [`21.3-01-PLAN.md:268`](.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-01-PLAN.md#L268).

### Suggestions
- Preserve enough lexical information to distinguish quoted punctuation from shell operators.
- Add focused cases for quoted operators, comments followed by another command, and wrapper options that consume arguments. Explicitly document unsupported wrapper forms rather than implying general support.

**Risk Assessment: MEDIUM.** Errors produce misleading or missing advice rather than changing commands, but affect ordinary shell syntax central to ADV-03.

## 21.3-03

**Summary:** Locking the read-modify-write cycle and recording throttled calls are sound choices. However, the fallback identity and state-validation rules do not fully support the advertised degradation behavior.

### Strengths
- Recording an advice ID even when throttled prevents the post-call hook from undoing the frequency policy. The advisor and reminder branches explicitly implement this at [`21.3-03-PLAN.md:173–176`](.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-03-PLAN.md#L173-L176) and [`21.3-03-PLAN.md:215–219`](.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-03-PLAN.md#L215-L219).
- The concurrency test verifies both the final count and number of emitted messages, catching lost updates that an atomic-write-only test would miss. See [`21.3-03-PLAN.md:145–148`](.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-03-PLAN.md#L145-L148).

### Concerns
- **MEDIUM — Missing call IDs permanently deduplicate repeated identical commands.** `call_key()` falls back to the command hash, while the advisor skips IDs already recorded under that key. Twenty-five identical commands without call IDs therefore advance the counter only once and advise only on call 1—not 1, 11 and 21. The mechanism is explicit at [`21.3-03-PLAN.md:162–175`](.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-03-PLAN.md#L162-L175). Existing frequency tests always supply distinct IDs.
- **MEDIUM — “Mis-shaped state becomes fresh” is only partially specified.** Validation checks that `counts` and `calls` have the right container types, but not their contents. Valid JSON such as `counts: {"grep": "bad"}` can fail during increment; a malformed call-record value can fail during membership or append. The outer fail-open handler would silence advice without repairing the file. See [`21.3-03-PLAN.md:163–176`](.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-03-PLAN.md#L163-L176), compared with the stronger promise at [`21.3-03-PLAN.md:29`](.planning/phases/21.3-visible-tool-advisory-hooks-as-setup-knobs/21.3-03-PLAN.md#L29).

### Suggestions
- Separate occurrence counting from correlation: missing IDs must not make identical future commands the same occurrence.
- Validate counter values and call-record contents, then test syntactically valid but malformed state and absent call IDs.

**Risk Assessment: MEDIUM.** The normal-ID path is well covered, but documented fallback and recovery paths can silently suppress advice.

Reminder-first records `grep`, so advisor-second stays silent. **Risk Assessment: HIGH.** The specified algorithm violates an explicit pi behavior guarantee, while the timeout test can falsely certify its safety mechanism.
