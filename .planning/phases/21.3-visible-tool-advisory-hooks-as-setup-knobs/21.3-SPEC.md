# Phase 21.3: Visible tool-advisory hooks as setup knobs — Specification

**Created:** 2026-10-18
**Ambiguity score:** 0.15 (gate: ≤ 0.20)
**Requirements:** 10 locked

## Goal

Every ai-kit hook becomes its own setup knob, with a wizard row and a headless id, through
the hook registry that Phase 21.2 introduces:
- the SessionStart tool briefing, now visible to the user;
- a PreToolUse advisor that flags `grep`/`cat`/`sed`/`find` and large reads;
- a PostToolUse reminder;
- the decision-system probe;
- the PreCompact pre-summary.

The advisors run on Claude Code and pi (opencode if a spike verifies it), name only installed
tools, never mention rtk, never decide permissions or rewrite a command, and are live-verified
in a real session.

## Background

Verified on 2026-10-18:
- **ai-kit today.**
  - `tools/hooks/detect.py` crosses five curated pairs (cat/bat, grep/rg, find/fd, sed/sd,
    ls/eza) with `shutil.which`, plus a parse of `rtk init --show`.
  - `compose_message()` names rtk in both branches.
  - `claude_session_start.py` emits only `hookSpecificOutput.additionalContext`, which the
    model sees and the user does not.
  - `tools/setup.py` wires that hook unconditionally in the wizard (`commit()` →
    `wire_hook_claude`/`wire_hook_cursor`), and headless through one boolean `--with-hooks`.
  - `tools/hooks/README.md` lists "No `PreToolUse` mechanism" as a non-goal (Phase 03 D-01,
    deferred).
  - Phase 21.2 R10 introduces the hook registry with its own row.
- **Tools on this machine:** bat 0.26.1, ripgrep 15.2.0, fd 10.5.0, sd 1.0.0 and eza are on
  PATH. `bat --plain --paging=never -l py -r 2:3 <file>` prints lines 2–3 (live check).
  rtk 0.44.1 is still on PATH; the owner considers it uninstalled, so no hook mentions it
  either way.
- **Claude Code docs** (code.claude.com/docs/en/hooks):
  - `systemMessage` is a universal field, a "Warning message shown to the user". The
    SessionStart section names no exception.
  - PreToolUse `hookSpecificOutput.additionalContext` is a "String added to Claude's context
    alongside the tool result". `permissionDecision` `"allow"` skips the permission prompt, so
    advice must omit it; "staying silent doesn't approve" a call. `updatedInput` rewrites the
    arguments.
  - PostToolUse receives `tool_input` and `tool_response` and also accepts `additionalContext`.
  - Each string field is capped at 10,000 characters.
  - The PreToolUse context reaches the model next to that call's result. The size report on
    a large Read therefore informs the next read; it cannot prevent the current one without a
    permission decision, which stays forbidden.
- **pi 1.3.0** (installed `docs/extensions.md`): `tool_call` "can mutate input or block
  execution". `tool_result` handlers compose, "each handler seeing prior changes", and can
  change the result content.
- **opencode** (opencode.ai/docs/plugins): `tool.execute.before`/`after` exist. Only argument
  mutation is documented; whether `after` can append text to the output is unverified.

## Requirements

1. **Every hook is its own knob**: The hook registry lists `session-briefing`, `tool-advisor` (PreToolUse), `tool-reminder` (PostToolUse), `decision-probe` and `precompact`. Each has a wizard row and a headless id; install and uninstall act per id.
   - Current: The wizard always wires the SessionStart briefing. `--with-hooks` is one boolean. 21.2 adds the registry with only `precompact`.
   - Target: The wizard shows one row per registry entry, pre-checked from what is installed, else the row's default. `--with-hooks=<id,...>` wires exactly those ids. Bare `--with-hooks` wires the registry defaults. Uninstall removes only ai-kit entries, per id. An existing install that has today's SessionStart entry is read as `session-briefing` on.
   - Acceptance: e2e tests under a temporary `HOME`. Each id alone wires only its own entries. The wizard (PTY test) lists five rows. Unchecking `session-briefing` removes only that entry. A foreign entry under every event survives install and uninstall.
   - *Amended 2026-10-18 (21.3 D-04):* headless `--with-hooks=<ids>` stays additive (it never unwires), and headless per-id removal is `uninstall --hooks=<ids>`; bare `uninstall` still removes every ai-kit entry.

2. **Visible briefing, no rtk**: The SessionStart briefing emits a one-line `systemMessage` for the user (≤ 200 characters) and an `additionalContext` for the model (≤ 2,000 characters), both naming only installed tools with their useful flags. No hook output or hook script mentions rtk.
   - Current: Model-only context that names rtk.
   - Target: `detect.py` drops the rtk probe and the rtk wording. The Cursor briefing uses the same composer.
   - Acceptance: Unit tests with a fake PATH holding only `rg` and `bat` show `systemMessage` naming exactly those two and `additionalContext` carrying `bat --plain --paging=never`. With no modern tool on PATH, the output is `{}`. `rg -n -i rtk tools/hooks/` finds nothing.

3. **PreToolUse command advisor**: For a Bash call, the advisor splits the command into simple commands (pipes, `&&`, `||`, `;`). For each command word `grep`/`cat`/`sed`/`find` whose replacement (`rg`/`bat`/`sd`/`fd`) is installed, it adds one advice line with the useful flags:
   - `grep` → `rg -n`, `rg -l`, `--glob`;
   - `cat` → the Read tool or `bat --plain --paging=never -l <lang>`;
   - `sed -n 'N,Mp'` → `bat --plain --paging=never -r N:M` or a ranged Read;
   - `sed -i`/`s///` → `sd`;
   - `find` → `fd --type f --glob`.
   - Current: No PreToolUse hook exists.
   - Target: The output is only `hookSpecificOutput` with `hookEventName: "PreToolUse"` and `additionalContext`. No permission field and no argument rewrite. Exit 0 on every path, `{}` when there is nothing to say. Words inside quotes, `git grep` and already-modern tools never trigger advice.
   - Acceptance: A table test of ≥ 20 commands, including `cat f | grep x`, `echo "cat"`, `git grep x`, `rg x`, `find . -name '*.py'` and `sed -n '5,9p' f`, matches the expected advice ids. A test asserts that no output contains `permissionDecision`, `updatedInput` or `decision`.

4. **Large-read report**: On a Read call with no range, the advisor reports bytes, lines and estimated tokens (characters / 4) and suggests a ranged Read or `bat -r`. It fires when the estimate exceeds 10,000 tokens or the file has more than 2,000 lines.
   - Current: Nothing reports read sizes.
   - Target: Counting is bounded: it stops at 64 MiB and reports "≥". Unreadable paths, directories and missing files give `{}`. The advice states that it applies to the next read, since Claude Code delivers it with this read's result.
   - Acceptance: Tests: a 3,000-line file reports its line count; a 1,999-line file of 39,000 characters stays silent; a Read with `offset`/`limit` stays silent; a missing path gives `{}`; a 100 MiB sparse file reports "≥" within 1 s.

5. **PostToolUse outcome reminder**: After a Bash call that used `grep`/`cat`/`sed`/`find` with its replacement installed, the reminder adds one line that names the output size ("printed N lines, about T tokens") and the better tool. It fires only when the output is over 200 lines or the pre-call advisor did not already advise that call.
   - Current: n/a.
   - Target: Same envelope rules as R3 (PostToolUse `additionalContext` only, no `decision`, no `updatedToolOutput`). It names installed tools only.
   - Acceptance: Tests: a `grep` call already advised by the pre-call hook with 20 output lines → `{}`; the same call with 500 lines → one reminder naming `rg`; `rg` itself → `{}`; `rg` not on PATH → `{}`.

6. **Advice frequency**: The same advice id is shown on its first occurrence in a session and then on every tenth repeat. State lives in a per-session file in a private temp dir.
   - Current: n/a.
   - Target: A missing, corrupt or foreign-session state file counts as the first occurrence. The state file is 0600 in a 0700 dir, and files older than 24 h are removed.
   - Acceptance: Tests: 25 identical `grep` calls in one session advise on calls 1, 11 and 21. A corrupt state file advises and rewrites it. Two sessions keep separate counts.

7. **Host coverage**: A host-neutral advisor core drives the Claude Code hooks and a pi extension. Its `tool_result` handler appends the same advice to bash and read results; it never removes or changes existing content, and its `tool_call` handler never blocks or mutates. opencode ships an adapter only if a spike shows `tool.execute.after` can append text; otherwise the README host table records the gap. Cursor keeps its SessionStart briefing (rtk removed); its per-call advisors are a recorded gap.
   - Current: Claude Code and Cursor SessionStart only.
   - Target: `tools/hooks/README.md`'s host table has a row per host × hook with status `wired`, `gap (reason)` or `experimental`.
   - Acceptance: A unit test of the pi adapter's core entry on a recorded `tool_result` fixture appends one advice block and keeps the original content byte-identical. The README table has no empty cell.

8. **Decision-system probe hook**: A `startup` SessionStart hook runs the 21.1 client's `--probe` (≤ 3 s). It reports availability as one `systemMessage` line and one `additionalContext` line naming the usable backends and the skill. With no usable backend it emits `{}`. The knob defaults to off.
   - Current: Agents learn about the decision skill only from its description.
   - Target: It never prints a key or URL credential, and it never sends question content.
   - Acceptance: Tests with a stub probe: usable Laya → both lines name `laya`; nothing usable → `{}`; probe timeout → `{}` within 3.5 s.

9. **Fast and fail-open**: Every advisor invocation finishes in under 1 s (median under 300 ms on this machine). Any error gives `{}` with exit 0.
   - Current: The existing hooks are fail-open.
   - Target: The same `_fail_open` excepthook pattern as `claude_session_start.py`. No subprocess per call except `shutil.which`.
   - Acceptance: A timing test over 20 runs of each hook script on fixtures records median < 300 ms and max < 1 s. A forced exception still prints `{}` and exits 0.
   - *Amended 2026-10-18 (21.3 D-17):* the < 1 s / no-subprocess budget covers `session-briefing`, `tool-advisor` and `tool-reminder`. `decision-probe` runs one bounded subprocess and is held to R8's 3 s / 3.5 s budget.

10. **Live-verified in real sessions**: In a scratch Claude Code session and a scratch pi session, the advisors' text reaches the model and the briefing's `systemMessage` is visible to the user. The permission flow is unchanged. Results go to `21.3-LIVE.md`.
    - Current: Only the old briefing was live-checked (2026-10-18).
    - Target: For each host, record the hook fired, the model quoting the advice, the user-visible line, and a Bash command that needs approval still prompting with the advisor on.
    - Acceptance: `21.3-LIVE.md` has one entry per host × hook with date, host version and observed result. Any "not observed" entry is a failure, not a pass.

## Boundaries

**In scope:**
- Extending the 21.2 hook registry to all five hooks, with wizard rows and headless ids, and
  migrating the existing SessionStart wiring.
- Removing rtk from `detect.py` and the hook outputs.
- The PreToolUse advisor, the large-read report and the PostToolUse reminder.
- The per-session frequency state.
- The pi extension adapter; the opencode spike and its adapter or gap entry.
- The decision-probe hook.
- `tools/hooks/README.md`, `README.md` and the wizard texts.

**Out of scope:**
- Blocking, approving or rewriting any tool call (`permissionDecision`, `updatedInput`,
  `updatedToolOutput`, `decision: block`). The owner direction is "advisor, never a replacer".
- Config doctor's own rtk integration check (`tools/config_doctor_*`). It is not a hook and
  reports rtk only when present. *(amended 2026-10-18, 21.3 D-15: one citation-only edit is in scope — the check's `source`/`why` text quotes `tools/hooks/README.md`'s rtk non-goal, which R2 removes, so it is repointed to Phase 03 CONTEXT D-02 without changing the check's behavior)*
- Cursor per-call advisors. Cursor is secondary; the gap is recorded (R7).
- Advice for tools beyond the four pairs plus large reads. `ls`/`eza` stays in the briefing
  only.
- Codex hooks. Codex is secondary and has no verified hook route here.

## Constraints

- Hook scripts are stdlib-only, run with `python3 -S`, and are fail-open. The pi and opencode
  adapters are thin shims over the Python core with no npm dependency.
- Config writes are atomic and keep every foreign entry. Uninstall touches only entries whose
  command points at ai-kit's hook scripts.
- Live checks run with scratch config dirs, never the user's real `~/.claude`, `~/.pi` or
  opencode config.
- The Claude Code delivery placement of PreToolUse context ("alongside the tool result") is
  documented and gets confirmed live (R10). If live behavior differs, this SPEC is amended.

- [ ] The pi adapter appends advice and keeps the original result byte-identical; the README host table has no empty cell.

- [ ] `21.3-LIVE.md` records each host × hook as observed, permission prompts included.

- [ ] MUST NOT: no hook names a tool that is not on PATH (test).
- [ ] MUST NOT: no hook output or hook script mentions rtk (test).
