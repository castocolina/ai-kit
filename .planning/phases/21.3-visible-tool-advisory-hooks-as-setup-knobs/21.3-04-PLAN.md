<objective>
Bring the advisor and the reminder to pi through two thin `tool_result` extension files over the
same Python core, appending advice as a separate text block and never touching the call or the
original result (SPEC R7; D-08, D-09, D-13; node-run tests skipped only without node, per D-18).

Purpose: pi is a primary host and has a documented, composable `tool_result` channel that reaches
the model (ADV-03, ADV-04).
Output: two pi shims, the core's `pi` entry, one recorded fixture, a harness branch, node-run
tests beside the 21.2 shim tests, and the 21.2 shim tests widened to the three pi files.

Rules binding every task: the plan 21.3-01 rules. The shims use only erasable TypeScript (type
annotations and `import type`; no enums, namespaces or parameter properties), no npm dependency,
no runtime import from a host package; each is one self-contained file because pi loads every
file in `extensions/`, so its `corePath`/`runCore` helpers are repeated on purpose (a comment
says so, as in `tools/hooks/pi/ai-kit-precompact.ts`). Node tests run `node` from PATH (no
`npx`, no install) and skip only when node is absent or lacks type stripping; no test runs pi.
Every node test sets a fresh `XDG_RUNTIME_DIR`, `HOME` and `XDG_*` under `tempfile.mkdtemp()`,
`AI_KIT_PYTHON=sys.executable`, and `PATH` = a temp bin of tool stubs.
</objective>
