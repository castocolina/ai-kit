## Findings

### WR-01: Substitution detection exceeds the hook’s time budget on bounded input
**File:** tools/hooks/advisor_core.py:177  
**Issue:** `_SUBST_RE` uses two greedy repetitions around backreferences, causing quadratic backtracking. A Bash command constructed as `"sed s" + "/" * 16000 + "! f"` took 1.10–1.11 seconds through `claude_tool_advisor.py` in three read-only reproductions. This happens even with an empty PATH, because `_sed_line()` runs before checking whether a replacement is installed. It exceeds R9’s local-fixture budget and delays the host call.
**Fix:** Replace the substitution expression with a linear delimiter scan, and skip edit classification when `sd` is unavailable. Add this adversarial command to the timing tests.

### WR-02: A command consumes arguments belonging to later pipeline commands
**File:** tools/hooks/advisor_core.py:127  
**Issue:** `_command_words()` yields `tokens[index + 1:]`, including every subsequent command rather than just the current command’s arguments. For example, `sed '/x/d' f | echo 's/a/b/'` incorrectly produces `sed-edit` advice recommending in-place editing, although the sed command only filters lines. Likewise, `sed '/x/d' f; echo -n '5,9p'` incorrectly produces range advice. Quoted arguments in unrelated commands therefore trigger advice against R3.
**Fix:** End each argument slice at the next actual command separator or comment boundary. Keep the existing quote-preserving lexer required by amended D-06, and add both examples as negative tests.

### WR-03: Assignment prefixes hide ordinary grep calls
**File:** tools/hooks/advisor_core.py:117  
**Issue:** The parser skips assignments only before wrappers, not after them. Consequently, `env FOO=1 grep x f` and `sudo env FOO=1 grep x f` produce no advice with `rg` installed. Separately, non-POSIX lexing splits `FOO='x y' grep x f` into assignment fragments and also misses grep. These are ordinary assignment forms covered by D-06’s stated assignment/wrapper handling, not the documented `sudo -u` shortcut.
**Fix:** Consume assignments and wrappers iteratively, and preserve joined quoted/unquoted fragments within assignment words without turning quoted punctuation into separators. Add these cases to the command table; do not simply revert amended D-06 to `posix=True`.

### WR-04: pi drops the output-size reminder when the advisor runs first
**File:** tools/hooks/advisor_core.py:415  
**Issue:** On a first pi grep result containing 500 lines, the advisor emits ordinary command advice and records `SHOWN`. The reminder then constructs its output-size message but discards it because `single_block` is true. A direct reproduction returned an advisor line followed by `None`, so no block reported the 500-line output. The existing deduplication tests accept this because they assert one block, not that the block preserves the outcome reminder.
**Fix:** For pi, include the large-output reminder in the single selected block, regardless of handler order. This preserves locked D-13’s deduplication rather than requiring two appended blocks. Assert the output-size text in both handler-order tests.

### WR-05: The cache fallback never persists state on a fresh HOME
**File:** tools/hooks/precompact_core.py:844  
**Issue:** When `XDG_RUNTIME_DIR` is unset, `private_dir()` falls back to `~/.cache` but opens that directory without creating it. On a fresh HOME without `.cache`, it returns `None`; `with_state()` then creates fresh in-memory state for every invocation. Repeated grep calls all advise instead of advising on calls 1, 11 and 21, and pre/post correlation also disappears. A read-only reproduction with a nonexistent fallback base returned advice on all three calls.
**Fix:** Safely create the cache fallback base when absent before creating and validating the private `ai-kit/advisor` directories. Keep the existing ownership and symlink checks. Add a frequency test with no `XDG_RUNTIME_DIR` and an initially absent cache directory.

### WR-06: Shared-wrapper import failures bypass fail-open handling
**File:** tools/hooks/claude_tool_advisor.py:10  
**Issue:** The new wrappers import `claude_session_start` before installing `_fail_open`. If that sibling is missing, unreadable, or contains an import-time error, the advisor exits 1 with a traceback and no JSON. Injecting `ModuleNotFoundError` for that import reproduced exit 1 and empty stdout. The same ordering exists in `claude_tool_reminder.py`, `claude_decision_probe.py`, and the refactored Cursor wrapper. Tests inject failures in later-loaded core modules, so they miss this branch. This violates locked D-17’s requirement to establish the handler before fallible imports.
**Fix:** Install a minimal local fail-open handler before importing the shared wrapper, or guard that import with an equivalent `{}`/exit-0 fallback. Extend failure-injection tests to cover this earliest sibling import.

### IN-01: Wizard documentation reverses the meaning of an unchecked hook
**File:** README.md:100  
**Issue:** The README says unchecked rows “follow the row’s recorded default.” In `apply_hook_selection()`, unchecked ids are instead uninstalled from every detected installed host. For example, unchecking the default-on `tool-advisor` removes it; it does not preserve its default-on state. This is a documentation error, not a request to change locked D-04 or the per-id removal behavior.
**Fix:** Say that defaults determine initial checkbox selections, checked rows are installed, and unchecked rows remove the corresponding ai-kit hooks.
