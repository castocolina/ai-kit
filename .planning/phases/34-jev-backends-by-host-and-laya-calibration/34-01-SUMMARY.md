# Phase 34 Plan 01: jev config copy and [jev] settings Summary

**jev-fast-decision copies Phase 33's config.toml reader and splicer (54 AST-pinned definitions) and adds `config_set`, the knob and the Laya URL order over the `[jev]` table**

## Accomplishments

- `jev_config.py` holds 54 definitions copied verbatim (10 from `config_io.py`, 42 from `toml_splice.py`, 2 from `cache.py`) and pinned by `ast.dump` parity.
- `config_set` writes only the user `[jev]` table through `set_table` and `publish`. Other bytes, comments and CRLF survive. A broken or unwritable file returns `config_unwritable` with nothing written.
- `config_set` refuses bad values with `invalid_value:<key>` or `unknown_key`. A `laya_url` with a user name, password, query or fragment is refused.
- `knob` returns the on/off decision with its source: `GSD_PATH_JEV` wins both ways, then `[jev] enabled` (project over user), then on by default with `needs_answer`. A broken file or a non-boolean `enabled` fails closed.
- `laya_url_setting` returns the URL in the order env, project, user, default. An empty string is the declined answer.
- `test_config_dir_parity.py` gains `test_jev_config_copy` in the shared user-dir table.
