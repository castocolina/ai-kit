<objective>
Deliver the pre-summary to pi, the one host where it replaces the summarization call: a thin
TypeScript extension over the core's `pi` entry (SPEC R6, R8; D-07, D-08).

Purpose: pi's `session_before_compact` result replaces the model-written summary, so this is where
the saving can be real; it must never lose earlier-compacted history or fail a compaction
(PCH-01).
Output: the shim, the `pi` entry and `main`, unit and node e2e tests, the README pi row.

Rules binding every task: the plan 21.2-01 rules. The shim uses only erasable TypeScript (type
annotations and `import type`; no enums, namespaces or parameter properties) so node's type
stripping and pi's loader both run it; it has no npm dependency and no runtime import from pi's
package. Node tests run `node` from PATH (no `npx`, no install) and skip only when node is absent
or lacks type stripping; no test runs pi itself. Live pi behavior is the orchestrator's S3 check
staged in 21.2-07.
</objective>

<interfaces>
pi 1.3.0 (installed docs and types, read at planning time; no pi run):
- Extension module: a default-export function receiving `pi`; `pi.on("session_before_compact",
  async (event, ctx) => result)`. `event`: `{preparation, branchEntries, customInstructions?,
  reason: "manual"|"threshold"|"overflow", willRetry, signal}`. `preparation`:
  `{firstKeptEntryId, messagesToSummarize, turnPrefixMessages, isSplitTurn, tokensBefore,
  previousSummary?, fileOps: {read: Set<string>, written: Set<string>, edited: Set<string>},
  settings}`. Result `{compaction: {summary, firstKeptEntryId, tokensBefore, details?}}` replaces
  the default summary; `undefined` keeps the default flow.
- `ctx.sessionManager` (ReadonlySessionManager) has `getSessionId()`, `getSessionName()` and
  `getCwd()`.
- `AgentMessage` roles: `user` (`content` string or `text`/`image` blocks), `assistant`
  (`text`, `thinking`, `toolCall` {`name`, `arguments`} blocks), `toolResult` (`toolName`,
  `content` blocks), `bashExecution` (`command`, `output`, `excludeFromContext?`), `custom`
  (`content`), `branchSummary` (`summary`), `compactionSummary` (`summary`); unknown roles must be
  tolerated.
- pi's own file lists (`computeFileLists`/`formatFileOperations`): modified = edited plus
  written, read-only = read minus modified, both sorted, formatted as `<read-files>\n...\n</read-files>`
  and `<modified-files>\n...\n</modified-files>`. pi does not carry file lists from an
  extension-provided summary into later compactions, so they must be inside the summary text.
- pi loads every direct `.ts`/`.js` file in `extensions/`, so the shim cannot have a helper
  file beside it.
