# Phase 21.2: PreCompact pre-summary hook via the decision system - Context

**Gathered:** 2026-10-18 (assumptions mode, after 21.2-SPEC.md)
**Status:** Ready for planning

<domain>
## Phase Boundary

The phase delivers:
- a host-neutral, stdlib pre-summary core: chunk, classify through the 21.1 client loopback-only,
  build an extractive summary of ≤ 9,500 characters;
- adapters for Claude Code (PreCompact prepares, compact-SessionStart injects), pi
  (`session_before_compact` returns the summary) and opencode (`experimental.session.compacting`
  adds context);
- a per-host measurement spike;
- the hook registry, with `precompact` as its first rows.

The SPEC (10 requirements; R6/R10 amended 2026-10-18) is the locked WHAT. Replacing Claude
Code's own summary, remote backends for transcript content, and the 21.3 advisors are outside.
</domain>

<decisions>
## Implementation Decisions

### Core and the client
- **D-01: The core calls the 21.1 client `jev_review.py` directly as a subprocess, never
  through `decide.py`.**
  - It finds the client from its own realpath at
    `<install>/skills/jev-fast-decision/scripts/jev_review.py` (env override for tests). It runs
    `--probe` once, pins `JEV_BACKEND` to the first usable row with `remote: false`, scrubs
    inherited `JEV_*`/`GSD_PATH_JEV*` (above all `JEV_ALLOW_REMOTE`) from the child env, and
    sets `JEV_CALLER=ai-kit-precompact`.
  - Evidence: `decide.py:224-233` rejects fields over 1,500 characters, code fences and
    secret-shaped runs, so nearly every transcript chunk would be rejected. 21.1 D-10 and D-09
    give the probe and scrub contract.
  - **Own reasoning** (Laya hardcode_laya 0.41 fb): a hardcoded name breaks the 21.1 R2 table
    seam. 21.1 CONTEXT amended.
- **D-02: One client process per chunk**, each with timeout = min(remaining budget, per-call
  cap), and the budget checked before each call (R8). A chunk with no answer counts as `keep`.
  - A single process for all chunks would lose every answer on timeout.
  - Laya per_chunk_process 0.49 fb, same choice.
- **D-03: The chunk size limit is a named constant set by the spike from Laya 0.4.2's measured
  truncation point**, with margin. It is not guessed, and it is not `decide.py`'s 1,500.
  - Laya spike_measured 0.42 fb, same choice. Open research item.
- **D-04: The core is `tools/hooks/precompact_core.py`** with one entry per host:
  - `claude` reads `transcript_path`;
  - `pi` reads the preparation JSON on stdin;
  - `opencode` reads the session messages JSON on stdin.
  - All host-shape conversion stays in Python, so `make test` covers it and the TS shims only
    pass data through. Fail-open uses the `_fail_open` excepthook of `claude_session_start.py`.
  - Analyzer Confident.

### Host adapters
- **D-05: Claude Code is one script, `tools/hooks/claude_precompact.py`, branching on
  `hook_event_name`.**
  - It is wired as two entries: `PreCompact` (matcher `manual|auto`) and `SessionStart`
    (matcher `compact`). These stay separate from the briefing entry, so marker-based unwire
    never removes both.
  - The transcript reader copies `tools/status-line.py`'s boundary rule (`type: system`,
    `subtype: compact_boundary`, `probe_transcript_compaction`, lines 965-998) as a stdlib copy
    pinned by a shared-fixture test. The status-line module's hyphenated name makes it
    unimportable (the `SEGMENT_DEFAULTS` precedent).
  - Each hook string is measured on its own (docs, 2026-10-18), so the briefing and the
    pre-summary do not share the 10,000-character cap.
  - Analyzer Confident.
- **D-06: The manual `/compact <instructions>` variant is measured, not built ahead.**
  - The docs say the user's text arrives only as `custom_instructions`. Nothing shows the
    summarizer can read a file the text names.
  - Expected Claude verdict: non-positive (the hook adds time and injected characters while
    Claude's own summary still runs), so the Claude knob likely ships default off (R9). This is
    a risk recorded for the planner, not a decision to skip measuring.
- **D-07: The pi shim is one self-contained file, `tools/hooks/pi/ai-kit-precompact.ts`,
  symlinked into `${PI_CODING_AGENT_DIR:-~/.pi/agent}/extensions/`.**
  - It finds the core from its own realpath. It spawns Python with `node:child_process` (stdin
    JSON, bounded timeout, the event's `signal`) and returns
    `{compaction:{summary, firstKeptEntryId, tokensBefore, details}}`; on any failure it
    returns `undefined`.
  - Evidence: `pi.exec` has no stdin option (`dist/core/exec.d.ts`). pi loads every direct
    `.ts` in `extensions/` (`docs/extensions.md:46`), so no helper file may sit beside it.
  - Laya child_process_stdin 0.52 fb, same choice.
  - Spike: whether jiti reports the symlink path or the realpath.
- **D-08: The pi entry includes `preparation.previousSummary` (oldest chunk, always kept) and
  `turnPrefixMessages`.**
  - When the previous summary plus the newest kept chunk cannot fit the budget whole, it
    returns nothing.
  - Evidence: pi's default flow merges the previous summary (`docs/compaction.md:43-48,
    104-121`). A replacement built only from `messagesToSummarize` drops all earlier-compacted
    history on the second compaction, which is data loss. SPEC R6 amended.
  - **Own reasoning** (Laya defer_to_default 0.50 fb): deferring would protect the data but
    remove the saving on every later compaction; the fail-safe keeps both.
- **D-09: The opencode plugin is one file, `tools/hooks/opencode/ai-kit-precompact.ts`,
  symlinked into opencode's global `plugins/` dir.**
  - The dir resolves as `OPENCODE_CONFIG_DIR` > `XDG_CONFIG_HOME/opencode` >
    `~/.config/opencode`, the same precedence as `tools/config_doctor_checks.py:69-86`.
  - The hook input carries only `sessionID`, so the plugin fetches messages through the
    injected SDK `client`. It pushes to `output.context` once and never sets `output.prompt`.
  - A failed spike (opencode v2.0.31 against the local 1.18.5 plugin types) records a gap
    instead.
  - **Own reasoning** (Laya disk_storage 0.42 fb): the on-disk session format is undocumented,
    and a defensive reader there would claim more than is known.
- **D-10: pi and opencode files are installed as symlinks under the existing
  `link_one`/`unlink_one` ownership rule** (target inside `install_dir`, never clobber a foreign
  file; `tools/setup.py:1030-1063`). They never touch JSON config. Analyzer Confident.

### Hook registry and setup
- **D-11: Registry rows are flat: one row per id × host × event** (`id`, `host`, `event`,
  `matcher`, `script` or link file, `default`, `experimental`), as a module-level tuple in
  `tools/setup.py`.
  - The wizard groups rows by id: one row per hook, pre-checked if installed, else if any
    present host's default is on.
  - The writer groups rows by settings file: one read, validation of every event key, one
    `_atomic_write_json`, so a PreCompact entry is never written without its injector.
  - `wire_hook_claude` generalizes to `(settings, event, matcher, script)`.
  - Laya flat_rows 0.89, taken with the write-grouping condition from the evidence
    (`_load_hook_config` validates one event key per call, `tools/setup.py:1495-1512`).
    SPEC R10 amended.
- **D-12: Defaults are per host (one row's `default`).**
  - Headless ids may be host-qualified (`precompact:pi`). A bare id wires every present host.
    Confirming the wizard row wires the present hosts whose default is on, plus any already
    installed.
  - Laya per_host_inside_row 0.50 fb, same choice; R9's verdict is per host.
- **D-13: Headless `--with-hooks` uses `nargs="?"` with a sentinel.**
  - Bare means today's briefing. `--with-hooks=<id,...>` is validated against the registry, and
    an unknown id is a `parser.error` naming it.
  - The ids must be validated because `--headless --with-hooks install` parses `install` as the
    value (live argparse check). `cmd_install_headless` keeps its positional `with_hooks`
    (`True` = bare, else a list), so the existing tests (`tests/test_setup.py:2317-2341`) keep
    passing.
  - Analyzer Confident (verified live).
- **D-14: Hooks are a fourth `hooks` category in the wizard's existing `Selection`**
  (`tools/setup.py:1239-1294`; `tools/wizard_app.py:548-590` groups rows by category
  generically).
  - `apply_selection` ignores the category (it loops over `CATEGORIES`), and `commit()` routes
    hooks to wire or unwire. Descriptions, including the verdict and "experimental", go through
    `component_meta`.
  - The briefing stays unconditional until 21.3 moves it in.
  - Both the 21.2 and 21.3 analyzers proposed this; Laya (21.3 item) own_panel 0.60 fb.
    **Own reasoning:** a second UI path duplicates toggle, help and net-change logic.

### Files and session matching
- **D-15: Pre-summaries live in `$XDG_RUNTIME_DIR/ai-kit/compact/`** (0700), falling back to
  `${XDG_CACHE_HOME:-~/.cache}/ai-kit/compact/`, never shared `/tmp` and never cwd.
  - Files are written 0600 through `mkstemp` + `os.replace`. Every run first deletes files
    older than 24 h.
  - Evidence: `/run/user/1000` is `drwx------` here. The `_private_dir` precedent is in
    `skills/ai-kit-spec-review/ai_kit_spec/detection.py:704-718`.
  - **Own reasoning** (Laya cache_only 0.59 fb): a cache-only dir survives reboots, leaving
    the 24 h sweep as the only cleanup for files holding secrets.
- **D-16: The name is `{session_id}-{slug}-compact.md`.**
  - The injector globs `{session_id}-*-compact.md` after checking `session_id` against a strict
    safe-character pattern (`util_safe_session` precedent, `tools/status-line.py:1008`).
  - The Claude slug is `basename(cwd)`, because PreCompact carries no `session_title`. pi uses
    `getSessionName()`, else its cwd basename.
  - The 9,500 cap covers header plus summary.
  - Laya glob_session_id 0.50 fb, same choice.
  - The R5 live check confirms that Claude keeps the session id across compaction.

### Measurement and tests
- **D-17: Measurements use documented metrics per host first; internal fields are recorded
  but labelled.**
  - Claude: wall time between scratch PreCompact and compact-SessionStart log lines, the
    status-line `context_window` input, and `PostCompact.compact_summary` length. The
    transcript `compact_boundary` `preTokens`/`postTokens` are labelled reverse-engineered.
  - pi: `session_before_compact` → `session_compact` timestamps, `CompactionEntry.tokensBefore`
    and `usage` (absent when hooked), and `ctx.getContextUsage()`.
  - opencode: the `session.compacted` timing; tokens are unverified.
  - Laya documented_first 0.46 fb, same choice.
- **D-18: Tests.**
  - Unit tier: a stub client selected by env override (labels from a map, call log) covers R1,
    R3, R4 and R8, including the zero-remote and no-model-call assertions.
  - Subprocess tests for the Claude script follow `TestClaudeWrapper`
    (`tests/test_tool_substitution_hook.py:122-250`) with synthetic transcripts only.
  - Setup e2e tests run under a temp `HOME` with a foreign PreCompact entry.
  - The opencode and pi shim handlers run under `node` 24 (type stripping present) in the e2e
    tier, skipped when node is absent.
  - **Own reasoning** (Laya live_only 0.42 fb): live-only testing would let an `output.prompt`
    regression ship unnoticed.
