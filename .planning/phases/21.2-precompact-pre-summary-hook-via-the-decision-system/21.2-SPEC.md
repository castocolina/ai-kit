# Phase 21.2: PreCompact pre-summary hook via the decision system — Specification

**Created:** 2026-10-18
**Ambiguity score:** 0.17 (gate: ≤ 0.20)
**Requirements:** 10 locked

## Goal

Before a compaction, a host-neutral core splits the active conversation into chunks. The
21.1 decision client, on a loopback backend only, classifies each chunk as keep, summarize or
discard. The core then builds an extractive pre-summary of at most 9,500 characters, which
each primary host consumes through its own documented route:
- Claude Code: injected after compaction;
- pi: returned as the compaction summary;
- opencode: added to the compaction prompt.

The saving against a baseline compaction is measured on each host. The hook is its own setup
knob, on by default only where the saving is positive.

## Background

Verified on 2026-10-18 against current docs and the installed tools:
- **Claude Code** (code.claude.com/docs/en/hooks):
  - `PreCompact` receives `session_id`, `transcript_path`, `cwd`, `trigger` (`manual`/`auto`)
    and `custom_instructions` (`manual` only, else `null`). Its only control is blocking
    (exit 2 or `"decision": "block"`), and it discards `systemMessage` and `continue`.
  - `PostCompact` receives `compact_summary` and has no decision control.
  - `SessionStart` with source/matcher `compact` fires after compaction and adds
    `hookSpecificOutput.additionalContext` to the model's context.
  - `additionalContext`, `systemMessage` and plain stdout are each capped at 10,000
    characters. Larger output is saved to a file and replaced by a 2,000-character preview.
  - Blocking a proactive auto-compaction skips it, and blocking a recovery compaction fails
    the request. A pre-summary hook must therefore never block.
  - The transcript JSONL is internal; compact boundaries are undocumented.
- **pi 1.3.0** (installed `docs/compaction.md`, `docs/session-format.md`):
  - The extension event `session_before_compact` receives `preparation.messagesToSummarize`,
    `previousSummary`, `firstKeptEntryId`, `tokensBefore` and `customInstructions`.
  - It can return `{ compaction: { summary, firstKeptEntryId, tokensBefore, details } }`,
    which replaces pi's model-written summary. This is the only host where a pre-made summary
    removes the summarization call itself.
  - Session files are documented JSONL with a `compaction` entry type.
  - Extensions load from `~/.pi/agent/extensions/*.ts`.
- **opencode** (opencode.ai/docs/plugins): the `experimental.session.compacting` plugin hook
  "fires before the LLM generates a continuation summary". It can push onto `output.context`
  or replace `output.prompt`. The hook is marked experimental.
- **ai-kit today.** `tools/hooks/` has `detect.py`, `claude_session_start.py` and
  `cursor_session_start.py`, all fail-open (`{}` and exit 0). `tools/setup.py` wires the one
  SessionStart hook unconditionally in the wizard (`commit()` calls `wire_hook_claude` and
  `wire_hook_cursor`). Headless wiring is a single boolean `--with-hooks`. No compaction
  hook exists.
- **The decision client** (Phase 21.1) provides Laya one item per request, `needs_fallback`,
  the answer log and a fast `--probe`. Laya answers in about 15 ms per question warm and
  silently truncates long input.

## Requirements

1. **Host-neutral core**: A stdlib-only module under `tools/hooks/` turns a list of conversation messages into chunks, classifies each chunk through the 21.1 client, and writes `{session-id}-{name}-compact.md`.
   - Current: No compaction code exists.
   - Target: The input is host-neutral messages (role, text, tool-call names); the hosts' adapters convert into it. Chunks hold whole messages and stay under the client's per-item size limit. The output file holds the pre-summary and a header with session id, chunk counts per label and the time used. `{name}` is a filesystem-safe slug of the session title or the project directory name.
   - Acceptance: A unit test feeds 40 synthetic messages with a stub client and gets a file whose header counts match the stub's labels. A message longer than the chunk limit is split at line boundaries, never mid-line.

2. **Defensive transcript reading (Claude Code)**: The Claude adapter reads `transcript_path` line by line. It skips and counts malformed or unknown entries, uses only the part after the last compaction boundary it can recognize, and treats a file with no usable message as "no pre-summary".
   - Current: Nothing reads transcripts.
   - Target: Unknown `type` values, truncated last lines, non-JSON lines and a missing file never raise. An unrecognized boundary means the whole file is the active part, with a counter recording that.
   - Acceptance: Fixture tests cover a well-formed synthetic transcript, a truncated last line, an unknown entry type, a missing file and an empty file. Each exits 0, and only the well-formed case writes a file.

3. **Loopback-only classification**: Chunks go only to a loopback decision backend, one chunk per request. With no loopback backend usable, the hook writes no file and exits cleanly.
   - Current: n/a.
   - Target: The core calls the client with `JEV_BACKEND` pinned to the local backend and never sets the remote consent flag. Each item is a `choice` among `keep`/`summarize`/`discard`. A `needs_fallback` or errored item counts as `keep`.
   - Acceptance: A test with a remote backend configured and consent recorded still makes zero remote requests. A test with Laya down writes no file and exits 0. A test with one low-confidence item labels it `keep`.

4. **Extractive pre-summary within the cap**: The pre-summary is built without any model call: kept chunks verbatim, summarize chunks reduced to their first non-empty lines, discarded chunks dropped. It never exceeds 9,500 characters.
   - Current: n/a.
   - Target: Chronological order is kept. Over the budget, the oldest summarize lines go first, then the oldest kept chunks are trimmed, so the newest kept chunk survives.
   - Acceptance: A test whose kept chunks total 30,000 characters gets a file of ≤ 9,500 characters that still holds the newest kept chunk whole. No model call is made (a stub asserts it).

5. **Claude Code delivery**: A `PreCompact` hook (matchers `manual` and `auto`) prepares the file. A `SessionStart` hook with matcher `compact` injects it as `additionalContext` and then deletes it. Neither hook ever blocks compaction.
   - Current: The SessionStart briefing uses `startup|compact` for tool advice only.
   - Target: Every PreCompact path exits 0 with no `decision` field. The compact-matcher injection reads only a file whose session id matches its own input's `session_id`, and finds no file → `{}`. The phase spike compares the manual variant (the user passes `/compact <instructions>` naming the file); it ships only if it measures better.
   - Acceptance: Subprocess tests pipe synthetic PreCompact and SessionStart payloads. Every output parses as JSON, no output contains `decision`, and injection happens only on a matching `session_id`. A live check in a scratch Claude Code session shows the injected header in the post-compaction context.

6. **pi delivery**: A pi extension on `session_before_compact` hands `preparation.messagesToSummarize` to the core. It returns the pre-summary as `compaction.summary` with the event's own `firstKeptEntryId` and `tokensBefore`; on any failure it returns nothing, so pi's default compaction runs.
   - Current: ai-kit ships no pi extension.
   - Target: A thin TypeScript extension that calls the Python core with a bounded timeout. `details` records the chunk counts.
   - Acceptance: A test runs the core's pi entry with a recorded `messagesToSummarize` fixture and gets a summary of ≤ 9,500 characters. A live check in a scratch pi session shows a `compaction` entry whose `details` carries the ai-kit counts.

7. **opencode delivery (experimental)**: An opencode plugin on `experimental.session.compacting` pushes the pre-summary onto `output.context` and never sets `output.prompt`.
   - Current: No opencode plugin ships.
   - Target: Labelled experimental in setup and docs, because the upstream hook is.
   - Acceptance: A test of the plugin's handler with a fake `output` object finds one pushed string of ≤ 9,500 characters and `output.prompt` untouched. A live check in a scratch opencode session confirms the hook fires.

8. **Bounded time, never in the way**: Each host adapter finishes within 10 s. On timeout or any error it falls back to the host's normal compaction with no pre-summary.
   - Current: n/a.
   - Target: The core enforces the budget across all chunk calls. Chunks not classified in time count as `keep`; if that pushes the summary past the budget, the cap rule of R4 applies.
   - Acceptance: A test with a stub that sleeps 1 s per chunk and 30 chunks returns within 10.5 s with a valid file or none. The Claude PreCompact hook still exits 0.

9. **Measured saving**: A spike run on each host records baseline and hooked compactions (≥ 3 each): compaction wall time and the post-compaction context size (tokens where the host reports them, else characters). The per-host verdict drives the knob default.
   - Current: No measurement exists.
   - Target: A phase artifact `21.2-MEASUREMENTS.md` holds the raw numbers, the method and the verdict per host. A host whose saving is zero or negative ships its knob default off, and setup shows the recorded result.
   - Acceptance: The artifact exists with ≥ 3 baseline and ≥ 3 hooked runs per host and a verdict line per host. Setup's description of the knob quotes that verdict.

10. **Own setup knob via a hook registry**: The pre-summary hook is installed and removed per host as its own knob. A wizard row and a headless selector come from one hook registry table that Phase 21.3 extends.
    - Current: One unconditional SessionStart wiring and a boolean `--with-hooks`.
    - Target: The registry row carries the hook id, hosts, event, matcher, script and default. Headless `--with-hooks=<id,...>` selects by id; bare `--with-hooks` keeps today's meaning (the SessionStart briefing) until 21.3 moves it into the registry. Uninstall removes only ai-kit entries. Config writes are atomic and keep foreign entries.
    - Acceptance: e2e tests under a temporary `HOME`: `--with-hooks=precompact` wires the Claude PreCompact and compact-SessionStart entries and nothing else; uninstall removes exactly those; a foreign PreCompact entry survives both.

## Boundaries

**In scope:**
- The core and its Claude Code, pi and opencode adapters.
- Defensive transcript reading for Claude Code.
- Loopback-only classification.
- The extractive pre-summary and its cap.
- The measurement spike and `21.2-MEASUREMENTS.md`.
- The hook registry with this hook as its first registered row, its wizard row and headless
  selector.

**Out of scope:**
- Replacing Claude Code's own compaction summary. The documented hooks cannot.
- Remote decision backends for transcript content. Transcripts hold code and secrets.
- A model-written summary. An extra model call works against the "cheaper" goal; the
  extractive builder is measured instead.
- Codex and Cursor adapters. These secondary hosts have no compaction hook verified here.
- Moving the existing SessionStart tool briefing into the registry, and the advisory hooks.
  Phase 21.3 owns both.
- Changing the transcript format or depending on undocumented fields beyond the defensive
  read.

## Constraints

- Hook scripts are stdlib-only, run with `python3 -S`, and are fail-open (`{}`, exit 0), as
  the existing hooks are. The pi and opencode adapters are thin shims over the Python core
  with no npm dependency.
- The pre-summary file lives in a per-user private temp dir (mode 0700, file 0600). It is
  deleted after injection, or at the latest 24 h after creation, and is never written inside
  the repo or a project dir.
- Live checks run in scratch host sessions with scratch config dirs, never the user's real
  config. Measurement runs need Laya healthy on loopback.
- No new dev dependency. Tests are stdlib `unittest` in `make test`.

## Acceptance Criteria

- [ ] The core turns 40 synthetic messages into a pre-summary file whose header counts match the stub labels.
- [ ] The transcript fixtures (well-formed, truncated, unknown type, missing, empty) all exit 0; only the well-formed one writes a file.
- [ ] With remote consent recorded, classification still makes zero remote requests; with Laya down, no file and exit 0.
- [ ] A low-confidence or errored chunk counts as `keep`.
- [ ] A 30,000-character input yields ≤ 9,500 characters, keeps the newest kept chunk whole, and makes no model call.
- [ ] No Claude hook output contains a `decision` field; injection happens only for a matching `session_id`, and the file is deleted afterwards.
- [ ] The pi extension returns a summary of ≤ 9,500 characters with the event's `firstKeptEntryId`, and returns nothing on error.
- [ ] The opencode plugin pushes to `output.context` and never sets `output.prompt`.
- [ ] Every adapter finishes within 10 s under a slow stub.
- [ ] `21.2-MEASUREMENTS.md` has ≥ 3 baseline and ≥ 3 hooked runs and a verdict per host; a non-positive verdict ships that host's knob default off.
- [ ] `--with-hooks=precompact` wires only this hook's entries; uninstall removes only them; foreign entries survive.
- [ ] MUST NOT: no hook ever blocks compaction (test: no `decision`, exit 0 on every path).
- [ ] MUST NOT: transcript content is never sent to a non-loopback backend (test).
- [ ] MUST NOT: the pre-summary file is never readable by other users or left in a project dir (test: mode 0600, path under the private temp dir).
