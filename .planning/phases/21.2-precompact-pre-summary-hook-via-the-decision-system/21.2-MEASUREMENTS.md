# 21.2 Measurements protocol (PCH-02, SPEC R9, D-17)

**Created:** 2026-10-19 (staged by plan 21.2-02; run by the orchestrator after
21.2-05 lands). Every live run obeys the SPIKE.md binding rules: scratch
`HOME` and the host's config dir under `$PWD/tmp/p212/<host>/`, install via
`python3 tools/setup.py install --headless --with-hooks=precompact:<host>`,
interactive human authentication only, Laya on loopback, all spawned processes
stopped at the end.

**Purpose.** Measure, per host, whether the precompact hook saves compaction
wall time without growing the post-compaction context. The measured verdict
decides each host's knob default (a host never measured stays `unmeasured`,
default off). A saving of exactly zero is non-positive (default off); fewer
than 3 runs in either arm is `unmeasured`.

## Method per host (metrics and their sourcing, D-17)

| Host | Time metric | Source | Size metric | Source |
|------|-------------|--------|-------------|--------|
| claude | wall time from the PreCompact log line to the compact-SessionStart log line (`claude_log_hook.py` timestamps) | documented hooks | `PostCompact.compact_summary` length + injected characters; status-line `context_window` after compaction | documented; transcript `compact_boundary` `preTokens`/`postTokens` recorded but reverse-engineered |
| pi | `session_before_compact` handler entry to `session_compact` event, plus the RPC `compact` round trip | documented events (`pi-measure.ts`) | `CompactionEntry.tokensBefore` and `usage` (absent when an extension supplied the summary), `ctx.getContextUsage()` | documented; noted heuristic, not provider-exact |
| opencode | hook entry to the `session.compacted` event | documented plugin/event hooks (`opencode-measure.ts`) | characters of the post-compaction context only | token fields unverified |

## Arms

- **Baseline:** the same scratch install with only the `measure/` logging hooks
  (measure-only mode: they log timestamps and do no chunking, classification
  or file work, so instrumentation overhead is identical in both arms).
- **Hooked:** the logging hooks plus
  `python3 tools/setup.py install --headless --with-hooks=precompact:<host>`.

## Session shape and run order (SPEC R9 ordering edge)

Fixed scripted prompt list for every run, identical across arms (baseline runs
first, all of them, then the hooked arm):

1. "Read file A and summarize its purpose in one line."
2. "Edit file A: change the constant to 42."
3. "What tests cover file A?"
4. "Compact now." (manual compaction trigger)
5. "What did we change in file A?" (qualitative check: does the post-compaction
   session still know the task?)

At least 3 runs per arm per host; record every run in `measure/runs.jsonl`.

## `measure/runs.jsonl` record format (units on every number)

```json
{"host": "claude", "arm": "baseline", "run": 1, "ts": "2026-10-19T12:00:00Z",
 "seconds": 4.2, "size": 5200, "size_unit": "tokens", "note": ""}
```

- `host`: `claude` | `pi` | `opencode`; `arm`: `baseline` | `hooked`;
  `run`: 1-based per arm; `ts`: ISO-8601; `seconds`: compaction wall time in s;
  `size`: post-compaction context size; `size_unit`: `tokens` or `chars`;
  `note`: free text (qualitative observations go in this file, not here).

## Orchestrator close-out (after the live runs)

1. Run
   `python3 .planning/phases/21.2-precompact-pre-summary-hook-via-the-decision-system/measure/verdict.py`.
2. Per host take its printed line. If that host's delivery check (S2(c), S3(d)
   or S4(b) in 21.2-SPIKE.md) recorded `fail`, use instead
   `gap: <reason>` with a reason of at most 24 characters (a longer explanation
   goes in this file, not in the verdict; a longer reason would be cut by
   `hook_description`'s 200-character cap).
3. Set exactly those strings in `PRECOMPACT_VERDICTS` in `tools/setup.py`
   (each precompact row's `verdict` and `default` derive from them) and in this
   file's `verdict <host>:` lines above.
4. Wherever a result contradicts ROADMAP Phase 21.2 or PCH-01/PCH-02 wording,
   add a dated `*(amended <date>, 21.2 close-out: ...)*` note to that file.
5. S5 passed: add a ROADMAP §Backlog entry `manual /compact pre-summary
   variant` with its numbers. S5 failed: put the line
   `The manual variant was measured and not built (D-06).` in the Phase 21.2
   entry.
6. Update `21.2-VALIDATION.md` statuses and sign-off.
7. Run `make test && make validate`.
8. Run the cross-check command (exits 0 only when registry, `verdict.py` and
   the verdict lines agree):

```bash
python3 -c '
import importlib.util, json, pathlib, re, runpy, sys
base = pathlib.Path(".planning/phases/21.2-precompact-pre-summary-hook-via-the-decision-system")
spec = importlib.util.spec_from_file_location("setup_mod", "tools/setup.py")
setup = importlib.util.module_from_spec(spec)
sys.modules["setup_mod"] = setup
spec.loader.exec_module(setup)
verdicts = setup.PRECOMPACT_VERDICTS
lines = dict(re.findall(r"^verdict (claude|pi|opencode): (.+)$",
                        (base / "21.2-MEASUREMENTS.md").read_text(), re.M))
for host, verdict in verdicts.items():
    assert verdict == lines[host], (host, verdict, lines.get(host))
    if verdict.startswith("gap: "):
        assert len(verdict) - 5 <= 24, (host, verdict)
rows = [r for r in getattr(setup, "HOOK_REGISTRY", ()) if r.get("id") == "precompact"]
for row in rows:
    v = verdicts[row["host"]]
    assert row["verdict"] == v or (v.startswith("gap: ") and row["verdict"].startswith("gap: ")), (row["host"], row["verdict"], v)
    assert row["default"] == (v == "positive"), (row["host"], row["default"], v)
print("close-out cross-check ok")
'
```

(If `tools/setup.py` names its registry or verdict table differently at
close-out time, adapt the two attribute lookups — the assertions stay.)

9. Commit through
   `node .claude/gsd-core/bin/gsd-tools.cjs query commit`.
