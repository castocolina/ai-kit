The 21.1 client `skills/jev-fast-decision/scripts/jev_review.py` (its documented interface; use
names, never line numbers):
- `--probe` (no stdin, kill switch not needed) prints one JSON object whose `backends` is a list
  in table order of `{name, remote, batch, host, usable, key_source}` plus `reason` when unusable.
  A remote row without consent answers `consent_required` without opening a socket.
- Screen mode reads one JSON object on stdin, `{"reviewed_head": <40 lowercase hex>, "items":
  [{"id", "type": "choice", "instructions", "criteria": {label: description, ...}, "context"}]}`,
  and prints `{"advisory": true, "status": "ok", "answers": {<id>: {"type": "choice", "choice",
  "probabilities", "confidence", "needs_fallback", "backend", "model", ...}}, ...}` or a `status`
  other than `ok`. It always exits 0.
- Env: `GSD_PATH_JEV=1` (else `{"status": "disabled"}`), `GSD_PATH_JEV_TIMEOUT_SECONDS` (positive
  float, else `invalid_timeout`), `GSD_PATH_JEV_DEADLINE_SECONDS` (whole-run deadline, 21.1-02),
  `JEV_BACKEND` (an explicit row runs that row only), `JEV_CALLER` (answer-log label),
  `JEV_ALLOW_REMOTE` (session consent), `AI_KIT_LAYA_URL`/`JEV_LAYA_URL` (loopback only), the
  consent record `${XDG_CONFIG_HOME:-~/.config}/ai-kit/jev-consent.json` (21.1-02), the answer log
  `${XDG_STATE_HOME:-~/.local/state}/ai-kit/jev-answers.jsonl` (no context text logged).
- The laya row's `state_chars_limit` (2000 in 21.1-01): an answer whose request state is longer is
  forced to `needs_fallback: true`. State size = `len(json.dumps(state, sort_keys=True,
  separators=(",", ":")))`, so non-ASCII text counts as `\uXXXX` escapes.
