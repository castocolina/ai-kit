## 21.2-01

**Summary.** The core-plus-Claude-route plan is exceptionally well grounded: every repo claim I traced verifies against the current code, and the client-interface contract matches the landed 21.1 client exactly. The task split (tracer → core edges → Claude edges) is correctly ordered, and the design reuses existing primitives (`_fail_open`, `emit`, `link`-style ownership, `_private_dir` precedent) instead of re-inventing them.

**Strengths**
- The 21.1 client contract is accurate: `CLIENT_PROTOCOL = 2` (`jev_review.py:33`), `--probe` emits a `backends` list of `{name, remote, batch, host, usable, key_source}` (`:828–836`, `:871`), kill switch `GSD_PATH_JEV=1` (`:979`), `invalid_timeout` on non-positive timeout (`:1125–1133`), laya `state_chars_limit: 2000` (`:658`), `_state_chars` = sorted-compact JSON length (`:921–923`) — exactly what `request_state_chars`/`fits` mirror.
- The scrub design is provably sufficient: `client_env` drops `JEV_*`/`GSD_PATH_JEV*` prefixes while `AI_KIT_LAYA_URL` survives and the client reads it loopback-gated (`jev_review.py:420–424` refuses non-loopback), and a keyed remote without consent returns `consent_required` **without a socket** (`:781–783`) — so zero-remote-request holds by construction, not by hope.
- `read_stdin` extraction claim matches reality: `_drain_stdin` is 16 rounds / 0.5 s idle / 1 MiB (`claude_session_start.py:43–65`), `emit` builds the SessionStart envelope (`:68–80`), `main`'s realpath-sys.path pattern (`:85`) and the no-extra-`SystemExit` rule (`:36`) are both honored by the new hook's design.
- Boundary parity is real, not aspirational: `_COMPACT_BOUNDARY_MARKER` and the byte-marker + `type`/`subtype` check (`status-line.py:965`, `:968–998`) are what `last_boundary` copies, and the parity test pins it against three fixtures.
- The 10 s budget holds by design: `started` is set at entry, the probe is deadline-capped, and classification stops at an absolute `started + CLASSIFY_SECONDS` — a slow read shrinks the classify window rather than the total. Slow-stub math (9 spawned calls, ~8.3 s) checks out.
- Honest scoping: nothing is wired into host config by this plan; `CHUNK_STATE_CHARS = 1600` is explicitly labeled provisional for 21.2-03.

**Concerns**
- **MEDIUM — `read_stdin`'s 16-round structural cap undermines `MAX_STDIN_BYTES`.** The extraction keeps "16 rounds" of 64 KiB reads (`claude_session_start.py:50–51`), so `read_stdin` can never return more than 1 MiB regardless of the `limit` argument. Claude payloads are fine, but 21.2-04's pi/opencode entries pass `MAX_STDIN_BYTES = 32 MiB` — long sessions (even image-blanked) over 1 MiB get silently truncated mid-JSON → `{}` → no pre-summary, with no counter saying why. Either scale rounds with `limit` or document the real 1 MiB ceiling.
- **MEDIUM — `MAX_CHUNKS` truncation is invisible in the header.** `chunk_messages` "returns only the newest `MAX_CHUNKS` chunks," but the header's `total` then under-reports; SPEC R1's header (counts per label) gives a reader no way to see that older chunks were dropped before classification. Add a counter (e.g. `dropped_before_chunking N`).
- **LOW — Task-1 must_haves already assert the 9,500-cap truths while Task 1 defers the cap step to Task 2** ("the cap step is Task 2's"). The tracer fixture must be sized so an uncapped all-keep document fits under 9,500; an executor following the truths literally can't make the red test green at Task 1.
- **LOW — per-call timeout rounding.** `f"{timeout_s:.2f}"` turns a remaining budget in (0, 0.005) s into `"0.00"` → client `invalid_timeout` and `subprocess` timeout 0. Both paths safely map to `keep`, so behavior is right, but the SPEC R8 boundary truth ("finishing at 10.0 s is in budget") has this rounding corner undocumented.

**Suggestions**
- In Task 1's action, state the fixture size constraint explicitly (all-keep rendered document ≤ 9,500 chars) so the Task-1 tracer is achievable without the Task-2 cap.
- Have `read_stdin` derive rounds from `limit` (`range(max(16, limit // 65536))`) so the 32 MiB constant in 21.2-04 is real, or cap `MAX_STDIN_BYTES` at 1 MiB and say so.

**Risk Assessment.** **LOW-MEDIUM.** The architecture is verified against the code it builds on; the residual risks are the 1 MiB stdin ceiling and header honesty, both cheap to fix during execution.
