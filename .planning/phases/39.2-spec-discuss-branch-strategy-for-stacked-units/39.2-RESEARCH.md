## Summary

All ten questions are answerable from the repo. The headline findings:

1. **GSD renders the phase branch name in `init execute-phase <N> --pick branch_name`** (not `init.phase-op`). It zero-pads the integer part (`9` -> `09`) and keeps a decimal verbatim (`39.2`). The fold tool computes its own name with `fold_adapters.gsd_unit()`; the CLI already reports it on line 1 of `fold.py guard --phase N` (read-only; run and quoted in Q1). A skill script cannot import `fold_adapters`: `tests/test_arch.py:1389-1394` (Phase 29 ruling 2) forbids a skill importing or `sys.path`-shimming another skill's folder. So `branch_preflight.py` shells out to `FOLD_PY guard` (D-06's wording) and compares line 1 with GSD's name.
2. **D-01 is safe to build by reusing `cascade(repo, settings, record, moved_unit=..., old_tip=...)`, but `cascade` pushes** when push consent is granted (`flow_stack.py:274`), and `restack --continue` publishes through the same `_publish`. SPEC R6 and the "must not push" prohibition therefore need an explicit no-push switch carried in the saved restack state. This is the largest hidden cost of D-01.
3. **`ai-kit-commit-fold` is in `.planning/judge/inputs.json` `excluded` (line 4)**, and the loop 39.1 drivers hard-code it in `NEVER_FIXED`. SPEC R10 requires judging it. This is a SPEC-vs-tool conflict that needs an owner decision before the judge plan is written (Open Question 1).
4. D-08's six evals omit one the SPEC demands (R2: an eval over the where-am-I printed fields).
5. `tests/test_ai_kit_gsd_spec_discuss.py:714-716` pins `scripts/` to exactly two files; adding `branch_preflight.py` fails it until updated.

**Primary recommendation:** build in D-10 order; implement D-01 as a new `_restack_moved_lower()` step inside `_sync_restacked` that calls `cascade(..., push=False)`; put the new `start` refusals after the existing `no_trunk`/`wrong_parent` checks and before `_carry`; make `branch_preflight.py` take the resolved GSD command and `FOLD_PY` as arguments and read the fold-side name from line 1 of `fold.py guard --phase N`; restack bottom-up one adjacent pair at a time (Q2).

### Q2. Every path to `sync`, `_sync_restacked`, `cascade`

Definitions: `_sync_restacked` `flow_stack.py:328-346`; `sync` `:349-351`; `cascade` `:283-314`. Callers (rg over `skills/` and `tools/`, then read):

| Caller | Reaches changed code via | Lines |
|--------|--------------------------|-------|

| `fold.py hotfix` | `cmd_hotfix` -> `_sync_restacked` | flow_stack.py:536 |
| `fold.py start` | `cmd_start` -> `_start_and_boundary` -> `_start` -> `_sync` -> `flow_stack.sync` | flow_unit.py:210, 74-75 |

Never reach them: `guard` (`_guard` reads the record and calls `_check_parent` only, flow_unit.py:243-247), `show` (read-only, flow_unit.py:436-445), `boundary` (no call), `merge-chain` (only `flow_stack.restack_pending`, flow_merge.py:365), `consent`, `settings`. The module docstring `flow_stack.py:3` ("sync runs first in every flow command except consent, settings and show") is wrong about `guard`/`boundary`/`merge-chain`: fix it in the same commit.

Indirect callers of the CLI that therefore inherit D-01: the GSD hook verbs (`skills/ai-kit-commit-fold/gsd/ai-kit-commit-fold/ai-kit-fold.cjs` runs `fold.py` subcommands), the superpowers adapter, `tools/flow_live_check.py:248` (`restack`), and spec-discuss's `start`.

Consequences of changing `_sync_restacked` (so `start`/`checkpoint`/`ready`/`hotfix` all restack):
- `cascade` raises `dirty_tree` for a modified TRACKED file (`_dirty` uses `--untracked-files=no`, flow_stack.py:80-81) and `detached_head`; `start`/`checkpoint`/`ready` can now raise these, or pause (`conflict`), where they did not before, but only when a lower unit has moved. Spec-discuss must commit before running `restack`/`start`; the recipe needs a row for "start paused a restack".
- `checkpoint` on the lower unit J after plain commits: `_sync` (line 268) restacks the units above onto J's tip first; the fold then rewrites J and `_cascade_if_moved` cascades again. Correct, one extra local rebase.
- Pin with a test and state in `unit-contract.md` that `start`, `checkpoint`, `ready` and `hotfix` restack a moved lower unit (CONTEXT plan-time check). `unit-contract.md` is pinned system-neutral (no "gsd", "superpowers", "grill-me", "spec-kit" substrings, `tests/test_flow_docs.py:35,46-48,67-71`), so write "adapter"/"planning system".

**Design for the detection (recommendation).** In `flow_stack.py` add `_moved_lower(repo, record)`: walk the stacked, non-merged units in record order; for each unit with a stacked non-merged unit below it, compute the lower branch tip; if it exists, differs from `entry["parent_tip"]`, and `flow_git.is_ancestor(repo, entry["parent_tip"], refs/heads/<entry.branch>)`, return `(lower_id, entry["parent_tip"])` for the lowest such pair. In `_sync_restacked`, after the trunk step (`:344-346`), call `cascade(repo, settings, record, moved_unit=lower_id, old_tip=old, push=False)`.

**Two lower units moved before one restack (R1's own batch: shared files on the lowest unit A plus an amendment on J=B) breaks a single call.** `cascade` takes one `(new, old)` pair: `--onto a2 a1 <top>` replays `a1..top` onto A's new tip, but the recorded boundary of C (`parent_tip` = B's OLD tip) is not refreshed against B's new commit, so after `_rebased` (`:215-227`) the recorded parent tips can fail `_check_parent` for B or C (by reading the code; confirm in a fixture before relying on either outcome). Prescribe a bottom-up loop: after each `cascade` returns, recompute `_moved_lower` and repeat until it returns None (each pass rebases the units directly above the lowest still-moved parent; `_record_rebase` refreshes `parent_tip` so the loop terminates). Add the fixture to the R6 row: plain commits on A and on B, one `restack`, assert one line and every `parent_tip` equal to its parent's tip. A paused conflict in pass N leaves the later passes to the next `restack` after `--continue`; `restack_pending` blocks a second start meanwhile (`flow_stack.py:330-331`).

**Never-pushed units.** `_record_rebase` sets `pending` whenever the new tip differs from `entry["pushed"]`, including `pushed is None` (`:247-250`), and `catch_up` (flow_unit.py:43-58) pushes `pending` units and opens draft PRs for those without one when consent is granted. So after a local restack the next consented `start` pushes never-pushed units and opens PRs. That is the existing consent flow, but say it in `unit-contract.md` and the recipe, and test it only as documented behavior. This reuses `_unmerged_above`, `_boundary`, `_preflight`, `_rebase_units`, `_rebased` (moves an empty unit to the new tip, `:215-227`), `_record_rebase` (sets every restacked `parent_tip`, `:243-253`) and the pause/`--continue`/`--abort` flow. Skip a unit whose branch does not contain its `parent_tip`: that is `wrong_parent` territory and must stay refused, not rebased.

**The push problem.** `_publish` (`flow_stack.py:274`): `refs = _push_refs(...) if consented(repo) else []`, and `_continue` publishes after gates (`:474`). The trunk case relies on this (existing tests assert `remote_tip == rev`, test_flow_stack_2.py:41-43). For D-01 add a `push` boolean to `cascade`, store it in the saved restack state (`state["push"]`, `:309-311`), and make `_publish` honor `state.get("push", True)`. `_record_rebase` already records `pending` for unpushed tips (`:247-250`), so a later checkpoint pushes them through `catch_up` with the recorded lease. Note `start` itself calls `catch_up` when consent is granted (flow_unit.py:211), so a `start` after the local restack pushes the pending tips: that is the existing consent flow ("push-consent rules stay as they are") and the doc must say so.

### Q3. `wrong_parent` versus the new restack; check order in `start`; where the refusals go

Current `_check_parent` (flow_unit.py:85-96) compares a unit's OWN recorded `parent_tip` with ancestry of its OWN branch, not the parent branch's current tip:
```
if not flow_git.is_ancestor(repo, entry["parent_tip"], f"refs/heads/{branch}"):

## Common Pitfalls

1. **Cross-skill import (arch ruling 2).** `test_arch.py:1389-1394` rejects a literal import of another skill's module, a `sys.path` shim onto its folder, or a path string naming it. `branch_preflight.py` must stay self-contained. Warning sign: `tests/test_arch.py` fails with the reach listed.
2. **Push on restack.** Reusing `cascade` pushes with consent (`flow_stack.py:274`), also after `restack --continue` (`:474`). Persist `push` in the restack state so `--continue` honors it; test with remote tips before/after.
3. **`start` now restacks.** It can raise `dirty_tree`, pause on `conflict`, or `detached_head`. Order the prose: commit, then restack, then `start` back. Add a recipe row for "start paused a restack".
4. **Blanket unrecorded-HEAD refusal breaks `_carry`.** Exempt commits that touch the plan paths (Q3). Run `tests/test_flow_contract*.py` and `test_flow_checkpoint*.py` after the change.
5. **Scripts folder pin.** `tests/test_ai_kit_gsd_spec_discuss.py:714-723` fails until `branch_preflight.py` is added to both lists.
6. **`{project}` template.** Fold crashes with `KeyError`; preflight must report it (refuse), not crash. Real GSD pads too, so the padding-only fixture needs a stub GSD command.
7. **Goal-prompt caps.** One extra rail line may exceed `RULE_CAP = 60` in the all-fields renders; regenerate goldens only after the caps hold.
8. **Judge exclusion.** `ai-kit-commit-fold` is excluded from the loop (`inputs.json:4`); copying the 39.1 drivers unchanged blocks it (`never-judged skill changed`, judged.py:84-85).
9. **`show` dereferences `args.unit`.** `show --all` has no unit: branch before the dereference and skip `_attach`.
10. **Docs neutrality.** `unit-contract.md` may not contain `gsd`/`superpowers`/`grill-me`/`spec-kit`; write "adapter".

def _moved_lower(repo, record):
    """(lower unit id, old boundary) of the lowest unit whose parent branch moved, or None."""
    open_units = [e for e in record["units"] if e["kind"] == "stacked" and e["state"] != "merged"]
    for lower, entry in zip(open_units, open_units[1:]):
        tip = flow_git.rev(repo, f"refs/heads/{lower['branch']}")
        if tip is None or tip == entry["parent_tip"]:
            continue
        if flow_git.is_ancestor(repo, entry["parent_tip"], f"refs/heads/{entry['branch']}"):
            return lower["id"], entry["parent_tip"]
    return None
```
