<decisions>
## Implementation Decisions

### Fold tool behaviours
- **D-01: Plain `fold.py restack` detects a moved lower unit and restacks the units above.** A unit whose recorded parent tip no
  longer matches its parent branch's tip is rebased onto the new tip; the cascade and the pause flow (`--continue`, `--abort`,
  `restack_pending`) are the existing ones; local only, never pushed; recorded tips are updated after. *(owner answer
  2026-11-23, recommended option)*
  - Evidence: the help text says "restack units after a lower unit moved" but `_sync_restacked` acts only on trunk movement
    (`flow_stack.py:344`); `wrong_parent` already compares a recorded parent tip with the branch (`flow_unit.py:86`).
  - **Plan-time check:** `flow_unit` calls `sync`, so `start` would restack too; the plan pins that behavior with a test and
    states it in `unit-contract.md`.
  - **Reversibility:** costly — `restack` and `sync` are called by `start` and the cascade; undoing changes an existing command's
    semantics for every caller and every doc that names it.
- **D-02: The all-units view is `fold.py show --all`** (a fifth selector in the existing mutually exclusive group, read-only):
  one row per recorded unit with id, branch, parent, state and whether the branch exists, in stack order. **Own reasoning** (jev
  not asked): reuses the existing verb the todo suggested. Ledger.
- **D-03: The unrecorded-HEAD check (SPEC requirement 5b) is a new refusal of `fold.py start`**, generic and naming no system, so
  spec-discuss, the GSD hooks and the superpowers adapter all get it; the refusal prints the commits the trunk lacks. **Own
  reasoning:** the fold docs are pinned system-neutral by `test_neutral_docs_name_no_system`, and every caller of `start` has the
  same hazard. Ledger. The reason name is chosen at plan time.
- **D-04: A stale parent unit is a refusal of its own** (name chosen at plan time) naming the unit and its missing branch; `no_trunk`
  keeps its meaning (no remote ref to stack on). Spec-discuss §1's refusal table gets a row: show the report and stop the run,
  never "unit flow off" for this reason. **Own reasoning:** the SPEC prohibits a silent flow-off (requirement 8). Ledger.

### Spec-discuss skill
- **D-05: Writing a file on its owning unit is prose steps over existing commands.** `fold.py start --phase J`, the commit
  helper, `fold.py restack`, `fold.py start` back to the unit the step came from; batched into one switch and one restack per
  phase step; evals and doc-contract tests pin the order. *(owner answer 2026-11-23, recommended option)*
  - Reversibility: reversible — a helper script can be added later without changing the commands it would call.
- **D-06: The GSD branching check (SPEC requirement 5a) is a new stdlib script in the spec-discuss skill's `scripts/`**
  (`branch_preflight.py`, name at plan time): it reads `git.branching_strategy` and `git.phase_branch_template` through gsd-tools,
  compares the name GSD renders for the phase with the unit branch name the fold tool reports, exits non-zero with the reason,
  never writes. **Own reasoning:** the skill already owns GSD knowledge and has fixture-tested helper scripts; the fold tool stays
  neutral. Ledger. The plan pins which gsd-tools verb renders the name and whether it zero-pads (home-mobility's branch was padded).
- **D-07: `references/branches.md` carries the recipe table, the where-am-I output shape and the end-report template**; SKILL.md
  gets the ownership rule and short pointers only (progressive disclosure keeps SKILL.md small). The where-am-I step runs
  `fold.py show --all` plus `git branch --show-current`.
- **D-08: Six new evals** (amendment of an earlier phase, resume to plan the first phase, end report, GSD branching on, unrecorded
  HEAD branch, stale unit) join `evals/evals.json`; doc-contract tests join `tests/test_flow_docs.py`; fold fixture tests join
  the flow test modules.
- **D-09: One goal-prompt rail line** says "go back with `fold.py start --phase J` then `fold.py guard --phase J` before planning
  or executing an earlier phase", pinned by a test; Phase 47.2 reworks rails later and must keep the line.

### Order
- **D-10: Build order is a vertical slice.** The fold behaviours first (restack detection, `show --all`, the two refusals) with
  fixture tests and non-vacuity cases; then the spec-discuss script, SKILL.md, reference file and evals; then the rail line; then
  the skill-judge loops of `ai-kit-gsd-spec-discuss` and `ai-kit-commit-fold`.

report, and the fixture-repo layout of the fold tests.
