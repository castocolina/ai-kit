# Phase 30 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Source: 30-RESEARCH.md "Validation Architecture".

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | stdlib `unittest`, run by `tools/run_unittest_parallel.py` (one subprocess per module, tripwire PATH, baseline env, temp HOME with `AI_KIT_REFUSE_REAL_HOME=1`) |
| **Config file** | none; groups come from `tests/test_*.py`; listings regenerated by `tools/gen_test_groups.py` |
| **Quick run command** | `python3 tools/run_unittest_parallel.py --group unit -- <dotted modules>` |
| **Full suite command** | `make test` (about 70 s); `make pyright` and `make check-dogfood` separately |
| **Estimated runtime** | ~70 seconds (full); under 15 seconds per covering module set |

---

## Sampling Rate

- **After every task commit:** the commit hook runs the covering modules (`--staged`); e2e modules over the 60 s budget defer to push.
- **After every plan:** one `make test` (through the plan's `scope.py test`) plus `make pyright`.
- **Before `/gsd-verify-work`:** `make test` and `make check-dogfood` green; install and live re-check from the branch tip.
- **Max feedback latency:** 70 seconds
