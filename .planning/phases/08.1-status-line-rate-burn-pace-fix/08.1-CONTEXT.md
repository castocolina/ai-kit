## Phase Boundary

Corrects `tools/status-line.py`'s rate-limit bucket burn-rate formula
(`util_rate_burn_ratio`), which Phase 8 shipped as
`used_percentage / remaining_fraction`. Live-observed regression reported by
the user: at 25% used with roughly half of a 5h window already elapsed, the
bucket rendered YELLOW/orange — the user expected GREEN/BLUE, since 25%
usage at the window's midpoint is a healthy pace, not a warning.

Color-only change, same scope boundary Phase 8 itself used: the displayed
`used_percentage` number and `resets_at`-derived reset suffix stay
byte-identical; only which `theme.ramps["rate"]` band gets picked changes.

<decisions>
## Implementation Decisions

### Burn-rate formula direction — reverses Phase 8's D-01
- **D-01 (supersedes 08-CONTEXT.md's D-01, amended 2026-09-11):** The ratio
  fed into the unchanged `theme.ramps["rate"]` thresholds is
  `used_percentage / elapsed_fraction` (elapsed_fraction = 1 -
  remaining_fraction), NOT `used_percentage / remaining_fraction`. This is a
  reversal of Phase 8's own "Formula Direction — Resolved" decision
  (`08-01-PLAN.md`), which was driven by ROADMAP SC1's literal wording
  ("identical usage, less time remaining must render more urgently") —
  correct as a pure math statement, but the wrong real-world semantics: it
  makes the color flare up near a window's end even at low usage, which is
  backwards (low usage well into the window is good pacing, not urgency).
  Live-confirmed with the user via a direct two-option comparison
  (pace-based vs. remaining-time-based, worked example at 25%/5h) —
  pace-based was the explicit, unambiguous choice.
  — **Reversibility:** reversible — same shape as Phase 8's own D-01, only
  the value fed into the existing `util_pick_color` call changes.
- **D-02:** Fallback-to-raw-pct now triggers when `elapsed_fraction` is ~0
  (too early in the window to extrapolate a pace from near-zero elapsed
  time — avoids spiking toward INF on no real signal), mirroring where
  Phase 8's D-03 clamped at `remaining_fraction == 0` instead. The
  window-reset-instant case (`elapsed_fraction == 1.0`) now reduces to raw
  `pct` unclamped rather than needing a special max-urgency clamp — having
  used `pct` over the ENTIRE window is just today's raw-percentage signal.
- **D-03:** Every other Phase 8 boundary is unchanged: stale/missing
  `resets_at`, an unparseable window key, and a `remaining_fraction` outside
  `[0, 1]` (clock skew / window-key mismatch) all still fall back to raw
  `pct` unchanged.
