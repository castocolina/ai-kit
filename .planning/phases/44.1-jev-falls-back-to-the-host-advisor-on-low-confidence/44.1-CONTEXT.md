# Phase 44.1: jev falls back to the host advisor on low confidence - Context

**Gathered:** 2026-11-23 (interactive, after 44.1-SPEC.md)
**Status:** Ready for planning

<domain>
## Phase Boundary

When jev ran and answered items low (Laya or TypeSafe: `needs_fallback`, forced or an item error), the agent that asked consults
its host's advisor tool once per step for all those items, weighs the answer, decides and records "advisor". Scripts without an
agent, a missing or switched-off jev, owner-routed questions and hosts without an advisor tool keep today's behavior.

</domain>

<decisions>
## Implementation Decisions

### Where the rule lives
- **D-01: The rule is written in `jev-fast-decision` only.** SKILL.md's description (line 3) and result recipe (lines 38 and 39) say:
  a low item after jev ran goes to the host advisor tool once per step, the agent decides and records "advisor"; without an advisor
  tool, own reasoning. A new `reference.md` section ("Low answers and the host advisor tool") holds the four statements of SPEC
  requirement 6, with a "read X when Y" pointer from SKILL.md. **Own reasoning** (jev not asked): jev is a black box to callers, so
  the rule belongs to the skill they chain. Ledger.
- **D-02: Owner-routed paths stay as they are** (owner decision 2026-11-23): Phase 40 R5 and Phase 42 R1 still send a low
  classification to the owner; the advisor replaces only the agent deciding alone. The Phase 40 to 44 code defaults (lane count,
  session model, executor order, changelog keywords, effort catalog) are scripted and stay. SPEC requirement 7 and the ROADMAP entry
  were amended accordingly (this commit).

### Switch and log
- **D-03: The switch is a boolean `[jev]` key** (proposed `advisor_fallback`, name fixed at plan time), read by the layered reader jev
  already holds (`scripts/jev_config.py`, the Phase 33 copy with its parity test), absent means on, a non-boolean refused with the
  key named. The rule text says "unless `[jev] <key>` is false". **Own reasoning.** Ledger.
- **D-04: The decider list lives in jev's `reference.md`** (jev confident, advisor, own reasoning, default) and spec-discuss's
  `log-formats.md` points to it; the new cell is `low 0.NN` followed by the advisor decider, with the separator taken from the
  existing log formats or plain ASCII (plan time). The client's `decided_by` is untouched. A lock test compares both files with the
  list. **Own reasoning.** Ledger.

### Callers and guard
- **D-05: Agent-run caller texts point to jev's rule instead of restating it**: spec-discuss SKILL.md §3 and §4,
  `decision-table.md` (the `needs_fallback` rows), `log-formats.md`, `worked-examples.md`; goal-prompt SKILL.md and the rail text
  `gp_sections.py` renders for a run agent (agent-run prose produced by a script; it names the rule, it calls nothing); commit-fold
  SKILL.md. Each change carries a dated 44.1 marker. **Own reasoning.** Ledger.
- **D-06: The guard is a whole-word test over the scripted callers** (`fold_group.py`, `goal_prompt.py`, `gp_host.py`,
  `precompact_core.py`, `claude_decision_probe.py`, `judge_loop.py`, and the `ai_kit_spec` modules `jev_names.py`,
  `skill_classify.py`, `lane_order.py`, `cli.py`, `config_io.py`), joining `tests/test_jev_fast_decision.py` with a non-vacuity
  case; it passes the word `advisory` and the tool-substitution hook's name. `gp_sections.py` is not in the list (D-05). **Own
  reasoning.** Ledger.

### Order
- **D-07: Build order is a vertical slice.** (1) jev's rule, reference section, switch and decider list with their tests; (2) the
  caller pointers and the guard; (3) evals (one low step with three items, jev off, no advisor tool, switch off) and the skill-judge
  loops of `jev-fast-decision` and each changed caller SKILL.md.

### Claude's Discretion
The key name, the reference section's wording, the cell separator and the exact pointer sentence in each caller.

### Folded Todos
None folded.
