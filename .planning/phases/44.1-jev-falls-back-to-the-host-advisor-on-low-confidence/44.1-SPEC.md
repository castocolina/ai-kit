# Phase 44.1: jev falls back to the host advisor on low confidence — Specification

**Created:** 2026-11-23
**Ambiguity score:** 0.19 (gate: ≤ 0.20)
**Requirements:** 8 locked

## Goal

When jev-fast-decision ran and answered an item low (Laya or TypeSafe: `needs_fallback`, a forced answer or an error), the agent
that asked consults its host's advisor tool, once per step for all of that step's low items, before it decides, and records
"advisor" as the decider; scripts that run without an agent, a missing or switched-off jev and hosts without an advisor tool keep
today's behavior.

## Background

Requirement JEV-14 (REQUIREMENTS.md) and the ROADMAP's Phase 44.1 criteria, from the owner's request of 2026-11-23 (translated):
"when Laya or jev have low confidence, use the advisor model instead".

**The owner's decisions (highest priority):**

- 2026-11-23: the advisor is the host's own advisor tool (a model reviewer the agent calls in session), not a new jev backend.
- 2026-11-23, answers to this phase's question batch: (1) the agent consults the advisor once per step, covering all the low items
  of that step's jev request, not once per item; (2) the fallback is on by default where the host has an advisor tool, with one
  off switch in the `[jev]` section of `config.toml`; (3) the rule applies only when jev ran and answered low, forced or errored:
  jev not installed, off by its knob or with every backend down keeps today's path exactly.
- jev stays advisory and never gates (2026-11-16): the decision stays the agent's; the advisor's answer is advice the agent weighs
  and, where it conflicts with a locked decision or evidence, reconciles through the existing "needs confirmation" rule.
- Owner rule: hosts and tools are named by capability and verified status, never claimed beyond what was seen.

**Decided by own reasoning on 2026-11-23, the owner may overrule:** the agent knows its host has an advisor tool because the tool
is present in its own tool list (no probe and no detection code); ai-kit's own `tools/hooks/advisor_core.py` is a different thing (a
tool-substitution hook) and the SPEC says "host advisor tool" throughout to avoid the clash.

## Requirements

1. **One rule, stated once in jev-fast-decision, sends a low answer to the host advisor tool (JEV-14)**: `jev-fast-decision`'s
   SKILL.md states that when jev ran and an item came back low (`needs_fallback` true, which includes a forced answer, or an item
   error), the agent asks the host advisor tool once for all the low items of that step, weighs its answer and decides, recording
   "advisor"; every agent-run caller chains that skill and holds no second copy of the rule.
   - Current: SKILL.md lines 3, 38 and 39 say the agent decides with its own reasoning.
   - Target: those three places carry the advisor rule; the callers' texts point to the skill instead of restating it.
   - Acceptance: a doc-contract test pins the rule in `jev-fast-decision/SKILL.md` and fails when "own reasoning" returns as the
     low-outcome without the advisor clause; a test finds the rule's wording in no caller SKILL.md or reference (callers point to
     jev's skill); the advisor is asked once per step in a spec-discuss eval with three low items.

2. **A missing or switched-off jev, and a host without an advisor tool, keep today's path (JEV-14)**: when jev is not installed, is
   off by its knob or every backend is down, the agent decides as it does today; when the host has no advisor tool the agent decides
   with its own reasoning and says so.
   - Current: those paths exist and are pinned by tests in Phases 29, 34 and 40 to 44.
   - Target: unchanged.
   - Acceptance: the existing no-jev fixtures and tests pass without edits to their expectations; an eval with no advisor tool
     shows own reasoning and the stated gap; an eval with jev off shows no advisor consultation.

3. **Scripts that run without an agent keep their rule-based default (JEV-14)**: the scripted callers listed in Background never call
   or name an advisor; a low answer there returns the sentinel or default they return today.
   - Current: each returns a sentinel or default (for example `fold_group.py`, the hooks, `jev_names.py`).
   - Target: unchanged, with a guard.
   - Acceptance: a guard test over those files finds no advisor call or advisor name; their existing tests pass unchanged.

4. **An off switch in `[jev]` controls the fallback, on by default (JEV-14)**: a boolean key in the `[jev]` section of `config.toml`
   (name fixed at plan time), read through the layered reader jev already copies from Phase 33, turns the advisor fallback off; absent
   means on; a non-boolean value is refused with the key named; project over user per key; a host without an advisor tool ignores it.
   - Current: `[jev]` holds the on/off knob and the Laya URL; no advisor key.
   - Target: one more key, documented beside the others.
   - Acceptance: config fixtures: the key false makes the rule say own reasoning; the key absent means on; a non-boolean is refused
     with the key named; a project value overrides the user value; the layered-reader parity test still passes.

5. **The decision log names the decider from one closed list (JEV-14)**: spec-discuss's log cells and jev's receipts name who decided

   - Current: `log-formats.md` has cells for jev answers and an "own reasoning" decider; no advisor.

   - Acceptance: a lock test compares the decider values of the log formats with the documented list and fails when one is added or

## Boundaries

**In scope:**
- The advisor rule in `jev-fast-decision` and its references, the `[jev]` switch, the closed decider list and log cell, the guard
  over scripted callers, the dated amendments, docs, evals and the judge loop.

**Out of scope:**
- A jev backend that calls an advisor model itself (a new backend with key, consent and receipts), and any change to the shared jev
  client's answer shape.
- Consulting an advisor when jev is absent, off or down (owner decision), and per-item consultations.
- Detecting an advisor tool in code (the agent sees its own tool list), and hosts other than Claude Code beyond naming them unverified.
- ai-kit's `tools/hooks/advisor_core.py` (a different feature).

## Constraints

- Runtime code stays stdlib-only; no code in jev-fast-decision or any script calls an advisor.
- jev stays advisory and never gates; the agent decides; a CRITICAL-style locked decision is never overridden by an advisor answer
  without the existing "needs confirmation" flag.
- The skill text keeps jev a black box to callers: callers say "ask that skill and follow its SKILL.md" and add no backend detail.
- The advisor sees the whole conversation; the skill states this and adds no new data path beyond it.
- No machine-specific absolute path in skill text, tests or fixtures.
