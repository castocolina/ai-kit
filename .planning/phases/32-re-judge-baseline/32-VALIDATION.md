# Phase 32 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | `unittest` through `tools/run_unittest_parallel.py` (one subprocess per module, baseline env with a temporary HOME, host-CLI tripwire stubs, `AI_KIT_REFUSE_REAL_HOME=1`) |
| **Config file** | none; groups are code in the runner, listings generated by `tools/gen_test_groups.py` |
| **Quick run command** | `AI_KIT_REFUSE_REAL_HOME=1 python3 tools/run_unittest_parallel.py <touched modules>` |
| **Full suite command** | `make test` plus `make check-dogfood` |
| **Estimated runtime** | quick: ~30 seconds; full: ~8 minutes |

---

## Sampling Rate

- **After every task commit:** run the quick command for the modules the task touches (the commit hook also runs the covering modules).
- **After every plan wave:** run `make test-unit` and `make arch-test`.
- **Before `/gsd-verify-work`:** `make test` and `make check-dogfood` must be green; the one-time comparison of the R8 fixtures against the npm `yaml` package is recorded in the verification.
- **Max feedback latency:** 60 seconds for the quick command.
