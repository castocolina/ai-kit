```python
def _call_floor(entries: list, floor: dict) -> dict:
    """A floor axis counts for this call only when at least one entry carries a finite value
    for it (D-01): with none, every entry would fail it and the ranking would be empty."""
    return {axis: minimum for axis, minimum in floor.items()
            if any(isinstance(e.get("scores"), dict) and _is_finite_number(e["scores"].get(axis))
                   for e in entries)}
```

### Pattern 2: guard skeleton (D-05), logic proven by `tmp/auto/plan-32.2/spike/scan_hits.py`
```python
import ast, io, subprocess, tokenize   # add to the imports at tests/test_skill_text_history.py:8-11

def python_pointer_hits(source, rel):
    """Phase-file and phase-folder names in string literals (docstrings, f-string constant parts)
    and comments of one Python source; a source that does not parse is itself a hit."""
    try:
        tree = ast.parse(source)
        comments = [t for t in tokenize.generate_tokens(io.StringIO(source).readline)
                    if t.type == tokenize.COMMENT]
    except (SyntaxError, tokenize.TokenError) as exc:
        return [f"{rel}:1: unparsable source {type(exc).__name__}"]
    hits = []
    for node in ast.walk(tree):
        if isinstance(node, ast.Constant) and isinstance(node.value, str):
            hits += _planning_name_hits(node.value, rel, node.lineno)
    for token in comments:
        hits += _planning_name_hits(token.string, rel, token.start[0])
    return sorted(hits, key=_hit_sort_key)
```
`_planning_name_hits` loops `POINTER_RULES[:2]` (phase folder, phase file) with `finditer`, formats `f"{rel}:{line}: {kind} {match.group(0)}"`. Do NOT iterate all four `POINTER_RULES` (backlog id and referee also live there; DEF-09 names files only). A multi-line docstring reports its first line (`node.lineno`); that is acceptable and stable. Whole-tree test: `subprocess.run(["git", "-C", str(REPO_ROOT), "ls-files", "-z", "--", "skills"], capture_output=True, check=True)`, split on `"\0"`, keep names ending `.py`, skip a path that does not exist (`(REPO_ROOT / name).is_file()`), read UTF-8, never use `kept_skills`/`EXEMPT` (those are Markdown-only; spec S2 says project-rules are checked).

## Common Pitfalls

### Pitfall 1: A red commit is refused
**What goes wrong:** committing the failing test before the fix. **Why:** `.pre-commit-config.yaml:58-65` `staged-tests` runs `tools/run_unittest_parallel.py --staged`, `always_run: true`, stage pre-commit [VERIFIED: read]. **How to avoid:** the failing test and its fix land in one commit; the plan verifies red by running the test module before the fix edit, then green after, in the same task. **Warning:** executor tries two commits.

### Pitfall 2: Generated test-group listings
**What goes wrong:** a new `tests/test_ai_kit_spec_review_checklist.py` makes `tests.test_gate_scope` fail ("stale listing; run: python3 tools/gen_test_groups.py") and the `unittest` hook entry lacks the module. **How to avoid:** after creating the module run `python3 tools/gen_test_groups.py` and commit the resulting `Makefile` and `.pre-commit-config.yaml` changes with it. **Collision hazard:** two plans in one wave that each add a module edit the same two generated blocks; here only plan C adds a module (A edits `tests/test_ai_kit_spec.py`, B edits `tests/test_skill_text_history.py` and `tests/test_ai_kit_spec_runtimes_table.py`, D adds no module), so there is no collision. Keep it that way: no second new `tests/test_*.py` in this phase.

### Pitfall 3: A finding-shaped note under Approved flips a merged report to Issues Found
**What goes wrong:** spike [VERIFIED: `tmp/auto/plan-32.2/spike/parser_spike.py` output]: an Approved report whose `### Non-blocking notes` holds a bullet `- **T9** — Location: s9. Required: r9. Why: w9.` parses as a finding with `severity None`, and `render_merged_report` (`review_reports.py:125-130`) relabels it MEDIUM and emits `### Status: Issues Found — fix and re-invoke` (`any_issues` is true whenever any bullet parsed). **How to avoid:** D-11's LOW-only "non-blocking notes" must be plain `- <text>` lines, never the `**title** — Location: … Required: … Why: …` shape; the doc-contract test fills an Approved-with-notes block and asserts `parse_findings(...) == []` and `report_status == "approved"`.

### Pitfall 4: Old template headings relabel severities
Same spike: with the current template headings `### MEDIUM            (optional)` and `### Cross-Document Consistency   (if 2+ files)` `_SEVERITY_RE` (`review_reports.py:9-10`, `\s*$`) does not match, so the MEDIUM bullet reads HIGH and the Cross-Doc bullet reads LOW. Bare headings parse as CRITICAL, HIGH, MEDIUM, LOW, CROSS-DOC. Optionality notes go in prose under the block.

`ast` reports a multi-line string at its first line; `detection.py` hit lines 232 below are the docstring start, the text sits at 252-270. Executors edit by text, not by the reported line.
