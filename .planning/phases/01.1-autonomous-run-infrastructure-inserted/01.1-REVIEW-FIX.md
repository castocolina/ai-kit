## Fixed Issues

### CR-01: Wizard-driven install silently enables a bundled example the user declined (or a fresh `--examples=none` install)

**Files modified:** `tools/setup.py`
**Commits:** `e6c4d12`, `73cd10b` (follow-up)
**Applied fix:** Applied the review's suggested fix (fold newly-installed, desired-OFF ids back into `known_ext_ids` so `_persist_layout` writes an explicit `segments.<id> = false`) as a first commit (`e6c4d12`). Running `make test` against that commit surfaced a real regression it introduced: `tests/test_system_memory_e2e.py`'s `--examples=all` E2E test started failing, because the wizard's own per-example toggle (`state["segments"]`) defaults to OFF for a not-yet-installed bundled example (`_build_wizard_context`), so the review's fix — using `state["segments"]` as the sole "declined" signal — also fired for "accept wizard defaults + `--examples=all` on the command line", since that CLI flag was never threaded into `_make_wizard_commit` and so could not override the wizard's own (default-off) toggle for the in-UI `persist_statusline` call.

Root-caused and fixed with a second commit (`73cd10b`): threaded `examples_flag` through `cmd_install` → `launch_wizard` → `_make_wizard_commit`. When set, the flag is authoritative for every discovered example (mirrors `resolve_example_selection`'s `all|none|<ids>` semantics), overriding the wizard's own toggle — matching the "flag wins" contract `cmd_install`'s own comment already documented for its (now redundant, see IN-01) post-wizard install step. When unset, behavior matches the review's original fix: the wizard's own `state["segments"]` toggle decides.

Net result: a user who declines a bundled example in the wizard (or leaves it untouched, since it defaults OFF) gets an explicit `false` written and it renders OFF; `--examples=all`/`--examples=none`/an explicit id list on the command line is honored exactly, overriding the wizard toggle; `--examples=none` can no longer be defeated by the eager in-wizard install step (the original CR-01 complaint).

### WR-01: `--examples=none`/wizard-decline path has no test coverage at all

**Files modified:** `tests/test_setup.py`
**Commits:** `0dd101b`, `17ec06d` (test-hygiene follow-up)
**Applied fix:** Added two fast unit tests to `TestExternalSegmentToggle` in `tests/test_setup.py` that call `_make_wizard_commit`'s `commit()` directly:
- `test_wizard_commit_declined_example_installed_but_explicitly_off` — a bundled example the user declines is still installed to disk (satisfies the doctor's structural check) but gets an explicit `system_memory = false` written. Verified this test fails against the pre-CR-01-fix code (confirms it's a real regression test, not a tautology).
- `test_wizard_commit_accepted_example_installed_and_no_explicit_write` — companion/no-regression check: an accepted example is installed with no explicit boolean write (renders on via the present-on-disk default, unchanged prior behavior).

`make e2e-docker`'s clean-room run caught a test-isolation bug in these two new tests: the doctor runs as a subprocess that inherits the real `os.environ`, not the test's fake `paths` dict, so without an explicit `CC_AI_KIT_EXTERNAL_DIR` override the doctor validated against this dev machine's real `~/.config/ai-kit/segments` (which happens to already have `system_memory` installed for real) instead of the test's tmp dir — passing by accident on this machine, failing in the clean container. Fixed in `17ec06d` by wrapping each `commit()` call in `mock.patch.dict(os.environ, {"CC_AI_KIT_EXTERNAL_DIR": paths.segments_dir})`, matching the existing pattern already used elsewhere in the same test class. Verified by temporarily moving aside the real `~/.config/ai-kit/segments/system_memory` and re-running the tests locally (still green), and by a full clean-room `make e2e-docker` re-run (green).

### WR-02: `_persist_layout`'s `known_ext_ids` docstring documents only the ON case, not the OFF case it silently breaks

**Files modified:** `tools/setup.py`
**Commit:** `a923ccd`
**Applied fix:** Rewrote the `known_ext_ids` docstring on `_persist_layout` to state the actual invariant: an id excluded from `known_ext_ids` skips the explicit-write branch entirely (treated as "not yet installed", renderer default applies); an id included is eligible for an explicit write whenever `state["segments"][id]` differs from that default. Made explicit that the caller (`_make_wizard_commit`) is responsible for deciding, per id, which of the two applies — this function only honors whatever set it is given.
