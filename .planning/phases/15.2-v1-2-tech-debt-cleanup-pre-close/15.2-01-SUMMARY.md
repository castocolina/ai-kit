## Decisions Made

- `gsd_run check tdd-red-evidence` requires Node's `--test` TAP output format (`# tests N` / `ok N - name` lines) to classify a RED run; this project's tests run under Python's `unittest`, which never emits TAP. The tool could not be used to auto-verify the RED phase for Task 1. Instead, the RED state was verified by directly running the 3 new tests before the dashboard.py fix and confirming the exact pattern the plan's `<behavior>` section predicted: the flat-mode test failed on its ordering assertion (`['r1', 'r2', ...]` vs expected `['r2', 'r3', ...]`), the drift-guard test failed with `'FLAT_SORT_KEYS' not found` (no declaration existed yet), and the grouped-mode test already passed by construction (regression-locking b9d8a52). This matches the plan's documented "Expected RED before the dashboard.py change" section exactly.
- Fixed one pre-existing, out-of-plan-scope ruff finding (E501 on `PRICE_NOT_APPLICABLE_TOOLTIP`, dashboard.py:718, predates this phase — introduced in Phase 15.1 commit `537106d`) because it sits in the same file Task 1's own `<verify>` command requires to be fully ruff-clean, and the fix is a trivial, zero-semantic-risk line wrap.
