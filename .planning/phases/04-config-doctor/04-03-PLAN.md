## Planner decisions recorded here (not silent)

1. **Only four rows become apply-eligible this wave, not all 25.** Each of
   the four exercises a genuinely different write-format concern (JSON
   top-level, JSON nested, JSONC top-level, TOML nested) so the FULL
   mechanism — dispatcher, atomicity, self-validation, the security-relevant
   literal-config path, the per-item confirm UI — is proven end to end
   without requiring the one case none of the 25 rows currently need
   (recursive nested-JSONC-object creation from nothing). `apply_row`'s
   dispatcher and `CheckRow.apply_target`/`security_relevant` fields are
   fully generic; wiring a 5th row later is a data change to that row's
   existing record, matching D-01's own "adding a row is a data change, not
   an engine rewrite" premise. See `<source_audit>`'s "Deferred" note for the
   full reasoning on why this is not the same class of gap as an unplanned
   REQUIREMENTS.md item.

2. **The TOCTOU window between read and write is accepted, not closed, this
   wave.** `04-RESEARCH.md`'s own Common Threat Patterns table frames this
   explicitly as a planner decision, not a pre-decided fix. See Task 2's
   `<reversibility>` block for the full trade-off; T-04-09 records the
   accepted disposition in the threat register.

3. **`opencode-share-mode`'s applier is the one exception operating on raw
   text rather than a parsed dict**, because `set_jsonc_value` is
   necessarily a text-in/text-out surgical function (that is the whole point
   of byte-preservation) — `claude-retention`/`claude-sandbox-enabled` mutate
   a parsed dict and re-serialize via `atomic_write_json` because plain JSON
   has no byte-preservation requirement in this codebase (value-preservation
   only, per Phase 3's own established precedent), while `codex-history-
   persistence` splices TOML text directly for the same structural reason
   JSONC does — no stdlib TOML writer exists, so a parse-mutate-dump
   round-trip is not an option regardless of byte-preservation policy.

4. **`apply_row` never lets an applier's exception reach the TUI.** The
   `cleanupPeriodDays: 0` refusal, and any other applier failure, is
   returned as `{"ok": False, "reason": ...}` from `apply_row` itself, never
   raised past it — Textual 8.x swallows an unhandled exception reaching a
   confirm handler into a graceful app shutdown (`tools/wizard_app.py:
   129-137`), which would silently end the whole TUI instead of surfacing a
   refused apply. (Addresses cross-AI review finding, MEDIUM severity.)

5. **`tools/config_doctor_appliers.py` is added to `[tool.pyright] include`
   in this wave, not assumed already-covered.** Wave 1 only ever populated
   that list with the three files it itself created; the Makefile `lint:`
   glob and the pre-commit `py-compile` regex happen to already be generic
   enough to cover a fourth `config_doctor_*.py` file, but `[tool.pyright]
   include` is a literal list and is not. (Addresses cross-AI review
   finding, MEDIUM severity.)

6. **`TestNoBulkApply`'s name pattern is explicitly framed as a tripwire,
   not an exhaustive structural proof**, and is extended to also catch
   plural/selector-suffixed names (`apply_rows`, `apply_selected`,
   `apply_each`) beyond the original `all`/`bulk`/`many`/`every` set. The
   primary guarantee remains architectural (`apply_row`'s own one-`row_id`
   signature); the must-haves wording above was softened to say so
   explicitly. (Addresses cross-AI review finding, LOW severity.)
