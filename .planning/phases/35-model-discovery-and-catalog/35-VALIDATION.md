# Phase 35 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Source: 35-RESEARCH.md "Validation Architecture".

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | `unittest` (stdlib), one subprocess per module through `tools/run_unittest_parallel.py` |
| **Config file** | none; groups in `tools/run_unittest_parallel.py` (`ARCH_MODULES`, `UNIT_UV_MODULES`, ...); module listings in `Makefile` and `.pre-commit-config.yaml` are generated by `python3 tools/gen_test_groups.py` |
| **Quick run command** | `python3 tools/run_unittest_parallel.py tests.test_<module>` |
| **Full suite command** | `make test` (tiers `make test-unit`, `make arch-test`, `make test-integration`, `make e2e-test`) |
| **Estimated runtime** | quick about 5-30 seconds per module; `make test-unit` plus `make arch-test` about 1-3 minutes |

---

## Sampling Rate

- **After every task commit:** run the task's own module command from its `<automated>` line (the commit hook also runs the staged modules).
- **After every plan wave:** `make test-unit` and `make arch-test`.
- **Before `/gsd-verify-work`:** `make test` green, `make check-dogfood`, and `python3 tools/gen_test_groups.py` leaves no diff.
- **Max feedback latency:** 180 seconds.
