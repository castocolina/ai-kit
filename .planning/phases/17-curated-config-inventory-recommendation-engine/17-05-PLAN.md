<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| inventory → ai-kit-spec.py subprocesses | the inventory's env and project dir cross into another CLI that may hit the network |
| ai-kit cache files → candidates | cached JSON (possibly stale or edited) becomes model choices |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-16 | Tampering | refresh_catalog env | medium | mitigate | explicit `env=` on both subprocesses; tests use a scratch HOME/XDG so the real cache is never read or written |
| T-17-17 | Denial of service | refresh subprocesses | medium | mitigate | 120 s timeout each; a timeout degrades to stale/none with a warning, never a hang or crash |
| T-17-18 | Information disclosure | candidates | low | mitigate | only the listed catalog fields are copied; the Artificial Analysis key is read solely inside ai-kit-spec.py and never enters the inventory |
| T-17-19 | Spoofing | vendor/router fields | medium | mitigate | routers get `vendor: null` and `router_confirmed` requires the user's recorded confirmation, so an unverified router never counts as a counterpart or wins a slot |
| T-17-SC | Tampering | npm/pip/cargo installs | high | mitigate | no package installs; stdlib only; uv/make calls run with `UV_NO_SYNC=1 UV_OFFLINE=1` |
</threat_model>
