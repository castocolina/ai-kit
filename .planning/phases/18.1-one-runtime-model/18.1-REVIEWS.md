## Cross-plan assessment

**Overall verdict: Changes requested before execution.**

The central architecture is strong: one runtime vocabulary, migration without unsolicited writes, per-call routing, one runner, and preserved custom commands. The main problems are at boundaries rather than in the overall direction:

1. **Migration correctness:** exact command equivalence and variant-aware merging.
2. **Routing correctness:** distinguish failed enumeration from successful empty results; keep native execution independent of subprocess quota.
3. **Supervision:** handle inherited pipes, detached descendants, interruption, and inconsistent status trailers.
4. **Safe setup:** distinguish unreadable files from absent files and propagate guidance-producer failure.
5. **Trustworthy completion evidence:** judge identical final bytes and count tests in isolated interpreters.

The 22-plan sequence also creates unnecessary transitional exposure. At minimum, move legacy compatibility ahead of producer renames and repair guard tests in the same commit that removes their inspected structures. Do not treat fixture-only green commits as proof of upgrade compatibility.

**Not checked:** No tests, live model calls, or real configuration operations were run; this was a read-only source review.

## Orchestrator Verification of Findings

### HIGH — verified, unresolved (10)

1. **18.1-06 factory-command recognizer is token-set membership, not argv-shape equality.**
   `18.1-06-PLAN.md` `<interfaces>` `_legacy_command_knobs` passes any token in `_FACTORY_TOKENS[rid]`
   in any order, count or position, so a hand-written command made only of factory tokens (reordered,
   duplicated, missing `--sandbox read-only`, an extra positional `text`) is dropped and replaced by the
   runner formula. Needed: match the exact factory sequence (binary, fixed flags in order, `{model}`
   slot, optional `-c`/`--mode` knob slots, nothing trailing); anything else stays a D-32 custom entry;
   add reordered/duplicate/missing-token cases to `TestFactoryTemplates`.
2. **18.1-07 field-wise merge can produce a runtime + command hybrid.** `cfg_merge_reviewers` uses
   `dict.update` (`config_io.py:122-126`); a global factory entry migrated to `runtime="codex"` plus a
   trusted local override `{key, command}` merges to both fields. 18.1-07 defines a custom entry as
   `runtime None` + `command` (`render_reviewer_command` prefers `command`, `screen_execute_clis` treats
   it as a runtime candidate) and 18.1-08 rejects the pair at save. Needed: a variant-aware merge rule
   (a local `command` clears an inherited `runtime`; a local `runtime` clears an inherited `command`)
   with tests through load, routing, execute screen and save.
3. **18.1-09 inventory cannot tell a failed listing from an empty one.** `detect_opencode_models` and
   `detect_cursor_agent_models` return `[]` on `OSError`/`TimeoutExpired` (`detection.py:144-148,
   161-166`), and `detect_codex_models` returns `[]` for both failure and a valid empty list
   (`detection.py:250-261`). 18.1-09's `list_runtime_models` is a thin dispatcher over them, and an
   empty list routes `bad_model` (a skip), so a transient opencode/cursor timeout skips every reviewer
