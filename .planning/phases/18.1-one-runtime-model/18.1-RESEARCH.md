## Summary

Phase 18.1 turns every reviewer/executor candidate into a `(runtime, model)` pair under one table in `ai_kit_spec/detection.py`, decides native-versus-subprocess at dispatch time, and routes every subprocess through the one runner template that Phase 18 already ships in `skills/ai-kit-spec-review/references/cross-ai.mjs`. Most of CONTEXT's decisions hold against the code as it stands after Phases 16.1, 17 and 18. The code that exists today is bigger than CONTEXT assumed in three places: Phase 17/18 curated-config already carries its own `cursor`/`cursor-agent` translation (`host.py:49-50`, `cross_ai.py:48-53`) and compares GSD lane `binary` values against installed runtime keys; the runner already has its own live model preflight, a closed `STATUS_TABLE`, and a claude review-only block; and `cfg_write_toml` is already atomic.

Four things in the runner contradict what R7/D-11/D-14 assume, and each was reproduced live this session without a model call. (1) `--timeout` can only lower the deadline, and with no GSD config the runner's outer cap is 300 s (270 s inner), so `timeout_tiers = [600, 1200, 1800]` cannot be honored. (2) The runner rejects cursor bracket-parameter model ids (`claude-opus-4-8[context=1m,effort=high,fast=false]`), a capability `build-model-id` has today. (3) `RUNTIMES.cursor.bins` includes a bare, unguarded `agent`, which D-02 and the cursor CLI profile both forbid. (4) The runner's status names differ from D-12's list (it has `billing`, `no_model`, `empty_stdin`, `usage`, `capacity`, `contract_violation`...; no `idle_stall`, `bad_prompt` or `billing_or_access` yet). Items 1-3 need one runner template bump (`template=3`); the existing sha256/`.new` machinery already supports a version bump (`tests/test_curated_config_script.py:280`).

One decision needs uz before it is built: D-05/D-07 drop the hand-written `command` template, which `ai-kit-spec-config/SKILL.md:224` documents as a supported escape hatch for CLIs outside the factory. uz's D-14 constraint is "add features, never remove them". Everything else is mechanical blast radius, mapped below with the test classes that pin each site.

**Primary recommendation:** Execute D-17's five plans, but insert a runner-contract task (template=3: `--outer-timeout`, bracket-safe cursor model ids, guarded `agent`) as the first task of the runner-swap plan, key every migration on the in-memory choke points (`cfg_resolve` per file, `split_catalog_meta` for the catalog), and put the closed status-to-reason map in data so Phase 25 can extend it.

### Pattern 1: Table rows as NamedTuples (project style, pylint `max-args=5`)
**What:** `RUNTIMES: dict[str, Runtime]` where `Runtime` carries `binaries`, `host_signals`, `list_argv`, `native_selectors`, `model_suffix`, `review_only`, `runner` (bool), `enumerated` (bool). Phase 21 D-09 already plans against the attribute name `RUNTIMES["cursor"].binaries`; keep that exact name.
**When to use:** every per-runtime fact. Derive `KNOWN_CLIS`, `_RUNTIME_ENV_SIGNALS`, `HOST_SIGNAL_ENV_VARS`, `_SUPPORTED_CODEGRAPH_CLIENTS`, `_MCP_LIST_COMMANDS`, `_CODEGRAPH_CAPABLE_MULTI_PROVIDER_CLIS` from it. Keep dict insertion order = detection precedence (pi > opencode > cursor > codex > claude), pinned by `TestRuntimePrecedenceMatrix` (`tests/test_ai_kit_spec.py:1327`).

### Pattern 2: Two entry points over one normalizer
**What:** `normalize_legacy_entry(entry) -> (entry, notes)` is lenient (load time, never raises, drops/maps). `validate_reviewer_fields` is strict (save time: rejects a pinned entry without `runtime`, an out-of-table `runtime`). `cfg_render_toml` runs the normalizer first so saving writes only the new form.
**Why:** SPEC R2 (reject) and R5 (load never fails) are about different moments.

### Pattern 3: Data-driven status map
**What:** `STATUS_TO_REASON = {...}` keyed by the runner's status names; a test parses `STATUS_TABLE` keys out of `cross-ai.mjs` and asserts every one is mapped (drift guard for Phase 25's additions).

### Anti-Patterns to Avoid
- **Hand-rolled per-runtime argv in Python** (the `commands.py` registry): deleted by D-14; `build_runner_argv` only emits the flags the runner documents.
- **Storing the routing decision**: `route` is ephemeral output of `resolve-reviewers`, never in config (SPEC MUST NOT).
- **Matching stderr in Python**: Phase 25 D-01 says Python never matches stderr; read the status line only.
- **Relying on Python's `child_env` for the CLI child**: the runner spawns the CLI and scrubs through its own CONFIG `scrubEnv`; keep `HOST_SIGNAL_ENV_VARS` in sync with it (11 names, tests below).

## Common Pitfalls

### Pitfall 1: Runner caps non-GSD runs at 270 s
**What goes wrong:** review lanes (`[600,1200,1800]` tiers) all time out at 270 s, then escalate through identical caps. **Why:** S3. **Avoid:** land the runner flag first, then the wrapper; prove it in `--self-test` with a small outer value and a fake CLI that outlives the old default inner deadline minus margin. **Warning sign:** `deadline 270s (outer 300s)` in the first stderr line.

### Pitfall 2: Model-suffix forms read as `bad_model`
**What:** the inventory test uses the raw configured model but the runtimes list holds bare ids (cursor `[...]`, opencode `#variant`, pi `:level`). **Avoid:** strip per-runtime `model_suffix` (table field) before membership, as the runner's preflight does (`cross-ai.mjs` `modelSuffix` at `:265` and `:277`, log line "the suffix ... is not validated").

### Pitfall 3: A 30-day inventory rejecting a brand-new model
**What:** SPEC's "never spawn a model absent from inventory" plus a stale `runtimes.json` blocks a model released last week. **Avoid:** on a miss, refresh that runtime's list once (`detect-runtimes --save`) before declaring `bad_model`; the runner's own live preflight is a second guard. **Warning sign:** `bad_model` for an id the CLI's `models` command lists.

### Pitfall 4: stderr swallowed, heartbeat invisible
**What:** `communicate()` returns stderr only at exit, so the runner's 30 s heartbeat (`CONFIG.heartbeatS`) never reaches the orchestrator and the "supervision" signal is lost. **Avoid:** relay stderr line by line while keeping the last `AIKIT-XAI status=` line; write stdout to a temp file. **Warning sign:** a silent 10-minute review.

### Pitfall 5: Binary names compared with ids
**What:** GSD lane `binary` (`cursor-agent`), CLI binary names, and runtime ids all flow through the same sets. **Avoid:** one `runtime_id()` at every boundary listed in section I; a test with a `cursor-agent`-only fixture must still select the cursor lane.

### Pitfall 6: Scrub-set drift
**What:** deriving `HOST_SIGNAL_ENV_VARS` from the table and forgetting the five non-runtime markers makes the Python set differ from the template CONFIG; a child then sees `AI_AGENT` and mistakes its host. **Avoid:** keep the extras in the table module; the existing equality tests (`tests/test_ai_kit_spec.py:11741-11800`) catch it.

### Pitfall 7: pylint/ruff limits on the new wrapper and normalizer
**What:** `build_runner_argv(runtime, model, mode, effort, service_tier, cursor_mode, timeout)` breaks `max-args=5`; the normalizer's branches break `max-branches=12`. **Avoid:** a `RunnerSpec` NamedTuple (the repo's `ExecuteDispatchSpec`/`ReviewerDispatchSpec` pattern) and one small function per legacy form.

### Pitfall 8: Generated test-group listing
**What:** a new `tests/test_*.py` makes `tests/test_gate_scope.py` fail until `python3 tools/gen_test_groups.py` rewrites the Makefile/pre-commit listing. **Avoid:** run it in the same commit as the new module.

### Pitfall 9: Docstring confidence labels
**What:** collapsing `detect_current_runtime`'s per-signal verification text into the table loses labels that a test pins. **Avoid:** keep the docstring and carry the label as table data.

### Pitfall 10: Consent display goes empty
**What:** `trust-local --show` prints a line only for entries with `command`; after the change no entry has one, so the user trusts a file blind. **Avoid:** print the runner argv (runtime, model, mode) per local reviewer; test it.

### Pitfall 11: `error_classifier` left half-dead
**What:** keeping `classify_error` while nothing calls it, or keeping the callers while D-12 says status line only. **Avoid:** decide in plan 4: delete the matchers (Phase 25 assumes so), keep `REASONS` and `entry_reason`, and re-point `TestClassifyError`-style tests at the status map. The suite count may drop only by tests of deleted code (R10).

### Pitfall 12: Clean-room container has no node
**What:** a dispatcher test that shells out to `node` passes locally and fails or hangs in `make e2e-docker`. **Avoid:** unit tests fake `which`/`Popen`; the runner-backed e2e carries `skipUnless` with a printed reason; one always-on test covers `dispatch_unavailable` with an injected `which_fn`.

### Pitfall 13: Ephemeral process leaks in verification
**What:** e2e fakes that hang. **Avoid:** reuse `run_group()` (new session, group kill on timeout, `tests/test_cross_ai_runner_e2e.py:75-95`) and kill anything you start (AGENTS.md).

### Routing (order is the SPEC R3 order)
```python
def route(candidate, host, mode, inventory) -> str:
    rt, model = candidate.runtime, candidate.model
    if rt is None or model == "":                      # session default
        return "native"
    spec = RUNTIMES.get(rt)
    if spec is None or not spec.runner:
        return "no_inventory"
    if rt == host and model in spec.native_selectors:  # host_can_select; claude host only today
        return "native"
    if spec.review_only and mode == "exec":
        return "review_only"
    models = inventory.get(rt)                          # None = no enumerator / failed listing
    if models is None:
        return "no_inventory"
    return "subprocess" if strip_suffix(rt, model) in models else "bad_model"
```
