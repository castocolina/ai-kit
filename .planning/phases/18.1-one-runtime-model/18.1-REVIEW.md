## Critical Issues

### A-CR-01: An exception during the supervised wait orphans the child (docstring promise is false)

**File:** `skills/ai-kit-spec-review/ai_kit_spec/runner_dispatch.py:390-420`
**Issue:** `_supervise_child` only returns a `_ChildRun` after `_wait_for_exit` completes.
If `_wait_for_exit` raises (a `KeyboardInterrupt` delivered in `seams.sleep_fn`, which is
exactly where the main thread sits for the whole run), the `proc` reference is lost: in
`_spawn_supervised` the `except BaseException` branch calls `_cleanup_spawn(run, ...)` with
`run is None`, which skips `_reap_group` entirely. The child was started with
`start_new_session=True`, so it does not receive the terminal's SIGINT either. Line 405's
"Cleanup runs on every exit path, including an exception during the wait" is not true.

Reproduced: `run_custom_command(CustomSpec(..., [20]))` with `_thread.interrupt_main()` after
1 s → `KeyboardInterrupt` propagates and the child (pid 794590) was still alive after cleanup.

Consequences by path:
- custom launcher (`run_custom_command`): no pgid file, so the full child survives until it
  exits on its own (a hung custom CLI: forever);
- runner (`run_runner`): the recorded CLI groups at that instant are killed via the pgid
  file, but the `node` runner itself survives, treats the killed CLI as `crash`, and in exec
  mode may retry or fall through to its own deadline (up to `--outer-timeout`) while the user
  believes the run was aborted.

**Fix:** keep `proc` reachable on the exception path; `_spawn_supervised` already re-raises
`run.error` after cleanup, so the smallest change is in `_supervise_child`:
```python
    relay = _start_stderr_relay(proc.stderr, work.seams)
    deadline = work.seams.time_fn() + work.request.deadline_s
    try:
        timed_out = _wait_for_exit(proc, work.seams, deadline)
    except BaseException as exc:  # KeyboardInterrupt included: the child is still reaped
        return _ChildRun(proc, True, relay, exc)
    return _ChildRun(proc, timed_out, relay)
```
Add one fake-seams test in `TestRunRunnerFake`: `sleep_fn` raises `KeyboardInterrupt`,
`assertRaises(KeyboardInterrupt)`, then assert `(4242, SIGTERM)` and `(4242, SIGKILL)` are in
`kills`. Fix the line-405 docstring if the behaviour is instead meant to be "not covered".

### A-WR-02: The unquoted GSD hook turns a cursor bracket model into a bash glob

**File:** `skills/ai-kit-spec-review/ai_kit_spec/runner_dispatch.py:30-31,126-149`
**Issue:** `project_runner_command` deliberately admits one `[k=v,...]` suffix for cursor
(`_HOOK_BRACKET_RE`). GSD runs the hook as `… -- ${CROSS_AI_CMD}` with no quotes
(`.claude/gsd-core/workflows/execute-phase/detail/elaboration.md:98`), so every token is
subject to pathname expansion before `run-with-timeout` sees it. `gpt-6[effort=high]` is a
bracket expression matching `gpt-6` + one of `e f o r t = h i g`. Reproduced: with a file
`gpt-6e` in the cwd, `bash -c 'for t in ${CMD}; …'` yields `[--model-cursor] [gpt-6e]`. The
run then fails as `bad_model` (or, worse, matches a real listed id). The allowlist comment
("none of the shell metacharacters") is incomplete: `[` and `]` are glob metacharacters.
This touches D-18/D-30 (bracket ids, the hook) but does not contradict them: the runner's
argv path keeps supporting bracket ids; only the unquoted hook string cannot carry them.

**Fix:** do not emit bracket models into the hook string; let the caller fall back to the
bare id or refuse, as it already does for any other unsafe token:
```python
def project_runner_command(spec, *, guidance=False):
    ...
    for token in tokens:
        if not HOOK_TOKEN_RE.fullmatch(token):   # no bracket exception: ${CMD} is globbed
            return None
```
Drop `_HOOK_BRACKET_RE` and `_hook_token_ok`; flip `test_bracket_model_only_for_cursor` to
`assertIsNone` for both runtimes and add a one-line note in the execute-gsd SKILL.md that
cursor effort/fast brackets are argv-only (Python dispatch), not hook-capable.

### A-WR-03: An unknown or non-string runtime with an empty model routes `native`

**File:** `skills/ai-kit-spec-review/ai_kit_spec/routing.py:129-143`
**Issue:** `_route_shape` checks `no_model` only for table runtimes, then returns `"native"`
for any empty model before the `unknown_runtime` check. Reproduced:
`route(RouteInput("gemini", ""), …)` → `native`; `route(RouteInput(["codex"], ""), …)` →
`native`. A hand-edited `runtime = "gemini"` entry with no model therefore silently becomes the
host's session default instead of the visible skip D-20 locks ("keeps an unknown name as an
entry that routes to a visible skip"). The `test_table` case for `gemini` only covers a
non-empty model.

**Fix:** decide `unknown_runtime` before the session-default rule, keeping D-07's
"no runtime, no model → session default":
```python
    runtime = entry.runtime
    if runtime is not None and (not isinstance(runtime, str) or runtime not in RUNTIMES):
        return "unknown_runtime"
    if isinstance(runtime, str) and (not isinstance(entry.model, str) or entry.model == ""):
        return "no_model"
    if entry.model == "" or entry.model is None:
        return "native"
    return None
```
Add to `test_table`: `(_entry("gemini", ""), "claude", "review", listed, "unknown_runtime")`.
