# Phase 18.1: One runtime model — Specification

**Created:** 2026-10-14
**Ambiguity score:** 0.15 (gate: ≤ 0.20)
**Requirements:** 10 locked

## Goal

ai-kit describes every model candidate as a (runtime, model) pair under one runtime-id
vocabulary. It decides native versus subprocess at dispatch time from the current host, and
spawns every subprocess through the one supervised runner. `native_runtime`, `native_claude` and
the cursor/cursor-agent split are removed, and old configs still load.

## Background

Source: `.planning/research/2026-10-13-audit/18-runtime-detection-and-subprocess-supervision.md` (§1–§2, §5).

- **`native_runtime` is validated but never read.** It appears in `config_io.py:96-135` and
  `model_catalog.py:50-53,157-164` (two duplicate `_VALID_NATIVE_RUNTIME` sets), in
  `cli.py`'s `detect-current-runtime` output, in AGENTS.md's Architecture paragraph, in the
  ai-kit-spec-config SKILL.md (Step 2.7/3) and in about 34 test lines. No code compares it with
  the host, so a native `model = "opus"` entry saved under Claude Code dispatches the same way
  from an opencode host.
- **One runtime, two names.** `detect_current_runtime()` says `cursor`, but `KNOWN_CLIS`
  (`detection.py:19`) says `cursor-agent`, so a `target == host` check never matches for cursor.
  `KNOWN_CLIS` also lacks `pi`.
- **Host-specific wording.** superpowers uses `mode: "native_claude"` (`dispatch_injection.py`,
  `cli.py`, SKILL.md, `references/escalation.md` and tests), and the review SKILL.md writes the
  four Agent-tool aliases as the rule rather than as the Claude Code example.
- **Two Python supervisors.** `dispatch_with_heartbeat` (`dispatch.py`, `execute_dispatch.py`,
  superpowers) and `dispatch_with_polling` (`reviewer_dispatch.py`) predate the runner contract
  that Phase 18 builds into the `cross-ai.mjs` template (XAI-02).
- **The Claude subprocess inventory** (`CLAUDE_FALLBACK_MODEL_IDS`, `_meta.anthropic_model_ids`,
  `claude_runtime_is_current`; about 25 references) serves Claude as a subprocess target.
  Claude is never an execution target (18 D-10, 16.1 D-15). It can still be a GSD review lane on
  a codex or opencode host, where Phase 18 R2 fills `review.models.claude` from the inventory.
- **Native per-call model selection** is verified only for Claude Code (`Agent(model=alias)`).
  For opencode, cursor, grok and pi it is unverified until Phases 20–22.
- **Phase 16.1** already adds the `GROK_AGENT` signal and `HOST_SIGNAL_ENV_VARS`. Phase 17
  derives pairs from the current catalog; this phase makes the pair the schema.

## Requirements

1. **One runtime-id vocabulary** (RTM-02): one name per runtime.
   - Current: `cursor` versus `cursor-agent`; no `pi` in `KNOWN_CLIS`.
   - Target:
     - One table in `ai_kit_spec/detection.py` lists the ids `claude, codex, opencode, cursor, grok, pi` with each id's binaries (cursor → `cursor-agent`, `agent`).
     - `KNOWN_CLIS`, host detection, quota keys, CLI profiles and curated-config all use the ids.
     - `detect-current-runtime` prints `{"host": …}`.
   - Acceptance: a test asserts every runtime id used anywhere in the code is in the table. A `cursor` host matches a `cursor` candidate. `rg cursor-agent` finds it only as a binary name.

2. **Pairs** (RTM-01): a candidate always names its runtime.
   - Current: native entries have `cli: None` plus an alias.
   - Target: every pinned candidate is `(runtime, model)`. The one exception is the session default, `model == ""`, meaning the host's default model (today's `NO_CONFIG_FALLBACK`).
   - Acceptance: schema validation rejects a pinned entry without `runtime`. The session default round-trips.

3. **Dispatch-time routing** (RTM-01): native or subprocess is decided, never stored.
   - Current: nothing compares an entry with the host.
   - Target:
     - A candidate runs as a native subagent when `runtime == host` and `host_can_select(model)` is true.
     - Otherwise it runs as a subprocess when the model is in that runtime's inventory.
     - Otherwise it gets `status=bad_model` and is skipped, never spawned.
     - `host_can_select` is true for Claude Code's aliases on a claude host. On other hosts it is true only for the session default, until Phases 20–22 verify per-call selection. That limit is labelled in code and SKILL.md.
   - Acceptance: a table test covers claude-host alias (native), claude-host non-alias (subprocess), opencode-host opencode model (subprocess), a model missing from the inventory (`bad_model`, no spawn) and the session default (native).

4. **`native_runtime` removed** (RTM-01).
   - Current: in schema, two validators, CLI output, AGENTS.md, SKILL.md and tests.
   - Target: no code, schema, doc or test mentions `native_runtime`, except the migration and its test.
   - Acceptance: `rg native_runtime` outside `.planning/` and `docs/` history matches only the migration code and its test.

5. **Old configs load** (RTM-01): no user is broken.
   - Current: n/a.
   - Target:
     - An entry with `native_runtime = X` loads as `runtime = X`.
     - A `cli`-less entry without it loads as the session default.
     - Both print one visible note per file naming the entry.
     - Saving writes only the new form.
   - Acceptance: fixtures of the old forms load, print the note and re-save in the new form. A load never fails on the old form.

6. **`native_claude` → `native`** (RTM-02).
   - Current: about 21 references in superpowers.
   - Target: the mode is `native`, and its payload carries `runtime` and `model`.
   - Acceptance: `rg native_claude` outside history is empty. Superpowers tests pass with the new payload.

7. **One supervisor** (RTM-01): every subprocess goes through the runner.
   - Current: `dispatch_with_heartbeat` and `dispatch_with_polling`.
   - Target:
     - ai_kit_spec's review and execute dispatchers spawn subprocess candidates through the runner template shipped inside the skill (the same file Phase 18 renders into projects), in `review` or `exec` mode.
     - They read its exit code and `AIKIT-XAI` status line.
     - The two Python supervisors are deleted.
   - Acceptance: dispatcher tests use a fake CLI behind the shipped runner and see each status mapped to the review/execute outcome. `rg "dispatch_with_(heartbeat|polling)"` outside history is empty.

8. **Claude subprocess inventory, review-only** (RTM-01).
   - Current: about 25 references serving claude as a subprocess target.
   - Target:
     - What the review path from non-Claude hosts needs (the model list for a `claude` review lane) stays, labelled review-only.
     - Execution-only parts are deleted.
     - Claude Code's alias set stays as the host's native selector set.
   - Acceptance: on a codex-host fixture a `claude` review lane gets models. No execution path can target claude. The label appears in code and SKILL.md.

9. **One-model wording** (RTM-03).
   - Current: host-specific wording in ai-kit-spec-review, ai-kit-spec-config, ai-kit-spec-execute-superpowers, ai-kit-spec-execute-gsd, ai-kit-gsd-curated-config and AGENTS.md (Architecture: the `native_runtime` paragraph and its 2026-09-09 amendment).
   - Target: every affected SKILL.md and AGENTS.md state the pair model and the dispatch rule host-agnostically. Claude Code is named only as an example.
   - Acceptance: each rewritten SKILL.md passes `/skill-judge` (≥ 96/120 or no Critical/Important finding, no regression).

10. **Gates** (RTM-03).
    - Current: green.
    - Target: the tests are updated, not deleted, wherever behavior survives. `make test` and `make validate` are green.
    - Acceptance: both are green. The test count drops only by tests of deleted code.

## Boundaries

**In scope:**
- The runtime-id table, the pair schema, the dispatch rule and the migration
- Removing `native_runtime`, `native_claude`, the cursor/cursor-agent split and the two Python supervisors
- Narrowing the Claude subprocess inventory to review-only
- SKILL.md and AGENTS.md rewrites with `/skill-judge`

**Out of scope:**
- The runner template and its contract: Phase 18 (XAI-02); this phase consumes it
- pi model enumeration: Phase 22; cursor wrapper: Phase 21
- Verifying per-call native model selection on non-Claude hosts: Phases 20–22
- Replacing the quota pre-probe with run classification: optional per the research, not required (see Interview Log)
- GSD's own review lanes: unchanged

## Constraints

- Runtime code stays stdlib-only. The runner is invoked as argv, with no shell.
- Old configs never fail to load (core value: never break a user silently).
- No routing fact is stored in config. The host is always detected at dispatch time.

## Acceptance Criteria

- [ ] Every runtime id in code is in the one table; a cursor host matches a cursor candidate
- [ ] A pinned entry without `runtime` is rejected; the session default round-trips
- [ ] The routing table test passes for all five cases, and `bad_model` never spawns
- [ ] `native_runtime` appears only in the migration and its test
- [ ] Old-form fixtures load with a note and re-save in the new form
- [ ] `native_claude` is gone; the superpowers payload carries `runtime` and `model`
- [ ] Subprocess candidates run through the shipped runner; the two Python supervisors are gone
- [ ] A `claude` review lane on a codex host gets models; no execution path targets claude
- [ ] Each rewritten SKILL.md passes `/skill-judge`
- [ ] `make test` and `make validate` are green
- [ ] MUST NOT: a config never stores a routing decision (native vs subprocess)
- [ ] MUST NOT: an old config never fails to load or silently changes meaning without a note
