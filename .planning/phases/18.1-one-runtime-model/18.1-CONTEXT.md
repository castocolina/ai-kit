# Phase 18.1: One runtime model - Context

**Gathered:** 2026-10-14 (assumptions mode, `--analyze --all --batch`, jev screening, best over easy)
**Status:** Ready for planning

<domain>
## Phase Boundary

Every model candidate becomes a (runtime, model) pair under one runtime table. Native versus
subprocess is decided at dispatch time, and every subprocess goes through the one shipped
runner. `native_runtime`, `native_claude` and the cursor/cursor-agent split are removed, and old
configs still load. The WHAT is locked in `18.1-SPEC.md` (R1–R10). This file locks the HOW.

Execution order: after 16.1, 17 and 18, which change the same files. Re-run the inventory greps
at plan time (see `<code_context>`).
</domain>

## Implementation Decisions

### Runtime table and detection (R1)
- **D-01: One `RUNTIMES` mapping in `ai_kit_spec/detection.py`.**
  - Per id it holds the binaries, the host env signals, the model-list command, the host's
    native selector set (claude: the 4 aliases; others empty) and a `review_only` flag.
  - Derived from it: `KNOWN_CLIS`, `_RUNTIME_ENV_SIGNALS`, 16.1's `HOST_SIGNAL_ENV_VARS`,
    `_SUPPORTED_CODEGRAPH_CLIENTS`, `_MCP_LIST_COMMANDS` and
    `_CODEGRAPH_CAPABLE_MULTI_PROVIDER_CLIS`.
  - A `runtime_id(name)` normalizer is exported for Phase 17's pair derivation.
  - `tools/config_doctor_checks.py` cannot import from `skills/`, so a test checks its runtime
    literals against the table.
- **D-02: Cursor binaries are `cursor-agent`, plus `agent` only after a realpath check.**
  - `~/.grok/bin/agent` also exists on this machine, so PATH order decides what a bare `agent`
    is.
  - `agent` is accepted only when its resolved real path's basename is `cursor-agent`.
  - The CLI profile's "never probe bare `agent`" rule stays true for unguarded probes.
  - This amends 18.1-SPEC R1 and 21-SPEC R4.
  - Own reasoning; both models were low (Laya both 0.39 fb, TypeSafe agent_with_realpath
    0.52 fb). Provisional, so it is on the end-of-run ledger.
- **D-03: grok is not a detectable host.**
  - Its id stays in the table for binaries and the host-signal scrub (16.1 D-14 keeps
    scrubbing `GROK_AGENT`).
  - `detect_current_runtime` does not return `grok`: its nesting order is unverified, and grok
    is dropped as a host and as a target (18 D-10).
  - TypeSafe "no" 0.89.
- **D-04: Only `model-catalog.json` needs a key migration.**
  - On load, `runtimes.cursor-agent` is renamed to `runtimes.cursor`, gated by
    `_meta.schema_version < 3`.
  - User-confirmed entries (`heuristic_confirmed`, `confirm-catalog-entry`) are never wiped.
  - `runtimes.json`: bump `RUNTIMES_SCHEMA_VERSION` current + 1 (4 → 5 after Phase 18; was
    documented as 2 → 3 before Phase 17 landed 3) (amended 2026-10-15, 18-22, research
    correction 7).
  - `quota.json` is keyed by reviewer key, not runtime id, so it needs nothing. This amends
    the SPEC R1 "quota keys" wording.
  - `opencode-providers` `cross_reference.py:57` also scans `runtime`.
  - The CLI profile `cursor-agent.md` becomes `cursor.md` (`id: cursor`; `detect:` stays the
    binary).
  - v1 `CLI_TO_REVIEWER_SLUG` becomes identity and is removed.

### Pairs, routing and migration (R2–R6)
- **D-05: One `runtime` field.**
  - It replaces `cli`, `native_runtime` and the `command` template on every pinned entry.
  - `_KNOWN_REVIEWER_FIELDS` becomes `{key, model, vendor, runtime}`, and `ResolvedReviewer`
    becomes `(key, model, vendor, runtime, extra)`.
  - The session default has neither `runtime` nor `model`.
  - `resolve-reviewers` adds an ephemeral per-run `route` to its JSON output, never to config.
  - TypeSafe 0.87, over Laya keep_cli 0.59 fb.
- **D-06: Migration is in memory, at the `cfg_resolve` choke point, per file.**
  - It runs before `cfg_merge_reviewers` and inside 16.1's trust gate.
  - Load normalizes and never fails. One note per file per process goes to stderr through an
    injected `warn_fn`; it names the entries and the re-save command.
  - Persisting happens only through the wizard or `render-toml --out`.
  - `cfg_write_toml` becomes atomic (`mkstemp` + `os.replace`).
  - Laya in_memory 0.78. Rewriting on load would break the trust-store hash and edit a user
    file unprompted.
- **D-07: Old forms map as follows.**
  - `native_runtime = X` → `runtime = X`.
  - `cli = <id>` → `runtime = runtime_id(<id>)`. `command` is dropped with a note, because
    argv now comes from the runner.
  - A `cli`-less entry without `native_runtime`, whose model is one of Claude Code's 4
    aliases, → `runtime = "claude"` with an **inferred** note. Before Phase 1.2, native meant
    Claude Code only (config SKILL.md:248-250).
  - Any other model → session default, with a note naming the dropped model.
  - `native_runtime = "unknown"` → session default.
  - Own reasoning; both models were low (Laya session_default 0.42 fb, TypeSafe
    unresolvable_skip 0.52 fb). Provisional, so it is on the ledger.
- **D-08: Routing is a small module that imports the table.**
  - Per call it returns `native | subprocess | bad_model | no_inventory`.
  - `no_inventory` means a runtime with no enumerator yet (grok; pi is enumerated from Phase 18): "cannot
    verify", never "bad model".
  - `host_can_select` is true for Claude Code aliases on a claude host, and for the session
    default elsewhere. The limit is labelled in code and SKILL.md.
  - TypeSafe no_inventory 0.89. This amends SPEC R3's empty-inventory edge.
- **D-09: superpowers `native_claude` → `native`.** The payload carries `runtime` and `model`.
  The `external_cli` mode name stays, and its payload field becomes `runtime`. `adapter.py`
  derives `tier` from "runtime is claude and model is an alias".
  `SMOKE_TEST_RESULTS.md` moves under `docs/` (history), so the R6 grep stays clean.

### One supervisor (R7)
- **D-10: The runner template lives in `ai-kit-spec-review`.**
  - An `ai_kit_spec` helper finds it, in the style of `tooling_guidance.py`.
  - Curated-config renders it through its existing sibling bridge
    (`model_detect.resolve_ai_kit_spec_path`), so the dependency stays one-way.
  - TypeSafe 0.87, over Laya config_skill 0.47 fb. Phase 18 adopts this location (18 CONTEXT).
- **D-11: The call shape is one candidate per call.**
  - Argv: `["node", <runner>, "--prefer", runtime, "--model-<runtime>", model, "--mode",
    "review|exec", "--timeout", s, "--no-preamble"]`.
  - It runs with `start_new_session=True`, and `killpg` is only a backstop.
  - Ladder, quota and vendor policy stay in Python.
  - `timeout_tiers` escalation re-invokes with the next tier's `--timeout` on exit 124.
- **D-12: One closed status table.** Python parses the last `AIKIT-XAI status=` line and maps
  it to 16.1 D-13's typed reasons:
  - `quota` → quota;
  - `auth`/`billing` → auth;
  - `timeout`/`idle_stall` → timeout;
  - `bad_model`/`bad_prompt`/`permission_blocked`/exit 2 → configuration;
  - runner 127 or `OSError` launching node → dispatch_unavailable;
  - everything else → real_error.

  `capacity` after retries (exit 75) needs a non-wake reason. That is a planner item: extend
  D-13's set with `capacity` rather than overload `quota`. Laya status_table 0.78.
  - *Amended 2026-10-14 (25 D-21):* `billing` no longer maps to `auth`. The runner's `billing_or_access` status maps to a new non-wake reason `billing_or_access` ("add credits or enable the model"); `quota_wait` maps to `quota`; `capacity` is added as the non-wake reason above.
- **D-13: No node means fail closed.** Subprocess candidates get `dispatch_unavailable`, with
  one visible line ("subprocess dispatch needs Node"). They are skipped, and the ladder or the
  native session default continues. `build_runtimes_snapshot` records `node` presence. There is
  no Python fallback supervisor. TypeSafe 0.99.
- **D-14: The Python builders are deleted and their callers re-pointed.**
  - One `build_runner_argv(runtime, model, mode)` replaces the `commands.py` builder registry,
    `build_execute_command`, `build_reviewer_command`, `NO_HARD_SANDBOX_CLIS` and the `command`
    field.
  - Four callers move:
    - the quota probe (`--mode review --timeout 30`);
    - v1 `cross_ai_build.build_execution_command`;
    - the GSD adapter `build_cross_ai_command`;
    - superpowers `_is_dispatchable`, which is replaced by routing.
  - The v1 tests are updated where behavior survives: v1 `apply-execution` still writes a
    working command, now the runner's.
  - **This touches 18 D-08** ("v1 intact, tests unmodified"). ~~It is decided provisionally and
    on the ledger for uz.~~ *(confirmed by uz 2026-10-14, with a constraint)*
  - **Constraint (uz, 2026-10-14): add features, never remove them.** Only the duplicated
    command-building code goes away. Every v1 subcommand, flag and behavior keeps working
    through the runner, and so does every feature added in v1.2/v1.3. A v1 test changes only
    where the generated command text changes; no test case for a feature is deleted. If
    re-pointing a caller would drop a capability, keep that capability (port it into the runner
    or keep the old path) instead of dropping it.
  - TypeSafe 0.97.
  - The soft-confinement prose (`execute_dispatch.py:19-29`) now applies to every runner exec
    target, because the runner uses full-permission flags (18 D-10).

### Plan-time research decisions (RUN-74, 2026-10-16)
Research (`18.1-RESEARCH.md` Open Questions) found facts the decisions above predate. Jev ladder
(TypeSafe, Laya fallback) per item; amended decisions marked here win over D-01..D-17.

- **D-18 (Q1): The runner gets a `template=3` bump in this phase.** It fixes three verified
  defects that block D-11/D-14: the non-GSD 270 s deadline ceiling that ignores
  `timeout_tiers` (add an explicit outer-timeout path), cursor bracket model ids
  (`model[context=1m,...]`) rejected by the id charset, and the bare `agent` binary accepted
  unguarded (realpath must resolve to cursor-agent). Each fix gets a `--self-test` case; the
  version-bump path (`.new` on a user-edited script) is reused. Status-line changes are
  coordinated with Phase 25. Amends SPEC Boundaries. TypeSafe A 0.99.
- **D-19 (Q2): One bounded refresh on an inventory miss**, then `bad_model` with no spawn.
  TypeSafe A 0.99.
- **D-20 (Q3): Out-of-table `runtime`:** load normalizes known legacy names (`cursor-agent`,
  `agent`) through `runtime_id()` with a note, keeps an unknown name as an entry that routes to a
  visible skip; save-time validation rejects anything outside the table. TypeSafe A 0.99.
- **D-21 (Q4): Keep the hand-written `command` escape hatch, amending D-05/D-07.** An entry
  with a `command` and no table runtime is a trust-gated custom entry (`trust-local` as today),
  run through a small fixed-argv launcher (no shell) as a subprocess outside the runner. D-07's
  "`command` is dropped" applies only when the entry also names a table runtime (argv then
  comes from the runner, with a note). Owner rule: never remove features. TypeSafe A 1.0.
- **D-22 (Q6): A migrated model-less subprocess entry** loads with a visible note and routes
  to a visible skip; save-time validation rejects it. TypeSafe A 0.99.
- **D-23 (Q7): Delete `classify_error` and its stderr signal tuples; keep `REASONS` and
  `entry_reason`.** Own reasoning over TypeSafe B 0.75 (Laya A): after D-11 every subprocess
  runs through the runner, which classifies, so a Python matcher has no input; Phase 25
  D-01/D-20 already assume the matchers are gone.
- **D-24 (Q9): Rename cross-module `cli` dict keys to `runtime`** in one mechanical commit
  (catalog_build, cli discovery, adapters); local variable names stay. Public flags keep `--cli`
  aliases. TypeSafe A 0.86 (Laya B fallback).
- **D-25 (Q10): GSD `native_tier` routing does not consult the host** in this phase; only its
  fields are re-keyed. TypeSafe A 0.96 (Laya B fallback).
- **D-26 (Q11): GSD `workflow.cross_ai_command` and v1 `apply-execution` point at the
  project-local rendered `.planning/scripts/cross-ai.mjs`** (relative path, Phase 18 renderer),
  never an install path. TypeSafe A 0.94.
- Q5 and Q8 (discretion): SKILL.md states "Node 24 (GSD's declared floor); older versions
  untested"; the thin wrapper lives in a new `ai_kit_spec/runner_dispatch.py`.

- **D-30 (ratifies the planner's `--append-file`, amends D-18/D-26):** the guidance file is

- **D-31 (amends D-08/SPEC R3): `unverified` route** only when a runtime's listing is

- **D-32 (amends D-07): a hand-tuned `command` on a table-runtime entry** whose flags go beyond
  what the runner formula reproduces migrates as a D-21 custom entry (trust-gated) with a note;

- **D-33 (amends D-26): the GSD hook setup renders or upgrades the project runner itself**
