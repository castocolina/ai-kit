<interfaces>
Judge procedure (18.1-22 reuses it verbatim):
- DIGEST_CMD (the content digest of what a judge reads for `<skill>`: SKILL.md plus every file under
  `references/`, by relative path and content):
  `python3 -c 'import hashlib,pathlib,sys; d=pathlib.Path("skills",sys.argv[1]); fs=[d/"SKILL.md"]+sorted(p for p in (d/"references").rglob("*") if p.is_file()); h=hashlib.sha256(); [h.update(p.relative_to(d).as_posix().encode()+b"\0"+hashlib.sha256(p.read_bytes()).digest()) for p in fs]; print(h.hexdigest()[:16])' <skill>`
- Digest check `tmp/judge/check_digests.py <evidence file> <skill>...` (written at setup, stdlib only):
  for each named skill, finds its `## <skill>` section, reads the table rows, and for every row whose
  Verdict cell does not start with `superseded` compares the Digest judged cell with DIGEST_CMD's
  output for that skill (run via `subprocess.run` with an argv list); prints `digests ok` and exits 0
  when all match and each skill has at least one non-superseded row, else prints each mismatch and
  exits 1.
- Setup: `mkdir -p tmp/judge/out tmp/judge/baseline`; rubric: `cp "$HOME/.agents/skills/skill-judge/SKILL.md" tmp/judge/rubric.md`
  (a read-only copy of the installed skill-judge skill: nothing under `$HOME` is ever written, and the
  real `~/.claude` is never read; the file missing -> stop and report: the gate cannot run); per skill,
  the whole baseline skill directory, so BASELINE is judged with its own `references/` exactly as
  CURRENT is (like for like): `git archive a8e24c3 skills/<skill> | tar -x -C tmp/judge/baseline`
  (it lands at `tmp/judge/baseline/skills/<skill>/`; a skill absent at `a8e24c3` -> stop and report).
- Prompt file `tmp/judge/<skill>.prompt.md`: "Use your read-only tools. Read the rubric at
  `tmp/judge/rubric.md`. Judge two versions of one skill: BASELINE at
  `tmp/judge/baseline/skills/<skill>/SKILL.md` (with its `references/` directory) and CURRENT at
  `skills/<skill>/SKILL.md` (with its `references/` directory). Score both on every rubric dimension, give each total out of 120, and list
  CURRENT's findings as Critical, Important or Minor with the line they concern. End with exactly four
  lines: `BASELINE <n>/120`, `CURRENT <n>/120`, `CRITICAL <n>`, `IMPORTANT <n>`."
- Before a skill's judges start, record `D_before` = DIGEST_CMD for that skill; after every judge of
  that round has returned, record `D_after`; `D_before != D_after` voids the round (re-run it; nothing
  may edit the skill while its judges run).
- Judge call (from the repo root; the two models run in parallel with `&` and `wait`):
  `node skills/ai-kit-spec-review/references/cross-ai.mjs --prefer pi --model-pi <model> --mode review --no-preamble --outer-timeout 1830 --timeout 1800 < tmp/judge/<skill>.prompt.md > tmp/judge/out/<skill>-<tag>.md 2> tmp/judge/out/<skill>-<tag>.err`
  with `<model>`/`<tag>` = `openai/gpt-6.1-sol:xhigh`/`pi-gpt-6.1-sol-xhigh` and
  `zai-coding-cn/glm-5.3:xhigh`/`pi-glm-5.3-xhigh`. The last `AIKIT-XAI` line of the `.err` file is
  the status: `ok` -> move the `.md` into `.planning/phases/18.1-one-runtime-model/skill-judge/`;
  `quota`/`capacity`/`billing` -> retry once after 60 s; any other status, or a second failure ->
  write `skill-judge/<skill>-<tag>.md` holding "judge unavailable" plus the status line verbatim.
- Pass rule per judge: (`CRITICAL 0` and `IMPORTANT 0`) or `CURRENT >= 96`, and
  `CURRENT >= BASELINE`. A failing judge: fix `skills/<skill>/SKILL.md` (or its references), run
  `python3 -m unittest tests.test_ai_kit_spec_runtimes_table -k TestWordingGrep`, mark every existing
  row of that skill `superseded (<new digest>)`, and re-run ALL judges of that skill (both pi judges
  and the in-session judge) on the new digest; at most three rounds per skill, then record the
  remaining findings verbatim.
- In-session judge: the executing agent applies the same rubric to each skill (baseline vs current)
  and writes one section per skill, with the same four closing lines, to the in-session report.
- Evidence file `18.1-SKILL-JUDGE.md`: one `## <skill>` section per skill with the table columns
  Judge, Digest judged, Score, Baseline, Critical/Important left, Verdict, Report; "Digest judged" =
  the `D_before` of that judge's round (equal to `D_after`); "Report" = the `skill-judge/` file;
  superseded rows keep their values and get Verdict `superseded (<new digest>)`; plus context rows
  (Digest judged `-`, Verdict `context`) for D-16's recorded scores (spec-config 104/120 from 16-SKILL-JUDGE.md; spec-review from
  16.1's loop results; opencode-providers: none recorded).
