## Method

The arms are **in-session subagents** (the general-purpose agent, sonnet) started by the
orchestrator — not `claude -p`. 5 reps per scenario per arm, and each rep's final message is
saved verbatim as `pressure/<arm>-<scenario>-<rep>.md` (for `none`, `current` and `green`:
5 scenarios x 3 arms x 5 reps = 75 files).

Weaker than the plan's original design, stated plainly (D-23):

- No `claude -p`, because a run writes session state under the real Claude config dir, and
  pointing `CLAUDE_CONFIG_DIR` at a scratch dir loses the login — so the control cannot be a
  fresh CLI process here.
- A subagent can still see globally installed skills, so the `none` arm is *told* not to load
  any skill instead of being prevented from doing so. The `none` arm is therefore an
  approximation of "no skill at all".
- Every arm prompt ends with: "Describe exactly what you would do and the commands you would
  run; do not run any command." So no arm spends a real call, dials a remote endpoint, or
  writes to a user config file.

A scenario whose `none` arm does not show the expected failure is redesigned before GREEN (plan
Task 1 Step 2).
