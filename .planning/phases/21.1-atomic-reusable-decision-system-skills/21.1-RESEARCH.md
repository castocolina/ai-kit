## Summary

The phase is a port-and-generalize job. The v3 reference (`main:.planning/docs/system-one-decision-skill/scratchpad/v3/skill/scripts/jev_review.py`, 523 lines, 42 test functions) already has the BACKENDS table, `_dispatch`, `screen()` and `--probe`. It branches on backend names in `backend_url`, `backend_key`, `probe`, `_remotes_available`, `_retry_opencode` and `screen()` (`/tmp`-extracted copy lines 60-91, 349-375, 388-495), so R2's stub-fourth-row test fails until those become row callables (D-05). It also has no Laya error taxonomy, `_PROB_SUM_TOLERANCE = 1e-3` (line 126; must be `2e-2`), no `score` type in `decide.py`, and no consent record, answer log, rung trail or deadline.

Five findings change plans and are not in CONTEXT.md:
1. **Laya `/v1/systemone/batch` is the wrong shape for item batching.** It answers ONE shared `questions` set over many `states`. Heterogeneous items (different instructions) cannot use it. Keep `batch: False`, one request per item (`laya/serve.py:1229-1251`, `docs/http-api.md:364-366`).
2. **Laya truncation is not silent.** The response carries `usage.truncated`, `state_tokens_dropped`, `truncated_questions` unless the server runs `LAYA_JEV_STRICT=1`. The client must read it and force `needs_fallback`.
3. **The Zen endpoint in the docs differs from the plan's.** Docs fetched today: `https://opencode.ai/inference/systemone/v1/systemone`, ids `jev-1.13` / `jev-1.13-free` only (no 1.14). The plan and live skill use `https://opencode.ai/zen/v1/systemone` (live-verified 2026-10-11). Make the row URL overridable and add a live-check step.
4. **`jev-latest` still resolves to `jev-1.13.0` in TypeSafe's docs today, and moves to 1.14.0 about 2026-10-21.** The exact-match pin in `decide.py:32` breaks then. Accept `jev-<version>`, request the alias, record the answering model.
5. **A new test module must be added to `.pre-commit-config.yaml:59` explicitly** (the `unittest` hook lists modules by name), and `pyproject.toml` pyright `extraPaths` needs the new skill dir. pylint limits (`max-statements=50`, `max-branches=12`, `max-locals=15`) apply to `skills/**.py`, so v3's 100-line `screen()` must be decomposed.

**Primary recommendation:** Port v3 into `skills/jev-fast-decision/` as a table of row dicts holding data plus small callables, split `screen()` into small pure functions (select, dispatch, classify, escalate, log), then make `decide.py` consume `--probe` JSON and the client's rung trail.

### Pattern 1: Row = data + callables (D-05)
**What:** each BACKENDS row is a dict with data (`remote`, `batch`, `min_confidence`, `default_model`, `response_model` regex, `cells`, `host`) and callables (`url(env)`, `key(env)`, `probe(env)`, `classify_error(exc)`, `retry_models(model, exc)`).
**Rule:** selection/dispatch/escalation/probe/log/remote-listing iterate `TABLE` and never compare a name literal. A repo `rg` test (`rg '"(laya|typesafe|opencode)"'` outside the table block) is the non-vacuity check for R2.

### Pattern 2: Total-deadline partial results (D-12)
Compute `deadline = now + per_call_timeout * n_local_items + retry_allowance + remote_timeout`. Each stage checks the remaining budget and returns already-answered items with `error: deadline` for the rest. Never raise mid-batch.

### Anti-Patterns to Avoid
- **Name branching** in helpers (the v3 flaw). **One giant `screen()`**: pylint fails it. **Importing the client from `decide.py`**: reopens the 24 D-06 env leak (D-10).
- **Honouring `JEV_API_URL` for remote rows with a key present**: sends a key to an attacker-chosen host (T-21.1-03). Remote URLs come from the row; an override must pass the consent host binding.

## Common Pitfalls

### Pitfall 1: Laya `/batch` misread as item batching
**What goes wrong:** assuming `states` x `questions` lets you send N different items in one call. **Why:** one `questions` map applies to every state (`laya/serve.py:1235-1251`, `1318-1320`). **Avoid:** `batch: False`; N items = N requests (R1 backstop test).

### Pitfall 2: Treating Laya truncation as invisible or absent
Non-strict servers return `usage.truncated` / `truncated_questions` (`docs/http-api.md:218-224`); with `LAYA_JEV_STRICT=1` those fields are dropped (`serve.py:174-209`, `docs/http-api.md:280`). **Avoid:** if `truncated` is true -> `needs_fallback`; if `usage` lacks the field, apply a conservative per-row state-size guard (english checkpoint window is 512 tokens, multilingual 1024, `serve.py:96-104,111-114`) rather than assuming "not truncated".

### Pitfall 3: Probe is not hook-safe
v3 `probe("laya")` uses a 1 s `/health` timeout (`/tmp` copy line ~84), so 3 unreachable backends can exceed R9's 3 s. **Avoid:** per-row connect timeout <= 0.7 s, deadline-shared, remote rows probe locally only (key present + gate), never a network call.

### Pitfall 4: Zen budget 429 vs free-tier 429
The plan retries to the paid id on any 429 (PLAN.md:18); the 2026-10-11 todo observed 429 "Policy budget exceeded" on both ids. **Avoid:** classify by body: `FreeUsageLimitError` -> try paid id; `budget exceeded` (Account or Policy) -> row unavailable, no further tries. `[CITED: main todo 2026-10-11/14; PLAN.md:18]` Exact bodies are not re-observed this session (Zen budget exhausted, no paid calls allowed).

### Pitfall 5: Response-model check as a hard equality
`decide.py:32` pins `jev-1.13.0`; v3 `response_prefix` is a prefix check. **Avoid:** per-row compiled regex, e.g. `^jev-[0-9]+(\.[0-9]+)*(-[A-Za-z0-9.]+)?$` for remote rows, `^laya-` for Laya (response `model` is `"laya-rl-agent"`, `laya/agent.py` window result). Test `jev-1.14.0-preview` accepted, `jevx-1` and `gpt-4o` rejected.

### Pitfall 6: Linting reach
`pylint` runs on `skills/**.py` with `max-statements=50`, `max-branches=12`, `max-locals=15`, `max-args=5` (`pyproject.toml:73-80`, `.pre-commit-config.yaml:30`); `ruff` line-length 100 (7 lines in v3 exceed it). `pyright` `extraPaths` lists each skill dir (`pyproject.toml:106+`) and needs `skills/jev-fast-decision`. `unittest` hook lists modules by name (`.pre-commit-config.yaml:59`).

### Pitfall 7: Sibling backup copy loaded as a duplicate skill
pi follows symlinks, discovers recursively, and keeps the first name; collisions only warn (`docs/skills.md`; `dist/core/skills.js:160-200,318-342`). It dedupes the same real file silently (`realPathSet`). So a backup beside the original shadows the repo client. D-15 (backups under XDG state) is correct.

### Pitfall 8: `claude --bare` cannot use the user's login
Bare mode never reads OAuth or the keychain and needs `ANTHROPIC_API_KEY` (code.claude.com/docs/en/headless, fetched today). A scratch `CLAUDE_CONFIG_DIR` also loses the login. See Open Question 8 for the D-23 recipe.

# 500 "inference failed" (1227/1360), 400/413/422 caller errors (1148, 733, 1216)

## Research answers to the DISCUSSION-LOG open questions

1. **Laya `/v1/systemone/batch` semantics.** `[VERIFIED: laya/serve.py:1229-1360 and docs/http-api.md:300-319,364-366, read from the 0.4.2 checkout; identical to the installed copy under the container layer (diff -q: SAME)]` Body is `{states: [...], questions: {...}, + controls}`; response `{results: [per-state result], total_usage}`. Large batches are split in forward passes, not refused (`LAYA_MAX_BATCH_TOKENS`). Verdict: unusable for heterogeneous items; per-state results are independent, but all states share one question set.
