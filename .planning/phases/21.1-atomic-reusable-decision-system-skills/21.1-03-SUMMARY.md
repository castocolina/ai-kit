# 21.1-03 Summary

**decide.py is now a thin one-call caller of the shared jev-fast-decision client — validation, trail-to-column mapping and delegated detect/consent — with score items, a CLIENT_PROTOCOL = 2 compatibility gate, leak-proof allowlisted output, and the spec-discuss docs rewritten around the client-owned ladder.**

## Performance

## Accomplishments

- Task 1: the ladder is one client subprocess per run. decide.py keeps item validation (now rejecting blank/repeated/`#`-prefixed ids and wrong-shaped `criteria` alone, keyed `#<stdin index>`), scrubs only the control variables, sets `GSD_PATH_JEV`, a per-call timeout and an item-scaled total deadline plus `JEV_CALLER`, and maps the client's rung trail onto one column per table backend plus `decided_by`. `client_ok` reads (never imports) the client's text for `CLIENT_PROTOCOL = 2`; a client without it — like the live global copy — is never run and every item is own reasoning with `client_status: incompatible_client`.
- Task 2: `detect` delegates to `--probe` and `consent` to the client's record subcommand, both through fixed output allowlists (eight scalar backend keys + `status`; seven consent keys); `--second-opinion` passes `--skip-local` (zero local requests); `score` items (2-10 levels) pass validation and the ladder; the parity test feeds edge items to both decide.py and the real client's request builder.
- Task 3: SKILL.md steps 3/5 and §3, decision-table.md rows 2-5 (stated in local/remote columns and the trail: `decided_by`, `own_reasoning`, `remote_available`, error columns), log-formats.md per-backend columns and README row 46 follow the client-owned ladder; the SKILL.md section diff stays a section edit (58 changed lines).
