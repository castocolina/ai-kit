  - **Own reasoning** (SPEC S1: Laya generic_rename 0.57 fb; analyzer Confident).
- **D-02: `decide.py` stays in `skills/ai-kit-gsd-spec-discuss/scripts/`** and finds the repo
  client as a sibling of its own skill dir (`abspath`, never `realpath`; 24 D-12 unchanged).
  Analyzer Confident.
- **D-03: Skill layout follows plan Task 6.**
  - `SKILL.md`, `reference.md` (with the capability matrix), `backends/{laya,typesafe,opencode}.md`,
    `scripts/jev_review.py`, `evals/cases.jsonl` and `scripts/eval_cases.py`.
  - The live skill's 2026-10-15 "Required reading" section is folded in.
  - The plan's `notes/` content (baseline scenarios, CHANGELOG, eval results, calibration,
    skill-judge scores) goes to this phase dir. The shipped skill never reads it, and anything
    in the skill dir ships to every host.
  - Laya phase_folder 0.84.
- **D-04: The plan's sources come onto this branch at their `main` paths.** The first plan task

  - Why: plans then read files, not `git show main:`. `main` is not an ancestor of HEAD, and
    cross-AI executors may lack the ref. Identical bytes at the same paths merge cleanly.
  - The plan's `/tmp/claude-1000`, `~/.claude/skills/...` and `diff -ru` checkpoints become
    repo paths and logical commits.
  - **Own reasoning** (Laya checkout_same_path 0.39 fb, same choice).
  - The v3 reference ran 45 passed on 2026-10-18 (analyzer, scratch copy).

### Backend table, escalation and the caller
- **D-05: Each backend-table row carries its data and small adapter callables in the one
  stdlib script.**
  - Data: URL resolver, key sources, probe, error classifier, retry rule, default model alias,
    response-model pattern, `batch`, `remote`, `min_confidence`, capability cells.
  - Selection, dispatch, escalation, probe, log and remote listing iterate the table and
    never branch on a backend name.
  - Evidence: the v3 reference still branches on names in `backend_url`, `probe`,
    `backend_key`, `_remotes_available` and `_retry_opencode`, so R2's stub-fourth-row and
    delete-`opencode` tests would fail.
  - **Own reasoning** (Laya data_only_table 0.44 fb, which fails R2).
- **D-10: `decide.py` learns the table from the client's `--probe` JSON**, run in its scrubbed
  child env. Per backend, in table order: `name`, `remote`, endpoint `host`, `batch`, and
  `usable` or `reason`.
  - It never imports the client: an in-process import would read the parent env and reopen
    the leak 24 D-06 closed.
  - **Own reasoning** (Laya module_import 0.41 fb).
- **D-11: The client returns a per-item rung trail.** Each item carries an ordered list of
  every backend's answer (`backend`, `model`, `choice`/`score`, `top`, `needs_fallback`) or
  error.
  - `decide.py` maps each table backend to a result column. `decided_by` is the last confident
    rung in escalation order, else `own_reasoning`, keeping the 24 D-07 shape and the
    spec-discuss "Laya overridden" logs.
  - `--second-opinion` asks the client to skip the local rung.
  - **Own reasoning** (Laya caller_two_calls 0.44 fb; two calls would sequence backends in
    the caller, which R3/R4 forbid).
- **D-12: `decide.py` passes a total deadline and the client returns partial answers in time.**
  - `decide.py` stops forcing `JEV_MIN_CONFIDENCE=0.7`, so each row's calibrated threshold
    applies (v3 calibrates Laya at 0.6).
  - The deadline scales with item count plus the Laya 503 retry allowance.
  - **Own reasoning** (Laya client_deadline 0.34 fb, same choice): one fixed timeout loses
    every answered item when it fires.
- **D-13: Laya 400/413/422 come back as errors and never escalate**; 503 is retried at most
  twice after `Retry-After`; 500, a refused connection and a timeout escalate.
  - 2026-10-11 todo taxonomy, locked by R1: a caller-bug request would fail remotely too and
    spend quota.
  - Analyzer Confident.

### Consent, keys and env
- **D-06: The persisted per-user consent record (24 D-10, same path, keys, host binding,
  announcement and revoke) moves into the client skill**, so every caller (GSD agents, triage,
  hooks, `decide.py`) shares one consent.
  - `jev_review.py consent grant|revoke|show <backend>` owns it. `decide.py consent` delegates.
  - SPEC R4/R6 amended.
  - **Own reasoning** (Laya client_skill 0.63 fb, same choice).
  - **Needs confirmation:** this extends uz's 2026-10-14 "once per user" ruling (made for the
    spec-discuss skill) to every caller of the client. Ledger.
- **D-07: The gate value is `1` (all remotes) or a comma list of backend names, and keys are
  looked up in the client.**
  - The client sets the list from matching records. A record for one remote never enables
    another, so a TypeSafe-only record cannot reach opencode on fallthrough.
  - The TypeSafe adapter's key order: `TYPESAFE_API_KEY`, `JEV_API_KEY`, `JEV_API_KEY_FILE`,
    then `${XDG_CONFIG_HOME:-~/.config}/ai-kit/secrets.env`. `decide.py` stops reading keys.
    Agent shells do not inherit login-shell exports (2026-10-14 todo), so file sources must
    stay. SPEC R6 amended; 24 D-09 amended.
  - **Laya overridden** (all_or_none 0.74): it contradicts the user-locked per-backend, per-host
    record of 24 D-10. No TypeSafe second opinion (no key), so own reasoning. Ledger.
  - Key lookup: **own reasoning** (Laya caller_lookup 0.59 fb; R2 bars `decide.py` from naming
    backends).
- **D-08: A non-loopback Laya URL is refused (`non_loopback_url`)**, per the plan's Global
  Constraints. `consent grant laya` is dropped, and the test at
  `tests/test_ai_kit_gsd_spec_discuss.py:211` changes with it. 24 D-08 amended.
  - **Own reasoning** (Laya refuse 0.37 fb, same choice).
- **D-09: `decide.py` scrubs only the control variables** (`JEV_BACKEND`, `JEV_ALLOW_REMOTE`,
  `JEV_MIN_CONFIDENCE`, `GSD_PATH_JEV*`) before setting its own. It passes key and URL variables
  through, so the client resolves them, each key going only to its own backend.
  - A parent-shell `JEV_ALLOW_REMOTE` therefore can never bypass the record check. 24 D-06
    amended.
  - **Own reasoning** (Laya control_only 0.51 fb, same choice).
- **D-26: Model ids per row.**
  - `typesafe` requests `jev-latest` by default.
  - The `opencode` row's alias stays the plan's `jev-1.13-free` → `jev-1.13` until research
    confirms Zen's 1.14 ids.
  - `laya` requests `jev-1`.
  - Every row accepts its `response_model` pattern (`jev-<version>`, or `laya-rl-agent` for
    Laya).
  - A per-row env pin overrides the alias (SPEC R5).
  - **Own reasoning**; the Zen alias is open research.

### Capability matrix
- **D-24: Matrix cells come from dated live notes plus freshly fetched TypeSafe docs**, each cell
  with its source and date.
  - Laya `score` is `verified-live` (llm-env `make check-server`, argmax 2, 0.99, 2026-10-12,
    per the 2026-10-11 todo). This contradicts the branch todo's "score unverified"; the dated
    live note wins.
  - Laya batching is per item (contamination measured 2026-10-10).
  - TypeSafe batching is `verified-live` (2026-10-13/14 notes).
  - Zen `score`/images are `unverified`.
  - Laya matrix_sourcing 0.58 fb, same choice.
- **D-25: In auto mode the feature check filters rungs per item.**
  - A rung whose cell is neither `verified-live` nor `documented` is skipped.
  - `unsupported_feature` (zero requests) is returned only when no rung is left, or when an
    explicit `JEV_BACKEND` lacks the feature.
  - **Own reasoning** (Laya explicit_only 0.43 fb): rejecting whenever the first rung lacks a
    feature would stop remote-only features in auto mode.
- **D-21: No image or `box` request builders in this phase.** The matrix and
  `unsupported_feature` gate them, and `score` is the only new type end to end.
  - Building them is backlog 999.8 (goal recorded in ROADMAP): no in-scope caller sends images,
    and no TypeSafe key or consent was available to verify the shapes live.
  - Laya gate_and_backlog 0.36 fb, same choice.
