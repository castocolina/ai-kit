## 21.1-04

**Summary:** The installer plan finds the main link and unlink paths, but its backup operation does not yet meet the project’s data-preservation standard.

- **Strengths:** It traces wizard selection, headless install and uninstall separately; those are distinct paths in [`setup.py:1347–1364`](tools/setup.py#L1347-L1364), [`setup.py:2882–2884`](tools/setup.py#L2882-L2884) and [`setup.py:2908–2920`](tools/setup.py#L2908-L2920). Isolating PTY environments is necessary because current tests inherit the environment while `resolve_paths` derives user directories from it ([`test_wizard_pty.py:408–414`](tests/test_wizard_pty.py#L408-L414); [`setup.py:51–79`](tools/setup.py#L51-L79)).
- **Concerns:**
  - **CRITICAL:** `replace_candidates` excludes “predecessor-shaped” links ([plan:291–304](.planning/phases/21.1-atomic-reusable-decision-system-skills/21.1-04-PLAN.md#L291-L304)), yet the existing predecessor detector recognizes target *shape*, not proven ownership, and its apply path removes the link ([`setup.py:1120–1162`](tools/setup.py#L1120-L1162)).   - **HIGH:** One second-resolution backup name followed by `shutil.move(path, dest)` has no exclusive destination claim ([plan:301–304](.planning/phases/21.1-atomic-reusable-decision-system-skills/21.1-04-PLAN.md#L301-L304)). The repository already uses an exclusive, numbered claim to avoid backup collisions ([`config_backup.py:57–71`](skills/ai-kit-gsd-curated-config/ai_kit_gsd_curated_config/config_backup.py#L57-L71)).
  - **HIGH:** Moving the entry precedes the separate `link_one` operation ([plan:301–304](.planning/phases/21.1-atomic-reusable-decision-system-skills/21.1-04-PLAN.md#L301-L304); [`setup.py:1052–1056`](tools/setup.py#L1052-L1056)). A link failure can leave the original skill path absent, with no restoration contract.
- **Suggestions:** Resolve ownership versus path shape before applying either gate. Claim a unique backup destination, and restore the original entry if linking fails; test same-second replacements and post-move failure.
- **Risk Assessment:** **HIGH**, because these paths mutate user skill data.

### Spot-check of raised HIGH/CRITICAL concerns

Verified (counted as HIGH):

1. **21.1-01 exhausted Laya 503 does not fall back.** The must_have (21.1-01-PLAN.md:42) and
   SPEC R1 (21.1-SPEC.md:184) say a third 503 falls back, and the 2026-10-11 todo says "retry
   at most 2 times, then fall back" in auto mode. But the Task 1 action (21.1-01-PLAN.md:285)
   turns exhausted retries into per-item errors, auto mode moves only `escalate` items
   (21.1-01-PLAN.md:294-297), and 21.1-02's ladder keeps only `escalate` errors pending
   (21.1-02-PLAN.md:226-227). No test checks that an exhausted 503 reaches the next rung in
   auto mode.
2. **21.1-03 consent output is passed through unfiltered.** `consent()` prints "the client's
   JSON as the result" (21.1-03-PLAN.md:296-297). `call_client` returns any dict
   (decide.py:283-301). The plan's own leaky-client no-leak test
   (21.1-03-PLAN.md:218) covers only the ladder output, so `consent` (and `detect`'s
   passed-through probe `backends`) skip the allowlist the plan applies elsewhere.
3. **21.1-03 decision-table.md keeps two-backend rules.** Task 3 edits only line 3
   (21.1-03-PLAN.md:338). Rows 2-5 of the mandatory-read table
   (references/decision-table.md:12-29; SKILL.md:52) still describe Laya and TypeSafe only,
   so an item that the opencode rung decides, or one where TypeSafe errors, matches no rule.
4. **21.1-04/05 shape-matched foreign links skip the replace gate.** Reported as CRITICAL;
   counted here as HIGH and merged with the 21.1-05 HIGH. `replace_candidates` excludes
   predecessor-shaped links (21.1-04-PLAN.md:299-300). `predecessor_candidates` matches by
   target shape only (`<any>/<cat>/<name>`, setup.py:1120-1148). The predecessor gate
   defaults to repoint on Enter (wizard_app.py:807), and its "No" deletes the link
   (setup.py:1151-1162, 1187-1197). So a user-managed symlink such as
   `<elsewhere>/skills/jev-fast-decision` gets labelled "a PREVIOUS ai-kit install" and
   offered only repoint or delete, never the backup that SPEC R8 promises for a foreign
   symlink. 21.1-04 extends this to the pi root. Mitigating fact: only the symlink changes,
   and its target is never touched.
5. **21.1-07 automated PASS check is weaker than the stated rule.** The decision table needs
   `TREE` equality, `CURRENT >= BASELINE`, `ACTIVATION ok` and the lowest same-digest score
   (21.1-07-PLAN.md:252-258). The python verify (21.1-07-PLAN.md:271) checks
   `CRITICAL 0`/`IMPORTANT 0`/`FLOORS ok`, the LAST `CURRENT` and a `DIGEST` substring only.
   The digest covers only `SKILL.md` plus `references/` (tests/gsd_curated_eval.py:388-407),
   so a change to `reference.md`, `backends/` or `scripts/` goes unnoticed.
6. **21.1-07 live checks are not hermetic for key sources.** `S` unsets only control
   variables (21.1-07-PLAN.md:181), and check 9 unsets only `TYPESAFE_API_KEY` (main PLAN.md
   Task 8 Part 3). The planned key order also reads `JEV_API_KEY` and `JEV_API_KEY_FILE`
   (21.1-01-PLAN.md:358), so either one exported in the owner's shell makes check 9's
   expected `missing_api_key` fail. `XDG_DATA_HOME` is not redirected either, so the probe's
   Zen key lookup reads the real `${XDG_DATA_HOME:-~/.local/share}/opencode/auth.json`.

Inaccurate or overstated (not counted as HIGH; actionable items listed below):

- **21.1-01 `git checkout main -- ...` overwrite (HIGH):** none of the target paths exists on
  this branch (`.planning/docs/system-one-decision-skill/` and both todos are absent), so no
  current work can be overwritten. A cheap preflight is still worth adding (LOW).
- **21.1-02 log lines above 4 KiB tear (HIGH):** `PIPE_BUF` applies to pipes and FIFOs, not
  regular files. An `O_APPEND` regular-file write is positioned atomically per call on Linux
  local filesystems. Accurate residue: the plan's "lines far below 4 KiB" premise is
  unenforced (whole 1,500-character `instructions` are logged, and `id`/`JEV_CALLER` are
  unbounded), and a short `os.write` is not handled (LOW).
- **21.1-04 same-second backup collision (HIGH):** after a run, the path is an ai-kit link and
  no longer a candidate. A collision needs a new real directory to appear at the same path
  within the same second, so it is practically unreachable. An exclusive claim is still cheap
  (LOW).
- **21.1-04 move before link (HIGH):** accurate that there is no rollback, but nothing is lost:
  the moved entry sits under the backups dir and its `moved <path> -> <dest>` line is printed
  first (MEDIUM).
- **21.1-01 `secret-scan` without a path (MEDIUM):** the automated verify passes the path
  (21.1-01-PLAN.md:457). Not actionable.
- **21.1-06 `tee` without `pipefail` (MEDIUM):** the verify requires 32 Laya cases in the
  results file, and `eval_cases.py --record` writes that file only on `n == 32` and exit 0.
  Not actionable.
