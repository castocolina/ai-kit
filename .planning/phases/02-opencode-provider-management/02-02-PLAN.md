    - A catalog entry whose `provider` value contains the provider id yields one `Reference` naming that catalog path, the entry's model-id key, and the field `provider`.
    - A catalog entry with a `runtimes.<cli>.model_id` containing the provider id yields one `Reference` naming the field `runtimes.<cli>.model_id`.
    - When the id is referenced in review-spec.toml AND in the catalog, both references are returned and both are printed — neither location silently wins (PRD edge case, ROADMAP SC-4).
    - When the id is referenced in neither, zero references are returned and the removal still proceeds.
    - A missing review-spec.toml, a missing catalog file, a TOML syntax error, and a JSON syntax error each yield zero references and no raised exception.
    - A catalog whose top-level JSON is a list, or whose entry value is not a dict, yields zero references and no raised exception.
    - A catalog entry whose `provider` or `runtimes.<cli>.model_id` value is a dict, a list, a number or `null` yields NO reference for that field and raises nothing — non-string values are skipped by an `isinstance(v, str)` filter, never stringified.    model-id key to entry dict — skip any non-dict top level and any non-dict

   `provider_id` is a substring of the entry's `provider` value, with `locator`

   Substring-test ONLY values that pass `isinstance(v, str)`; skip every
   non-string value outright rather than coercing it with `str()`. A `str()`
   coercion never raises, which is why round 1 reached for it, but it buys that
   safety with two defects the filter does not have: a dict- or list-valued field
   in a hand-edited catalog stringifies into a blob that can contain the provider
   id incidentally (an over-match), and that same blob then becomes the
   `Reference.value` printed verbatim — echoing an entry's internal structure into
   the warning line, which is the corner T-02-07's "never widen it to dump the
   whole entry" rule exists to close. Skipping loses nothing real: `provider` and
   `runtimes.<cli>.model_id` are string-typed in `model_catalog.py`'s own schema,
