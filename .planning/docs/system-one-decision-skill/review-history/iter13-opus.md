### CRITICAL
- **Plan A's `valid_cfg` fixture instruction rests on a wrong claim about the existing tests** — Location: Plan A Task 1, Step 1, the sentence after the test block ("build one from `models.yml.example` the way the file's existing validation tests do"). Required: the plan defines the fixture exactly, for example `valid_cfg = make_cfg(system_one={"enabled": False, "port": 8010, "image": "localhost/llm-env-system-one:rocm", "models": "english", "vram_reserve_mib": 4096})`, and drops the claim about `models.yml.example`. Why: `tests/test_config.py` has no `valid_cfg` fixture. Its validation tests build configs with `make_cfg()` (lines 30–127), and none of them load `models.yml.example`. The plan's two instructions therefore point in different directions. If the engineer follows "reuse its setup", they get `make_cfg()`, which has no `system_one` key. Then `valid_cfg["system_one"]["models"] = ...` in `test_validate_config_rejects_unknown_or_malformed_system_one_models` raises `KeyError` every time, even after the feature is implemented.
### HIGH
- **The `_print_endpoints` test helper fails before it runs anything** — Location: Plan A Task 7, Step 1, `_print_endpoints` and `test_print_endpoints_system_one_follows_the_flag`. Required: the helper creates its root before the `bin` directory (`commands.mkdir(parents=True)` or `tmp_path.mkdir()`), so both the "on" and "off" calls can pass. Why: it is called with `tmp_path / "on"` and `tmp_path / "off"`, which do not exist yet. `(tmp_path / "bin").mkdir()` without `parents=True` raises `FileNotFoundError`, so the test errors in both the RED and GREEN steps.
- **The `make clean` test cannot pass through `run_lifecycle_script`** — Location: Plan A Task 9, Step 1, `test_clean_removes_the_system_one_image`. Required: the test runs `clean.sh` in a way that lets `systemctl --user daemon-reload` succeed. Options: pass `llm_server_enabled=False`, use a `run_cleanup_with_stubs`-style helper (tests/test_shell.py:3296), or state the change to the stub. It must reach and assert the `podman rmi` and `podman volume rm` lines. Why: `run_lifecycle_script`'s `systemctl` stub (tests/test_shell.py:4632) exits 66 on `daemon-reload` unless `LLM_SERVER_ENABLED=false` or the mDNS unit file exists. `clean.sh` never renders that unit, and `scripts/clean.sh:67` runs `daemon-reload` unguarded under `set -e`. The script exits 66 before the new removal lines, so `assert result.returncode == 0` fails.
- **The old `MIN_CONFIDENCE` constant breaks the invalid-threshold test** — Location: Plan B Task 2, Step 3 ("replace the `API_URL`/`MODEL`/`RESPONSE_MODEL` constants") and Task 4 `test_invalid_jev_min_confidence_is_rejected`. Required: the plan explicitly deletes `MIN_CONFIDENCE = float(os.environ.get("JEV_MIN_CONFIDENCE", "0.7"))` (`scripts/jev_review.py:29`) and its comments. After that, importing the module with `JEV_MIN_CONFIDENCE=not-a-number` must succeed. Why: that line parses the variable when the module loads. The test sets the bad value before `load()`, so loading raises `ValueError` and the test errors. Task 4 Step 2 says such a failure "means fix screen()", which sends the engineer to the wrong place.
- **The `runpy` eval tests always fail on `SystemExit`** — Location: Plan B Task 5, Step 2, `test_eval_cases_reports_accuracy` and `test_eval_cases_sends_nothing_when_kill_switch_unset`. Required: each test either wraps the `runpy.run_path(...)` call in `pytest.raises(SystemExit)` and asserts the code is 0, or calls `_eval().main()` directly. Why: `eval_cases.py` ends with `raise SystemExit(main())`. pytest reports a test that raises `SystemExit: 0` as failed (checked with a minimal reproduction), so neither test can pass, even with a correct implementation.
