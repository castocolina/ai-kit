# Phase 15.1 Plan 05: Charts, SKILL.md sync, real-data gate run, and mid-execution UX/correctness fixes Summary

**Closes out Phase 15.1 with 3 charts wired to deduped real data, the phase-wide gate suite green
against the operator's actual usage-metrics store, and 7 unplanned-but-necessary fixes discovered
during live human review — most significantly a CDN transform bug that had been silently
preventing every Material Web Component from rendering since Plan 01.**

## Performance

- **Duration:** ~3h across two sessions (an initial automated pass that reached and correctly
  halted at Task 4's `<human-check>` gate, then a second pass where the coordinator did
  substantial additional live-browser-verified work directly on this branch before handing back
  for close-out)
- **Tasks:** 4/4 (Task 1: charts; Task 2: SKILL.md sync; Task 3: D-20/D-21 gap-closure layout;
  Task 4: phase-wide gates + real-store re-refine + human-check)
- **Files modified:** 6 tracked source/doc files across this plan's commits, plus CONTEXT.md and
  deferred-items.md

## Accomplishments

- Tokens/price-over-time and family/subfamily distribution charts, both deduped by turn identity
  (fixes the original compound-command double-counting bug) and updated in place on filter/sort
  events without ever redrawing on a pure sort (SD-6).
- **Found and fixed a real CDN-loading bug that was the actual root cause of most of the "ugly,
  stone-age, doesn't work" feedback from the Wave-1 human-check**: esm.run's `+esm` transform
  triggered a `customElements` "md-focus-ring already defined" collision that silently aborted
  the entire Material Web Components loading script, so `md-outlined-select`, `md-select-option`,
  and `md-dialog` never registered and rendered as raw unstyled text. Switching to unpkg's
  `?module` transform (verified via Playwright: 0 console errors, all selects and the dialog
  render and function) fixed this for every plan that had already shipped Material components
  (Plans 01, 03, 04) without any of them needing to be re-touched.
- D-20/D-21 gap closure: filter bar now sits beside the charts row instead of stacked below it;
  charts/table/filter bar scale with viewport width instead of rendering small and fixed-size.
- D-24 (found live, not pre-planned): airline/hotel-style date-range preset chips, defaulting to
  "Last 30 days" instead of the full unfiltered dataset on first load.
- family.py was surfacing genuine decomposer/tokenizer garbage as filterable "family" values (337
  distinct values, many unusable — bare flags, unclosed process-substitution fragments). Fixed the
  command-substitution-glued-to-assignment tokenizing bug, added `export` to the wrapper skip
  list, added a plausibility filter, and re-ran the fix against the real store: 337 -> 269
  distinct values. Two deeper tokenizer edge cases were found and explicitly documented (not
  silently dropped) in `deferred-items.md` as needing a real `shlex`-aware rewrite, out of scope
  for this fix.
- rtk's price tooltip corrected from "not in catalog" (implies a failed lookup) to "not
  applicable" (rtk never performs a model-catalog lookup at all — the prior wording was
  misleading, not just imprecise).
- Grouped-mode column-width fix: `session_id` (a UUID, needs room) now gets the flexible/growing
  column instead of the now-empty price column.
- Live "N matching commands" count added above the table.
- `frontend-design` skill invoked (per explicit user request) for a proportion/rhythm pass:
  charts were being squeezed to ~220-330px by equal flex-weight against the filter bar; they now
  get roughly 2x the filter bar's share (canvas height 260-400px vs the previous 220-320px, panel
  padding 24px vs 16px), plus subtle alternating-row tint and hover highlight on the table. The
  locked 56px row height and Material Baseline color/type tokens (D-04/D-08) were deliberately
  left untouched — this was a proportion pass on the existing locked design system, not a new
  visual identity.
- Real store re-refined end-to-end and dashboard regenerated against it (backed up first): codex
  rows 1,946 -> 8,306, cursor null-date rows 41 -> 0, non-simple-shape rows still carrying a
  family 3,218 -> 0, codex rows outside the original 3-day window 0 -> 2,449.
- Test suite grew from 137 (end of Plan 04) to 150 as each fix landed, all green throughout.
