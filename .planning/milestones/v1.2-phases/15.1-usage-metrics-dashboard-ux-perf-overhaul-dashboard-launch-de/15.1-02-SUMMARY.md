## Accomplishments

- **Defect A (family noise, D-16):** `_build_row` now computes `family` only for `command_shape == "simple"` steps; `control_flow_script`/`unclassified` rows get `""` instead of a mechanically-derived garbage family (a bare `if`, `"$(git`, `gsd_run()`, etc.). `family_of()` itself is unchanged.
- **Defect B (cursor date, D-16/D-19):** Added `_cursor_timestamp_text`, `_parse_cursor_timestamp`, `_cursor_timestamps`, `_cursor_timestamp_for` — recovers a usable ISO timestamp from cursor's already-captured `<timestamp>...</timestamp>` block (a localised stamp like `Monday, Aug 31, 2026, 1:24 AM (UTC-4)`), inherited from the nearest preceding timestamped record in the same session. `capture_cursor.py` is untouched; this is a refinement-layer fix that self-heals existing rows via the UPSERT.
- **Defect C (codex custom_tool_call, D-19):** Added `_codex_custom_tool_args`/`_codex_custom_tool_cmd`/`_codex_custom_tool_workdir` (single memoized `json.JSONDecoder().raw_decode` parse of the JS-source-string `input` field) and `_codex_seed_cwd`, called once per record above `_rows_for_record`'s step loop. `RESOLVE_CWD["codex"]` intentionally stays `_cwd_state_resolver` — the generic `resolve_for` -> `observe` contract now works correctly because the workdir is already seeded before the loop runs.
- **D-11:** Added `family.subfamily_of()` plus `_VALUE_FLAGS` (14-binary option-arity table) and a plausibility-filter regex. Reuses `family_of`'s exact `_WRAPPERS`/`_ASSIGNMENT_RE` skip logic. Not wired into any production row — canonical reference for Plan 03's client-side mirror.

### `_VALUE_FLAGS` grounding (D-11, real `refined.db`, 84,082 rows)

Sampled up to 500 `simple`-shape commands for each of the 30 most frequent `family` values and ran `subfamily_of()` against each, looking for a high empty-result rate driven by an *unlisted value-consuming flag* specifically (not just "no subcommand exists"):

- Every family with a >30% empty rate (`grep`, `cd`, `head`, `echo`, `sed`, `tail`, `ls`, `cat`, `pytest`, `find`, `python3`, `wc`, `jq`, `bash`, `test`, `node`, `shellcheck`, `curl`, `nl`, `gsd_run()`, `sort`) has **no subcommand concept at all** — these binaries take only flags and positional paths/patterns, never a subcommand token, so an empty `subfamily_of()` result is the correct answer, not a defect.
- Re-checked all 14 seed `_VALUE_FLAGS` families (`git`, `make`, `docker`, `kubectl`, `npm`, `cargo`, `go`, `pip`, `pip3`, `systemctl`, `apt`, `apt-get`, `tar`, `rsync`) directly against real invocations: rejected candidates were either genuinely no-subcommand invocations (`npm --version`, `systemctl --version`, `apt-get --version`, `tar -x -C ...` with no further token) or unclassified/multi-line blobs (`git -C "$(dirname "$DOC")" ...` — a `$(...)`-containing script fragment correctly rejected by the plausibility filter, not the arity table).
- **No `_VALUE_FLAGS` entries added.** The seed table from SD-1 already covers every value-consuming flag observed in this real dataset.

## Decisions Made

See `key-decisions` in frontmatter. The most consequential: codex's `workdir` is seeded exactly once per record, above the step loop, into the SAME `CwdState` instance the generic `resolve_for`/`observe` step loop already threads through the session — not via a per-step resolver. This was the Round 2 cross-AI review's core finding (a per-step resolver would reset `cd src && pwd`'s second step back to `/repo` instead of `/repo/src`), and the fix is verified both by a dedicated compound-command fixture and by the plan's own structural verify gate (asserting the seed call and its consumers never appear inside `for step in steps:`).
