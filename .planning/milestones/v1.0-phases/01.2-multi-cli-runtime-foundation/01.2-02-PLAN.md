**Open Question 1 resolution (documented here, per this plan's own authority to make this call —
see 01.2-RESEARCH.md's Open Question 1 and 01.2-CONTEXT.md's code_context section):**
01.2-RESEARCH.md verified live, this session, that `model_catalog.py`'s catalog-entry schema
never carries a `cli` key at all — entries are keyed `provider/model_id` with a
`runtimes: {cli_name: {...}}` dict, by design, so multiple CLIs can map to one canonical model.
`cli: None` (and `cli`-omitted) genuinely exists today only in `review-spec.toml`'s
`[[reviewers]]` entries and the candidate dicts `execute_dispatch.py`/`quota.py` build from them
(`quota.py` never even imports `model_catalog.py`). AGENTS.md's Architecture section says "a
model-catalog entry with `cli: None` means native" — true in intent, wrong in file: that
semantic lives in `config_io.py`/`review-spec.toml` today, not `model_catalog.py`. Following
01.2-RESEARCH.md's own explicit fallback recommendation ("if the planner must proceed without a
pause, default to (a) + (b) together — both are cheap, additive, non-conflicting"), this plan
adds `native_runtime` to **both**: `model_catalog.py` gets forward-compatible schema support
(satisfies REQUIREMENTS.md's literal "model-catalog entries" wording, validated but not yet
reachable by any live code path — documented as such, never silently upgraded to "wired"), and
`config_io.py` gets the functionally-reachable path (the native review-spec.toml entry Plan 04
actually writes `native_runtime` onto). AGENTS.md/REQUIREMENTS.md/ROADMAP.md are formally amended
with a dated note recording this, per AGENTS.md's own Workflow rule.

Purpose: give ai-kit a reliable, honestly-confidence-labeled answer to "which CLI is hosting this
process right now," and a validated place to record and later surface that answer.
Output: `detect_current_runtime()` with full test coverage; `native_runtime` schema validation in
both `model_catalog.py` and `config_io.py`; formally amended AGENTS.md/REQUIREMENTS.md/ROADMAP.md.
