The runner's ladder as built by 25-01..25-06 (describe it, never restate it differently):
- One CLI per call: the first of `--prefer`/`CONFIG.prefer`; the rest is the owner's menu.
- Classes from the pattern table: `transient` (`[400]: event: error`, 5xx, overloaded/capacity
  text, cut stream); `quota` (usage limit, quota, rate limit, 429; on a router lane also billing,
  access and router-tail credential rows); everything else stops (auth, off-router billing,
  permission, bad model, crash, empty answer, no change).
- Rung 1: up to `sameSessionRetries` (3) same-session retries where the CLI can continue the
  session; rung 2: up to `newSessionRetries` (3) new sessions, same CLI and model; the dirty-tree
  rule gates rung 2 (unchanged tree, or only the prompt's `<files>` paths changed).
- Router quota: after rung 2, the runner exits 75 with `retry_after_s=` (`cooldownS` 600) and
  `cycle=<n>`; the caller waits and re-invokes. A cross-call state file (0600, XDG state dir,
  keyed by lane and model — the quota budget is not task-keyed) stores `first_seen`,
  `last_attempt_at` and the cycle; the session id to resume is stored separately, per task key
  (the plan id or the prompt's objective digest), and is never reused for a different task on the
  same lane (cycle-3 session-resume ruling). A new cycle starts while `now + cooldown <= first
  quota failure + capS` (14400, the clamp maximum); past the cap the runner exits 69 and stops
  for good. A re-entry before the state file's due time is refused without spawning a child.
  A file whose `last_attempt_at` is older than the cap is a stale episode: it is replaced and the
  call proceeds, noted `stale-state-fresh-start`.
- Evidence: `cross-ai: attempt ...` per failed attempt, `cross-ai: report status= lane= route=
  attempts= cycles= first_failure= last_failure= stopped=` once on a stop, and the last
  `AIKIT-XAI status=... action=stop route= rule= pattern= attempts= cycles=` line;
  `--classify-only <file>` classifies a capture without running anything.
