Design notes:
- plan-set result: `op` `set`, `source` `user`, why `set by the user (plan-set)`, `status` and
  `candidates` removed; equal to `existing` -> `op` `keep` with `source` `user`. When `--force`
  overrode a refusal for the key, the entry also gets `forced: true` (the D-44 command guard
  reads it at every load; apply repeats the full-permissions warning for a forced command).
- Every consumer reads plans through `load_plan`, and the CLI runs `validate_plan` on the edited
  plan before `write_plan`, so no path writes or applies a plan the validator refuses.
- `plan-set workflow.cross_ai_timeout N` also sets the script artifact's
  `config.outer_timeout_s` to N when that artifact exists, so the baked `outerTimeoutS` (18-13)
  follows the user's edit; the entry and the artifact config never disagree (18-04 single copy
  of runner settings; the entry is the config-key mirror). plan-unset of this key needs no sync:
  18-15 refuses it while execution is on and removes both when execution is off.
- `--force` overrides only the candidate-style refusals: a non-candidate value for a
  `needs_choice` entry, a `review.default_reviewers` slug outside the inventory lanes, and the
  D-44 command guard. These refuse even with `--force`: a key the probe rejected, a
  `workflow.cross_ai_timeout` below 1800 or not an integer, a string the strict encoder refuses,
  a skill that is not installed or not addressable, and a new trusted root (one not in the
  entry's recorded `existing` list) that is not `~/`-relative. D-17 names only the timeout (and 18-15's `plan-unset` of an absent key); the
  other four are a recorded deviation (ledger, Round 2) that 18-22 writes into 18-CONTEXT.

- `load_plan(path) -> tuple[dict | None, str | None]`: JSON object with `schema_version ==
  plan_schema.PLAN_SCHEMA_VERSION` (exact int), str `host`, `profile`, `rigor`,
  `inventory_digest`, list `entries` (each a dict with str `key`, `op` in set/unset/keep, str
  `source`, str `why`), list `notes`, list `artifacts`, then `validate_plan`; errors end `;
  rerun recommend`.
- `validate_plan(plan: dict) -> str | None` (the one shared validator; imports `.cross_ai` and
  `.host` constants only; first problem found, naming the key or field):
  - `host` in `host.HOSTS`; entry keys non-empty str and unique (a duplicate is named);
    `status` absent or `needs_choice`; a `set` entry has a `value` key, which may be None only
    with `status == "needs_choice"`; `candidates`, when present, a list;
  - a `keep` entry whose `existing` is not None has `value == existing`: a keep never claims a
    value the config does not hold (apply never writes a keep, and 18-15 reads a keep's
    effective value as its `existing`). A keep whose `existing` is None may show the gsd default
    as its `value`, as recommend's native slots do (`recommend.py` `_keep_why`, `_tier_slot`);
  - the per-key checks below apply to `set` entries with a non-None `value`; a `needs_choice`
    entry's None value skips them (review cycle 2, plan-checker I4);
  - `workflow.cross_ai_timeout` set: int (not bool) >= `cross_ai.MIN_TIMEOUT_S`;
  - `workflow.cross_ai_command` set: equal to `cross_ai.CROSS_AI_COMMAND` unless the entry has
    `forced: true`;
  - `agent_skills_security.trusted_global_roots` set: a list of str; each element starts with
    `~/` or equals an element of the entry's `existing` list (an already-configured root keeps
    its recorded form, absolute included; plan-checker W2);
  - `agent_skills.<agent>` set: a list of str, each matching `^[A-Za-z0-9_-]+$` (installed and
    addressable are inventory checks: plan-set here, apply's `skill_value` in 18-17);
  - `artifacts`: at most one, a dict with `kind == "cross-ai-script"`, `path ==
    cross_ai.SCRIPT_PATH` (no other path is ever written), `template == cross_ai.TEMPLATE_NAME`,
    int `version`, `config` holding `prefer` (non-empty list of unique `cross_ai.RUNNER_CLI`
    ids, never the plan's host), `models` (id -> non-empty str), int `outer_timeout_s` >=
    `MIN_TIMEOUT_S`, `router_backed` (id -> bool, every id in `models`); `choices` (id -> a dict
    holding a `candidates` list); every `prefer` id is in exactly one of `models` and `choices`
    and neither holds an id outside `prefer`, so no target is left without a model or an open
    choice (review cycle 2); `status` `needs_choice` exactly when `choices` is non-empty, else
    `ok`.
- `sibling_inventory_path(plan_path) -> str` (`inventory.json` in the plan's directory).
- `check_plan_inventory(plan: dict, inv: dict) -> str | None` (pure, beside `validate_plan`,
  which stays plan-only and I/O-free): the `agent_skills_security.trusted_global_roots` entry,
  when present, must have `existing == presets.get_dotted(inv["existing_config"]["values"],
  key)` (how recommend records it), so a hand-written `existing` can never vouch for an absolute
  root; else `<key>: the plan's existing value is not the inventory's; rerun recommend`. The
  plan-set/plan-unset load and 18-17's `load_inputs` (apply, followups) run it (review cycle 3).
