## Summary

The phase is almost entirely stdlib Python plus registry plumbing in `tools/setup.py`. No external package is needed. The riskiest unknowns are three host behaviors that no document settles: whether PreToolUse and PostToolUse carry the same `tool_use_id`, whether SessionStart `systemMessage` is rendered to the user (the docs call it universal but warn that "some events discard them or deliver `systemMessage` somewhere other than the transcript"), and whether opencode 2.0.31 still honors the legacy `tool.execute.after` plugin hook with a mutable `output`. Design each so the wrong answer degrades to a harmless duplicate or a recorded gap, and make R10's live run the arbiter.

Three design corrections to carry into plans (details in Pitfalls): (1) D-06's "add `\n` to the separators" does not work through `punctuation_chars`; pre-replace `\n` with ` ; ` before lexing, and cut heredoc bodies. (2) The SPEC R5 rule "fire when the pre-call advisor did not already advise that call" defeats R6 throttling (calls 2-10 are throttled by pre-call, so post-call would fire on every one of them); pre-call must record *throttled* calls too and post-call treats "recorded (advised or throttled)" as handled. (3) Large-read counting must `stat` for a regular file first; opening a FIFO or `/dev/zero` blocks or never ends.

**Primary recommendation:** Build `advisor_core.py` as a pure function `advise(event_dict, which, state, env) -> str | None` shared by the Claude entry scripts and the pi/opencode shims (via stdin JSON), keyed on `tool_use_id` with a `sha256(command)` fallback, and gate every hook output through one `emit()` that can only produce `{}` or `{hookSpecificOutput:{hookEventName, additionalContext}}` (plus `systemMessage` for SessionStart/probe).

### Pattern 1: Single output gate
**What:** every script builds its dict through `emit(event_name, context, system_message=None)`, which refuses any key outside an allow-list. The MUST-NOT tests then assert on one function plus an end-to-end grep of outputs for `permissionDecision|updatedInput|updatedToolOutput|decision`.
**Envelope (documented):** PreToolUse `additionalContext` is "String added to Claude's context alongside the tool result. Ignored when `permissionDecision` is `"defer"`." `[CITED: code.claude.com/docs/en/hooks]`. `"allow"` "skips the permission prompt", so it must never appear.

### Pattern 2: Pre/post state machine (fixes SPEC R5 vs R6 interplay)
State per session: `counts{advice_id: n}` and `calls{key: "advised"|"throttled"}` (cap the map at the last 256 keys).
- Pre (Bash): for each candidate advice id, `n += 1`; advise when `n == 1 or (n - 1) % 10 == 0`... i.e. calls 1, 11, 21 (matches the SPEC test). Record the call key as `advised` if any line was emitted, else `throttled`.
- Post (Bash): if `calls[key]` exists, fire only when stdout lines > 200 (then emit the outcome line; subject to its own id `big:<tool>`). If no record (advisor knob off, key mismatch), run the same counter logic as pre using id `<tool>` so `tool-reminder` works alone and still honors R6.
- Without this, post-call fires on every throttled call and the "every tenth" promise is void.
- Key: `tool_use_id` when present on both events, else `sha256(tool_name + command)[:16]`. Store only the hash and id, never command text.

### Pattern 3: Lexing a Bash command (live-tested on Python 3.14.7, 2026-10-19)
`[VERIFIED: ran shlex in this session]` results:
- `shlex.shlex(s, posix=True, punctuation_chars=True)` with `whitespace_split=True` splits `cat f | grep x` to `['cat','f','|','grep','x']`, keeps `echo "cat"` as `['echo','cat']` (quoted word is a plain argument), and `a && grep -r x . || find . ...` into separate commands.
- **Passing `\n` inside `punctuation_chars` swallows the newline** (`'echo a\ngrep b'` gave `['echo','a','grep','b']`, no separator). Instead use `shlex.shlex(s.replace("\n", " ; "), posix=True, punctuation_chars=True)`: `echo a\ngrep b` becomes `['echo','a',';','grep','b']`, and a newline inside quotes stays one token (`'echo "a\ngrep b"'` gave `['echo','a ; grep b']`), so quoted text cannot trigger advice.
- `2>&1` lexes as `['2','>&','1']` and `grep x <<EOF\ncat\nEOF` lexes `cat` as its own command: **cut the command at the first `<<` (not `<<<`) heredoc marker's line end** or `cat` inside a heredoc body is flagged.
- Command position follows a separator token (`| |& && || ; ( )` and `$ (`), after which skip `VAR=value`, the wrapper list, and shell keywords (`if then elif else do while until ! { time`). `if grep -q x f; then cat f; fi` lexes `if` before `grep`, so without the keyword skip the first `grep` is missed. Backtick command substitution (`` `grep x` `` lexes as one token `` `grep ``) is not detected; accept and record as a known limit (`shortcut:` comment).
- `man grep`, `git grep x`, `git -C d grep x`: `grep` is an argument, never in command position. Good.
- Unbalanced quotes raise `ValueError` (`'echo "it\'s'`): fall back to `str.split()` per D-06. Cap the command at 16 KiB before lexing.

### Pattern 4: Large-read counter
`os.stat` first; require `stat.S_ISREG`; open `os.O_RDONLY | os.O_NONBLOCK`; read 1 MiB chunks to 64 MiB; count `b"\n"`. `[VERIFIED: ran]` a 100 MiB sparse file reads 64 MiB in 0.024 s here (matches D-08's 22 ms). Treat "has more than 2,000 lines" as `newlines > 2000` or (last byte not newline and newlines == 2000 and ...) per the SPEC boundary rows; unit-test exactly 2,000 lines/40,000 chars silent and +1 reports. `offset` or `limit` present (including `limit` only) means silent.
- Claude's own Read default window is 2,000 lines `[ASSUMED]` (training knowledge, not in the doc excerpts read). If true, the ">2,000 lines" trigger coincides with the point where a no-range Read is truncated, which is worth stating in the advice ("a full Read returns at most the first 2,000 lines") only after the live run confirms it.

### Anti-Patterns to Avoid
- **Echoing untrusted text** (the command, file path, or output) into advice: composed text uses fixed templates, numbers and installed tool names only. The `-l <lang>` token comes from a fixed extension map, never from the path itself.
- **Importing argparse** or anything that can `SystemExit` before `sys.excepthook = _fail_open` (existing docstring rule).
- **Naming a replacement tool without `shutil.which`** in the same invocation.

## Common Pitfalls

### Pitfall 1: Hook entries from different ids collide on shared event keys
**What goes wrong:** `session-briefing` (SessionStart, `startup|compact`), `decision-probe` (SessionStart, `startup`) and 21.2's compact injector all live under `hooks.SessionStart`; `_refresh_or_append_claude_hook` replaces the *first* entry whose command contains the single `CLAUDE_HOOK_MARKER`, with the single `CLAUDE_HOOK_MATCHER`.
**Evidence (quoted):** `CLAUDE_HOOK_MATCHER = "startup|compact"` and `CLAUDE_HOOK_MARKER = os.path.join("tools", "hooks", "claude_session_start.py")` `[VERIFIED: tools/setup.py:1380-1381]`; the loop `if CLAUDE_HOOK_MARKER in hook.get("command", ""): entries[index] = new_entry` `[VERIFIED: tools/setup.py:1522-1526]`; ownership `return any(marker in hook.get("command", "") for hook in entry.get("hooks") or [])` `[VERIFIED: tools/setup.py:1784]`.
**How to avoid:** parametrize wire/unwire/refresh by `(event, matcher, marker)` per registry row (21.2 D-11). Marker strings must not be substrings of each other (`claude_tool_advisor.py` vs `claude_tool_reminder.py` are safe; do not name a script `claude_session_start_x.py`). One read and one `_atomic_write_json` per settings file across all rows, validating every event key first, so the file is never half-written.
**Warning signs:** unchecking one row removes a sibling; a foreign entry under the same event disappears.

### Pitfall 2: Tests and docs that assume unconditional wiring
Rewrite `test_wizard_commit_wires_the_hook` and `test_headless_with_hooks_*` (CONTEXT D-15). The argparse flag is currently `parser.add_argument("--with-hooks", action="store_true", ...)` `[VERIFIED: tools/setup.py:3126]`; 21.2 D-13 turns it into `nargs="?"` with a sentinel and validates ids (live-verified there that `--headless --with-hooks install` would swallow `install`). 21.3 adds `uninstall --hooks=<ids>` with the same validation, and the bare form wires registry defaults (`decision-probe` off).

### Pitfall 3: Plans collide in `tools/setup.py`
21.1 plans 04 and 05 edit `_build_wizard_context`, `_make_apply_housekeeping`, `launch_wizard`, `replace_candidates`, `backup_and_link`, and `tests/test_setup.py` housekeeping tests (3660-3760), `tests/test_wizard_pty.py` env isolation (all five host-root env vars; "the wizard commit rewrites the cursor hooks file whenever its dir exists"). 21.2 owns the registry and `--with-hooks` argparse change. 21.3 must plan after both, touch only the hook sections (1379-1604, 1782-1840, 2769-2780, 2840-2924, 3126-3133) and registry rows, and reuse 21.1-04's `noskip` Textual-gated test pattern for wizard tests. New PTY tests must isolate `CLAUDE_CONFIG_DIR`, `CURSOR_CONFIG_DIR`, `PI_CODING_AGENT_DIR`, `XDG_CONFIG_HOME`, `XDG_STATE_HOME` (21.1-04), and also `XDG_RUNTIME_DIR`/`XDG_CACHE_HOME` for advisor state.

### Pitfall 4: PreToolUse context cannot prevent the current read
Documented placement is "alongside the tool result". The size report informs the next read only. Advice text must say so; never promise prevention. Preventing would need `permissionDecision`, which is forbidden.

### Pitfall 5: R5 throttling hole — see Pattern 2.

### Pitfall 6: Special files and slow mounts
Reading a FIFO, `/dev/zero`, `/proc/*`, or a stalled network path in the hook blocks past the 1 s budget. `S_ISREG` check, `O_NONBLOCK`, and set a hook `timeout` in the settings entry. Hook defaults are "600 for `command`" seconds `[CITED: code.claude.com/docs/en/hooks]`, so the wired entry should carry `"timeout": 5` (probe: 5, advisors: 3) rather than rely on the default. A hung hook with default timeout would stall tool calls for up to ten minutes.

### Pitfall 7: Exit-code semantics
"Exit code 1 without valid JSON output is a non-blocking error"; exit 2 blocks on events that can block `[CITED: code.claude.com/docs/en/hooks]`. PreToolUse can block, so an advisor must never exit 2; `_fail_open` uses `os._exit(0)`. Keep stderr silent on the success path.

### Pitfall 8: Large PostToolUse payloads
`tool_response` for Bash carries `stdout`, `stderr`, `interrupted`, `isImage` `[CITED: code.claude.com/docs/en/hooks, updatedToolOutput warning]`. The docs do not say it is truncated. Read stdin to a bound (suggest 8 MiB), and on overflow or `JSONDecodeError` emit `{}`. Do not reuse the 1 MiB discard drain for parsing. Count lines with `str.count("\n")` plus one for a missing trailing newline; handle CRLF (SPEC edge). Report "about" and use "at least N lines" if the payload was cut.

### Pitfall 9: pi `tool_call` handlers can block
"A `tool_call` handler failure blocks the tool as a fail-safe" `[CITED: pi docs/extensions.md:263, installed 1.3.0]`. Register `tool_result` only; wrap the whole handler in try/catch returning `undefined`; spawn Python with a timeout and the event `signal`.

### Pitfall 10: rtk text hides in docs and comments
`rg -n -i rtk tools/hooks/` must be empty. That includes `README.md` (currently full of rtk), `detect.py` docstrings, and any comment. Rewrite the README's three headings' bodies (headings stay, per D-15). The config doctor row at `tools/config_doctor_checks.py:1008-1025` quotes `tools/hooks/README.md` as `source` and `why`; repoint to Phase 03 CONTEXT D-02 or the doctor test at `tests/test_config_doctor.py:888` fails.

### Claude Code `[CITED: code.claude.com/docs/en/hooks]`
- `systemMessage`: "Warning message shown to the user." Universal, but "some events discard them or deliver `systemMessage` somewhere other than the transcript. Each event's section says so." Sections read here that discard it: Setup, InstructionsLoaded, MessageDisplay, Notification. The SessionStart section's statement on it was not in the portion fetched (about 27% of the page, characters 200,000+, was not read), so visibility on `startup` and `compact` is **MEDIUM**: keep as the R10 live check.

- Cap: "A hook's `additionalContext`, `systemMessage`, and `initialUserMessage` strings, and its plain stdout, are capped at 10,000 characters", larger output is saved to a file and replaced by a path plus up to 2,000 characters. SPEC limits (200/2,000) are well inside it.
- PreToolUse input: `tool_name`, `tool_input`, `tool_use_id` ("PreToolUse hooks receive `tool_name`, `tool_input`, and `tool_use_id`"). Bash `tool_input` example: `command`, `description`, `timeout`, `run_in_background`. Read `tool_input`: `file_path` (absolute), optional `offset`, optional `limit`.

- Matcher syntax: strings of letters, digits, `_`, `-`, spaces, `,` and `|` are an exact list, so `Bash|Read` is valid. Hook timeout default 600 s for `command`.
- Output to avoid: `permissionDecision` (allow/deny/ask/defer), `updatedInput`, `updatedToolOutput`, `decision`.

The `input` field means the shim can read the bash `command` and read `path/offset/limit` **in `tool_result`**, so no `tool_call` handler is ever needed.
- Result type, quoted: `export interface ToolResultEventResult { content?: (TextContent | ImageContent)[]; details?: unknown; structuredContent?: JsonValue; isError?: boolean; usage?: Usage; }` `[VERIFIED: types.d.ts:1114-1120]`. "replacing `content` without returning `structuredContent` drops the structured content": the shim returns only `{content: [...event.content, advice]}` and must also return `structuredContent: event.structuredContent` when it is defined.
- Truncation: `DEFAULT_MAX_LINES = 2000` and `DEFAULT_MAX_BYTES = 50 * 1024` `[VERIFIED: dist/core/tools/truncate.js:10-11]`; `BashToolDetails { truncation?: TruncationResult; fullOutputPath?: string }` `[VERIFIED: dist/core/tools/bash.d.ts:27-30]`; `TruncationResult` has `truncated`, `totalLines`, `totalBytes`. So pi's read result already carries total lines and bytes in `details.truncation`: the pi large-read report needs no filesystem counting. pi's read tool also contributes the guideline "Use read to examine files instead of cat or sed." `[VERIFIED: dist/core/tools/read.d.ts]`, so on pi the advisor's value is mainly `grep` and `find`.
- Extension load: direct `.ts` files in the extensions directory (21.2 D-07/D-10).

### opencode (v2.0.31 binary, plugin types 1.18.5, static reads only)
- Documented legacy hooks `[CITED: opencode.ai/docs/plugins]`: `tool.execute.before` and `tool.execute.after`, no formal signature, only `output.args` mutation shown. Installed types `[VERIFIED: @opencode-ai/plugin dist/index.d.ts:235-258]`:

### Cursor `[CITED: cursor.com/docs/hooks]`
Events include `sessionStart`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `beforeShellExecution`, `afterShellExecution`. `sessionStart` outputs `env` and `additional_context`. `preToolUse` outputs only `permission`, `user_message`, `agent_message`, `updated_input` (no context field, so pre-call advice is impossible without permission semantics). `postToolUse` outputs `additional_context` ("Extra context injected into the conversation after the tool result") and `updated_mcp_tool_output`. ## Briefing and Probe Composition
- `compose_message(detection) -> (user_line, model_context)`; `user_line` plain ASCII, no ANSI, ≤ 200 chars, naming only installed pairs; `model_context` ≤ 2,000 chars with the refreshed `TOOL_GUIDANCE` (D-07). No installed tool: both empty, output `{}`.
- Emit on every fire (D-12): `{"systemMessage": user_line, "hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext": model_context}}`.
- `decision-probe`: run the client with `subprocess.run([sys.executable or "python3", script, "--probe"], timeout=3, stdin=DEVNULL, capture_output=True)`; parse JSON; keep backend names and `host:port` (strip userinfo and query via `urllib.parse`); on timeout or non-zero, `{}`. The overall script must return within 3.5 s (R8), so use a 3 s probe timeout with no retries.

### Known Threat Patterns (T-21.3-NN)
| ID | Threat | STRIDE | Mitigation |
|----|--------|--------|------------|
| T-21.3-01 | An advisor output approves, denies or rewrites a call (`permissionDecision`, `updatedInput`, `updatedToolOutput`, `decision`) | Elevation / Tampering | Single `emit()` allow-list; MUST-NOT test over all outputs and over the source |
| T-21.3-02 | Prompt injection through advice text: file names, commands or output echoed into model context | Tampering | Fixed templates; only numbers and installed tool names interpolate; extension-to-language fixed map |
| T-21.3-03 | State-file attack: symlink or world-writable dir, session-id path traversal | Tampering / Info disclosure | Private dir 0700 not under shared `/tmp`, `O_NOFOLLOW`, owner check, strict id regex, atomic replace 0600 |
| T-21.3-04 | DoS: hook blocks or stalls the tool (FIFO read, huge payload, slow PATH, hung probe) | DoS | `S_ISREG`, 64 MiB cap, stdin bound, `timeout` on the hook entry, probe 3 s, exit 0 on every path |
| T-21.3-05 | A hook crash blocks a tool (exit 2 or uncaught error) | DoS | `_fail_open` before any fallible import; never exit 2; pi: no `tool_call` handler |
| T-21.3-06 | Probe leaks a key or URL credential to the user transcript | Info disclosure | Argv-list subprocess, keep backend names and `host:port` only, never echo env |
| T-21.3-07 | Probe or advisor executes an attacker-chosen script | Tampering | Script path from this file's realpath inside the install dir; no shell; ignore PATH lookups for the script |
| T-21.3-08 | Setup clobbers or deletes foreign hook entries on install or uninstall | Tampering | Marker-by-script-path ownership, one validated atomic write per file, per-id tests with a foreign entry under every event |
| T-21.3-09 | Advice names an uninstalled tool or mentions rtk | Integrity | `shutil.which` in the same invocation; output scan test |
| T-21.3-10 | Pathological command makes the lexer slow | DoS | Cap command at 16 KiB, bounded tokens |
| T-21.3-11 | Live checks touch the real user config | Tampering | Scratch `CLAUDE_CONFIG_DIR`, `PI_CODING_AGENT_DIR`, `OPENCODE_CONFIG_DIR`, `HOME`; LIVE tasks assert the paths first |
