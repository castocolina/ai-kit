## Critical Issues

### CR-01: GSD hook builder never checks the per-runtime model grammar, so a refused id becomes a live hook (known item a)

**File:** `skills/ai-kit-spec-execute-gsd/ai_kit_spec_gsd/gsd_cross_ai.py:21-30`, `skills/ai-kit-spec-review/ai_kit_spec/runner_dispatch.py:181-193`, `skills/ai-kit-spec-execute-gsd/ai_kit_spec_gsd/adapter.py:203-215`

**Issue:** `build_cross_ai_command` goes straight to `project_runner_command`. That function only
checks `HOOK_TOKEN_RE`, a charset check. Neither calls `model_id_ok`, even though 25.1 made the
runner validate each runtime's grammar (`cross-ai.mjs:1295-1297`, enforced in `main` at
`:9906-9909` with exit 2). Verified:

```
pi glm-4.6        -> node .planning/scripts/cross-ai.mjs --runtime pi --model glm-4.6 ...   model_id_ok=False
opencode gpt-5    -> node .planning/scripts/cross-ai.mjs --runtime opencode --model gpt-5 ... model_id_ok=False
pi fake/ok:free   -> hook built                                                              model_id_ok=False
```

The adapter returns `mode: cross_ai_hook`, writes it into GSD's `workflow.cross_ai_command`, and
every GSD cross-AI call then exits 2 (`usage`). Review mode is protected: `run_runner` checks
(`runner_dispatch.py:589`). Curated-config is protected too: `cross_ai_build.runner_model_problem`.
The exec hook path is the only one with no check. `_unsafe_hook_notice` (`adapter.py:218-231`)
would also mislabel the case as an unquotable token.

**Fix:** put the check once, in the shared builder, so every caller gets it:

```python
def project_runner_command(spec: RunnerSpec, *, guidance: bool = False) -> str | None:
    if spec.runtime not in SUPPORTED_EXECUTE_CLIS or not model_id_ok(spec.runtime, spec.model):
        return None
    ...
```

Then give `_unsafe_hook_notice` its own reason (for example `unsupported_model_id`, with prose
naming `model_id_src(runtime)`) when `model_id_ok` is false. Add an adapter test: a bare pi id
yields a `fallback_notice`, not a hook.

### CR-02: The live relay leaks a secret's later copies and any ANSI-split key, against D-17

**File:** `skills/ai-kit-spec-review/references/cross-ai.mjs:1569-1576` (relay), `:1551-1564` (`redactSecrets`)

**Issue:** D-17 says: "One extended redactor runs on every relayed child line … Order: strip
ANSI, decode, redact". The relay calls `log(redactSecrets(line))` on the raw line. That has two
consequences:

1. **Copies are tracked per line only.** `redactedValues` is computed inside each line, so a
   value redacted on one line is printed in clear on the next.
2. **No ANSI strip before matching.** A colored key (`\x1b[31mapi_key\x1b[0m: …`) breaks the
   `\s*[:=]` adjacency, and the value passes through.

Hermetic repro (fake `pi` writes to stderr and exits 1). Relayed stderr as printed:

```
{"error":{"message":"bad","api_key":"<redacted>"}}
retrying with key zz9QQsecretvalue77          <- copy of the redacted value, in clear
^[[31mapi_key^[[0m: zz8ANSIsecretvalue         <- ANSI-split key, in clear
```

These lines go to the runner's stderr. That is GSD's error log and the `.err` evidence file that
every skill tells the agent to relay verbatim to the owner and the transcript.

**Fix:** keep a per-run set of redacted values in the relay, and normalize before matching:

```js
function makeLineRelay(hooks = {}) {
  let pending = '';
  const seen = new Set();            // values redacted earlier in this run
  const emit = (line) => {
    (hooks.onLine || (() => {}))(line);
    if (hooks.quiet) return;
    const clean = normalizeInput(line);              // strip ANSI + decode first (D-17)
    for (const v of redactedValues(clean)) seen.add(v);
    log(redactSecrets(clean, [...seen]));
  };
  ...
```

Share one `seen` set across the stdout and stderr relays of a run, and feed it into
`upstreamOf`'s `extras`. Add self-test cases for a cross-line copy and an ANSI-colored key.

## Warnings

### WR-01: A spent transient hard tier (exit 69 `status=transient`) is classified `real_error` and given the capacity fix (known item b)

**File:** `skills/ai-kit-spec-execute-superpowers/ai_kit_spec_superpowers/dispatch_injection.py:398-423`, `skills/ai-kit-spec-execute-superpowers/SKILL.md:180,356-359,398-404`

**Issue:** The hard handler (`cross-ai.mjs` `hardHandler`) and the stopped-lane refusal
(`:3846-3857`, `status: loaded.class`) both end with `status=transient exit=69
stopped=hard-waits|cap`. `STATUS_TO_REASON["transient"]` is `capacity`
(`error_classifier.py:39`), and `classify_dispatch_failure` then returns `real_error`. A bare
exit 75 `status=transient` hits the same path. That bare 75 happens when the state file was
unwritable and the hint was dropped.

So the agent never reaches the `stopped=hard-waits`/`cap` owner-stop rule in the `"quota"`
branch. It reports Step 2's capacity fix instead: "a later retry or another model"
(`SKILL.md:180`). That contradicts the never-switch rule, and a later retry on that lane is
refused anyway. The owner is also never told the reset (delete the named state file).

**Fix:** return `quota` from `classify_dispatch_failure` when `status` is a dict with
`status["status"] in ("transient", "quota")` and `returncode in (69, 75)`. This keeps the "only
exit 75 + tokens re-invokes" rule in the SKILL. Also make the SKILL's hard-tier stop rule key on
`stopped=` regardless of the branch, and drop "or another model" from the capacity fix text. Add
regression tests for 69/`transient` and bare 75/`transient`.

### WR-02: `--classify-only` reports a copilot capture as `verified`, while live runs force `unverified` (known item c)

**File:** `skills/ai-kit-spec-review/references/cross-ai.mjs:4396-4400` (vs. live path `:4000-4005`)

**Issue:** Live classification applies `rt.errorsUnverified`. `runClassifyOnly` emits `cls.label`
directly. Verified:

```
[{"cli":"copilot","stderr":"Error: quota exceeded"}] ->
{"status":"quota","rule":"text-quota-exceeded","pattern":"verified",...}
```

This breaks the policy text ("Every copilot pattern reads `unverified`",
`subprocess-quota-policy.md:145-146`). It also breaks the non-negotiable rule that no
classification is shown with more certainty than its sourcing.

**Fix:**
```js
const pattern = RUNTIMES[cli].errorsUnverified ? 'unverified' : cls.label;
lines.push(JSON.stringify({ name: entry.name, status: cls.status, rule: cls.rule, pattern, route }));
```
Add a copilot case to the classify-only self-test.

### WR-03: Redactor misses common credential shapes (`?key=`, `password=`, `Authorization: Basic`)

**File:** `skills/ai-kit-spec-review/references/cross-ai.mjs:1507-1516`

**Issue:** `KEY_VALUE_RE` keys only on `api[_-]?key|token|secret`, and `SECRET_RES` has no
Basic-auth, password or bare `key=` rule. Hermetic repro, relayed unchanged:
- `password=hunter2hunter2`. This line also became `cross-ai: upstream body="password=hunter2hunter2"`.
- `Authorization: Basic dXNlcjpwYXNzd29yZA==`
- `GET https://x.googleapis.com/v1/m?key=AIza... 403`. This one also leaked through the upstream body line.

Google-style `?key=` URLs are exactly what a vendor 4xx error echoes.

**Fix:** extend the key alternation to
`api[_-]?key|token|secret|password|passwd|authorization|(?<=[?&])key`, add
`/\bBasic [A-Za-z0-9+/=]{8,}/gi` and `/\bAIza[0-9A-Za-z_-]{20,}/g` to `SECRET_RES`, and widen
`Bearer` to `[A-Za-z0-9._~+/=-]`. Add self-test cases.

### WR-04: Copilot is an enabled GSD exec hook target with no unverified notice

**File:** `skills/ai-kit-spec-review/ai_kit_spec/detection.py:117-118`, `skills/ai-kit-spec-execute-gsd/ai_kit_spec_gsd/adapter.py:211-214`, `skills/ai-kit-spec-review/references/cross-ai.mjs:1431-1450`

**Issue:** `"copilot": Runtime(("copilot",), (), runner=True)` puts copilot in
`SUPPORTED_EXECUTE_CLIS`, so the GSD adapter will install a copilot exec hook. Several things
about that hook are unverified:
- Copilot's error, quota and exit shapes are unverified (`errorsUnverified: true`).
- Its exec profile is `--allow-all-tools` with no confinement.
- It takes the whole GSD task prompt on argv, so the prompt is visible in the process table.

The adapter flags only pi (`PI_EXEC_NOTE`). The hook is enabled with no visible caveat, against
the certainty rule.

**Fix:** add a `COPILOT_EXEC_NOTE`, printed and returned in `notes` the same way as pi's. It
should name the unverified classification and the argv visibility. Or leave copilot out of
`SUPPORTED_EXECUTE_CLIS` until a live capture exists.

### WR-05: The pi grammar refuses ids with `:` in the model part (Ollama-style tags), and the template-8 upgrade never re-checks kept models

**File:** `skills/ai-kit-spec-review/references/cross-ai.mjs:1295`, `skills/ai-kit-gsd-curated-config/ai_kit_gsd_curated_config/cross_ai_script.py:229-246`

**Issue:** `PI_MODEL_ID` allows `:` only as one of the seven thinking suffixes. So
`provider/qwen3:8b` or `openrouter/...:free` is refused with exit 2, even though
`parsePiListingIds` builds exactly such `provider/id` strings from pi's own RPC listing. Template
7 accepted these ids, because it used `MODEL_ID`.

`_upgrade_config` keeps the old `CONFIG.models` verbatim and never re-checks them against the new
grammars. An upgraded runner can therefore exit 2 on every call with no warning at
`ensure-runner` time.

Not live-verified: I did not check whether pi on this machine lists colon ids, or whether pi
itself splits only a known thinking suffix.

**Fix:** allow `:` in pi's model part and anchor only a trailing known level:
`/^[A-Za-z0-9][A-Za-z0-9._@+-]*\/[A-Za-z0-9][A-Za-z0-9._:\/@+-]*$/`, keeping `modelSuffix` for
the thinking strip. Do this if a live pi check confirms pi accepts such ids; otherwise document
the limit. In `_upgrade_config`, run each kept model through
`cross_ai_build.runner_model_problem` and report or drop the failing ones.

### IN-01: A hand-edited stopped record with no `stopped_at` crashes the refusal path

**File:** `skills/ai-kit-spec-review/references/cross-ai.mjs:3849-3850`, `readCycleState` `:3190-3198`

**Issue:** `new Date(loaded.stopped_at).toISOString()` throws `RangeError` when `stopped_at` is
missing. `readCycleState` does not check that field. The result is `status=crash` instead of the
documented refusal.

**Fix:** in `readCycleState`, require `typeof parsed.stopped_at === 'number'` whenever `parsed.stopped` is set, or print `-` when it is missing.

### IN-02: The policy text says upstream fields are copied "with their values unchanged", but string values are redacted

**File:** `skills/ai-kit-cross-ai/references/subprocess-quota-policy.md:122-124`, `cross-ai.mjs:1856-1859`

**Issue:** `upstreamOf` passes string field values through `redactSecrets(replaceCopies(...))`.
The self-test even expects `"retry_after":"<redacted>"`.

**Fix:** reword: "copied verbatim, except a string value that matches a redacted secret is
`<redacted>`".

### IN-03: Cycle-state read-modify-write has no lock

**File:** `skills/ai-kit-spec-review/references/cross-ai.mjs:3820-3895` (load), `saveCycle`, `dropStateFile`

**Issue:** Two concurrent calls on the same checkout, CLI, model and route kind can race. An
example is GSD parallel plans without worktrees. One call's success `dropStateFile()` can delete
the other's pending hard-tier record, which resets its cycle count and its 4-hour cap clock. The
atomic rename prevents torn files, but not lost updates. I did not prove a failure.

**Fix:** document "one in-flight call per lane", or take an `O_EXCL` lock file next to the state
file for the duration of `runCli`.
