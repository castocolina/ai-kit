# Phase 25.1 Plan 01: Retry Config Resolution Summary

**The runner resolves `workflow.cross_ai_retry` per key from the project config, the user file and CONFIG `retry`, logs one `cross-ai: retry` line, and refuses a bad key by name**

## Accomplishments

- CONFIG carries a sorted `retry` object (`base_s` 1, `factor` 1.5, `max_retries` 5, `session_resets` 1, `hard_waits_s` [600, 900, 1800]), pinned by `test_header_and_config_contract`; the Phase 25 ladder keys stay until 25.1-02
- `resolveRetry` reads each key from the scoped project config, the root config under a workstream, `${XDG_CONFIG_HOME:-$HOME/.config}/ai-kit/cross-ai.json`, CONFIG `retry`, then the frozen `RETRY_DEFAULTS`, which is never refused
- A bad value, an unknown key, a malformed file and a `capS` above 14400 are logged with the key and the source, and the next source fills the key; the retry read is realpath-confined, the timeout read is not
- `softWaitMs` is `base_s x factor^(k-1)` in milliseconds, jittered by at most +-10% and floored at 0.9 times the previous wait of the same series
- `selftest_s_baseline=121` (full template self-test at HEAD before any edit); the full run after Task 1 was 122 s

## Decisions Made

- `RETRY_DEFAULTS` is never validated against `capS`. With `capS` 300 and a refused CONFIG `hard_waits_s`, the resolved waits stay `[600, 900, 1800]`; the cap stops the hard tier later (25.1-03).
- The timeout read passes no root to `workflowValue`, so it still follows a symlinked `.planning/config.json` the way gsd-tools `config-get` does. Only `resolveRetry` confines its reads. The dated SPEC amendment stays with 25.1-15.
- A refusal of a CONFIG value is logged as `retry.<key>` (CONFIG holds `retry`, not `cross_ai_retry`); a project or user refusal is logged as `cross_ai_retry.<key>`. Both name the source.

### Auto-fixed Issues

**1. [Rule 1 - Bug] The +-10% band is measured before rounding**
- **Found during:** Task 1 (pure-soft-waits)
- **Issue:** `Math.round` of a value 10% above nominal can land half a millisecond past `nominal x 1.1` (3713 vs 3375 x 1.1 = 3712.5)
- **Fix:** The case allows half a millisecond, which is the rounding, not extra jitter
- **Files modified:** skills/ai-kit-spec-review/references/cross-ai.mjs
- **Verification:** `pure-soft-waits` passes at factors 1.5, 1.01 and 1.0
- **Committed in:** `35a0368` (part of Task 1)

**2. [Rule 2 - Missing] The read-only case's stamp has to cross the two-run boundary**
- **Found during:** Task 2 (retry-config-read-only)
- **Issue:** `check` for a `second` case receives the `runTwice` result, which did not carry the case context where `setup` stored the file stamp
- **Fix:** `runTwice` spreads the case context onto its result, so the stamp, bytes and mtimes are visible after both runs
