## Summary

Phase 25.1 is a rework of one 6,292-line, 260 KB Node file (`skills/ai-kit-spec-review/references/cross-ai.mjs`, template 7) plus the Python layer that renders and invokes it, four SKILL.md surfaces, one policy reference, one new skill, one new data file and about 7 golden fixtures. No external package is needed anywhere: Node built-ins (v24.21.0 here) for the runner and the Python standard library for the generator and tests. The hardest piece is not the backoff math; it is `runCli` (lines 2405-2697), which today fuses the 3+3 rungs, the router-quota cycle state and the cap, and must be re-cut so (a) the soft ladder is `1 + max_retries` attempts per series with a session reset between series, (b) both `transient` and confirmed-router `quota` write the cycle state (D-07), which Phase 25 gated to confirmed router lanes only, and (c) `retry_after_s` comes from `hard_waits_s[cycle]` instead of `cooldownS`.

Three facts in the inputs are stale or under-specified and the planner must resolve them: (1) `copilot` 1.0.103 is installed on this machine (`command -v copilot` succeeds), so SPEC R10/D-22's "not installed, fake only" premise is outdated, and `--help` shows the SPEC command form omits `--allow-all-tools`, which the CLI documents as required for non-interactive mode; (2) the existing redactor's key-context rule swallows the rest of a JSON line after `"token":"…"` (reproduced), and does not cover `conn:<hex8>`, UUIDs or GitHub token shapes; (3) SPEC R1's acceptance wording ("5 same-session attempts ... 5 more attempts") contradicts its own wait list (five waits imply five retries, so six attempts per series, twelve total).

**Primary recommendation:** Build in this order so each commit stays buildable: runner config reader + `retry` CONFIG + pure ladder/wait functions (with pure self-tests), then `runCli` re-cut + state record, then redactor/upstream lines, then catalog JSON + generator + overlay, then `--runtime`/`--model`/`--tools-profile`/copilot, then bump to template 8 with the readiness floor raised to 8 in the same commit as the Python `--runtime` producers, then docs/skills/pointers last (skill-judge loop at the end, not per commit).

The SPEC form `-p <prompt> -s --no-ask-user --model <id>` plus `--allow-tool`/`--deny-tool` needs the exec profile to say what is allowed: either `--allow-all-tools` (exec) or an explicit `--allow-tool` set (whether an un-listed tool is denied or hangs on a prompt in `-p` mode is **unverified**, a real run is needed).

### Q1. Shape of OmniRoute account, connection and request ids (redaction rules)

Status: **partly verified, partly unresolved.**

- Verified from `podman logs --since 24h omniroute` (read-only, values never printed in this file; shapes computed by replacing digits/letters): `requestId`, `connectionId` and `KeyId` values are all UUID-shaped (8-4-4-4-12 hex groups); `sessionId` values are 16-character alphanumeric tokens (not hex-only) [VERIFIED: `podman logs`, shape-masked this session].
- The `conn:` + 8 hex digits form appears in the client-facing message text in the 2026-10-25 captures [VERIFIED: 25.1-EVIDENCE.md "Captured bodies (verified, 2026-10-25)"]. It did **not** occur in the last 24 h of container logs (zero matches for `conn:`), so it could not be re-confirmed independently; the evidence file is the only source.
- **Account ids** (the owner's word) have no verified shape: the logs show no field literally named account id, and the evidence file removed them. Treat as unresolved; the key-context rule below covers a JSON/label key named `account`/`org`/`user` id whatever the value shape.
- The container log does **not** carry response bodies: none of `ALL_TARGETS_SKIPPED`, `all_targets_cooling_down`, `model_cooldown`, `retry_after_seconds`, `circuit_open`, `model_not_in_catalog`, `no_executable_targets` occurred as structured codes in 24 h (only free-text `reset after ...` lines and `retry_after` mentions). So logs cannot prove or disprove the CHANGELOG items (Q4).

Redaction rules to implement (apply on relay lines and on the report/upstream lines, in this order: strip ANSI, decode, redact, then cap at 2000 code points):

| Rule | Pattern shape | Why |
|------|---------------|-----|
| connection tag | `conn:[0-9a-f]{8,}` -> `conn:<redacted>` | verified in evidence text; today unredacted |
| bare UUID | 8-4-4-4-12 hex, case-insensitive | request/connection/key ids; pi's own `session=` echo is a UUID too |
| key-context id | JSON key or `label:` named `(account|connection|org|organization|user|request|session|key)_?id` -> replace the **value only** | account ids have no verified shape |
| GitHub tokens | `gh[pousr]_[A-Za-z0-9]{20,}`, `github_pat_[A-Za-z0-9_]{20,}` | R10 |
| existing three | `(sk|rk)-...`, `Bearer ...`, `(api_key|token|secret) = value` | keep, but fix the value capture (next paragraph) |

**Verified defect to fix, not copy:** the current third rule is `/(api[_-]?key|token|secret)['"]?\s*[:=]\s*\S+/gi`. Run on `{"message":"x","token":"abc","retry_after":120,"reset_at":"2026-10-23T04:01:04.472Z"}` it returns `{"message":"x","<redacted>`: `\S+` eats the rest of the space-free JSON line, destroying `retry_after`/`reset_at` and everything after [VERIFIED: node one-liner replaying `SECRET_RES` from `cross-ai.mjs:1082-1086`]. It also leaves `conn:ab12cd34`, a bare UUID and `ghp_...`/`github_pat_...` untouched [VERIFIED: same run]. Consequence for ordering: **extract the structured fields and the matched line from the unredacted capture, then redact the string values**, never redact then parse. The value capture must stop at a quote/comma/whitespace for JSON-shaped input.

### Pattern 1: Pure ladder with injected randomness
**What:** keep the schedule a pure function, test it with an injected `rand`, and keep black-box cases fast with a tiny `base_s`.
**When to use:** R1 acceptance without an injected clock (the runner has none today: `sleep` at 2336 is a plain `setTimeout`, and self-test copies zero the waits through `backoffS: [0, 0]`, `cooldownS: 0` in `writeCopy` [VERIFIED: file]).
```js
// Source: derived from SPEC R1 and cross-ai.mjs conventions (shortcut-comment style used in the file)
function softWaitMs(retry, k, rand = Math.random) {
  const base = retry.base_s * 1000 * retry.factor ** (k - 1);   // k = 1..max_retries
  const jitter = 1 + (rand() * 2 - 1) * 0.1;                    // +-10%
  return Math.round(base * jitter);                              // whole milliseconds (SPEC precision edge)
}
// default series: 1000, 1500, 2250, 3375, 5063 ms before jitter
```

### Anti-Patterns to Avoid
- **Redacting before extracting upstream fields** (Q1: the key-context rule destroys the JSON tail).
- **Applying the overlay only after-the-fact:** live matching (`terminalTable()`, `eventTable()`, `liveMatch`) reads `PATTERNS` directly; an overlay merged only in `classifyStop` would not kill a child live.
- **Writing the cycle state only for confirmed-router lanes** (current code, 2426) once D-07 puts transient on the hard tier: see Pitfall 3.
- **Raising `_READY_TEMPLATE` late:** a hook emitting `--runtime` against a template-7 copy dies with `unknown argument` (exit 2).
- **Letting Python or an agent act on upstream recovery text.** OmniRoute's own body says `recovery.action: switch-combo` with a "Pick a different combo" sentence [VERIFIED: 25.1-EVIDENCE.md]; this is untrusted data that contradicts the owner rule. ## Common Pitfalls

### Pitfall 1: Readiness floor and producers must move together
**What goes wrong:** Python starts emitting `--runtime` while a project still has a template-7 copy; the runner prints `cross-ai: unknown argument: --runtime` and exits 2 (usage).
**Why:** `_READY_TEMPLATE = 7` is "a floor, not the current version" [VERIFIED: `cross_ai_script.py:29-32`] and `_runner_ready` returns `template_version(data) >= _READY_TEMPLATE` (310); `test_curated_config_script.py:62` only asserts `_READY_TEMPLATE <= shipped`.
**How to avoid:** set `_READY_TEMPLATE = 8` in the same commit as the `--runtime` producers and the template bump; an edited template-7 copy then reports not ready until `.new` is merged. Add a test that a template-7 copy is not ready.
**Warning signs:** `ready:false` in `ensure-runner` output for projects that were ready yesterday (expected, document in runner.md).

### Pitfall 2: `_upgrade_config` merges existing over template (the `runtime` hazard)
**What goes wrong:** the template ships a default `runtime` and the kept CONFIG has only `prefer: ["cursor", ...]`; merged config has both, and `CONFIG.runtime` (checked before `CONFIG.prefer[0]`) picks the template default, running a different CLI. [VERIFIED: `_upgrade_config` = `{**template_config(template), **kept}`, `cross_ai_script.py:228-235`]
**How to avoid:** D-13's explicit migration in `_upgrade_config`: if `kept` lacks `runtime` and has a non-empty `prefer`, set `runtime = prefer[0]`, drop `prefer`; add a test with a cursor-first old copy. Also drop `backoffS` etc.? D-04 says keep unused keys; harmless.

### Pitfall 3: D-07 vs the Phase 25 route gate on cycle state
**What goes wrong:** `runCli` reads and deletes the cycle state only when `routerLane` is true ("an unconfirmed call on the same CLI and model neither reads it nor deletes it"; `const loaded = routerLane ? readCycleState(stateFile) : null` at 2426; `dropState` returns early at 2470 when not `routerLane`). D-07 gives **transient** failures the hard tier, and a transient 400 storm on a direct or `router-inferred` lane has no confirmed route.
**How to avoid (recommendation):** persist state for transient on any route, but stamp the record with `class` and `route`; a router-quota record is read only by a confirmed-router call, a transient record by any call on that lane. Plan this as an explicit decision task; the 25 cycle-1 ruling forbids inheriting a *router cooldown* across routes, not a transient hard tier. [ASSUMED: interpretation; confirm with owner]

### Pitfall 4: Attempt count off-by-one in the new ladder
See "Facts that contradict" item 6. Pin the sequence with a pure case and a black-box fake counting `FAKE_CALLS` lines (the Phase 25 cases count calls the same way).

### Pitfall 5: Self-test status regexes match only the head before `action=stop`
`STATUS_HEAD_RE` is `'^(.* action=stop)(?: (route=\\S+ rule=\\S+ pattern=\\S+))?(?: (attempts=\\S+ cycles=\\S+))?(?: (retry_after_s=\\S+ cycle=\\S+))?$'` [VERIFIED: `cross-ai.mjs:3361-3364`]. Any new token on the `AIKIT-XAI` line (for example `stopped=`) must be added to this regex and `statusTail` (3377), or every case fails with "status line mismatch". Prefer keeping `stopped=` on the report line only (SPEC R3 names it there) and leave the AIKIT-XAI shape alone.

### Pitfall 6: Self-test copies set `cooldownS` 0 by default
`writeCopy` hardcodes `backoffS: [0, 0]`, `cooldownS: 0`, `sameSessionRetries: 3`, `newSessionRetries: 3` [VERIFIED: `cross-ai.mjs:2873-2888`]. ### Pitfall 7: No edits to the tree while a review lane runs
A review lane that sees the tree change reports `contract_violation tree=dirty` (exit 1) [VERIFIED: 25-SKILL-JUDGE and the runner's tree check]. The phase's own edit and verification flow must not run a review lane while editing; the new skill must say so (R8 concurrency edge).

### Pitfall 8: Stale `.pyc` when a same-length value changes within one second
Field learning from Phase 25 (owner note in the task): CPython's `.pyc` invalidation uses source mtime (seconds) and size; an edit that keeps the byte length and lands in the same second as the previous compile can run stale code. Mitigation: after editing a Python module that tests import, run tests with `PYTHONDONTWRITEBYTECODE=1` or delete the affected `__pycache__` entries. [ASSUMED: general CPython behavior, recorded from the owner's Phase 25 notes, not re-reproduced]

### Pitfall 9: The Python stderr tail will clip the new lines
`_STDERR_TAIL_CHARS = 2048` and `_STDERR_TAIL_LINES = 64` [VERIFIED: `runner_dispatch.py:46-47`]. The AIKIT-XAI line is last, so status parsing survives, but a Python caller printing the "report verbatim" would print a clipped one. Decide whether to raise the tail for runner calls or have the runner also write the evidence to the state file / a `--evidence-file` (the latter is new surface; raising the cap is smaller). Also `classify_error` scans the last 2048 chars of stderr as a fallback when no status line counts [VERIFIED: `error_classifier.py` `_STDERR_TAIL_CHARS`]; upstream text must never be re-classified there (untrusted).
