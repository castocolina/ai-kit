# 18.1-18: one command builder and one supervision core

The Python command-builder registry and both Python supervisors are gone. The runner builds every table runtime's command, grok keeps its custom-entry generator, and Rule 11 stops a second supervisor from coming back.

## Accomplishments

- Deleted the command-builder registry (`_COMMAND_BUILDERS`, every `_build_*_command` except grok's, `_build_command`, `_require_target_dir`, `_codex_effort_service_tier_flags`, `build_reviewer_command`, `build_execute_command`, `NO_HARD_SANDBOX_CLIS`, and the `_REVIEW`/`_EXECUTE` kinds). Renamed grok's builder to public `build_grok_command()`.
- `build-command` now prints `{"kind": "runner", "argv": [...]}` with a stderr note for a runner runtime, `{"kind": "custom", "command": ...}` for grok, and exits 1 naming the hand-written custom-command path for anything else (gemini included, no KeyError).
- Deleted `dispatch_with_heartbeat`, `dispatch_with_polling`, both seam types, and their private helpers. `child_env` and `write_resumable_state` stay; the module docstring names `runner_dispatch` as the one supervision core.
- Added test-arch Rule 11 (`_START_NEW_SESSION_ALLOWED`, `check_one_supervisor`, `supervisor_spawn_count`) with a non-vacuity case and a positive assertion that `runner_dispatch.py` holds the spawn.
- ai-kit-spec-config Step 2.4 stores `runtime`/`model` plus `effort`/`service_tier`/`cursor_mode` for a table runtime, and keeps the custom `command` path for grok and anything outside the runner. `TestRegistryIdsInTable` dropped the two deleted registries and gained `execute_dispatch.OS_SANDBOXED_EXEC`.
- Gates: `make test-unit` 41/41 + 1/1, `e2e-test` 7/7 plus 45 install checks, `arch-test` 1/1, and ruff, pylint, pyright, vulture all passed.
