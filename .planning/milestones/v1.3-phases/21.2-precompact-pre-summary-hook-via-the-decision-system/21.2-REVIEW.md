## Findings

### CR-01: Private-directory validation leaves writable ancestors unchecked
**File:** tools/hooks/precompact_core.py:825
**Issue:** Only the final `compact` directory is checked for ownership, permissions and symlinks. If `$XDG_CACHE_HOME/ai-kit` is writable by another user, `private_dir()` accepts a user-owned `compact` directory beneath it. That other user can rename the directory and replace it with a symlink after validation; subsequent pathname-based writes can expose transcript content outside the private directory. The existing test checks only a symlink at the final directory.
**Fix:** Reject symlinked or foreign-writable ancestors beneath the selected base, and retain a validated directory descriptor for file creation and replacement so swapping the pathname cannot redirect writes. Add an ancestor-replacement regression test.

### CR-02: Overlong lines lose their tails even when classified as keep
**File:** tools/hooks/precompact_core.py:456
**Issue:** `_cut_line()` retains only a fitting prefix and permanently discards the remainder before classification. For a user message containing `"A" * 8000 + "IMPORTANT-LAST-INSTRUCTION"`, the resulting document omits the final instruction even when every chunk is labelled `keep`. On pi, this document replaces the normal summary, making the loss persistent. `test_chunk_overlong_line_cut_with_marker` explicitly expects this lossy behavior. It violates locked SPEC R1’s line-boundary requirement and R4’s verbatim-kept-chunk rule.
**Fix:** If a line cannot fit without being cut, return no pre-summary and let normal compaction run. Replace the truncation test with a regression asserting fallback and preservation of the original input.

### WR-01: Hook-only uninstall also removes installed skills, agents and commands
**File:** tools/setup.py:3610
**Issue:** The category-link removal loops execute before checking `hooks`. Consequently, `setup.py uninstall --hooks=precompact` removes all owned category links under Claude and pi, not just the requested hook. The same happens with `--hooks=`, despite its warning saying nothing will be removed. The existing selective-uninstall test checks a foreign skill link, which these loops already preserve, so it misses this regression.
**Fix:** Run the category-link removal loops only when `hooks is None`. Add a selective-uninstall test containing owned Claude and pi skill links and assert they survive.

### WR-02: Claude transcript reading is unbounded and can block before classification
**File:** tools/hooks/precompact_core.py:1004
**Issue:** A host-supplied absolute path is accepted without verifying that it names a regular file. A FIFO passes `getsize()` but blocks in `open()`. A multi-gigabyte regular transcript is read in full twice, with additional copies made by `_lines()`, before classification can enforce its deadline. Neither path is bounded by the core’s classification timeout; Claude’s installed hook timeout is 15 seconds, exceeding locked R8’s 10-second adapter budget.
**Fix:** Open the transcript once with nonblocking, no-follow semantics, verify it is a regular file, and stream bounded lines and total bytes under an adapter-wide deadline. Return no pre-summary when a limit is exceeded. Test a FIFO and an oversized synthetic transcript.

### WR-03: Shim timeout and cancellation kill only the Python parent
**File:** tools/hooks/pi/ai-kit-precompact.ts:83
**Issue:** Both shims call `child.kill("SIGKILL")`, but the Python core launches a separate decision-client process. Aborting pi during a classification, or reaching the shim deadline while that child is running, kills the core without killing its child. The decision process can continue requests and logging after the handler returns. The timeout test substitutes an interpreter that uses `execv()`, leaving only one process, so it cannot detect this failure.
**Fix:** Start the core in an owned process group and terminate the group on timeout or cancellation, in both shims. Add a test interpreter that actually spawns a child and verify both processes are terminated.

### WR-04: Invalid UTF-8 on a boundary-looking line bypasses malformed-line recovery
**File:** tools/hooks/precompact_core.py:924
**Issue:** `last_boundary()` catches only `JSONDecodeError`, although `json.loads(raw_line)` can also raise `UnicodeDecodeError`. A line such as `b'{"type":"system","subtype":"compact_boundary","bad":"\xff"}\n'` aborts the entire transcript read. The outer fail-open handler prevents a host error, but valid surrounding messages are never processed. The existing invalid-UTF-8 test lacks the boundary marker, so it misses this branch.
**Fix:** Catch `UnicodeDecodeError` during boundary detection and let the normal transcript parser skip and count the malformed line. Add a fixture containing this line between valid messages.

### WR-05: Wizard reports success when hook installation fails
**File:** tools/setup.py:2872
**Issue:** `_make_wizard_commit()` ignores the boolean returned by `apply_hook_selection()`. If pi’s extension destination contains a foreign file, or Claude’s hook settings are refused, hook installation returns `False` but the wizard still returns `{"ok": True}` when status-line adoption is disabled. Thus the new knob can fail while the completion screen reports success.
**Fix:** Fold the hook result into `ok`, and preserve that failure if status-line persistence subsequently succeeds. Add a commit-path test with a foreign hook destination and assert `outcome["ok"]` is false.

### WR-06: The cap rejects a protected document that fits exactly
**File:** tools/hooks/precompact_core.py:555
**Issue:** The protected-size calculation adds two separator characters for every protected entry without subtracting the unused final separator. For example, `apply_cap("h", [("keep", "x" * 9499)])` returns `None`, although the complete document is exactly 9,500 characters. The equivalent pi boundary with a pinned previous summary also falls back unnecessarily. This contradicts the locked SPEC edge requiring exactly 9,500 characters to be accepted.
**Fix:** Calculate the protected floor using the same actual joining rules as the final document. Add exact-cap tests with one kept entry and with a pinned summary plus the newest kept entry.

## Ponytail pass (verbatim)

### What this change does

Phase 21.2 adds a local-only, extractive pre-summary before compaction, with delivery adapters for Claude Code, pi and experimental opencode. It also adds the hook registry, wizard selection and headless installation/removal. This review preserves every SPEC/CONTEXT-required feature and assumes the documented single-user workload.

### Must fix

1. **HIGH — Hook-only uninstall also removes installed skills** — `tools/setup.py:3610–3619`  
   Both skill-unlinking loops run **before** checking `hooks`. Consequently, `uninstall --hooks=precompact` removes unrelated ai-kit component links; even `--hooks=` does so despite warning that nothing will be removed. The e2e test misses this because it checks a **foreign** skill link, not an owned one.  
   **Smaller change:** Put the existing component-unlinking block inside `if hooks is None`; add an owned-link preservation assertion.  
   **Estimated saving:** 0 lines; this needs a guard, not deletion.

### Should fix

2. **MEDIUM — Handwritten subprocess wrappers duplicate Node functionality and corrupt split UTF-8** — `tools/hooks/pi/ai-kit-precompact.ts:65–129`; `tools/hooks/opencode/ai-kit-precompact.ts:71–121`  
   Both wrappers implement output buffering, timeout killing, exit handling and—in pi—abort handling. They decode each stdout buffer independently, so an accented character or emoji split between buffers becomes replacement characters. I reproduced this with split UTF-8 buffers; the existing encoding test does not force that boundary.  
   **Smaller change:** Use `node:child_process.execFile` in each self-contained shim, with `timeout`, `killSignal: "SIGKILL"`, `maxBuffer`, UTF-8 encoding and pi’s `signal`; retain stdin writing, its error handler and JSON parsing. No shared extension file is needed.  
   **Estimated saving:** 80–100 lines across both shims.

3. **MEDIUM — The transcript reader loads and splits the entire transcript twice** — `tools/hooks/precompact_core.py:908–944, 1003–1020`  
   `last_boundary()` reads the whole file and constructs a list of copied lines. `read_claude_transcript()` then reads it again and constructs another line list. `MAX_CHUNKS` only applies afterward, so it does not bound this memory work. This contradicts R2’s line-by-line reading requirement and adds avoidable cost as a transcript grows.  
   **Smaller change:** Use one size-bounded binary line iterator. Clear accumulated active messages and reset active-part counters at each recognized boundary; preserve the boundary predicate and shared-fixture parity test. Delete the blob splitter and second scan.  
   **Estimated saving:** Approximately 20–30 lines, plus removal of whole-file byte/line copies.

4. **MEDIUM — One malformed UTF-8 line can discard the entire usable transcript** — `tools/hooks/precompact_core.py:922–926`  
   A line containing `"compact_boundary"` reaches `json.loads(raw_line)`, but this handler catches only `JSONDecodeError`. Invalid UTF-8 raises `UnicodeDecodeError` instead. I reproduced the exception with a malformed boundary-shaped line followed by a valid user message; the outer fail-open path then abandons the pre-summary rather than skipping the bad line.  
   **Smaller change:** Catch `UnicodeDecodeError` alongside `JSONDecodeError` here—or in the single-pass reader from finding 3—and add this case to the existing invalid-UTF-8 test.  
   **Estimated saving:** 0 lines; one exception tuple extension.

5. **MEDIUM — The wizard throws away hook installation failures** — `tools/setup.py:2872, 2951–2956`  
   `apply_hook_selection()` already returns failure for refused settings, foreign link paths and failed writes, but `commit()` ignores it. With `adopt=False`, the wizard reports `ok=True` even when the selected hook was not installed. With adoption enabled, the status-line result alone determines success.  
   **Smaller change:** Include the existing hook result in `ok`, and combine rather than overwrite that result when persisting the status line. Extend the current wizard test with a foreign plugin file.  
   **Estimated saving:** 0 lines; reuse the error result already provided.
