## Summary

Three findings reshape the plan. First, the 21.1 client does not exist on this branch yet: `skills/jev-fast-decision/` is absent here (only 21.1 plans exist) [VERIFIED: directory listing this session]. Phase 21.2 cannot be executed before 21.1 lands; the planner must make "client present and `CLIENT_PROTOCOL = 2`" a Wave 0 gate and develop 21.2 against a stub client selected by env (D-18) so tasks stay testable regardless. The stdin contract to stub is `{"reviewed_head": <40 hex>, "items": [{id, type:"choice", instructions, criteria, context}]}` with results under `answers` (v3 reference, to be matched with the 21.1-01..05 plans); the kill switch `GSD_PATH_JEV=1` and `GSD_PATH_JEV_TIMEOUT_SECONDS` must be set in the child env or the client answers `disabled`/`invalid_timeout`.

Second, the Claude route cannot save anything by construction. Claude Code's summarizer request reuses the warm prompt cache and sends the same history (docs: a mid-session `/compact` "costs a fraction of what the context size suggests"), PreCompact can only block, and the documented compact-SessionStart injection ADDS up to 9,500 characters after Claude's own summary. The honest predicted verdict is non-positive on time and context size; the plan should build the adapter (locked) but treat the Claude spike as a delivery-feasibility check and ship the knob default off unless the numbers contradict this. pi is the only host where the model call itself disappears (`session_before_compact` return replaces it, confirmed in installed `agent-session.js`), so pi carries the real saving; opencode can only add context to a summary that still runs.

Third, throughput is the hidden risk. With one client process per chunk (D-02) and a 10 s total budget (R8), an active transcript of hundreds of KB yields hundreds of chunks, but only a few dozen process spawns fit the budget. The core needs a deterministic pre-pass (drop thinking, system reminders and tool-output bodies down to head lines before chunking) and a priority order for what gets classified (newest first), with everything unclassified counting as `keep` and trimmed by the R4 cap. The spike must measure per-call latency (spawn plus Laya) to size this; that number, not the 15 ms Laya figure, bounds classified chunks per run.

**Primary recommendation:** Build the stdlib core with a deterministic pre-pass and a newest-first classified window; run the S1 (Laya truncation + per-call latency) and S2-S4 (host observations) spikes before any adapter task; ship pi as the only default-on candidate, Claude and opencode default off pending numbers.

### Pattern 1: Version-tolerant Claude transcript reader
**What:** read bytes line by line; `json.loads` each in a try; keep dicts only; count `skipped_malformed`, `skipped_unknown_type`; the boundary rule is `type == "system"` and `subtype == "compact_boundary"` (copied from `probe_transcript_compaction`); the active part is every line after the LAST recognized boundary, else the whole file with `boundary_unrecognized: true` in the header counters.
**Message extraction (synthetic-fixture-defined, all `[ASSUMED]` to match real files; the repo's own tests use this shape):** `type` in `user|assistant`; `message.content` is a string OR a list of blocks (`text`, `tool_use` {name,input}, `tool_result` {tool_use_id,content}, `thinking`); everything else skipped and counted. `[CITED: tests/test_ai_kit_usage_metrics.py:78-115 synthetic lines; tools/status-line.py util_iter_tool_uses docstring: "message.content is a list of blocks for tool turns but a plain string for text turns"]`. The transcript format is not documented by Anthropic (docs only say "Path to conversation JSON", the examples end in `.jsonl`) [CITED: code.claude.com/docs/en/hooks, common input fields].
**Verbatim boundary rule (to pin by a shared-fixture test)** [CITED: tools/status-line.py probe_transcript_compaction, read this session]:
```python
if (rec.get("type") == "system"
        and rec.get("subtype") == "compact_boundary"):
```
**Bound the read:** the whole-file scan must not be unbounded. Read at most the last N MB (name the constant, e.g. 32 MB) and treat the cut as "boundary unrecognized". The docs warn the file "is written asynchronously and may lag the in-memory conversation", so the newest messages can be missing at PreCompact time (spike S2 measures this).

### Pattern 2: Extractive build with the cap (R4)
Chronological list of `(label, text)`; if `len(text) > 9500`: drop oldest `summarize` lines first, then trim oldest kept chunks at line boundaries (never inside a code fence line or a multi-byte char: operate on `str`, not bytes), newest kept chunk whole. The budget is Python `len` (characters), which is how the host cap counts (docs: "capped at 10,000 characters").

### Pattern 3: Claude delivery (documented)
- `PreCompact` entry: `{"matcher": "manual|auto", "hooks": [{"type": "command", "command": "python3 -S <script>", "timeout": 15}]}`. Always exit 0, never print `decision`. Set `timeout` explicitly: the documented default for command hooks is 600 s, which would let a hung hook hold a compaction for 10 minutes [CITED: code.claude.com/docs/en/hooks, `timeout` field].
- `SessionStart` entry with matcher `compact`. Documented: "SessionStart hooks that match the `compact` source: Claude Code runs them and adds their output to the compacted context" [CITED: code.claude.com/docs/en/context-window#what-survives-compaction]. Output envelope is the same as `claude_session_start.emit` (`hookSpecificOutput.hookEventName = "SessionStart"`, `additionalContext`).
- It is a different entry from the briefing (`CLAUDE_HOOK_MATCHER = "startup|compact"`, `CLAUDE_HOOK_MARKER = os.path.join("tools", "hooks", "claude_session_start.py")`) [CITED: tools/setup.py:1379-1381]. On `compact` both SessionStart entries run; each string has its own 10,000-char cap [CITED: hooks docs, "Claude Code measures each string on its own"].
- Over-cap is not an error path to rely on: >10,000 chars is replaced by a path plus a 2,000-char preview ("Claude Code doesn't ask Claude to read the file"). 9,500 leaves 500 chars of margin for the envelope text.

### Pattern 4: pi delivery (read from installed files)
Event (installed `types.d.ts`): `SessionBeforeCompactEvent { preparation, branchEntries, customInstructions?, reason: "manual"|"threshold"|"overflow", willRetry, signal }`. Result: `{ cancel?, compaction?: { summary, firstKeptEntryId, tokensBefore, estimatedTokensAfter?, usage?, details? } }`. In `agent-session.js` an extension `compaction` replaces the default summary generator (the default LLM call is skipped; `fromExtension = true`). Preparation: `firstKeptEntryId, messagesToSummarize, turnPrefixMessages, isSplitTurn, tokensBefore, previousSummary?, fileOps, settings`. Messages are `AgentMessage` with roles `user|assistant|toolResult|bashExecution|custom|branchSummary|compactionSummary` (consumers "should tolerate unknown custom roles").
Facts that bite:
- `fileOps` is `{read: Set, written: Set, edited: Set}`; `JSON.stringify` turns a Set into `{}`. The shim must convert Sets to arrays itself (pass-through still needs this one conversion).
- ImageContent carries base64 `data`; thinking blocks carry opaque signatures. Strip images and thinking in the shim, or in Python before chunking; never pipe megabytes of base64.
- "Pi does not automatically carry file lists from extension-generated summaries whose `fromHook` field is `true`; extensions manage their own `details`": after a hooked compaction, pi's later default compaction loses the cumulative read/modified file lists unless the pre-summary carries them. Put a compact file list (from `fileOps`) inside the summary text, as pi itself appends file lists [CITED: docs/compaction.md "Cumulative File Tracking", "Summary Format"].
- The pi handler has no documented timeout; only `signal`. The shim must run its own timer (R8: 10 s including process start) and kill the child.
- The default flow summarizes from the previous kept boundary and merges `previousSummary` (D-08). Default tool results are truncated to 2000 chars at serialization; the extractive builder should apply the same head-lines idea.

### Pattern 5: opencode delivery (version-gated)
Legacy hook (local types 1.18.5): `"experimental.session.compacting"?: (input: {sessionID: string}, output: {context: string[]; prompt?: string}) => Promise<void>` with the comment "`prompt`: If set, replaces the default compaction prompt entirely"; docs: "When `output.prompt` is set ... The `output.context` array is ignored" [CITED: local `@opencode-ai/plugin` `dist/index.d.ts:283-288`, opencode.ai/docs/plugins]. Messages: `client.session.messages({ path: { id }, query: { limit } })` returns `Array<{ info: Message; parts: Array<Part> }>`; `Part` includes `text` (`text`, `synthetic?`, `ignored?`), `tool` (`tool`, `state.status`, `state.output`, `state.time.compacted?`), `reasoning`, `compaction` (`auto: boolean`); AssistantMessage has `summary?: boolean` [CITED: local `@opencode-ai/sdk` `types.gen.d.ts`]. A prior compaction is visible as a `compaction` part and an assistant message with `summary: true`: use both as the boundary, tolerate neither.
**Version gap (do not assert):** the local plugin package also ships `dist/v2/*` entry points (`./v2/effect`, `./v2/promise`) whose `.d.ts` files contain no occurrence of "compact" (grep this session). A search of the installed opencode binary's raw bytes found no `experimental.session.compacting` string, but it also found no `tool.execute.before` (a core, documented hook), so the binary does not expose hook names to byte search and this absence means nothing. Whether v2.0.31 still calls the legacy hook is therefore `[ASSUMED]` and is spike S4's question. Do not execute `opencode --version` in research or planning (project rule); the spike observes it inside a scratch session with a scratch config dir.

### Pattern 6: Registry, wiring, headless
- One tuple of flat rows (D-11). The Claude writer must validate both event keys (`PreCompact`, `SessionStart`) before its single `_atomic_write_json`; the current `_load_hook_config(path, event_key, nested)` validates one key per call [CITED: tools/setup.py:1495-1512]. Generalize to validate a set of keys, then mutate both, then write once.
- Ownership marker per row: the briefing marker is `tools/hooks/claude_session_start.py`; the new rows use `tools/hooks/claude_precompact.py`. Both markers are matched by substring (`_entry_is_ours_nested`), so make sure neither path is a substring of the other (they are not). The `SessionStart` precompact entry and the briefing entry live in the same `hooks.SessionStart` list; `_refresh_or_append_claude_hook` currently replaces "the" ai-kit SessionStart entry by marker, so it must be keyed by the row's marker or the briefing refresh would clobber the injector entry (and vice versa).
- Headless: `--with-hooks` is `action="store_true"` today [CITED: tools/setup.py:3126]; change to `nargs="?"` with a sentinel `const`; validate ids because `--headless --with-hooks install` parses `install` as the value (D-13, live argparse check recorded in CONTEXT).

### Anti-Patterns to Avoid
- **Importing `jev_review.py` in-process or going through `decide.py`:** locked out by D-01; `decide.py` rejects fields over 1,500 chars, code fences and secret-shaped runs [CITED: 21.2-CONTEXT D-01 evidence].
- **Returning `decision`/non-zero from PreCompact:** blocks compaction (auto: skipped; recovery: request fails) [CITED: hooks docs].
- **Using `os.path.realpath`-less shim lookup:** the pi shim is a symlink; resolve the core from the realpath (spike S3 checks what jiti reports).
- **Reading the real `~/.claude/projects` transcripts for fixtures:** forbidden; build synthetic JSONL.
- **A sandbox-less spike against real config:** use `CLAUDE_CONFIG_DIR`, `PI_CODING_AGENT_DIR`, `OPENCODE_CONFIG_DIR` pointing at `./tmp/` scratch dirs.

## Common Pitfalls

### Pitfall 1: Process-per-chunk cannot meet a 10 s budget on a real transcript
**What goes wrong:** hundreds of chunks times per-call cost (Python start of the client + Laya) overshoot 10 s; nearly everything becomes `keep`, so the summary is mostly truncated raw text and Jev adds little.
**Why:** D-02 plus R8 plus a transcript far larger than 9,500 chars.
**How to avoid:** deterministic pre-pass shrinks input first; classify newest-first inside the budget; count `unclassified` in the header; spike S1 measures ms per call. If measured cost makes classification a rounding error, record that in the verdict instead of hiding it.
**Warning signs:** header shows `classified << total`.

### Pitfall 2: Client answers `disabled` or `invalid_timeout`
**What goes wrong:** every item fails, the hook silently produces nothing.
**Why:** the v3/21.1 client returns `{"status": "disabled"}` unless `GSD_PATH_JEV=1`, and requires a positive finite `GSD_PATH_JEV_TIMEOUT_SECONDS` [CITED: v3 `jev_review.py` main/screen on `main`; 21.1-01 plan must_have "With `GSD_PATH_JEV` unset the client returns `{"status": "disabled"}`"]. The D-01 scrub removes the inherited values, so the core must set them.
**How to avoid:** child env = scrubbed parent + `GSD_PATH_JEV=1`, per-call `GSD_PATH_JEV_TIMEOUT_SECONDS`, `JEV_BACKEND=<pinned>`, `JEV_CALLER=ai-kit-precompact`, optionally `GSD_PATH_JEV_DEADLINE_SECONDS`. Test: a stub client that records its env.

### Pitfall 3: Laya truncation looks like a confident answer
**What goes wrong:** a chunk beyond Laya's window is classified on its first part only.
**Why:** english window 512 tokens, multilingual 1024 [CITED: 21.1-RESEARCH Pitfall 2, `serve.py:96-104`]; code and non-English text use more tokens per character than prose.
**How to avoid:** the client forces `needs_fallback` on `usage.truncated` or over the row's `state_chars_limit` (planned 2000); the core maps `needs_fallback` to `keep`. Choose `CHUNK_CHARS` below the point the spike finds on code-heavy and non-English fixtures, not on prose.

### Pitfall 4: Session-file glob and prefix collisions
**What goes wrong:** `glob` with an unvalidated `session_id` containing `[`, `*`, `?` matches other sessions' files; a session id that is a prefix of another (`abc` vs `abc-def`) matches the wrong `{id}-*-compact.md`.
**How to avoid:** strict allow-list regex for `session_id` (letters, digits, `-`, `_`; length cap; the existing `util_safe_session` only rejects separators and `..`, which is weaker) [CITED: tools/status-line.py:1600-1604 (CONTEXT cited :1008, which has drifted)]; list the directory with `os.scandir` and compare, and verify an in-file header line `session_id: <id>` equals the caller's id before injecting. Never `glob`.

### Pitfall 5: A late or concurrent writer replaces a file the injector is reading
**How to avoid:** write only via `mkstemp` + `os.replace` in the same directory; the injector reads then `unlink`s; a read error or missing file returns `{}`.

### Pitfall 6: Second-order prompt injection through the summary
**What goes wrong:** old tool output (a fetched web page, a file) carrying instructions is re-surfaced inside a `system-reminder` (Claude `additionalContext`) or as pi's authoritative summary, with higher authority than where it first appeared.
**How to avoid:** the file header states the content is verbatim transcript excerpts to be treated as data; the pre-pass keeps tool results to head lines only; classification `instructions` are fixed English text and the chunk goes only as `context`. This reduces, not removes, the risk: record it as a residual risk in the threat model.

### Pitfall 7: pi and opencode stale-symlink / foreign-file cases
`link_one` already refuses a foreign file; the uninstall must unlink only links whose target is inside `install_dir`. pi loads every direct `.ts` and `.js` in `extensions/` [CITED: docs/extensions.md "Add it to Pi"; loader `readdirSync` accepts files and symlinks], so a second helper file beside the shim would be loaded as another extension: keep the shim self-contained.

### Pitfall 8: Test-group listing drift
Adding `tests/test_*.py` modules without running `tools/gen_test_groups.py` fails `tests/test_gate_scope.py`. Add a task step.

### Pitfall 9: Hook timeouts
Set `"timeout"` on both Claude entries (PreCompact ~15 s, injector ~10 s). pi/opencode have no documented handler timeout; the shim enforces its own.

### pi shim skeleton (self-contained, no extra files)
```typescript
// Source: pi docs/compaction.md "session_before_compact"; D-07
import { spawn } from "node:child_process";
import { realpathSync } from "node:fs";
import { dirname, resolve } from "node:path";
import { fileURLToPath } from "node:url";

export default function (pi: any) {
  pi.on("session_before_compact", async (event: any, ctx: any) => {
    try {
      const here = realpathSync(fileURLToPath(import.meta.url)); // S3: what does jiti report?
      const core = resolve(dirname(here), "..", "precompact_core.py");
      const p = event.preparation;
      const input = JSON.stringify({
        messages: p.messagesToSummarize, turnPrefix: p.turnPrefixMessages,
        previousSummary: p.previousSummary ?? null,
        fileOps: { read: [...p.fileOps.read], written: [...p.fileOps.written], edited: [...p.fileOps.edited] },
        sessionName: ctx.sessionManager?.getSessionName?.() ?? null });
      const out = await runPython(core, input, 10_000, event.signal); // kill on timeout/abort
      if (!out?.summary) return undefined;
      return { compaction: { summary: out.summary, firstKeptEntryId: p.firstKeptEntryId,
                             tokensBefore: p.tokensBefore, details: out.counts } };
    } catch { return undefined; }
  });
}
```

## Measurement Method (PCH-02, R9)

- **Arms.** Baseline = host with the same hooks/extension installed in *measure-only* mode (logs monotonic and wall timestamps, does no chunking, classification or file work) so instrumentation overhead is identical; hooked = full mode. Same synthetic session shape, same scratch config, baseline runs first (R9 ordering edge). N >= 3 per arm per host.
- **Time metric.** Claude: wall time from the PreCompact log line to the compact-SessionStart log line. pi: `session_before_compact` handler entry to `session_compact` event, plus RPC `compact` round trip. opencode: hook entry to `session.compacted` event.
- **Size metric.** Claude: `PostCompact.compact_summary` length plus injected characters (the hooked arm adds up to 9,500), and status-line `context_window` after compaction; transcript `preTokens`/`postTokens` recorded but labelled reverse-engineered. pi: `CompactionResult.estimatedTokensAfter` (documented heuristic, not provider-exact) and `tokensBefore`. opencode: characters only (token fields unverified).
- **Verdict rule (conservative, so N=3 noise cannot flatter the hook).** `positive` only if every hooked time is lower than every baseline time AND the median post-compaction size is not larger; `non-positive` otherwise (including exactly zero); `unmeasured` with fewer than 3 runs in either arm. The artifact records units with every number. The verdict string is what `component_meta` quotes in setup (R9 acceptance).
- **Predicted outcomes (to be overturned only by data):** Claude non-positive (adds hook time and injected characters; Claude's summarizer still runs and reuses a warm cache); pi plausibly positive on time (no model call) but the size comparison is against pi's structured default summary; opencode non-positive or `unmeasured` if the hook is absent. These are predictions, tagged `[ASSUMED]`.
- **Quality is not measured** by R9. Record one qualitative note per host (did the post-compaction session still know the task?) so a positive time verdict is not read as a quality claim.
