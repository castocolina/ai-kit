# v1.3 Phases 16–27 — One-Shot

This is an OpenGSD project, so the run uses `/gsd-autonomous` with convergence. GSD delegates a
plan to cross-AI only when its frontmatter has `cross_ai: true`; without it, that step is
skipped. Start Claude Code in the v1.3 worktree with the jev variables exported, then paste the
block.

```
/gsd-autonomous --from 16 --to 27 --converge

OBJECTIVE
Finish ai-kit v1.3 Phases 16 to 27, each one verified. Then leave the repository clean.

ROLE
You are the orchestrator. Dispatch plan work to subagents, reusing one or starting a fresh one
as you judge best. Verify every result yourself; never accept a reported "passed".

RULES FOR EVERY PLAN
- Every PLAN.md frontmatter carries cross_ai: true, so GSD delegates it to cross-AI.
- Reviewers come from .planning/config.json. Probe each one once before the first review.
  Record any failure; never substitute a model.
- Read AGENTS.md, then the phase SPEC and CONTEXT. Their decisions are locked; never
  re-discuss them.

ORDER
- Numeric. Phases 20, 21 and 22 (each needs only 19) and 23 may continue past a parked phase.
- 16 and 24: verify only. 24 also gets a cross-AI skill-judge re-run.
- 16.1 to 19: before planning, run edge_floor.py check on the SPEC; if it fails, regenerate
  the table.
- 21: run its D-01 spike in a scratch Cursor config dir.
- 26: run its SPEC R2 spike before planning.
- 27: plan only after 26 is executed. Its output must stay short.

QUOTA
- This session: create one hourly CronCreate job that resumes the earliest incomplete phase
  from STATE.md. Delete it when the run is done.
- Cross-AI child limits:
  - Router-env routes wait. Direct Zen, Go or Cursor billing errors do not.
  - Clean tree and another candidate available: fall back. Dirty tree: wait, then resume the
    same session.
  - Re-check every 10 minutes, for at most 4 hours.
  - Answer GSD's retry prompt only after the wait.

DECISIONS
- Verifiable: fix it directly.
- Gray areas: use the decide.py ladder (Laya, then TypeSafe, then your own reasoning). Prefer
  the best design over the easiest. Log every decision.
- Use the same ladder (it calls the jev-fast-decision client) at every other workflow decision
  point too: escalation and "proceed anyway" gates, REVISION_CONFLICT resolution, checkpoint
  decisions, triage of review and plan-checker findings, ambiguous quota-error routing. Answers
  are advisory: verify before acting, and treat a low-confidence answer as "reason it yourself".
- Code mapping and intel (map-codebase, intel updates, pattern mapping, research): run
  `codegraph sync` first, then search with the `codegraph_explore` MCP tool. A subagent without
  MCP access runs `codegraph explore "<query>"` in the shell instead. Fall back to rg or
  reads only for what CodeGraph does not index.
- Plan review: every phase's plans also get a read-only `ponytail:ponytail-review` pass (is
  each change needed? over-engineered? does it reuse what exists? any missing callers or tests?).
  It runs alongside the plan checker, and its findings go to the replan the same way the
  checker's findings do.
- Never pause for UAT or questions. Put critical items that block nothing in the ledger and
  continue.
- Never remove existing features.

SAFETY
- Never touch the real ~/.claude, ~/.cursor, ~/.config/opencode, ~/.codex, ~/.pi or ~/.gsd.
  Use a scratch HOME or make e2e-docker instead.
- No real curated-config apply on this repo.
- Never print secrets.
- Never push, never skip pre-commit hooks, never stage everything blindly.
- GSD is installed per project: any new worktree must resolve gsd_run or get its own local
  install.

DONE WHEN (print each command with its exit code)
- Every phase 16 to 27 shows verification status passed, or appears under human_verification
  with the reason.
- make test, make validate and make e2e-test pass and print a test count above zero.
- make e2e-docker passes for every phase that touches tools/*.py, tools/install.sh or a
  config-writing SKILL.md.
- Every process an e2e run started is killed, with proof.
- Every new or changed skill has committed skill-judge evidence with no open Critical or
  Important finding.

CLEANUP
1. Leave no stray files.
2. Remove the directory and ROADMAP entry of each 999.x item that a phase completed. List the
   rest for uz.
3. Merge the v1.3 branch into main in the main checkout. The quota todo exists on both
   branches; keep both edits. Stop on non-trivial conflicts.
4. Delete the merged branch.
5. For every other worktree: tag its unmerged branch archive/<branch>, then remove the worktree
   and its branch.
6. Remove the v1.3 worktree last. Force the removal only if all that remains in it is the
   ignored GSD install.

STOP IF
- A decision blocks other phases and nothing resolves it.
- The same failure repeats 3 times with no progress.
- A step needs a real config write, a login or sudo.
- Every cross-AI candidate for a role is unusable.
In each case, park the phase, continue the independent ones, then report.

REPORT (in Spanish)
- Per phase: status, verification, the cross-AI CLI used, e2e evidence.
- The ledger: this run's decisions, plus every entry marked "Ledger" in the phase CONTEXT
  files.
- human_verification items and quota waits.
- One advisory jev closeness check. It is a note only, never a gate.
- Commits and tags made. Nothing pushed.
```
